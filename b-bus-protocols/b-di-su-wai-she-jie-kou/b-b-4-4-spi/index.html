    B-B.4.4 SPI 调试与选型¶

    所属章节：第五部 B. 总线协议 > B-B.4 SPI 总线

    难度：[B→I] Beginner → Intermediate | 预计阅读时间：35 分钟

    本节导读¶

    **SPI 读不到或读错数据时，怎样用一笔答案已知的 JEDEC ID 读取逐层缩小故障范围，选择下一项检查，并恢复正常基线？**本页给出的产出不是一张从头做到尾的工具清单，而是一条可判定的调试路径：先确认正常读取，再根据异常选择内部回环、外部短接、完整数字帧或模拟波形，最后撤销隔离措施和临时参数，用同一笔读取复测。

    完整路径从用户命令进入 spidev，经 SPI Core、RK3568 SPI1 控制器、引脚与接线到达 W25Q128JV，再由 MISO 和接收缓冲区把结果交回用户态。任何一层都可能让最终 ID 出错；每项检查只覆盖其中一段，所以“测试成功”必须连同覆盖范围一起解读。

    JEDEC ID：器件按 JEDEC 标准返回的身份标识。本例用它提供已知答案，避免拿内容未知的数据区判断通信是否正确。

    spidev：把 SPI 设备暴露为 /dev/spidevB.C 字符设备的内核驱动。B 是总线号，C 是片选号；用户态程序通过 open() 和 ioctl() 配置并发起传输。

    贯穿实例固定为 RK3568 SPI1 CS0、W25Q128JV-IQ/JQ、Mode 0、8 位、MSB-first（每字节最高位先传）、低有效 CS 和 1 MHz 请求速率：

    TX：9F 00 00 00
有效 RX：?? EF 40 18
拍数：8 拍命令 + 24 拍响应 = 32 拍

    0x9F 是 Read JEDEC ID 命令，后三个 00 只用于继续提供时钟。?? 表示命令阶段的接收值不参与身份判断；有效判据是 RX[1]～RX[3] = EF 40 18。这个答案只适用于本例 IQ/JQ 后缀，IM/JM 后缀的 Device ID 不同。

    SPI 位流、事务帧和 Linux 对象模型分别见 B-B.4.1～B-B.4.3。本页只在调试需要时回收这些结论；设备创建与驱动匹配的展开归 B-B.4.3，正式产品接入与烧录归 B-B.4.5，速率与接口选择归下一页。

    先取得一次可判定的正常结果¶

    确认这笔受控读取可以安全执行¶

    正常路径是受控工具验证，不是现场 Flash 的日常访问方式。开始前同时满足四个条件：

    1. 专用测试节点 spi1.0 已绑定 spidev，字符设备为 /dev/spidev1.0。
    2. 当前节点没有同时绑定 spi-nor（内核的 SPI NOR Flash 驱动）或其他协议驱动。不要在启动盘、已挂载根文件系统或业务正在访问的 Flash 上换绑驱动。
    3. 原理图已确认 SPI1 CS0 连接本例 W25Q128JV-IQ/JQ，供电、共地、CS、MOSI、MISO 和必要状态引脚符合器件手册。
    4. 当前账户有权读取 sysfs（内核导出设备对象与属性的文件系统）、打开字符设备并执行 spidev_test。工具来自 Linux v6.6 的 tools/spi/spidev_test.c，目标系统应使用与内核 UAPI（用户态与内核之间的接口约定）兼容的构建版本。

    🔴 回环短接和驱动换绑都可能改变现有硬件或软件状态。只在专用测试环境执行；外部短接前必须断电并隔离可能同时驱动 MISO 的 Flash，结束后恢复连接再复测。

    先检查驱动绑定和字符设备。readlink 读取驱动符号链接，basename 去掉目录部分，test -c 检查路径是否为字符设备：

    basename "$(readlink /sys/bus/spi/devices/spi1.0/driver)"
test -c /dev/spidev1.0
printf 'char_device_check=%d\n' "$?"

    满足前提时，完整预期输出为：

    spidev
char_device_check=0

    spidev 证明当前绑定驱动名称，0 证明 test -c 成功。若 readlink 报错、名称不符或字符设备不存在，应停止传输，转入 B-B.4.3 检查控制器注册、设备创建和驱动匹配。设备存在与驱动绑定是两个阶段，不能由“没有 /dev”反推 Flash 没有上电。

    用 0x9F 同时核对工具返回和有效 ID¶

    下面的 -D 选择设备，-s 1000000 设置 1 MHz 请求上限，-p 给出四个发送字节，-v 打印收发缓冲区。工具显式设置 Mode 0、8 位字长和 MSB-first；单条 SPI_IOC_MESSAGE(1) 让四字节处于同一笔全双工传输，也就是发送与接收在同一组时钟中进行。

    spidev_test -D /dev/spidev1.0 -s 1000000 -p '\x9f\x00\x00\x00' -v
printf 'exit=%d\n' "$?"

    以下输出依据 v6.6 工具打印逻辑和器件手册推演，不是当前板卡实测。为展示完整格式，假设不参与身份判断的 RX[0] 恰好为 00；实际也可以是其他值。

    spi mode: 0x0
bits per word: 8
max speed: 1000000 Hz (1000 kHz)
TX | 9F 00 00 00 __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ |....|
RX | 00 EF 40 18 __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ __ |..@.|
exit=0

    spi mode: 0x0 是驱动读回的当前模式，不只是用户输入；若控制器改写了请求模式，工具会先打印警告。max speed 是用户态读回的请求上限，不是引脚实测频率，v6.6 spidev 文档明确说明该接口不能报告实际移位速率。

    每行末尾的 __ 是工具把不足 32 字节的显示行补齐，不是总线上额外的数据。竖线后是不可打印字节显示为点的 ASCII 区，0x40 因而显示为 @。这些显示字段都不改变有效判据：TX 必须为 9F 00 00 00，RX 的身份位置必须为 EF 40 18。

    **正常基线要求 exit=0 与有效 ID 同时成立。**SPI 没有低层 ACK（接收确认），退出 0 只表示本次工具调用正常返回。普通 -p 路径也不会自动比较 TX/RX；v6.6 的 transfer()只检查传输 ioctl 返回值是否小于 1，没有向用户打印实际完成长度。因此，即使工具成功，也仍须人工或脚本检查 RX[1]～RX[3]。

    若打开设备失败，程序自身的典型错误行是：

    can't open device: No such file or directory

    它只说明本次 open() 失败。下一步检查节点、权限和绑定，不要先改模式或短接引脚。工具在打开、配置或传输失败时经 perror() 和 abort() 退出，失败退出状态不写成固定值，更不能解释成 Flash 返回了 NACK。

    沿同一笔事务看清证据在哪里产生¶

    用户结果正确，并不代表每一层都留下了独立证据。下面的交互图标出完整收发路径；点击“正常 ID、内部回环、外部短接、数字帧、模拟波形”，可以分别查看该证据覆盖的层和不能覆盖的部分。图中高亮只是证据范围，不表示对应硬件已经实测通过。

    即使不使用交互图，也可以按文字守住边界：正常 ID 覆盖本次端到端事务，但不证明长期稳定或模拟裕量；内部回环不经过外部引脚和 Flash；外部短接的证据停在短接点，不证明器件应答；数字帧说明探针处的位流关系，不证明用户缓冲区和接收端模拟裕量；模拟波形说明探针处的电平与时间窗口，不证明命令、位序和 ID 内容正确。

    异常后选择下一项证据，而不是顺序做完所有测试¶

    先区分两类失败：调用没有完成与调用完成但身份数据不对。前者保留 open()、配置或 ioctl 的原始错误，回到对应软件层；后者才把 RX[1]～RX[3] 与 EF 40 18 比较，并选择能区分当前候选机制的检查。

    • 全 00、全 FF 或完全无响应：先抓完整数字帧，确认 CS、SCLK、MOSI、MISO 是否出现预期活动。固定电平可能来自上下拉、错误 CS、器件未就绪、DO 高阻、接线或采样配置，不能由数值直接定根因。
    • 用户结果整体错位：用数字帧判断线上是否已有正确 ID。若线上正确，回查软件接收长度、RX[0] 前导和缓冲区偏移；若线上也错位，再查采样边沿、CS 边界和额外时钟。
    • 怀疑控制器或位序路径：先做不改接线的内部回环；需要覆盖某段外部收发线路时，再在断电和隔离条件下做外部短接。
    • 降速后恢复或偶发失败：先确认完整数字帧，再用示波器检查接收端附近的电平、边沿和采样窗口。

    W25Q128JV Rev F 的 tVSL 是器件达到最低工作电压 VCC(min) 后到允许拉低 CS 的时间，最小 20 μs。上电就绪要按手册判断，不能把一次全 00／全 FF 归成固定毫秒延时问题，也不能在未读手册前随意增加 msleep()（内核毫秒级睡眠函数）。

    内部回环：不动接线时，先检查控制器提供的回环路径¶

    **为什么此时做：**正常 ID 不对，而当前疑问是用户传输、SPI Core 和控制器能否把已知数据送回。它适合在接触外部接线前缩小范围，不是每次失败的强制第一步。

    -l 设置 SPI_LOOP，-S 4 生成四字节测试数据，-I 1 只执行一次。RK3568 的 v6.6 控制器驱动在 spi-rockchip.c:856 声明支持 SPI_LOOP；工具的随机缓冲区路径会逐字节比较 TX/RX，不一致时打印 transfer error ! 并以 1 退出。

    spidev_test -D /dev/spidev1.0 -s 1000000 -l -S 4 -I 1
printf 'exit=%d\n' "$?"

    若控制器接受回环模式、比较一致且本次执行未跨越工具的 5 秒统计间隔，完整预期输出为：

    spi mode: 0x20
bits per word: 8
max speed: 1000000 Hz (1000 kHz)
total: tx 0.0KB, rx 0.0KB
exit=0

    0x20 是 SPI_LOOP 模式位，CPOL/CPHA 仍为 0。0.0KB 是四字节除以 1024 后保留一位小数的结果，不表示没有传输。测试数据由 C 库的 random() 生成，本条命令没有 -v，所以不打印其内容；失败时打印的 TX/RX 也随数据而变，不能伪造固定失败输出。

    **证据覆盖与下一步：**成功只支持当前控制器回环配置和传输路径可工作，不证明外部引脚、焊接、连接线、CS 或 Flash 正常。若模式不支持、传输失败或比较失败，保留原始错误并检查控制器配置；若回环成功而正常 ID 仍错，转向完整数字帧，观察控制器之外实际发生了什么。

    完整数字帧：让软件结果与线上事务对得上¶

    **为什么此时做：**回环不能回答 Flash 是否收到正确命令，也不能回答线上 ID 与用户 RX 是否一致。逻辑分析仪把 CS、SCLK、MOSI、MISO 放在同一时间轴上，适合区分软件偏移、片选边界、时钟数和器件应答。

    **怎样操作：**从 CS 有效开始捕获完整事务，按 Mode 0 的空闲低、上升沿采样和 MSB-first 解码。核对 CS 是否连续覆盖 32 拍，MOSI 是否为 9F 00 00 00，MISO 有效响应位置是否为 EF 40 18。采样率、触发和存储深度按仪器带宽与完整捕获需求设置，不用统一倍数代替测量条件，也不反复切换解码参数直到结果“看起来合理”。

    证据覆盖与下一步：

    • MOSI 没有 9F 00 00 00：回查用户缓冲区、SPI Core、控制器和 pinctrl（引脚复用配置）。
    • MOSI 正确但 CS 未覆盖 32 拍：检查 CS 配置、映射和事务边界。
    • CS、SCLK、MOSI 正确而 MISO 不动：检查器件供电、上电就绪、复位、DO 驱动权和输入门限，必要时转模拟波形。
    • 线上已有 EF 40 18 而用户缓冲区不同：回查软件接收长度、前导保留约定和偏移。本例只有 8 拍命令与 24 拍响应，不能套用其他命令的 dummy（额外等待时钟）位置。
    • 数据呈 F7 02 18：它恰好是 EF 40 18 的逐字节位序反转，只形成位序假设。用已知发送数据的内部回环或隔离后的外部短接验证，再核对器件手册，不能仅凭一次模式切换定案。

    数字解码正确只说明分析仪在自己的门限和采样条件下识别出预期位流，不证明接收端具有充分模拟裕量，也不证明数据已正确交付用户态。

    外部短接：只把证据扩展到短接点¶

    **为什么此时做：**内部回环正常而外部路径仍有疑问，需要用一个不依赖 Flash 协议答案的已知收发关系检查线路。它不是内部回环的同义重复，覆盖范围由短接位置决定。

    **怎样操作：**断电后，在指定测试点短接 MOSI 与 MISO，并隔离可能同时驱动 MISO 的 Flash。若保持 Flash 的 DO 与主机 MOSI 对接，两个推挽输出可能争用，不能把这种做法当作无风险测试。恢复供电后沿用正常命令但不加 -l：

    spidev_test -D /dev/spidev1.0 -s 1000000 -p '\x9f\x00\x00\x00' -v

    本次用于判读的预期关键行如下，不是完整工具输出，也不是实测：

    TX | 9F 00 00 00 ...
RX | 9F 00 00 00 ...

    普通 -p 路径不会自动比较，必须逐字节核对。相等只说明短接点以内、当前配置下的收发路径一致，不能证明 Flash 会回答，也不能证明短接点之外、另一速率或其他 CS 正常。若不等，检查短接点以内的接线、引脚配置和控制器外部路径；若相等而正常 ID 仍错，下一项转向完整数字帧或 Flash 侧的供电、驱动权与应答检查。

    模拟波形：数字关系成立后，检查接收端是否真的能采准¶

    **为什么此时做：**数字帧异常涉及电平驱动，或降速能恢复、故障随频率和布局变化时，仅靠解码结果无法区分输出有效延迟、传播、输入建立时间、过冲和振铃。

    **怎样操作：**在接收端附近用示波器同时观察 CS、SCLK 和相关数据线，按主从手册检查输入高低门限、过冲与下冲限制、边沿形态，以及输出有效到采样之间的窗口。0.9 VCC 或 0.5 VCC 在某些手册图中只是测量参考电平，不能直接当作所有器件的输入合格门限。

    B-B.4.2 已给出 MISO 的时间预算：

    启动边沿到采样边沿的间隔
≥ tCLQV(max) + 走线传播 + 主机建立时间 + 设计余量

    **证据覆盖与下一步：**波形可以支持或否定探针处的门限、边沿和采样窗口假设，但不能证明命令、位序、帧边界和器件应答内容正确。若窗口不足，依据实际超限项调整硬件或时序；若模拟条件满足而数字帧仍错，回到协议帧和配置；若两者都正确而用户结果仍错，回到 RX 缓冲区与交付路径。

    多从机场景还要检查驱动权：只选中目标 CS，其他从机应按各自手册释放 MISO。若某从机未释放，或 reg 把访问引到另一 CS，主机可能读到固定值或争用后的无效电平。电气机制见 B-B.4.1，DTS 的 CS 与设备对象关系见 B-B.4.3。

    降速只改一个变量，用来判断故障是否与时间窗口相关¶

    当 1 MHz 下 ID 异常，而需要判断故障表现是否随频率变化时，保持其他条件不变，只把请求速率改为 100 kHz：

    spidev_test -D /dev/spidev1.0 -s 100000 -p '\x9f\x00\x00\x00' -v
printf 'exit=%d\n' "$?"

    预期结果仍是 exit=0 且 RX[1]～RX[3] = EF 40 18，只有读回的 max speed 应变为 100000 Hz (100 kHz)；这里不重复整段显示输出，也不把该预期写成实测。

    若高速异常而低速恢复，只能说明故障与频率或可用时间窗口相关。候选机制包括超过器件或控制器限制、Flash 输出有效延迟、走线传播、主机输入建立时间不足、边沿过慢、过冲和振铃。下一步先看完整数字帧，再用模拟波形区分这些候选，不能凭“低速能读”宣布走线或端接就是根因。

    当前 RK3568 v6.6 驱动在 spi-rockchip.c:602-607 选择不小于理想值的偶数分频，使结果不超过请求速率。这个控制器事实不能推广为所有 SoC，也不能代替引脚实测。

    撤销临时状态，用同一笔读取完成恢复¶

    无论走了哪条分支，收尾都不是“某项隔离测试通过”，而是恢复正常事务：

    1. 若做过外部短接，断电、移除短接并恢复 Flash 连接；检查没有遗留争用接法。
    2. 回环命令不加 -l，恢复 Mode 0、8 位、MSB-first、低有效 CS 和原 CS 映射。若做过降速对照，把请求速率恢复为 1 MHz；一次只改一个参数，并记录本次实际改动。
    3. 重新执行开头的正常命令，同时核对工具成功返回和 RX[1]～RX[3] = EF 40 18。RX[0] 仍不参与身份判断。
    4. 若正常 ID 没有恢复，回到最后一个已确认正常的边界，不叠加新的改动。若已恢复，只说明本次事务回到已知基线，不据此宣称其他速率、长期运行或所有产品访问均已验证。

    偶发故障需要有限次数、明确判据的记录：每次检查 ioctl 结果、有效 ID 和实际测试条件，再统计失败数。普通 spidev_test -p 不会自动比较数据，单纯用 while true 循环它并不能得到错误率。

    本文命令行为依据 Linux v6.6 的 spidev_test.c、spidev.rst、spi.c 与 spi-rockchip.c；器件结论依据 Winbond《W25Q128JV》Revision F 第 8.1.1、8.2.27、9.3 节。文中输出均为按源码和手册推演的预期，不是实测日志。目标板运行、目标器件 ID、回环与外部短接、逻辑分析仪抓取、示波器测量和长期压测均为 not_verified。
