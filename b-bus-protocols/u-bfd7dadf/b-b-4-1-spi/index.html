    B-B.4.1 SPI 物理层与四种模式¶

    所属章节：第五部 B. 总线协议 > B-B.4 SPI 总线

    难度：[B] Beginner | 预计阅读时间：25 分钟

    本节导读¶

    SPI（Serial Peripheral Interface，串行外设接口）没有统一的器件地址帧，也没有标准化的 ACK（Acknowledgement，接收确认）。主机选中一个从机并产生时钟，双方就能交换位流；至于每个字节是命令、地址还是数据，由器件自己的协议规定。

    这种简洁把责任转移给了硬件配置和板级实现：主机与从机必须事先约定时钟极性、采样边沿、位序和片选行为，线路还必须让接收器在采样时看到稳定、合法的电平。SPI 不会因为某一项约定错了就主动报错，错误可能直接表现为读回的数据不可信。

    本节只回答一个问题：在常见的单主机、四线 SPI 中，一次全双工传输怎样开始、怎样逐位交换数据、怎样结束，模式、速率和电气条件又怎样决定它是否可信？

    三线 SPI、Dual/Quad SPI、DDR（Double Data Rate，双倍数据速率）和多主机会改变信号或时序模型，不放进这条主线。命令帧和寄存器地址属于 B-B.4.2，Linux 设备对象与 spidev_test 分别属于 B-B.4.3、B-B.4.4。

    四根信号线各自改变什么¶

    本节的“四线 SPI”指 SCLK、MOSI、MISO 和一根片选线。先固定最常见的一组约定：一个主机、一个被片选独立选中的从机，CS（Chip Select，片选）低电平有效。

    • SCLK（Serial Clock）：主机输出的串行时钟。它的边沿告诉双方何时更新输出、何时采样输入。
    • MOSI（Master Out Slave In）：主机输出、从机输入。主机要发送的位依次出现在这里。
    • MISO（Master In Slave Out）：从机输出、主机输入。被选中从机要发送的位依次出现在这里。
    • CS/SS（Chip Select/Slave Select）：主机选择本次通信对象的控制线。本例中拉低表示选中，拉高表示结束；其他器件也可能采用高有效，必须看数据手册。

    厂商也会使用 SDI/SDO、COPI/CIPO 等名称。接线时应先确认每一端的方向，再对照名称，不能只凭缩写猜测。

    SPI 没有类似 I2C 的统一总线寻址帧，并不等于 SPI 器件没有“地址”。主机可以用 CS 选中一颗 Flash，随后在 MOSI 上发送该器件规定的命令和寄存器地址；这些字节不是物理层用于选择芯片的总线地址，而是器件协议的一部分。

    MOSI 与 MISO 是两条独立数据线，所以双方可以在同一组时钟中同时发送数据，这称为全双工。相对地，半双工通信在同一时刻只能沿一个方向传输。全双工描述的是位怎样在线路上移动，并不保证每个方向的字节都对上层协议有意义，也不能据此推出 SPI 的吞吐率恒为其他总线的两倍。

    跟随一次 8 位全双工传输¶

    传输前：约定模式、位序和参与者¶

    下面用一笔传输贯穿本节：

    • 使用 Mode 0，即 CPOL=0、CPHA=0；这两个参数稍后完整解释。
    • 每次传输 8 位，采用 MSB-first（Most Significant Bit first，最高有效位先发）。
    • 主机发送 0xA5，二进制为 10100101。
    • 从机同时发送 0x3C，二进制为 00111100。

    MSB-first 表示 8 位字节从 b7 到 b0 依次上线。因此，MOSI 上应依次出现 1、0、1、0、0、1、0、1，MISO 上应依次出现 0、0、1、1、1、1、0、0。如果一端按最高位先发、另一端按最低位先收，即使时钟模式正确，解释出的字节也会不同。

    双方的发送和接收电路可以用移位寄存器理解：它是一个按时钟移动的位序列，一端把当前输出位送到引脚，另一端把刚采样的输入位移入。8 位移位寄存器连续工作 8 次，就完成一个字节的移出和移入。真实控制器可能还有 FIFO（First In First Out，先进先出缓冲），但这不改变引脚上逐位移动的观察方式。

    片选有效：先确定谁可以驱动 MISO¶

    空闲时，CS 为高，SCLK 按 Mode 0 保持低电平。若多个从机共享 MISO，未被选中的从机通常必须让 MISO 处于高阻态：引脚不主动拉高，也不主动拉低，相当于退出对该线路的驱动。推挽、高阻和开漏的电气基础可回看 B-B.2.1 与 B-B.3.1。

    主机拉低目标从机的 CS 后，目标从机进入本次传输，其他从机继续忽略 SCLK 和 MOSI，并释放 MISO。CPHA=0 要求第一个时钟边沿就采样，所以本例双方在 CS 有效后、第一个 SCLK 边沿前，分别把 b7 放到 MOSI 和 MISO 上。这个动作称为首位预载：它不是由第一个采样边沿临时“取出来”的，而是在采样前就已经稳定。

    8 个时钟：在更新边沿换下一位，在采样边沿读当前位¶

    Mode 0 的规则是下降沿更新、上升沿采样。第一个上升沿到来前，MOSI 和 MISO 分别已经是双方的 b7；上升沿到来时，主机采样 MISO，从机采样 MOSI。

    第一个下降沿随后把输出推进到 b6。第二个上升沿再采样 b6，第二个下降沿更新到 b5。如此重复，直到第八个上升沿采样 b0。最后一个下降沿之后，线路是否再改变输出已经不影响这 8 个已采样位。

    8 个采样边沿上的结果依次为：

    采样次序 主机在 MOSI 发出 从机在 MISO 发出 主机收到 从机收到
    1 1（0xA5 的 b7） 0（0x3C 的 b7） 0 1
    2 0 0 0 0
    3 1 1 1 1
    4 0 1 1 0
    5 0 1 1 0
    6 1 1 1 1
    7 0 0 0 0
    8 1（b0） 0（b0） 0 1

    即使去掉这张表，前面的位序和边沿规则也已经给出完整过程：主机把 10100101 逐位发到 MOSI，同时从 MISO 收齐 00111100；从机把 00111100 逐位发到 MISO，同时从 MOSI 收齐 10100101。因此，8 个时钟结束后，主机收到 0x3C，从机收到 0xA5。

    接收器并不是只在理想边沿瞬间“看一眼”就必然可靠。数据手册中的建立时间要求数据在采样边沿前至少稳定多久，保持时间要求它在采样边沿后再保持稳定多久。更新边沿与采样边沿分开，正是为了给这些稳定窗口留出时间；实际允许的最小窗口仍以双方数据手册为准。

    片选释放：结束本次传输，而不是确认数据正确¶

    完成所需时钟后，主机把 CS 拉高，本例的一次传输结束。被选中从机退出传输，并按器件规定释放 MISO，使其他从机之后可以使用这条线。

    CS 释放只表示这段片选事务结束，不表示从机已经确认“数据无误”。SPI 物理层没有标准 ACK，主机不能仅凭 8 个时钟已经发出、CS 已经恢复高电平，就证明从机正确执行了命令。需要确认时，应使用器件协议提供的读回、状态寄存器或校验机制。

    为什么读取时还要发送 dummy 位¶

    假设主机只想从从机读出一个字节，SCLK 仍由主机产生，MISO 上的位也仍需要时钟才能逐位移出。主机因此继续发送 8 个无协议含义的位，常见取值是 0x00 或 0xFF，具体由器件规定。这些占位数据称为 dummy 位或 dummy 字节，作用是提供时钟，而不是向从机提交新的有效命令。

    反过来，主机只写命令时，MISO 仍可能同步返回一些位。若器件没有把它们定义为有效响应，主机读取后丢弃即可。dummy TX（发送占位数据）和丢弃 RX（接收数据）都是上层对全双工位流的处理，并没有关闭任何一条数据线。

    CPOL 与 CPHA：四种模式怎样推出来¶

    CPOL（Clock Polarity，时钟极性）只回答一个问题：没有传输时，SCLK 停在高电平还是低电平？

    • CPOL=0：空闲低，所以每个时钟周期的第一个边沿是上升沿，第二个边沿是下降沿。
    • CPOL=1：空闲高，所以第一个边沿是下降沿，第二个边沿是上升沿。

    CPHA（Clock Phase，时钟相位）回答另一个问题：接收器在第几个边沿采样？ CPHA=0 在第一个边沿采样，CPHA=1 在第二个边沿采样。另一个边沿通常用于更新输出，使下一位在下一次采样前稳定。

    把两个参数组合起来，就得到四种模式：

    • Mode 0（CPOL=0，CPHA=0）：空闲低，第一个边沿为上升沿，所以上升沿采样、下降沿更新。
    • Mode 1（CPOL=0，CPHA=1）：空闲低，第二个边沿为下降沿，所以下降沿采样、上升沿更新。
    • Mode 2（CPOL=1，CPHA=0）：空闲高，第一个边沿为下降沿，所以下降沿采样、上升沿更新。
    • Mode 3（CPOL=1，CPHA=1）：空闲高，第二个边沿为上升沿，所以上升沿采样、下降沿更新。
    模式 CPOL CPHA 空闲电平 采样边沿 更新边沿
    Mode 0 0 0 低 上升沿 下降沿
    Mode 1 0 1 低 下降沿 上升沿
    Mode 2 1 0 高 下降沿 上升沿
    Mode 3 1 1 高 上升沿 下降沿

    CPHA 还改变首位上线时机。CPHA=0 在第一个边沿采样，首位必须在 CS 有效后、第一个边沿前预载；CPHA=1 在第二个边沿采样，第一个边沿可以先更新输出，再由第二个边沿读取。前面的 Mode 0 示例之所以强调首位预载，原因就在这里。

    四种模式没有天然的性能优劣，主从双方必须使用从器件要求的组合。模式不匹配可能采到旧位、相邻位、固定值或随机值，也可能让器件状态机收到错误命令；不能把它概括成“数据一定整体移一位”。

    用逻辑分析仪检查未知连接时，可以先由 SCLK 空闲电平判断 CPOL，再结合已知测试数据观察发送端在哪个边沿更新、接收端在哪个边沿应当采样，从而判断当前波形符合哪种 CPHA。若数据长期为常量，就没有足够的跳变可供判断；抓到的波形符合当前主机配置，也不能单独证明它符合从机数据手册的要求。

    实际 SCLK：先过分频，再受三重上限约束¶

    SPI 没有标准 ACK 和仲裁开销，原始位率容易估算：在每个时钟传 1 位的四线 SPI 中，单个方向的原始位率等于 SCLK 频率，8 个时钟传 8 位。命令、地址、dummy 周期间隔和软件准备时间都会降低有效吞吐率，不能把原始位率直接当成应用层读写速度。

    控制器通常也不是直接从请求值生成任意频率，而是对源时钟分频：

    fSCLK = fsource / N

    其中 fsource 是控制器得到的源时钟，N 是控制器支持的分频数。以已核对的 Linux v6.6 Rockchip SPI 驱动 drivers/spi/spi-rockchip.c 为例，它要求偶数分频，并在不能精确命中请求值时选择不超过请求值的档位。假设源时钟为 100 MHz，请求 30 MHz：

    1. 理想分频是 100 / 30 ≈ 3.33，不是可用整数。
    2. 若取 3，会得到约 33.33 MHz，超过请求值，而且该驱动也不接受奇数分频。
    3. 最小可用偶数分频是 4，因此实际 SCLK 为 100 / 4 = 25 MHz。

    25 MHz 是这个特定源时钟和驱动约束下的计算结果，不是所有控制器请求 30 MHz 时的统一答案。该驱动中的 50 MHz 控制器上限同样不等于板级安全速率；实际可用上限还要同时满足以下三项：

    • 控制器能力：源时钟、分频粒度、驱动支持范围以及片选和字长能力。
    • 从器件要求：数据手册给出的最高 SCLK、最小高低电平时间，以及不同命令或供电条件下可能不同的限制。
    • 板级信号质量：电压、走线、连接器、负载和边沿形态是否让接收端始终满足采样要求。

    最终频率不能超过三者中最严格的一项。调试时可以从一个保守且双方明确支持的频率开始，用已知数据或读回结果验证，再逐步提高；降速后稳定只能说明问题可能与速度、时序或信号质量有关，不能单独证明逻辑已经完全正确。

    多从机：独立片选与菊花链不是同一种选择方式¶

    独立 CS：共享数据总线，但一次只选一个驱动者¶

    常见接法是让所有从机共享 SCLK、MOSI、MISO，再为每个从机分配独立 CS。四个信号角色不变，因此 N 个从机通常需要 N+3 根线。主机只拉低目标从机的 CS，其他 CS 保持无效。

    片选可以来自控制器原生 CS，也可以在驱动和板级支持时使用 GPIO（General Purpose Input/Output，通用输入输出）。实际数量不能只看 SoC（System on Chip，片上系统）型号：需要同时核对具体控制器、芯片手册、设备树中的片选与 pinctrl（引脚复用）配置，以及原理图真正怎样连接。

    不同从机可以要求不同 SPI 模式，但主机必须在总线空闲、CS 均无效时重新配置，再开始下一次传输。若两个推挽 MISO 输出同时有效，一个试图拉高、另一个试图拉低，不仅数据无法判断，还可能形成过大的直通电流。因此，“未选中的从机释放 MISO”不是可选优化，而是常见共享总线安全工作的前提。个别器件不能在 CS 无效时释放 MISO，就需要按数据手册增加三态缓冲或改变连接方式。

    菊花链：数据依次穿过整链¶

    菊花链不是给每个从机增加一根 CS，而是把前一级的数据输出接到后一级的数据输入，所有级共享时钟和片选，最后一级再回到主机：

    主机 MOSI → 器件 1 → 器件 2 → … → 器件 N → 主机 MISO

    每个器件必须明确支持相应的级联协议。假设链中有两个器件，每个器件的移位寄存器都是 8 位，那么主机看到的链长就是 16 位。每个时钟都让整条链移动一位：前 8 个时钟后，主机最早发出的位已经从器件 1 进入器件 2，并不是只停在第一级；继续提供后 8 个时钟，主机发出的 16 位才分别占据两级，同时原链中的 16 位依次移回主机。CS 释放后何时锁存或执行这些数据，由器件手册规定。

    链中器件不必天然“同型号、同配置”，但各级必须支持级联，并且字长、数据顺序、电平和时序能够共同工作。代价是主机通常要按整链长度移位，不能像独立 CS 那样只选一个器件通信；链越长，所需时钟和协议组织也越复杂。

    电气特性：为什么时钟正确仍可能采样错误¶

    推挽负责驱动，高阻负责让出总线¶

    常见 SPI 数据线和时钟线采用推挽输出：输出级既能主动拉高，也能主动拉低，因此不需要 I2C 开漏总线那种用于形成高电平的上拉电阻。推挽的两个输出不能直接互相对抗，这就是共享 MISO 必须配合高阻释放的原因。

    “不需要 I2C 式上拉”不等于“任何 SPI 引脚都禁止上拉”。CS、MISO/SDO 等引脚仍可能因器件复位状态、总线驻留电平或数据手册建议而需要上拉，应以原理图和器件手册为准。

    双方还必须使用兼容的逻辑电平并共地。SCLK 在主机侧看起来有正确边沿，不代表从机侧越过其输入判决门限；电压不匹配还可能损坏器件。这里的检查属于电气兼容性，不能靠修改 CPOL/CPHA 解决。

    信号完整性关注边沿形状，而不只是频率数字¶

    信号完整性指信号到达接收端时，是否仍具有可被正确识别的电平和时序。走线、连接器与负载会形成分布电感和电容；快速边沿可能引起过冲、下冲和振铃。若振铃反复穿过输入门限，接收器可能在一次预期跳变附近产生错误判决。

    影响边沿的不只是 SCLK 标称频率，驱动强度和上升、下降时间同样关键。因此不存在适用于所有板卡的“超过 10 cm 就必须怎样”或“22–33 Ω 必然解决问题”的统一规则。

    在驱动端附近串联小电阻，可以与输出阻抗一起减缓边沿、抑制部分反射和振铃，这种方法称为源端串联阻尼。是否采用以及阻值多大，需要结合驱动能力、走线阻抗、负载和实测波形决定；常见小阻值只能作为调试起点，不是 SPI 标准规定。

    逻辑分析仪适合核对 CS 范围、SCLK 边沿和数字位序，但不能代替示波器判断过冲、振铃和真实电平质量。模拟波形异常应观察接收端附近的实际信号，并注意测量接地和探测方式本身也会改变结果。

    从物理层观测到系统验证¶

    物理层观测回答的是“位有没有按约定在线路上出现”，系统验证回答的是“器件有没有正确理解并执行”。两者不能互相替代。

    例如，逻辑分析仪看到主机发出 0xA5、收到 0x3C，可以验证 CS、SCLK、MOSI、MISO 与预期一致；但它不能单独证明 0x3C 在当前命令下就是合法状态值。还需要按 B-B.4.2 的帧格式解释数据，并用器件规定的读回或状态检查完成协议验证。

    建议按以下顺序缩小问题范围：

    1. 核对约定：模式、位序、字长、CS 有效电平和器件要求的 dummy 方式是否一致。
    2. 检查一次事务的边界：CS 是否在完整传输期间保持有效，是否只选中了预期从机。
    3. 观察数字时序：首位是否在首个采样边沿前稳定，采样边沿和位序是否与数据手册一致。
    4. 降低速率并复测：判断问题是否随速度变化，但不把降速成功当作根因证明。
    5. 检查模拟波形与协议结果：分别用示波器看电气质量，用已知数据、状态读回或校验确认系统功能。

    spidev_test 回环、完整命令和输出判读属于 B-B.4.4 的工具验证；Linux 控制器如何实际产生这些波形属于 B-B.4.3。本篇不把一个未运行的命令或一次未上板的回环结果写成功能验证结论。

    本节总结¶

    一次常见四线 SPI 传输可以概括为：主机选中从机，双方在首个采样边沿前准备好首位，在规定的更新与采样边沿上逐位移动两个方向的移位寄存器，最后用 CS 结束事务，并由被选中的从机按器件规定释放 MISO。

    全双工意味着两个方向同时移位，不意味着两个方向总有协议意义；读取时发送 dummy、写入时丢弃 RX 都是正常现象。CPOL 决定空闲电平，CPHA 决定第一还是第二边沿采样，四种模式都可由这两条规则推导。

    SPI 没有标准 ACK，波形完成不等于数据正确。实际 SCLK 先受控制器分频约束，再受控制器、从器件和板级信号质量共同限制；独立 CS 与菊花链则用不同方式决定哪些移位寄存器参与一次传输。物理层、协议层和系统验证各自回答不同问题，排障时不应相互替代。

    本节自查（Q&A）

    Q1. 在 Mode 0 示例中，为什么双方的 b7 必须在第一个 SCLK 边沿前上线？第一个上升沿和随后的下降沿分别完成什么？

    CPHA=0 要在第一个边沿采样，所以 b7 必须提前预载并稳定。第一个上升沿分别采样双方的 b7；随后的下降沿把双方输出更新为 b6，供第二个上升沿采样。

    Q2. 主机只读一个字节时为什么还要发送 dummy 字节？主机只写时，同步收到的位是否一定是有效响应？

    从机需要主机继续提供 SCLK，才能把 MISO 上的位移出；dummy 为这些时钟占位，不表示有效命令。只写时 MISO 仍会随全双工时序返回位，只有器件协议把它们定义为响应时才有相应含义，否则应丢弃。

    Q3. 已知 SCLK 空闲为高、第二个边沿采样，这是哪种模式？采样和更新分别位于什么边沿？

    空闲高说明 CPOL=1，第二个边沿采样说明 CPHA=1，因此是 Mode 3。空闲高时第一个边沿为下降沿、第二个为上升沿，所以上升沿采样、下降沿更新。

    Q4. 为什么模式不匹配不一定表现为“整体移一位”，而且主机可能收不到明确错误提示？

    错误配置会改变采样相对于数据跳变的位置，可能采到旧位、相邻位或不确定电平，结果取决于真实波形和器件行为，不保证只形成一种移位图样。SPI 没有标准 ACK 或错误确认帧，主机不能仅靠时钟发完就发现这些错误。

    Q5. 源时钟为 100 MHz、请求 30 MHz、控制器只接受偶数分频时，为什么本例得到 25 MHz 而不是 33.33 MHz？

    理想分频约为 3.33。分频 3 既是不受支持的奇数，又会得到超过请求值的约 33.33 MHz；最小可用且不超过请求值的偶数分频为 4，所以实际为 100/4=25 MHz。

    Q6. 两个独立片选从机同时有效时，共享 MISO 可能发生什么？为什么“推挽不需要 I2C 式上拉”不等于“MISO 永远不需要高阻释放”？

    两个推挽输出若一高一低会互相对抗，既使数据不可信，也可能产生过大的直通电流。推挽负责主动驱动有效数据，高阻负责在器件未参与传输时退出驱动，两者解决的是不同问题。

    Q7. 两个各含 8 位移位寄存器的器件组成菊花链时，为什么需要 16 个时钟才能完成整链交换？

    两级寄存器串成一条 16 位链。每个时钟只让整链移动一位，经过 16 个时钟，主机新发的 16 位才占据两级，原来的 16 位才全部移回主机。

    Q8. 降速后读数稳定，为什么不能单独证明协议逻辑正确，也不能单独证明已经完成信号完整性验证？

    降速只说明故障表现与速度、时序或信号质量有关，不能证明命令和数据解释正确。信号完整性还需要结合实际走线与负载观察接收端电平、过冲、振铃和时序裕量，单次读数稳定不能替代这些检查。
