## <span class="blue"> 知识点 235：irq affinity 与多队列配置 [I]

### 中断亲和性的核心思路

网卡收到数据包后，会触发一个**硬件中断**通知 CPU。传统单队列网卡只有一个中断号，所有流量都涌向一个 CPU，很快成为瓶颈。现代多队列网卡可以把流量分到多个队列，每个队列有独立的中断号——**中断亲和性**做的就是把这些中断分别绑定到不同的 CPU 核心上，让多核真正并行干活。

<br>

### /proc/irq/&lt;n&gt;/smp_affinity 位掩码

Linux 通过 proc 文件系统暴露每个中断的亲和性掩码：

```
/proc/irq/<中断号>/smp_affinity
```

这个文件里是一个**十六进制位掩码**，每一位对应一个 CPU。写入不同的值就能控制中断由哪个 CPU 处理。

| 命令 | 含义 |
|------|------|
| `echo 2 > /proc/irq/42/smp_affinity` | 绑定到 CPU1（第2位） |
| `echo 4 > /proc/irq/42/smp_affinity` | 绑定到 CPU2（第3位） |
| `echo f > /proc/irq/42/smp_affinity` | 绑定到 CPU0~3（低4位全1） |
| `echo 0 > /proc/irq/42/smp_affinity` | 恢复自动分配 |

<br>

> 💡 **提示**：如果你的系统有 8 个核心（CPU0~CPU7），要绑定到 CPU0 和 CPU4，对应的二进制是 `0001 0001`，十六进制写 `11`。
>
> 超过 32 个 CPU 时，Linux 使用 `smp_affinity_list`（如 `echo 0-3,8-11`）会更直观，避免数十六进制的噩梦。

<br>

### ethtool -L 配置网卡队列数

首先看看你的网卡支持多少队列：

```bash
# 查看当前队列配置和支持的最大值
$ ethtool -l eth0
Channel parameters for eth0:
Pre-set maximums:
RX:         8          # 最大 RX 队列数
TX:         8
Other:      0
Combined:   8          # 最大 combined 队列数（常用）
Current hardware settings:
RX:         1
TX:         1
Combined:   4          # 当前实际使用 4 个队列
```

设置队列数很简单：

```bash
# 设置 4 个 combined 队列（通常队列数 <= CPU 核心数）
$ sudo ethtool -L eth0 combined 4
```

设置后，网卡会创建 4 个独立的硬件队列，每个队列对应一个独立的中断号。你可以用 `cat /proc/interrupts | grep eth0` 看到这些中断。

<br>

### irqbalance：便利与代价

irqbalance 是一个系统守护进程，**自动**根据负载调整中断的 CPU 亲和性。它听起来很美好，但嵌入式高性能场景下往往是个陷阱。

| 维度 | irqbalance 自动模式 | 手动绑定 |
|------|-------------------|---------|
| **核心思路** | 根据负载动态迁移中断 | 固定中断与 CPU 的映射关系 |
| **适用场景** | 通用服务器、负载波动大的业务 | 网络性能敏感、流量模式稳定的嵌入式设备 |
| **性能表现** | 上下文切换开销大，缓存局部性差 | 零迁移开销，CPU 缓存命中率高 |
| **维护难度** | 低，开机自启即可 | 需编写配置脚本，升级网卡驱动后可能需调整 |
| **可预测性** | 差，同一场景中断可能跑在不同 CPU | 强，每次行为一致，便于问题定位 |

<br>

> 🔴 **危险**：irqbalance 运行时会**持续覆盖**你手动写入的 `smp_affinity`！很多工程师花半天调好了亲和性，过几分钟发现又乱了——十有八九是 irqbalance 在背后"帮忙"。手动绑定的第一步永远是先停掉它：
>
> ```bash
> $ sudo systemctl stop irqbalance
> $ sudo systemctl disable irqbalance
> ```

<br>

### 完整配置步骤（RSS + irq affinity + RPS/RFS）

下面是一套标准的生产环境配置流程。假设你的设备有 4 核 CPU，eth0 支持 4 个队列：

**第一步：设置网卡队列数**

```bash
# 设置 4 个硬件队列，与 CPU 核心数匹配
$ sudo ethtool -L eth0 combined 4

# 验证
$ ethtool -l eth0 | grep -A4 "Current hardware"
```

**第二步：关闭 irqbalance**

```bash
$ sudo systemctl stop irqbalance
$ sudo systemctl disable irqbalance
```

**第三步：手动绑定每个队列的中断到不同 CPU**

```bash
#!/bin/bash
# irq_bind.sh - 手动绑定网卡中断到指定 CPU

IFACE="eth0"
# eth0 的 4 个队列中断名，实际名称因驱动而异
# 常见模式：eth0-rx-0, eth0-rx-1 或 eth0-0, eth0-1 等
IRQ_NAMES=("eth0-rx-0" "eth0-rx-1" "eth0-rx-2" "eth0-rx-3")
TARGET_CPUS=(0 1 2 3)  # 分别绑定到 CPU0~CPU3

for i in "${!IRQ_NAMES[@]}"; do
    irq_name="${IRQ_NAMES[$i]}"
    cpu="${TARGET_CPUS[$i]}"
    
    # 从中断名找中断号
    irq_num=$(grep -w "$irq_name" /proc/interrupts | awk '{print $1}' | tr -d ':')
    
    if [ -n "$irq_num" ]; then
        # 计算掩码：cpu0=1, cpu1=2, cpu2=4, cpu3=8
        mask=$(printf '%x' $((1 << cpu)))
        echo "$mask" > "/proc/irq/$irq_num/smp_affinity"
        echo "Bound $irq_name (IRQ $irq_num) to CPU$cpu with mask $mask"
    fi
done
```

**第四步：配置 RPS/RFS 补充**

硬件队列只解决了"谁来触发软中断"的问题，RPS/RFS 继续解决"哪个 CPU 处理协议栈"。两者配合才能达到最优：

```bash
# 假设网卡有 4 个队列，绑定到 CPU0~CPU3
# 对未绑定硬件中断的剩余 CPU（如有），启用 RPS 分担

# 每个队列对应的 sysfs 路径（示例为队列 0~3）
for i in 0 1 2 3; do
    queue_sys="/sys/class/net/eth0/queues/rx-$i"
    
    # RPS：将该队列的软中断分发到对应 CPU
    # CPU0 处理队列 0，以此类推
    mask=$(printf '%x' $((1 << i)))
    echo "$mask" > "$queue_sys/rps_cpus"
    
    # RFS：启用流表（大小建议 32768）
    echo 32768 > "$queue_sys/rps_flow_cnt"
done

# 全局 RFS 流表大小
echo 32768 > /proc/sys/net/core/rps_sock_flow_entries
```

> ⚠️ **陷阱**：不要把 RPS 的目标 CPU 和硬件中断绑定的 CPU 搞混了。理想情况下，硬件中断在某个 CPU 触发后，软中断**也在同一个 CPU 处理**，这样可以最大化缓存局部性。RPS 的目标掩码应该包含处理该队列的 CPU。

<br>

### 配置命令速查表

| 目的 | 命令 | 验证方法 |
|------|------|---------|
| 查看网卡队列支持数 | `ethtool -l eth0` | 看 "Pre-set maximums" |
| 设置 combined 队列数 | `ethtool -L eth0 combined N` | 再看 `ethtool -l eth0` |
| 查看中断号 | `cat /proc/interrupts \| grep eth0` | 确认中断名与数字对应 |
| 绑定中断到 CPU | `echo <mask> > /proc/irq/<n>/smp_affinity` | `cat` 回读确认 |
| 停止 irqbalance | `systemctl stop/disable irqbalance` | `ps aux \| grep irqbalance` |
| 查看中断分布 | `watch -n1 'cat /proc/interrupts'` | 各 CPU 列数值是否均匀 |
| 配置 RPS CPU 掩码 | `echo <mask> > /sys/.../rps_cpus` | `cat` 回读确认 |
| 配置 RFS 流表大小 | `echo N > /sys/.../rps_flow_cnt` | `cat` 回读确认 |

<br>

### 验证：/proc/interrupts 告诉你真相

配置完成后，用 `watch` 命令实时监控：

```bash
# 每秒刷新，只看 eth0 相关的中断
$ watch -n1 'cat /proc/interrupts | grep eth0'
```

你会看到类似这样的输出：

```
  42:    1024000          0          0          0   PCI-MSI  eth0-rx-0
  43:          0     980000          0          0   PCI-MSI  eth0-rx-1
  44:          0          0    1050000          0   PCI-MSI  eth0-rx-2
  45:          0          0          0     990000   PCI-MSI  eth0-rx-3
```

看到没有？每个中断都只在一个 CPU 上计数，而且四个 CPU 都在干活——这就是配置成功的标志。如果某个 CPU 的数值一直是 0，或者某个中断在多个 CPU 间跳来跳去，说明绑定没生效。

> 💡 **提示**：观察 `/proc/interrupts` 时，**均匀分布**不等于**绝对平均**。实际流量本身可能不均衡（比如某个源 IP 发得多），关键是每个队列**固定在目标 CPU 上处理**，而不是 irqbalance 把它到处乱挪。

<br>

### 实战带练：从零配置 RSS + RPS + irq affinity

现在把前面学的内容串起来，完成一个完整的实战配置。假设场景：

- 4 核 ARM 嵌入式平台
- eth0 是千兆网卡，支持最多 8 个 combined 队列
- 业务是高并发的数据采集，要求低延迟

**目标**：最大化网络收包并行度，减少单核瓶颈。

```bash
#!/bin/bash
# complete_network_tuning.sh - RSS + RPS + irq affinity 完整配置

set -e
IFACE="eth0"
NUM_CPUS=$(nproc)

echo "=== Step 1: 设置网卡队列数 ==="
# 队列数不超过 CPU 核心数
QUEUES=$NUM_CPUS
ethtool -L "$IFACE" combined "$QUEUES"
echo "Set $IFACE to $QUEUES combined queues"

echo "=== Step 2: 关闭 irqbalance ==="
systemctl stop irqbalance 2>/dev/null || true
systemctl disable irqbalance 2>/dev/null || true
echo "irqbalance stopped"

echo "=== Step 3: 绑定硬件中断到各 CPU ==="
# 获取网卡中断列表（适配 ixgbe/igb/e1000e 等常见驱动命名）
irq_lines=$(grep -i "$IFACE" /proc/interrupts | grep -i "rx\|tx\|msi" || \
            grep -i "$IFACE" /proc/interrupts)

echo "$irq_lines" | while read -r line; do
    irq_num=$(echo "$line" | awk '{print $1}' | tr -d ':')
    irq_name=$(echo "$line" | awk '{print $NF}')
    
    # 简单轮询分配：irq 依次分到 CPU0, CPU1, ...
    cpu_idx=$((irq_num % NUM_CPUS))
    mask=$(printf '%x' $((1 << cpu_idx)))
    
    echo "$mask" > "/proc/irq/$irq_num/smp_affinity"
    echo "IRQ $irq_num ($irq_name) -> CPU$cpu_idx (mask=$mask)"
done

echo "=== Step 4: 配置 RPS/RFS ==="
for i in $(seq 0 $((QUEUES - 1))); do
    queue_path="/sys/class/net/$IFACE/queues/rx-$i"
    
    # RPS：允许所有 CPU 参与软中断处理（作为补充）
    # 如果硬件队列已覆盖所有 CPU，RPS 掩码可设为 0（禁用）
    rps_mask="0"
    echo "$rps_mask" > "$queue_path/rps_cpus"
    
    # RFS 流表
    echo 32768 > "$queue_path/rps_flow_cnt"
done

echo 65536 > /proc/sys/net/core/rps_sock_flow_entries

echo "=== Step 5: 验证配置 ==="
echo "--- 队列配置 ---"
ethtool -l "$IFACE" | grep -A8 "Current hardware"
echo "--- 中断分布（初始快照）---"
grep -i "$IFACE" /proc/interrupts
echo ""
echo "配置完成！用 'watch -n1 cat /proc/interrupts' 观察流量分布"
```

运行完这个脚本后，发包测试（比如 `iperf3`），同时观察 `/proc/interrupts`。理想情况下你会看到每个 eth0 队列中断稳定在一个 CPU 上递增。

<br>

## <span class="blue"> 本节总结

| 内容 | 要点 |
|------|------|
| **中断亲和性** | 通过 `/proc/irq/<n>/smp_affinity` 的十六进制位掩码，精确控制哪个 CPU 处理哪个硬件中断 |
| **多队列配置** | `ethtool -L eth0 combined N` 设置队列数，通常不超过 CPU 核心数 |
| **irqbalance 的取舍** | 自动模式适合通用场景，高性能嵌入式场景务必手动绑定 |
| **关键陷阱** | irqbalance 会持续覆盖手动绑定，配置前必须先停掉 |
| **验证方法** | `watch cat /proc/interrupts` 观察中断是否稳定在目标 CPU 上 |
| **与 RPS/RFS 配合** | 硬件队列解决并行收包，RPS/RFS 解决软中断分发，两者叠加达到最优 |
