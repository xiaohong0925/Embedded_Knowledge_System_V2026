# 11.1.4 模式④ Legacy 裸驱动：无设备树的老式写法

> 所属章节：第11章 设备模型 > 11.1 其然台阶·六种写法
>
> 难度：[I] | 预计阅读时间：35分钟（含上板实操） | 验证分级：A级（上板可验证）

## <span class="blue"> 本节导读

本节覆盖：

- 六种写法中的第四种：**Legacy 裸驱动**——不写设备树、硬编码总线号和地址、`register_chrdev` 静态注册字符设备、用户手动 `mknod` 的老式驱动
- 用同一颗 LM75 写一份完整的 Legacy 驱动，`cat /dev/mytemp` 直接读出温度
- 这种写法与模式②的三处关键差异，以及它至今仍然适用的两个场景

## <span class="blue"> 场景一句话 [B]

维护十年前的老项目（代码里没有 `.dts`，硬件信息写死在 C 文件里），或临时调试——只想用 30 行代码验证"这颗芯片到底通不通"，不想动设备树和内核配置。

## <span class="blue"> 驱动源码 legacytemp.c [I]

```c
// SPDX-License-Identifier: GPL-2.0
/*
 * legacytemp.c - Legacy 裸驱动写法：无设备树、硬编码、静态字符设备
 * 同一颗 LM75（I2C 地址 0x48），与模式②对照阅读
 */
#include <linux/module.h>
#include <linux/fs.h>             // register_chrdev、file_operations
#include <linux/uaccess.h>        // copy_to_user
#include <linux/i2c.h>

#define TEMP_I2C_BUS	1		/* 硬编码：传感器挂在 1 号 I2C 总线 */
#define TEMP_I2C_ADDR	0x48		/* 硬编码：芯片地址 */
#define TEMP_MAJOR	240		/* 硬编码：静态主设备号（234-254 为实验用途段） */
#define DEVICE_NAME	"mytemp"

static struct i2c_client *temp_client;

/* cat /dev/mytemp 时执行：读芯片、格式化、拷贝给用户 */
static ssize_t temp_read(struct file *filp, char __user *buf,
			 size_t count, loff_t *ppos)
{
	u8 raw[2];
	s16 val;
	char str[16];
	int len, millic;

	if (*ppos > 0)		/* 简单起见，每次打开只支持从头读一遍 */
		return 0;

	if (i2c_smbus_read_i2c_block_data(temp_client, 0x00, 2, raw) < 0)
		return -EIO;

	val = (s16)((raw[0] << 8) | raw[1]);
	millic = (val >> 7) * 500;

	len = snprintf(str, sizeof(str), "%d.%d C\n",
		       millic / 1000, (millic % 1000) / 100);
	if (copy_to_user(buf, str, len))
		return -EFAULT;

	*ppos += len;
	return len;
}

static const struct file_operations temp_fops = {
	.owner = THIS_MODULE,
	.read  = temp_read,
};

/* 芯片探测信息：手动创建 i2c 设备时提供给 I2C 核心 */
static struct i2c_board_info temp_board_info = {
	I2C_BOARD_INFO("lm75-legacy", TEMP_I2C_ADDR),
};

static int __init legacytemp_init(void)
{
	struct i2c_adapter *adap;
	int ret;

	ret = register_chrdev(TEMP_MAJOR, DEVICE_NAME, &temp_fops);
	if (ret < 0)
		return ret;

	/* 不用设备树：直接按总线号找到适配器，手动创建 i2c 设备 */
	adap = i2c_get_adapter(TEMP_I2C_BUS);
	if (!adap) {
		unregister_chrdev(TEMP_MAJOR, DEVICE_NAME);
		return -ENODEV;
	}
	temp_client = i2c_new_client_device(adap, &temp_board_info);
	i2c_put_adapter(adap);
	if (IS_ERR(temp_client)) {
		unregister_chrdev(TEMP_MAJOR, DEVICE_NAME);
		return PTR_ERR(temp_client);
	}

	pr_info("legacytemp: registered, mknod /dev/%s c %d 0\n",
		DEVICE_NAME, TEMP_MAJOR);
	return 0;
}

static void __exit legacytemp_exit(void)
{
	i2c_unregister_device(temp_client);
	unregister_chrdev(TEMP_MAJOR, DEVICE_NAME);
}

module_init(legacytemp_init);
module_exit(legacytemp_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Legacy bare driver for LM75, no device tree");
```

## <span class="blue"> 编译、加载、验证 [B]

`Makefile` 同款（`obj-m += legacytemp.o`）。注意：**做这个实验前，确认设备树里没有 0x48 的节点、也没有加载模式②的驱动**——这颗芯片现在归你手动创建的 i2c 设备管。

```bash
insmod /home/root/legacytemp.ko
mknod /dev/mytemp c 240 0
cat /dev/mytemp
```

预期输出：

```
26.5 C
```

设备节点是手动 `mknod` 创建的——这份代码走的 `register_chrdev` 老路不产生 kobject，所以没有 uevent、没有 devtmpfs 自动生节点（自动链条见 11.5）。`rmmod` 后记得 `rm /dev/mytemp`，内核不会替你清理。

> 💡 自动出节点的开关是 `device_create()`，不是设备树。改用 `alloc_chrdev_region` + `cdev_add` + `class_create` + `device_create()`，无设备树的 Legacy 驱动同样能自动出现 `/dev` 节点、卸载时自动消失。设备树决定"硬件信息从哪来"，uevent 决定"节点怎么自动出现"，两条线互不相干，机制细节见 11.5.2。

> 💡 主设备号 240 取自内核文档规定的实验用途段（234-254），仅用于本机实验。静态主设备号撞上已注册号码时 `register_chrdev` 直接失败，`dmesg` 里没有解释——老项目移植时这是个经典暗坑。

## <span class="blue"> 与模式②的三处关键差异 [I]

| 对比项 | 模式② I2C 写法 | 模式④ Legacy 写法 |
|--------|---------------|-------------------|
| 硬件信息来源 | 设备树节点（`reg = <0x48>`） | `#define` 硬编码在 C 文件里 |
| i2c 设备创建 | I2C 核心解析设备树自动创建 | `i2c_new_client_device()` 手动创建 |
| 用户接口 | 注册 hwmon 框架，标准目录 | `register_chrdev` + 手动 `mknod` |
| 换一个总线/地址 | 改 `.dts` 重新编译 dtb | 改源码、重编模块 |

第四行就是 Legacy 写法的死穴：**硬件信息进了源码，换一块板子就要改代码重编译**。设备树要解决的正是这个问题——理解这一点，比记住语法重要。

> 💡 "裸"还可以更深一层：连 I2C 核心都不走，在内核里直接 `ioremap()`（资源管理版 `devm_ioremap_resource()`）映射控制器寄存器，用 `readl`/`writel` 自己触发传输——这是内核态对应用户空间 `mmap /dev/mem` 的玩法。它绕开了总线核心的一切保护（占用仲裁、锁定、错误恢复），只剩调试价值；写正式驱动时应回到 I2C 核心的 API 上。

## <span class="blue"> 今天仍然适用的两个场景 [I]

1. **临时验证**：新芯片到手，先 30 行裸驱动确认 I2C 通信正常，再投入正式驱动的开发——比直接写 platform/i2c_driver 少两个变量（设备树、匹配流程），问题域最小。
2. **老项目维护**：内核 2.6 时代的代码量以百万行计存在于工控、医疗设备里。读懂这种写法，是接手这类项目的基本功。

> ⚠️ Legacy 写法只适合实验和维护场景。新设计用它，等于把"这块板子的布线"冻结进二进制——下一版硬件改一根线，你就得发一个新的 `.ko`。

## <span class="blue"> 引出的问题

`cat /dev/mytemp` 能读出温度，但这个 `/dev/mytemp` 节点是你 `mknod` 出来的，重启就消失。而模式①②的 hwmon 目录、`/dev` 下的标准节点都是自动出现、自动消失的——**谁替它们做的 `mknod`？** 这个"自动"背后是 uevent 和 devtmpfs，正是 11.5 要拆的机制。下一节先看最后两种写法：借父辈力量的 MFD，以及干脆不进内核的用户空间方案。

## 本节总结

| 要件 | 要点 |
|------|------|
| 写法定位 | 无设备树老项目维护、临时硬件验证 |
| 三个硬编码 | 总线号、地址、主设备号全在 C 文件里 |
| 用户接口 | `register_chrdev` + 手动 `mknod`，无自动节点 |
| 致命伤 | 硬件信息进源码，换板即改代码 |
