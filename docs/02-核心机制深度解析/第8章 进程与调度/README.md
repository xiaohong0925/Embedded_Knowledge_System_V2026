# 第8章：进程与调度

> 所属：第 二 部 核心机制深度解析
>
> BIEM：[I→E] | 核心问题：内核如何管理任务与分配CPU？

## 核心问题

内核如何管理任务与分配CPU？

## 为什么需要这一章

有经验工程师知道 ps 怎么看进程、top 怎么看 CPU 占用、知道 nice 可以调整优先级。但当面对"为什么我的 SCHED_FIFO 任务偶尔延迟 2ms？""为什么系统负载不高但响应很慢？""cgroup 限制了 CPU 为什么效果不明显？"这些问题时，缺乏源码级的调度器理解就会束手无策。

本章要解决的核心矛盾是：调度器的"公平"是数学意义上的公平（vruntime 相等），而非工程意义上的公平（每个任务都按时完成）。理解这个区别，是做出正确调度决策的前提。此外，现代 ARM SoC 的 big.LITTLE 架构使 EAS 能效调度成为标配，cgroups v2 使资源控制成为容器化嵌入式系统的必备知识——这些 [E] 级内容帮助工程师在多核异构环境下做出正确的调度设计。

## 本章主线：一个任务的一生，加上两道管理闸门

本章的六节围绕同一条主线展开：**一个任务从被创建到获得 CPU 时间的完整过程**，以及它跑起来之后必须穿过的两道管理闸门：

```
一个任务的一生：

 fork/clone ──> 进入就绪队列 ──> 被选中运行 <──> 睡眠/唤醒 ──> 退出
     │               │                │
     ▼               ▼                ▼
   8.2 创建机制   8.1 task_struct   8.3 CFS：普通任务怎么排队
  （COW 省了什么）（调度器眼中的任务） 8.4 RT：实时任务怎么插队

 跑起来之后，还要穿过两道管理闸门：

   8.5 cgroups：给它用的 CPU 设上限      8.6 EAS：决定它跑在大核还是小核
```

每一节要深入的细节，都由主线上的**一个必须回答的问题**驱动：

| 小节 | 主线上要回答的问题 | 为什么必须深入这些细节 | 对应的典型故障/场景 |
|------|------------------|----------------------|-------------------|
| **8.1 task_struct** | 调度器眼中的"一个任务"长什么样？ | 调度器操作的不是"进程"而是 sched_entity/rt_entity；不理解 task_struct 的字段组织与状态机，任何调度器源码都读不进去 | 看不懂 /proc/\<pid\>/stat 的字段语义、任务状态异常 |
| **8.2 fork 与 COW** | 新任务怎么被造出来，代价有多大？ | fork 只复制页表不复制物理页，是 COW 的核心优化；理解它才能解释 fork 大内存进程为何瞬间完成、fork 后 RSS 为何"虚高" | fork 后内存统计异常、COW 分裂引发延迟尖峰 |
| **8.3 CFS** | 普通任务之间 CPU 时间怎么分？ | vruntime 记账与红黑树选择给出了"公平"的精确定义；nice 值、权重、调度延迟、负载均衡全部由这套机制推出 | 负载不高但响应慢、nice 调整效果不符预期 |
| **8.4 实时调度** | RT 任务凭什么插队，为什么还会延迟？ | SCHED_FIFO 的实现与优先级继承决定了实时性的边界；延迟的敌人常常不是调度器，而是中断和不可抢占的内核代码段 | RT 任务偶发 2-3ms 延迟、优先级反转 |
| **8.5 cgroups** | 怎么给一组任务的资源设上限？ | quota/period 硬限制与 shares 比例分配有本质区别；分不清 v1/v2 语义是"限制不生效"的最常见根因 | cpu.max 限制不生效、失控进程拖垮系统 |
| **8.6 EAS** | 任务该跑在大核还是小核？ | big.LITTLE 上能效与性能不可兼得；Energy Model 与 find_energy_efficient_cpu 的决策逻辑决定省电还是卡顿 | UI 卡顿、功耗超标、关键任务跑错核 |

## 学习目标

建立从 task_struct 到 CFS/RT 调度、再到 cgroups 与 EAS 的源码级认知，面对"任务为什么没按时运行"类问题时，能用 cyclictest、ftrace、cgroup 接口定位到具体机制层。

## 前置知识

- 第 7 章 启动链深度解析：sched_init() 建立了调度器的基础数据结构

## 与前后章的关联

- **第 7 章**：start_kernel 中 sched_init() 初始化 init_task 与运行队列，是本章的运行时基础
- **第 9 章 内存管理**：每个 task_struct 的 mm 指针指向内存描述符，context_switch 通过 switch_mm 切换地址空间
- **第 10 章 中断与时间**：定时器中断（tick）是触发调度决策的主要事件，hrtimer 是 CFS 调度延迟的基础
- **第 13 章 并发与同步**：优先级继承（PI）依赖 rtmutex 的实现，是多任务同步的核心组成
- **第 15 章 电源管理**：EAS 与 Energy Model 的协同（8.6 节）是 DVFS 与 cpufreq 的调度器端接口
