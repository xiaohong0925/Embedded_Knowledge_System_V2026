## 核心问题

多核并发怎么不崩？

## 本章简介

独特设计：从”随机崩溃”这个最令人头疼的问题出发，建立系统化的并发思维框架。有经验工程师知道并发需要加锁、知道spinlock和mutex的区别、会用pthread_mutex保护共享数据。但面对”系统随机崩溃、dmesg显示无法复现的oops”“加了锁但数据仍然不一致”“为什么RCU比普通锁快那么多”“lockdep报告了什么警告”这些实际问题时，需要源码级的理解。本章的核心认知是：并发bug不是”少加了一把锁”这么简单——80%的并发bug来自对锁的适用范围和使用上下文的误解。理解每种同步原语的精确语义、适用上下文和限制条件，是编写在任何场景下都能正确工作的并发代码的基础。...
