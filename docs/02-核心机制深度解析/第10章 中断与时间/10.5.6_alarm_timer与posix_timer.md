# 10.5.6 Alarm Timer与POSIX Timer

> 所属章节：第10章 中断与时间 > 10.5 时间子系统
>
> 难度：[E] | 预计阅读时间：15分钟

## <span class="blue">本节导读

IoT 设备每晚 11 点上报一次传感器数据，上报完就进入 suspend。<BR>
问题：suspend 后 CPU 停走、总线断电，hrtimer 靠什么把系统叫醒？<BR>
另外，用户态程序想用微秒级定时，标准 API 是什么？

本节覆盖：

- alarm timer 如何借助 RTC 实现 suspend 唤醒、
- 设备树 `wakeup-source` 的作用、
- POSIX timer（`timer_create` 家族）的用法与通知方式选择，
- 以及三者（hrtimer / alarm timer / POSIX timer）的分工边界。

## <span class="blue">Alarm Timer：Suspend状态下的定时唤醒 [E]

hrtimer 再精确，也有一个前提——CPU 在运行。<BR>
系统进入 suspend 后，CPU 时钟停止、本地定时器不再计数，hrtimer 的到期事件既无法触发，也无法把系统唤醒。

这个场景的答案是把定时职责移交给 RTC（实时时钟芯片）。

### RTC：独立供电的唤醒源

RTC 由纽扣电池或独立电源域供电，主系统断电时它仍在计时。<BR>
alarm timer 的机制就是：**把"未来某个时刻唤醒系统"的请求编程进 RTC 的 alarm 寄存器**。

流程：

1. 内核通过 RTC 框架设置唤醒时刻（`rtc_set_alarm`，用户态对应 `/sys/class/rtc/rtc0/wakealarm`）
2. 系统进入 suspend，CPU、总线、外设断电
3. RTC 走到设定时刻，拉起唤醒引脚（中断线接 PMU 或 SoC 唤醒域）
4. 电源管理硬件重新上电，系统 resume
5. resume 后，alarm timer 的回调得到执行

### 设备树里的 wakeup-source

RTC 要具备唤醒资格，设备树里必须声明：

```dts
&rtc {
	compatible = "nxp,pcf8563";
	interrupt-parent = <&gpio>;
	interrupts = <25 IRQ_TYPE_LEVEL_LOW>;
	wakeup-source;        /* 关键：声明该设备可作为系统唤醒源 */
};
```

`wakeup-source` 告诉电源管理框架：这个设备有能力把系统从睡眠状态唤醒。<BR>
缺了这个属性，RTC 的 alarm 中断在 suspend 期间不会被当作唤醒事件处理。

### 内核中使用 Alarm Timer

```c
#include <linux/alarmtimer.h>

static struct alarm my_alarm;

/* 初始化 */
void alarm_init(struct alarm *alarm, enum alarmtimer_type type,
		alarm_callback_t *callback);

/* 设置绝对到期时间 */
int alarm_start(struct alarm *alarm, ktime_t exp);

/* 取消 */
int alarm_cancel(struct alarm *alarm);
```

`alarmtimer_type` 两种选择：

| 类型 | 时钟基 | 说明 |
|------|--------|------|
| `ALARM_REALTIME` | `CLOCK_REALTIME` | 基于 wall time，受系统时间调整影响 |
| `ALARM_BOOTTIME` | `CLOCK_BOOTTIME` | 包含 suspend 时长，不受 NTP/手动调时影响 |

IoT 定时上报这类场景应选 `ALARM_BOOTTIME` : 管理员手动调一次系统时间，不该让今晚的上报任务落空。

> ⚠️ alarm timer 的精度由 RTC 硬件决定，**典型为秒级**<BR>
> ——多数 RTC 的 alarm 寄存器以秒为最小单位，部分芯片（如 PCF8563）的 alarm 甚至只支持分钟级粒度。
<!-- -->
> 它的定位是"长时间后唤醒系统"，不是精确定时；运行时的高精度任务仍然归 hrtimer。

## <span class="blue">POSIX Timer：用户空间的高精度定时 [E]

内核驱动用 hrtimer，用户空间的标准答案是 POSIX timer（`timer_create`/`timer_settime` 家族）。

### 核心API三步

```c
#include <time.h>
#include <signal.h>

/* 第一步：创建定时器 */
timer_t timerid;
struct sigevent sev = {
	.sigev_notify = SIGEV_THREAD,            /* 到期时创建线程执行回调 */
	.sigev_notify_function = timer_handler,
	.sigev_notify_attributes = NULL,
};
timer_create(CLOCK_MONOTONIC, &sev, &timerid);

/* 第二步：设置首次到期与周期 */
struct itimerspec its = {
	.it_value    = { 1, 0 },         /* 首次：1 秒后 */
	.it_interval = { 0, 500000000 }, /* 周期：500ms */
};
timer_settime(timerid, 0, &its, NULL);

/* 第三步：清理 */
timer_delete(timerid);
```

### 通知方式的选择

`sigevent.sigev_notify` 决定到期时的通知方式：

| 通知方式 | 值 | 行为 | 适用场景 |
|----------|-----|------|----------|
| 信号 | `SIGEV_THREAD_ID` | 向指定线程发信号 | 轻量通知，处理函数里做最少的事 |
| 线程 | `SIGEV_THREAD` | 每次到期创建新线程执行回调 | 回调逻辑复杂、需要独立栈 |
| 无 | `SIGEV_NONE` | 不通知，只能 `timer_gettime` 查询 | 轮询/调试 |

> ⚠️ `SIGEV_THREAD` 每次到期都创建一个新线程。<BR>
> 1ms 周期的定时器意味着每秒创建 1000 个线程，线程创建与销毁的开销会吞掉大量 CPU。<BR>
> 高频场景改用 `SIGEV_THREAD_ID` 信号通知，或回调里只写 eventfd、把实际工作交给固定线程池。

### 底层映射到hrtimer

POSIX timer 不是独立实现，内核里最终落在 hrtimer 上：

```
用户空间              内核空间
   |                      |
   | timer_create()       |  hrtimer_init()
   |--------------------->|
   | timer_settime()      |  hrtimer_start()
   |--------------------->|
   |    <---到期通知----  |  hrtimer 到期
   |                      |  -> posix_timer_fn()
   |                      |  -> 信号/线程通知用户空间
```

`kernel/time/posix-timers.c` 的 `posix_timer_fn()` 就是 hrtimer 到期与 POSIX 通知机制之间的桥。<BR>
所以 POSIX timer 的精度直接继承 hrtimer——微秒级，且同样受 C-state 等因素影响（10.5.5）。

## <span class="blue">三种定时器全景对比

| 特性 | hrtimer | alarm timer | POSIX timer |
|------|---------|-------------|-------------|
| 运行上下文 | 内核空间 | 内核空间 | 用户空间 |
| 时间基准 | CPU 本地时钟（clocksource） | RTC 硬件时钟 | 内核 hrtimer（间接） |
| 生效场景 | 系统运行时 | suspend 期间可唤醒系统 | 进程运行时 |
| 精度 | 微秒级 | 秒级（取决于 RTC 芯片） | 微秒级 |
| API | `hrtimer_init()`/`hrtimer_start()` | `alarm_init()`/`alarm_start()` | `timer_create()`/`timer_settime()` |
| 适用场景 | 驱动精确定时、内核周期任务 | 定时唤醒休眠设备 | 用户态采样、实时控制 |
| suspend 期间 | 无法触发，也不能唤醒系统 | 正常工作，到期唤醒系统 | 进程冻结，停止 |
| 典型用例 | 音视频节拍、协议超时 | IoT 定时上报、定时开机 | 数据采集、周期任务 |

### 运行时与休眠期的分工

```mermaid
gantt
    title 系统生命周期中两类定时器的有效区间
    dateFormat X
    axisFormat %s

    section 系统状态
    RUNNING        :a1, 0, 40
    SUSPEND        :a2, 40, 70
    RESUME/RUNNING :a3, 70, 100

    section hrtimer
    有效工作        :b1, 0, 40
    冻结（无法触发） :b2, 40, 70
    恢复工作        :b3, 70, 100

    section alarm timer
    待命            :c1, 0, 38
    写入 RTC alarm  :c2, 38, 40
    有效（负责唤醒） :c3, 40, 70
    回调执行        :c4, 70, 72
    待命            :c5, 72, 100
```

分工很明确：

1. 系统运行时由 hrtimer 负责高精度定时；
2. suspend 前 alarm timer 把唤醒时刻写进 RTC；
3. RTC 到期唤醒系统，alarm 回调执行；
4. resume 后 hrtimer 恢复接管。

两者覆盖系统生命周期的不同区间，是互补关系。

### POSIX Timer完整示例

```c
/* posix_timer_demo.c
 * gcc -o posix_timer_demo posix_timer_demo.c -lrt */

#define _GNU_SOURCE
#include <stdio.h>
#include <time.h>
#include <signal.h>
#include <unistd.h>

static int tick_count = 0;

void timer_handler(union sigval val)
{
	struct timespec ts;
	clock_gettime(CLOCK_MONOTONIC, &ts);
	printf("[tick %d] monotonic: %ld.%09ld\n",
	       ++tick_count, ts.tv_sec, ts.tv_nsec);
}

int main(void)
{
	timer_t timerid;
	struct sigevent sev = {
		.sigev_notify = SIGEV_THREAD,
		.sigev_notify_function = timer_handler,
		.sigev_value.sival_ptr = &timerid,
	};

	if (timer_create(CLOCK_MONOTONIC, &sev, &timerid) == -1) {
		perror("timer_create");
		return 1;
	}

	struct itimerspec its = {
		.it_value    = { 1, 0 },
		.it_interval = { 1, 0 },
	};
	timer_settime(timerid, 0, &its, NULL);

	while (tick_count < 10)
		pause();

	timer_delete(timerid);
	return 0;
}
```

运行效果：

```
./posix_timer_demo
[tick 1] monotonic: 12345.123456789
[tick 2] monotonic: 12346.123457012
[tick 3] monotonic: 12347.123456901
```

间隔稳定在 1 秒，抖动在微秒量级。

> 💡 POSIX timer 的时钟源选 `CLOCK_MONOTONIC` 而不是 `CLOCK_REALTIME`：<br>
> 后者受 NTP 校时和手动调时影响——定时中途系统时间被回拨一小时，基于 REALTIME 的定时器就会多等一小时。

## <span class="blue">本节总结

| 主题 | 核心要点 |
|------|----------|
| alarm timer | 基于 RTC，suspend 期间负责定时唤醒系统 |
| wakeup-source | 设备树声明，RTC 充当唤醒源的前提 |
| 分工模型 | hrtimer 管运行时（微秒级），alarm timer 管 suspend 唤醒（秒级），互补 |
| POSIX timer | 用户态标准高精度 API，底层映射到 hrtimer |
| SIGEV_THREAD 陷阱 | 每次到期创建新线程，高频场景开销巨大 |
| 时钟源选择 | 内核用 BOOTTIME，用户态用 MONOTONIC，避开 REALTIME 跳变 |

### 选型速查

- 内核驱动 + 运行中 + 微秒级 → **hrtimer**
- 需要 suspend 定时唤醒 → **alarm timer**
- 用户态 + 微秒/毫秒级 → **POSIX timer**
- 跨电源状态 → 运行时 hrtimer/POSIX timer，suspend 前设置 alarm timer
