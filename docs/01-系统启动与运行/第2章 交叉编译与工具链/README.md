## 核心问题

怎么在PC上编译板子程序？

## 本章简介

你的PC是x86_64架构，开发板是ARM或RISC-V架构。你不能直接把PC上编译的程序放到板子上运行——架构不同，指令集不兼容。交叉编译是嵌入式开发的”翻译器”，而工具链就是翻译器的完整套件。不理解工具链，后续所有”编译内核”、“编译U-Boot”、“编译应用程序”都会变成机械执行命令而不知道在做什么。

如果跳过这一章直接编译U-Boot，当编译失败报出”undefined reference to __aeabi_uidiv”或者发现libc版本不匹配时，你会完全不知道从何入手。本章不展开编译器前端/后端、链接器算法等深层知识，只聚焦一个目标：让读者理解gcc、binutils、libc三者的关系，能正确选择或构建工具链，并知道arm-linux-gnueabihf-这类前缀的含义。

这是从”用别人脚本”到”自己掌控”的关键一步。前置知识：第1章确定了你的处理器架构（ARM 32/64位？RISC-V？），这直接决定工具链的target triple。...
