## <span class="blue"> 查找自己板子的 dts 文件 [B]

编译 dtb 之前，先确认内核源码中是否包含目标板子的设备树源文件。`.dts` 文件按 SoC 厂商分布在子目录中：

```bash
# 简单查找（仅顶层目录的 .dts）
ls arch/arm64/boot/dts/*.dts 2>/dev/null | grep -i <芯片型号>

# 递归查找所有子目录中的 .dts
find arch/arm64/boot/dts -name "*.dts" | grep -i <芯片型号>

# 示例：查找树莓派相关 dts
find arch/arm64/boot/dts -name "*.dts" | grep -i rpi

# 示例：查找 Rockchip 相关 dts
find arch/arm64/boot/dts -name "*.dts" | grep -i rockchip
```

ARM32 的目录结构相同，只需将 `arm64` 替换为 `arm`：

```bash
cd arch/arm/boot/dts
find . -name "*.dts" | grep -i imx6
```

> ⚠️ 部分厂商将 `.dts` 放在三级子目录中（如 `rockchip/rk3399-nanopi4.dts`），`ls arch/arm64/boot/dts/*.dts` 只能命中顶层文件，建议使用 `find` 命令递归查找。

## <span class="blue"> 编译单个 dtb [B]

若只修改了某一板子的设备树（如调整串口波特率或 GPIO 定义），无需重新编译整个内核。直接指定 `.dtb` 目标即可：

```bash
export ARCH=arm64
export CROSS_COMPILE=aarch64-linux-gnu-

# 编译树莓派4B的dtb
make bcm2711-rpi-4-b.dtb

# 编译 i.MX6ULL EVK 的dtb（ARM32）
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- imx6ull-14x14-evk.dtb
```

编译完成后，产物输出在 `arch/$(ARCH)/boot/dts/` 下的对应子目录中：

```bash
ls -lh arch/arm64/boot/dts/broadcom/bcm2711-rpi-4-b.dtb
```

> 💡 单次编译通常耗时 3~10 秒，远小于完整内核编译的数分钟至数小时。设备树修改频率通常高于内核代码，掌握此命令可显著提升调试效率。

## <span class="blue"> 编译全部 dtb [B]

若需要一次性编译当前架构下所有已选中的设备树，执行：

```bash
make dtbs
```

`make dtbs` 是内核 Makefile 中定义的伪目标，它会遍历 `arch/$(ARCH)/boot/dts/` 下的 Makefile，根据 `.config` 中的 `CONFIG_ARCH_xxx` 选项决定编译哪些 `.dtb`。ARM64 通常生成数十个 dtb，覆盖不同 SoC 与板型；ARM32 的 dtb 数量可能更多。

## <span class="blue"> dtb 在常规编译中的自动触发 [B]

执行常规内核编译命令时，设备树通常会被自动附带生成，无需额外操作。dtb 编译已被加入以下目标的依赖链：

| 编译命令 | 是否自动编译 dtb | 说明 |
|---------|----------------|------|
| `make` | 是 | 默认目标 `all`，dtb 在内核镜像之后编译 |
| `make all` | 是 | 显式编译全部目标 |
| `make zImage` | 是 | ARM32 压缩镜像目标 |
| `make Image` | 是 | ARM64 未压缩镜像目标 |
| `make uImage` | 是 | U-Boot 专用镜像目标 |
| `make modules` | 否 | 仅编译内核模块，不触发 dtb |
| `make dtbs` | 是 | 仅编译 dtb，不碰内核 |

这意味着，若已执行过 `make` 或 `make Image`，dtb 通常已生成完毕，可直接前往 `arch/$(ARCH)/boot/dts/` 查找。

## <span class="blue"> 修改后的增量编译 [B]

设备树的构建系统支持增量编译。修改 `.dts` 或 `.dtsi` 文件后，再次执行 `make <xxx>.dtb` 或 `make dtbs`，Makefile 会根据时间戳和依赖关系自动重新编译受影响的目标：

```bash
# 修改设备树源文件后，重新编译该文件对应的 dtb
vim arch/arm64/boot/dts/rockchip/rk3399-nanopi4.dts
make rk3399-nanopi4.dtb
```

`.dtsi` 文件被多个 `.dts` include 时，修改 `.dtsi` 会触发所有依赖它的 `.dtb` 重新编译。构建系统通过 `scripts/dtc/dtc` 和预处理器 `cpp` 处理 include 关系，依赖链已内嵌在 `arch/$(ARCH)/boot/dts/Makefile` 中。

> ⚠️ 修改 `.dts` 后若执行 `make` 而未看到 dtb 重新生成，检查两个条件：一是 `ARCH` 环境变量是否设置正确；二是 `.config` 中是否启用了对应 SoC 的 `CONFIG_ARCH_xxx` 选项。若 SoC 配置未选中，该厂商目录下的 dtb 会被 Makefile 排除。

> ⚠️ 不要以 `.dts` 后缀作为 `make` 目标。Makefile 中定义的目标是 `.dtb` 后缀，写成 `make xxx.dts` 不会报错，但构建系统不会执行任何编译操作。
