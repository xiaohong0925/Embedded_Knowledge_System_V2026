## <span class="blue"> 安装编译依赖 [B]

在编译 Linux 内核之前，需要先安装构建系统所需的基础依赖包。不同发行版的包名略有差异，但核心组件一致。

### 依赖包清单与作用

| 包名 | 作用 | 不安装的后果 |
|------|------|-------------|
| build-essential | 提供 gcc、make、ld 等基础构建工具 | 无法执行任何编译 |
| libncurses-dev（或 libncurses5-dev） | 提供终端 UI 库，menuconfig 依赖它 | `make menuconfig` 报错无法启动 |
| bison | Kconfig 语法解析器生成工具 | 编译阶段报错 `bison: command not found` |
| flex | 词法分析器生成工具 | 编译阶段报错 `flex: command not found` |
| libssl-dev | 提供 OpenSSL 头文件与库，用于模块签名等 | 启用模块签名时编译失败 |

> 💡 `libncurses-dev` 是较新系统的包名，旧版系统可能使用 `libncurses5-dev` 或 `libncursesw5-dev`，安装时按系统提示选择即可。

### 各发行版安装命令

**Ubuntu / Debian：**

```bash
sudo apt update
sudo apt install build-essential libncurses-dev bison flex libssl-dev
```

**Fedora / CentOS / RHEL / AlmaLinux：**

```bash
sudo dnf groupinstall "Development Tools"
sudo dnf install ncurses-devel openssl-devel elfutils-libelf-devel bc flex bison
```

**Arch Linux / Manjaro：**

```bash
sudo pacman -S base-devel bc flex bison ncurses openssl
```

## <span class="blue"> 工具链可用性检查 [B]

交叉编译器将 C 代码转换为目标处理器可执行的机器码。以 ARM64 平台为例，工具链前缀为 `aarch64-linux-gnu-`，核心命令是 `aarch64-linux-gnu-gcc`。

### 检查编译器版本

```bash
aarch64-linux-gnu-gcc --version
```

正常输出应包含版本号，例如 `aarch64-linux-gnu-gcc (GCC 12.3.0) 12.3.0`。若报错 `command not found`，说明工具链未安装或 PATH 未包含其 bin 目录。

### 确认目标三元组

`gcc -v`（小写 v）输出编译器详细构建信息，其中 `Target:` 行确认其目标架构：

```bash
aarch64-linux-gnu-gcc -v
```

输出中 `Target: aarch64-linux-gnu` 即目标三元组（Target Triple），由 `aarch64`（CPU 架构）- `linux`（操作系统）- `gnu`（ABI）组成。该值必须与目标板一致。

### 验证产出文件架构

写一个最小 C 程序，用交叉编译器编译后检查文件属性：

```bash
echo 'int main(){ return 0; }' > hello.c
aarch64-linux-gnu-gcc -o hello_arm hello.c
file hello_arm
```

输出应包含 `ARM aarch64` 或 `ELF 64-bit LSB executable, ARM aarch64`。若显示 `x86-64`，说明误用了主机原生 gcc。

## <span class="blue"> 环境变量检查 [B]

内核编译依赖两个关键变量：ARCH 和 CROSS_COMPILE。

### 检查 ARCH

```bash
echo $ARCH
```

目标值应为 `arm`、`arm64`、`riscv`、`x86_64` 等之一。该值决定内核 Makefile 进入 `arch/<ARCH>/` 目录提取架构专属代码。

### 检查 CROSS_COMPILE

```bash
echo $CROSS_COMPILE
```

目标值应为 `aarch64-linux-gnu-`、`arm-linux-gnueabihf-` 等。**前缀末尾必须带 `-`**。若写成 `aarch64-linux-gnu`（无末尾短横线），内核 Makefile 拼接 `$(CROSS_COMPILE)gcc` 时会生成 `aarch64-linux-gnugcc`，导致命令找不到。

### 检查 make 版本

```bash
make --version | head -1
```

内核构建系统要求 GNU Make 4.0 或更高版本。Ubuntu 20.04+、Debian 10+ 自带版本均满足要求。

## <span class="blue"> 工具链完整工具集检查 [B]

内核编译除 gcc 外，还需要 ld、objcopy、nm、strip 等工具。交叉编译工具链应提供完整一套：

```bash
for tool in gcc ld objcopy nm strip; do
  which aarch64-linux-gnu-${tool} && echo "  OK"
done
```

> ⚠️ 某些精简安装只包含 gcc，缺少 binutils（ld、objcopy 等）。编译时会在链接阶段报错 `aarch64-linux-gnu-ld: command not found`。确保完整安装，例如 Debian/Ubuntu 上需同时安装 `gcc-aarch64-linux-gnu` 和 `binutils-aarch64-linux-gnu`。

## <span class="blue"> 快速检查表

| 检查项 | 核心命令 | 合格标志 | 常见错误 |
|--------|---------|---------|---------|
| 交叉编译器 | `aarch64-linux-gnu-gcc --version` | 输出版本号 | PATH 未包含工具链 bin 目录 |
| ARCH 变量 | `echo $ARCH` | arm / arm64 / riscv 等 | 与工具链架构不匹配 |
| CROSS_COMPILE 前缀 | `echo $CROSS_COMPILE` | 末尾带 `-` | 漏写末尾横线，工具名拼接失败 |
| make 版本 | `make --version` | GNU Make 4.0+ | 老系统自带 Make 3.80 |
| 深度验证 | `gcc -v` + `file` | Target Triple 匹配 + ELF 架构正确 | 误用主机 gcc 编译出 x86 内核 |
