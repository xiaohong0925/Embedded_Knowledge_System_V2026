# 第3章：Bootloader：系统的第一段代码

> 所属：第 一 部 系统启动与运行
> BIEM：[B] | 核心问题：上电后谁加载内核？

## 核心问题

上电后谁加载内核？

## 本章简介

上电后，处理器执行的第一行代码不是Linux内核——它甚至不知道内核在哪里。有一个”接力”过程：处理器先执行芯片内固化的BootROM，BootROM加载第一阶段引导程序（SPL），SPL初始化基本硬件后加载U-Boot，U-Boot再加载Linux内核。理解这个接力过程，是理解整个嵌入式系统启动的核心。

如果跳过这一章直接进入内核配置，当板子”启动不了”时，你无法判断问题是出在BootROM找不到SPL、SPL找不到U-Boot、U-Boot找不到内核，还是内核找不到根文件系统。本章的核心目标是：让读者理解上电到内核启动之间的完整链路，能独立配置、编译、烧录U-Boot，并通过TFTP/NFS建立高效的开发循环。

设备树（Device Tree）在本章引入，因为它是U-Boot传递给内核的”硬件描述说明书”——没有这个，内核根本不知道你的板子上有多少内存、串口在哪个地址。前置知识：第1章的硬件知识（知道BootROM从哪个存储介质启动）和第2章的工具链（用来编译U-Boot）。...
