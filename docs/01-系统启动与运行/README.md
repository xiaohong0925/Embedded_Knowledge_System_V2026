# 第 I 部：系统启动与运行

> **BIEM [B→I] | 从拿到开发板到看到 Shell 提示符**

**核心价值**：让读者能够独立完成一个最小可启动系统的全流程——从认识硬件、建立工具链，到编译 Bootloader、内核、根文件系统，最终看到 shell 提示符，并点亮第一个 LED。这是嵌入式 Linux 开发者的「第一口氧气」。

## 终点成就检查清单

完成第 I 部后，你应该能独立完成以下任务：

1. [ ] 拿到一块新开发板，能识别其 SoC、存储介质和调试接口
2. [ ] 成功连接串口，看到 BootROM / U-Boot 的输出
3. [ ] 配置并编译交叉编译工具链，或正确使用预构建工具链
4. [ ] 编译 U-Boot 并烧录到开发板，能进入 U-Boot 命令行
5. [ ] 配置、编译 Linux 内核，生成支持目标板的 Image
6. [ ] 使用 TFTP / NFS 建立网络开发环境
7. [ ] 手工构建 BusyBox 根文件系统，编写 init 脚本
8. [ ] 看到 shell 提示符，执行基本命令（ls、cat、ifconfig 等）
9. [ ] 从用户空间控制 GPIO，点亮 / 熄灭 LED
10. [ ] 编写设备树节点，加载 LED 驱动，通过 sysfs 控制 LED

## 与第 II 部的衔接

第 I 部建立的认知基础 → 第 II 部回答的深层问题：

- **"U-Boot 怎么知道板子上有多少内存？"** → 第 II 部第 7 章：设备树深入与内存管理子系统
- **"那个让 LED 亮起来的驱动到底是怎么工作的？"** → 第 II 部第 8 章：字符设备驱动开发
- **"每次手工编译太麻烦，有自动化的方法吗？"** → 第 II 部第 6 章：Buildroot 与 Yocto 构建系统
- **"根文件系统只有 BusyBox 太简陋了，怎么添加更多功能？"** → 第 II 部第 9 章：系统服务与进程管理
- **"内核启动时打印的那些日志到底是什么意思？"** → 第 II 部第 7 章：内核子系统深入
- **"GPIO 只有 sysfs 一种控制方式吗？"** → 第 II 部第 8 章：字符设备接口与 ioctl

## 螺旋学习模型说明

本书采用**螺旋学习模型**：同一主题会在不同深度多次出现，而非一次讲透。

| 主题 | 第 I 部（第一次） | 第 II 部（第二次） | 第 III 部（第三次） |
| :--- | :--- | :--- | :--- |
| 设备树 | 3.5.1 设备树基础：知道它是什么、怎么写节点 | 7.x 启动链深度解析：解析器机制、内存映射、/of 子系统 | 11.x 设备模型：与 platform_driver 的绑定关系 |
| 驱动 | 4.5.x / 6.3.x 初识：加载、控制、感受现象 | 8.x 字符设备驱动：open/read/write、file_operations | 全 III 部：总线、框架、中断、并发、电源 |
| 文件系统 | 5.2.x 创建目录、挂载 proc/sys | 12.x 文件系统深度：VFS、页缓存、具体文件系统实现 | 构建与部署：initramfs、overlayfs、只读根文件系统 |

> **建议**：如果第 I 部某节感到吃力，先完成后续章节，建立整体体感后再回头精读。第 I 部的目标是「让系统跑起来」，而非「理解每个细节」。
