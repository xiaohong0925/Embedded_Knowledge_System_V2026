## <span class="blue"> 知识点275 [B] — I2C协议状态机

I2C总线上的每一次通信，都严格遵循一个**五状态机**模型。理解这个状态机，是读懂I2C的核心。

```
                    ┌─────────┐
         ┌─────────→│  IDLE   │←────────────────┐
         │          │ (空闲)  │                 │
         │          └────┬────┘                 │
         │               │ START条件             │ STOP条件
         │               ↓                      │
         │          ┌─────────┐    地址匹配成功   │
         │    ┌────→│  ADDR   │────────────────→┘
         │    │NACK │ (地址帧) │                 │
         │    └─────┤         │                 │
         │          └───┬─────┘                 │
         │              │ ACK                    │
         │              ↓                        │
         │         ┌─────────┐   最后一字节      │
         │    ┌───→│  DATA   │────────────────→┘
         │    │NACK │ (数据帧) │                 │
         │    └─────┤         │                 │
         │          └───┬─────┘                 │
         │              │ Repeated START         │
         │              └──────────────────────→┘
         │
         └──────── 回到IDLE(释放总线)
```

### 状态转移详解

| 状态 | 触发条件 | SDA状态 | SCL状态 | 说明 |
|:---:|:---|:---|:---|:---|
| **IDLE** | 总线空闲，无通信 | 高（被上拉） | 高（被上拉） | 等待START条件 |
| **START** | SDA下降沿且SCL=H | H→L（下降沿） | 高电平 | 由Master发起，总线被占用 |
| **ADDR** | START后发送9个CLK | 7bit地址+R/W | 时钟驱动 | 第9个时钟是ACK位 |
| **DATA** | 地址ACK后 | 逐bit数据 | 时钟驱动 | 每字节后紧跟ACK/NACK |
| **STOP** | SDA上升沿且SCL=H | L→H（上升沿） | 高电平 | 由Master发起，总线释放 |

START和STOP条件是I2C协议的**灵魂**。记住这两个黄金规则：

- **START条件**：SCL为高电平期间，SDA从高变低（下降沿）
- **STOP条件**：SCL为高电平期间，SDA从低变高（上升沿）

在数据传输过程中，SCL为高时SDA**必须稳定不变**——这正是I2C用SDA电平变化来表示START/STOP的巧妙之处：正常数据只在SCL低电平期间变化。

```
SCL  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──
       └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘
SDA  ──────┐     ┌────┐     ┌────┐     ┌────┐     ┌────┐     ┌────┐
           └─────┘    └─────┘    └─────┘    └─────┘    └─────┘    └──────
           ↑START                               ↑ACK                   ↑STOP
           SDA↓                                 SDA↓                   SDA↑
           @SCL=H                               @SCL=H                @SCL=H

           [S][A6][A5][A4][A3][A2][A1][A0][RW][ACK] ... [D7]...[D0][ACK]...[P]
```

### 地址帧格式：7bit地址 + R/W位

每个I2C从设备都有一个**7bit唯一地址**，Master在START后首先发送这7位地址，外加1位读写方向位，共构成1字节（8bit）的地址帧。

```
地址帧（1字节 = 8bit）：
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ A6  │ A5  │ A4  │ A3  │ A2  │ A1  │ A0  │ R/W │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
  ↑                                   ↑         ↑
  │                                   │         │
  MSB（最高位先发）              LSB    0=写(Write), 1=读(Read)
```

举个例子：EEPROM芯片AT24C02的I2C地址是`0x50`（二进制`1010000`）。当Master要写入数据时，发送的地址字节是`0xA0`（`10100000`，R/W=0）；要读取时发送`0xA1`（`10100001`，R/W=1）。注意这里的差别——**你代码里写的`0x50`是7bit地址，实际线路上传输的是8bit（含R/W位）**。

> ⚠️ **陷阱**：很多新手在Linux的`i2c_transfer()`里把`0xA0`当地址传，结果设备没响应。正确做法是传7bit地址`0x50`，驱动会自动处理R/W位。

### ACK/NACK 握手机制

I2C没有单独的"应答线"，ACK/NACK也是通过SDA实现的。每传输完1字节（8个数据bit），**接收方**必须在第9个时钟周期内拉低SDA，表示ACK；如果接收方让SDA保持高电平，就是NACK。

| 类型 | 发送者 | 线路表现 | 含义 | 处理方式 |
|:---:|:---:|:---:|:---|:---|
| **ACK** | 接收方 | SDA在第9个CLK期间=**L** | "我收到了，继续发" | Master继续发送下一字节 |
| **NACK** | 接收方 | SDA在第9个CLK期间=**H** | "我没收到/我不要了" | Master必须发STOP或Repeated START |

ACK/NACK可能发生在两个关键时刻：

1. **地址ACK**：在地址帧的第9位。如果从设备没拉低SDA（NACK），说明这个地址上没有设备响应，或者设备正忙。
2. **数据ACK**：在每个数据字节的第9位。如果是Master写操作，从设备ACK表示"数据已接收"；如果是Master读操作，Master发ACK表示"我还要继续读"，发NACK表示"这是最后一字节，停吧"。

```
地址ACK示例（成功匹配）：
SCL  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──────┐  ┌──
       └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  │ ACK  │  └──
SDA  ──A6──A5──A4──A3──A2──A1──A0──R/W─│←──L──→│──────────
                                         从设备拉低SDA

数据NACK示例（从设备无法接收更多）：
SCL  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──────┐  ┌──
       └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  │NACK  │  └──
SDA  ──D7──D6──D5──D4──D3──D2──D1──D0──│←──H──→│──────────
                                         SDA保持高（上拉）
```

### 时钟拉伸（Clock Stretching）

这是I2C协议中一个**从设备可以主动控制总线速度**的机制。如果某个从设备处理速度较慢（比如低速MCU或需要较长时间操作内部EEPROM），它可以在任何时候把**SCL拉低**。Master检测到SCL被拉低后，**必须等待**SCL重新变高才能继续发送下一个时钟脉冲。

```
正常时钟：              时钟拉伸：
SCL  ┌──┐ ┌──┐ ┌──┐    SCL  ┌──┐ ┌──┐ ┌────────┐ ┌──┐
     └──┘ └──┘ └──┘              └──┘ └──┘        └──┘ └──┘
                      ↑                  ↑
                      │                  │
                   从设备拉低SCL        从设备释放SCL
                   （告诉主设备：        （主设备检测到SCL变高，
                    我还没准备好）       继续下一个时钟）
```

时钟拉伸对软件驱动编写有直接影响。Linux I2C驱动的`i2c-algo-bit.c`里有一段专门检测SCL是否被拉低的代码，通常会设置一个超时值（常见100ms），如果超时还没等到SCL变高就会报错。

> ⚠️ **陷阱**：**时钟拉伸死锁**。假设某个从设备因为固件bug在拉低SCL后死机，再也释放不了SCL。Master会一直等，整个I2C总线就此瘫痪。更隐蔽的是，有些软件的I2C Master实现（比如用GPIO模拟的bit-bang方案）根本不检测SCL状态，只是盲目输出时钟——这种实现对时钟拉伸完全"无感知"，一旦遇到拉伸就直接挂掉。实际产品中，**务必在I2C控制器驱动里设置超时检测，配合看门狗防止永久死锁**。

> 💡 **提示**：有些I2C设备（如BMP280传感器）在上电初始化时会进行内部校准，此时会自动拉伸时钟几百微秒。如果你的I2C驱动在初始化阶段报"timeout"，先确认是不是设备在时钟拉伸，而不是地址错误或线路故障。

### 10bit地址扩展

7bit地址空间只有128个（0x00~0x7F），其中一些还被保留（如0x00通用呼叫、0x77~0x7F特殊用途），可用的不重复地址大约112个。当总线上设备多时不够用了，I2C协议定义了**10bit地址扩展**模式。

10bit地址的传输需要**两个字节**来完成寻址：

```
第一字节（地址头）：
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│  1  │  1  │  1  │  1  │  0  │ A9  │ A8  │ R/W │  = 0xF0 + (A9:A8) + R/W
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
  ↑高5bit固定为0b11110                  ↑10bit地址的高2位

第二字节（地址低8位）：
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ A7  │ A6  │ A5  │ A4  │ A3  │ A2  │ A1  │ A0  │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
  ↑10bit地址的低8位

完整10bit地址时序：
[S][11110 A9 A8 R/W][ACK][A7~A0][ACK][DATA][ACK]...[P]
  ↑START  ↑第一字节    ↑从ACK  ↑第二字节 ↑从ACK ↑数据
```

注意10bit地址模式有一个精妙设计：第一字节的高5bit固定为`0b11110`，这意味着它与任何7bit地址（最高位bit7=0）都不会冲突。所以**10bit设备和7bit设备可以混接在同一条总线上**。

### 重复START（Repeated START）

重复START是I2C协议里一个非常实用的技巧。Master在不停下发STOP的情况下，直接发送一个新的START条件，从而在不释放总线的情况下切换通信方向或更换从设备地址。

```
没有Repeated START（效率低）：
[S][Addr+W][ACK][RegAddr][ACK]  [P]  ← STOP，释放总线
[S][Addr+R][ACK][Data][NACK]    [P]  ← 重新START，重新寻址

使用Repeated START（更高效）：
[S][Addr+W][ACK][RegAddr][ACK]  [Sr] [Addr+R][ACK][Data][NACK][P]
                                  ↑
                                  Repeated START，不释放总线
```

典型的应用场景是**"写寄存器地址 + 读数据"**的复合操作，比如从传感器读取某个寄存器的值。第一步先把寄存器地址写过去（写方向），第二步立刻切换成读方向取数据。Repeated START在这里比STOP+START更高效，省了一个STOP条件的时间，而且在多主设备环境中减少了总线被抢占的风险。

> 💡 **提示**：Repeated START不仅省时间，更重要的是在多主设备环境中保证**原子性**——从START到STOP之间总线一直被当前Master占用，其他Master插不进来。如果你的读操作分两次（先STOP再START），中间可能被其他Master抢走总线，导致读出错误数据。

## <span class="blue"> 知识点276 [I] — 完整时序图与错误处理

### 写字节完整时序

以Master向从设备（地址0x50）写入一个数据字节`0xAB`为例：

```
Phase:  S    Address     A    Data Byte      A    P
       ─┬─ ─────────── ─┬─ ─────────────── ─┬─ ─┬─
        │  1 0 1 0 0 0 0 0 L  1 0 1 0 1 0 1 1  L
        │  │ │ │ │ │ │ │ │ │  │ │ │ │ │ │ │ │  │
SCL   ──┘  ┘ ┘ ┘ ┘ ┘ ┘ ┘ ┘ ┘  ┘ ┘ ┘ ┘ ┘ ┘ ┘ ┘  ┘
         ↑                  ↑                  ↑
      SDA↓@SCL=H        SDA↓@SCL=H        SDA↑@SCL=H
      (START)          (从ACK)            (STOP)

位序说明（MSB先发）：
地址帧 = 0x50 << 1 | 0 = 0xA0 → 线上: 1 0 1 0 0 0 0 0
数据帧 = 0xAB → 线上: 1 0 1 0 1 0 1 1
```

### 读字节完整时序（使用Repeated START）

以从从设备（地址0x50）的寄存器0x01读取1字节为例：

```
Phase:  S   Addr+W   A  RegAddr  A  Sr  Addr+R  A   Data    N  P
       ─┬─ ─────── ─┬─ ─────── ─┬─ ─┬─ ────── ─┬─ ────── ─┬─ ─┬─
        │ 1010000 0 L  00000001 L  │  1010000 1 L 11110000 H │
        │                          │  ↑Sr                  NACK  ↑STOP
SCL   ──┘                          └────────────────────────────┘
        START:告诉从设备"我要写"    Sr:切换方向    STOP:读取完成
```

### 连续读（Burst Read）时序

连续读在传感器、EEPROM等场景中非常常见。Master除了最后一个字节发NACK，中间所有字节都发ACK：

```
[S][Addr+R][ACK][Data0][ACK][Data1][ACK][Data2][ACK]...[DataN-1][NACK][P]
   ↑开始读     ↑第一字节  ↑继续  ↑继续    ↑继续     ↑Master发NACK
   │           │         │      │       │          "够了，不用再发了"
   └───────────┴─────────┴──────┴───────┴──────────┘
                 总线一直被当前Master占用（原子操作）
```

### 常见错误与故障排查

在实际调试I2C时，以下三类错误最高频。用示波器抓波形时对照这张表定位问题：

| 错误类型 | 根本原因 | 示波器症状 | 解决方法 |
|:---:|:---|:---|:---|
| **地址NACK** | 从设备地址设置错误；设备未上电；设备损坏 | 地址帧后SDA第9位=H | 核对芯片手册地址；检查供电；用`i2cdetect`扫描 |
| **仲裁丢失** | 多Master同时发送，某一位一个发H一个发L | 波形正常但某字节传输中断；Master状态寄存器报ARB_LOST | 检查是否有多个Master初始化；添加软件仲裁层 |
| **总线忙检测** | 某次通信异常终止（如Master死机），未发STOP导致总线永久占用 | SDA或SCL持续为L | 发送9个SCL时钟脉冲"clock out"恢复；复位相关设备 |
| **数据CRC错** | 信号完整性差（线缆太长、上拉太强/太弱）；时钟拉伸超时 | 波形有毛刺；ACK位异常 | 缩短线缆；调整上拉电阻；降低总线速度 |
| **时钟拉伸死锁** | 从设备拉低SCL后死机 | SCL持续为L | 看门狗复位从设备；I2C驱动设置超时 |

#### 仲裁丢失详解

I2C支持多主设备（Multi-Master），仲裁机制基于一个简洁原则：**SDA是开漏输出，线与逻辑。谁发0谁赢**。

```
Master A 想发: 1 0 1 ...
Master B 想发: 1 1 0 ...
             ─┬─┬─┬─
SDA实际波形:  1 0 0  ← 第2位：A发0，B发1，实际=0（线与结果）
                        ↑
                        B读到SDA=0，但自己发了1 → B输掉仲裁 → B立即停止发送

继续传输:    1 0 1 0 ...
             ─┬─┬─┬─┬─
             ↑只有A还在发，A赢得仲裁
```

仲裁可以发生在地址帧或数据帧的任何一位。输掉仲裁的Master会在**当前字节结束后**退出，等待总线空闲后重试。现代SoC的I2C控制器（如i.MX6、STM32、Allwinner）都有硬件仲裁检测，会在状态寄存器中设置ARB_LOST标志。

#### 总线恢复技巧

如果I2C总线因为异常而"卡住"（SDA或SCL被持续拉低），可以用**clock out**技术手工恢复：

```c
// GPIO模拟SCL输出9个时钟脉冲，强制"clock out"被锁住的从设备
for (int i = 0; i < 9; i++) {
    gpio_set_value(scl_gpio, 0);
    udelay(5);          // 根据总线速度调整延时
    gpio_set_value(scl_gpio, 1);
    udelay(5);
    if (gpio_get_value(sda_gpio) == 1)  // 检测到SDA释放
        break;
}
// 最后发一个STOP条件
gpio_direction_output(sda_gpio, 0);
gpio_set_value(scl_gpio, 1);
delay(5);
gpio_set_value(sda_gpio, 1);  // STOP: SDA↑ @ SCL=H
```

Linux内核的`i2c-core.c`里就有类似的bus recovery逻辑，可以通过`i2c_generic_scl_recovery`调用。某些驱动还支持`i2c-gpio`的`scl-gpio`/`sda-gpio`方式直接用GPIO恢复。

## <span class="blue"> 本节总结

| 要点 | 内容 |
|:---|:---|
| **状态机** | IDLE → START → ADDR → DATA → STOP，START/STOP由SDA在SCL=H时的边沿定义 |
| **地址帧** | 7bit地址 + 1bit R/W = 8bit；10bit地址用2字节发送，头字节固定`11110` |
| **ACK/NACK** | 接收方在第9个CLK拉低SDA=ACK；保持高=NACK；读操作的NACK告诉从设备"停止发送" |
| **时钟拉伸** | 从设备可拉低SCL让Master等待；注意死锁风险，驱动必须设置超时 |
| **Repeated START** | 不发STOP直接发新START，用于原子性切换读写方向；比STOP+START更高效 |
| **仲裁丢失** | 多Master时"谁发0谁赢"；硬件控制器自动检测ARB_LOST标志 |

  ```bash
  # 从0x50读取1字节
  i2cget -y 0 0x50 0x00
  # 向0x50写入0xAB到寄存器0x00
  i2cset -y 0 0x50 0x00 0xAB
  ```
