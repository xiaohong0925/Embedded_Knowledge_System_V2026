## <span class="blue"> 本节导读

上一节我们了解了I3C诞生的背景和物理层的基础电气特性。本节将深入I3C的**协议层心脏**——三种不同的传输模式（SDR/DDR/TSP）如何适应不同带宽需求，**CCC命令集**如何实现总线级别的设备管理，以及**IBI带内中断**和**热加入**机制如何让从设备主动"开口说话"。掌握这些，你就能理解I3C为何能用一个两线接口同时替代I2C+SPI+GPIO中断——它不只是跑得更快的I2C，而是一套完整的总线治理体系。

## <span class="blue"> 知识点297 [I] — I3C协议模式

I3C没有把所有鸡蛋放在一个篮子里。它定义了三种传输模式，让主设备可以根据通信对象和数据量灵活切换。

### SDR：Single Data Rate

SDR模式是I3C的"默认档位"，也是与I2C最像的模式。数据在SCL的**单个时钟边沿**上采样，使用传统的8位数据+1位ACK格式。但别小看它——I3C的SDR可以跑到**12.5Mbps**，是Fast-mode Plus I2C（1Mbps）的十倍以上。

SDR帧格式保留了I2C的起始位（S）和停止位（P），但加入了I3C特有的**广播地址（0x7E）**。所有I3C从设备都必须识别0x7E，这是总线管理命令的入口。

```
SCL  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──────
       └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘
SDA  ──████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░████
       S   D7 D6 D5 D4 D3 D2 D1 D0  ACK           P
       └───── 8-bit Data ─────┘  └─ 9th bit ──┘

     ▓▓ = Start (S)     ████ = Stop (P)     ░░ = Data bits
```

### HDR-DDR：Double Data Rate

HDR-DDR是I3C的主力高速模式。它放弃了传统的ACK位，改用**16-bit数据字**封装两个8位字节，数据在SCL的**上升沿和下降沿都被采样**——这就是"Double Data Rate"的含义。DDR模式下最高可达**25Mbps**。

DDR帧以专门的起始模式（HDR Restart Pattern）进入，以HDR退出模式（HDR Exit Pattern）退出。关键细节：**DDR帧中没有ACK位**，接收方通过CRC来校验数据完整性。

```
SCL  ──┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐
       └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─
         ↑  ↓  ↑  ↓  ↑  ↓  ↑  ↓  ↑  ↓  ↑  ↓  ↑  ↓  ↑  ↓
SDA  ──░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
       └─ Byte0 ─┘└─ Byte1 ─┘└─ Byte2 ─┘└─ Byte3 ─┘
       ←────── 16-bit Word (no ACK) ──────→

     ↑ = Rising edge sample    ↓ = Falling edge sample
```

### HDR-TSP：Ternary Symbol Packet

HDR-TSP是I3C的"终极速度模式"。它不再用二进制的0和1传输数据，而是利用SDA和SCL两条线定义**三种符号状态**，每个时钟周期传输更多信息。TSP模式最高可达**33.3Mbps**。

```
SCL+SDA组合状态：
  (SCL=0, SDA=0) → Symbol '0'
  (SCL=0, SDA=1) → Symbol '1'  
  (SCL=1, SDA=0) → Symbol '2'
  (SCL=1, SDA=1) → 非法状态 (reserved)
```

TSP的复杂度更高，目前主流I3C控制器（如DW I3C、NXP）普遍先支持SDR和DDR，TSP尚在逐步普及中。

### 三种模式对比

| 模式 | 速率 | 编码方式 | I2C设备可见性 | 数据格式 | 适用场景 |
|------|------|----------|---------------|----------|----------|
| SDR | ~12.5 Mbps | 单沿采样，8-bit+ACK | 可识别 | 传统字节+ACK | 兼容I2C设备、小数据量控制 |
| HDR-DDR | ~25 Mbps | 双沿采样，16-bit字 | **必须忽略** | 双字节字，无ACK | 大批量传感器数据读取 |
| HDR-TSP | ~33.3 Mbps | 三进制符号 | **必须忽略** | 三符号编码包 | 极高带宽需求（图像/音频） |

> ⚠️ **陷阱**：进入HDR模式（DDR或TSP）之前，**必须确保总线上所有I2C设备处于安全状态**。I2C设备不认识HDR的进入模式（HDR Entry Pattern），可能会把总线上的特殊时序误解为普通数据，导致误触发或总线锁死。正确的做法是：进入HDR前通过广播CCC命令检查总线状态，或确保I2C设备已上电但处于不寻址状态。

## <span class="blue"> 知识点298 [I] — CCC命令集

CCC（Common Command Code）是I3C总线治理的核心机制。它是一组标准化的命令，主设备通过它们管理从设备的状态、地址和行为。CCC命令使用**广播地址0x7E**作为目标，所有从设备都能听到。

### CCC命令格式

```
SCL  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
       └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘
SDA  ──████████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░████████████
       S   RnW=0(Write)  Broadcast Addr = 0x7E  ACK  CCC Code  ACK  [Data]  P
       └─────── 7-bit Address ──────┘  └─ 8-bit CCC ─┘
```

### 关键CCC命令集

| 命令 | 方向 | 功能 | 参数 | 响应 |
|------|------|------|------|------|
| `ENTDAA` | 广播→所有 | 进入动态地址分配流程 | 无 | 从设备按优先级响应PID |
| `SETDASA` | 定向→指定设备 | 利用静态I2C地址直接设置动态地址 | 静态地址+新动态地址 | ACK确认 |
| `ENTAS0` | 广播/定向 | 进入Activity State 0（低功耗等待） | 无 | ACK |
| `ENTAS1` | 广播/定向 | 进入Activity State 1（正常活动） | 无 | ACK |
| `RSTDAA` | 广播→所有 | 重置所有动态地址，回到广播模式 | 无 | 从设备清除动态地址 |
| `ENEC` | 定向 | 使能指定事件（如IBI、热加入） | 事件掩码 | ACK |
| `DISEC` | 定向 | 禁用指定事件 | 事件掩码 | ACK |
| `GETPID` | 定向 | 读取从设备的48-bit Provisional ID | 无 | 48-bit PID返回 |
| `GETBCR` | 定向 | 读取Bus Characteristic Register | 无 | 8-bit BCR返回 |
| `GETDCR` | 定向 | 读取Device Characteristic Register | 无 | 8-bit DCR返回 |
| `SETMWL` | 定向 | 设置最大写长度 | 16-bit长度值 | ACK |
| `SETMRL` | 定向 | 设置最大读长度 | 16-bit长度值 | ACK |
| `ENTHDR0` | 广播 | 进入HDR-TSP模式 | 无 | 总线切换至TSP |
| `ENTHDR1` | 广播 | 进入HDR-DDR模式 | 无 | 总线切换至DDR |

### 广播CCC vs 定向CCC

```
广播CCC (Broadcast):
  Master → [S] [0x7E+W] [ACK] [CCC] [ACK] [P]
           └── 所有从设备都监听并执行 ──┘
  例：RSTDAA —— 同时重置所有设备的动态地址

定向CCC (Directed):
  Master → [S] [0x7E+W] [ACK] [CCC] [ACK] [DevAddr+W] [ACK] [Data] [P]
           └── CCC命令指定目标 ──┘  └── 从设备地址跟随 ──┘
  例：ENEC 0x08 —— 仅对地址0x08的设备使能事件
```

> 💡 **提示**：`SETDASA`命令是I2C到I3C迁移的神器。如果你的传感器有固定的I2C静态地址（比如0x68的MPU6050），主设备可以直接用`SETDASA`给它分配动态I3C地址，跳过完整的DAA流程，启动速度快得多。

## <span class="blue"> 动态地址分配（DAA）流程 [I]

I3C从设备刚上电时没有动态地址，必须通过DAA流程获取。这是I3C"即插即用"特性的核心。

### DAA完整流程

```
阶段1：主设备发起DAA
┌─────────┐                                    ┌─────────┐
│  Master │──[S]→[0x7E+W]→[ACK]→[ENTDAA]───→ │  Slaves │
│         │                                    │ (all)   │
└─────────┘                                    └─────────┘

阶段2：从设备竞争响应（按PID优先级）
┌─────────┐                                    ┌─────────┐
│  Master │←──────────[PID[47:32]]─────────────│ Slave 1 │  ← 最高优先级
│  (已知  │←──────────[PID[31:16]]─────────────│ (wins)  │    (PID最小)
│   PID)  │←──────────[PID[15:0]]──────────────│         │
└─────────┘                                    └─────────┘
         ↓ 其他从设备检测到冲突，自动退出本轮竞争

阶段3：主设备分配动态地址
┌─────────┐                                    ┌─────────┐
│  Master │──[NewAddr+W]→[ACK]────────────────→│ Slave 1 │  ← 现在有了
│         │                                    │ 0x08    │    动态地址!
└─────────┘                                    └─────────┘

阶段4：重复直到所有设备分配完毕
┌─────────┐                                    ┌─────────┐
│  Master │←──────────[PID[47:0]]──────────────│ Slave 2 │  ← 次高优先级
│         │──[NewAddr+W]→[ACK]────────────────→│ 0x09    │
└─────────┘                                    └─────────┘
         ↓
     [P] —— ENTDAA帧结束
```

### 优先级仲裁机制

DAA的核心巧思在于**SDA开漏竞争**。从设备在响应PID时，逐位驱动SDA。如果某个从设备想发1（开漏释放）但检测到SDA被拉低（有更优先的设备在发0），它就自动放弃本轮。PID值最小的设备（最高优先级）总能赢得仲裁——这与I2C的时钟延展和CAN的ID仲裁异曲同工。

```
PID仲裁逐位对比示例：
  Slave A PID[47]: 0 0 1 0 1 1 0 1 ... = 0x2D...
  Slave B PID[47]: 0 0 1 0 0 1 1 1 ... = 0x27...
                      ↑ 第4位不同：A发1(释放), B发0(拉低)
                      → SDA被拉低，A检测到冲突，退出竞争
                      → B继续响应，获得优先分配权
```

### 热加入（Hot-Join）

热加入让设备在总线**已经运行时**动态接入，不需要重新初始化整条总线。

```
时序图：热加入流程

SCL  ───────────────────────────────────────────────
SDA  ───────┐        ┌─────────────────────────────
            └────────┘
            ↑        ↑
         新设备      主设备检测到
         拉低SDA     热加入请求
         发Hj请求   发送ENTDAA重新分配

步骤：
  1. 新设备上电，监听总线等待空闲
  2. 新设备在总线空闲时拉低SDA（热加入请求）
  3. 主设备检测到SDA被意外拉低，识别为热加入事件
  4. 主设备发送广播ENEC使能热加入响应
  5. 主设备发送ENTDAA，仅为新设备执行地址分配
  6. 新设备获得动态地址，开始正常通信
```

> ⚠️ **陷阱**：热加入设备的IBI请求可能在主设备处理前一个IBI时到达。主设备控制器必须有足够的FIFO深度和中断响应能力来处理**背靠背的IBI事件**，否则可能丢失热加入请求。建议在主设备驱动中启用IBI队列缓冲。

## <span class="blue"> IBI带内中断 [M]

IBI（In-Band Interrupt）是I3C最 killer 的特性之一。它让从设备**通过总线本身**主动发起中断，彻底省掉了传统的INT引脚。

### IBI vs GPIO中断对比

| 维度 | IBI | GPIO中断 |
|------|-----|----------|
| 额外引脚 | **不需要**，复用SDA/SCL | 需要专用INT引脚 |
| 布线成本 | 两线搞定通信+中断 | 通信线+N条中断线 |
| 中断响应延迟 | ~10-100μs（总线竞争+传输） | ~1-10μs（电平直接触发） |
| 可携带数据 | **支持1-8字节payload** | 仅电平/边沿信号 |
| 多设备共享 | 总线仲裁自然解决优先级 | 需额外中断控制器/共享线 |
| 功耗 | 从设备可完全关闭时钟唤醒 | 需持续监测GPIO电平 |
| 软件复杂度 | 需要I3C控制器支持IBI处理 | 标准GPIO中断处理 |
| 适用场景 | 传感器事件、数据就绪通知 | 低延迟唤醒、简单开关 |

### IBI时序

```
正常总线空闲状态：
SCL  ─────────────────────────────────────────────────────────
SDA  ─────────────────────────────────────────────────────────
           ↑
       从设备要发中断！

IBI发起过程：
SCL  ────────────────────────────┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌─
                                 └──┘  └──┘  └──┘  └──┘  └──┘  └──┘
SDA  ────────────────────┐       ████░░░░░░░░░░░░░░░░░░░░░░░░░░░░████
                         └───────┘  S   DynAddr  RnW=1 ACK  [Data]  P
                         ↑
                    从设备主动拉低SDA
                    （类似START条件）

详细分解：
  1. 总线空闲时，从设备将SDA拉低
  2. 主设备检测到SDA变化（IBI请求）
  3. 主设备开始提供SCL时钟
  4. 从设备发送自己的动态地址 + Read位（RnW=1）
  5. 主设备ACK确认
  6. [可选] 从设备发送1-8字节IBI payload数据
  7. 主设备发送STOP或继续读取
```

> 💡 **提示**：IBI带数据（IBI Payload）功能非常强大！一个温度传感器在数据就绪时，可以通过IBI直接携带2字节的温度值。主设备收到中断的同时就已经拿到了数据，**省去了后续一次完整的读操作**——这意味着温度告警事件只需一轮总线事务就完成，而不是"中断+读寄存器"的两轮。对于电池供电的IoT设备，这减少了一半的总线活动时间，省电效果显著。

### IBI payload大小协商

IBI能带多少数据不是固定的，主设备和从设备在初始化时协商：

```
配置流程：
  Master → [GETMRL] → Slave  ← 查询从设备最大读长度
  Slave  → [MaxRL]  → Master → 得知从设备支持的最大payload
  
  Master → [SETMRL] → Slave  ← 设置实际使用的最大长度
  
典型值：
  - 简单事件通知：0字节payload（仅地址）
  - 传感器数据就绪：2-4字节payload
  - 批量状态上报：8字节payload（最大值）
```

## <span class="blue"> 本节总结

| 主题 | 核心要点 |
|------|----------|
| SDR模式 | 12.5Mbps，单沿采样，兼容I2C格式，默认工作模式 |
| HDR-DDR | 25Mbps，双沿采样，16-bit字无ACK，需I2C设备先忽略 |
| HDR-TSP | 33.3Mbps，三进制符号编码，最高速度模式 |
| CCC命令 | 通过0x7E广播地址管理设备状态，分广播和定向两类 |
| DAA流程 | ENTDAA→PID竞争仲裁→分配动态地址→ACK确认 |
| 热加入 | 总线运行时动态接入，通过拉低SDA发请求 |
| IBI | 从设备主动中断主设备，可携带1-8字节数据 |
| IBI vs GPIO | IBI省引脚+能带数据，GPIO更低延迟 |

I3C协议层的精妙之处在于**分层设计**：低速兼容走SDR，高速大批量走HDR-DDR，极限带宽走TSP；CCC命令提供统一的总线治理；IBI和热加入赋予从设备主动性。这套组合拳让它能在一个两线接口上同时满足兼容性、高性能和灵活性的三重需求。
