# 总线协议

> <span class="blue">BIEM 定位：</span><span class="red">[B→E]</span> 从低速到高速，掌握嵌入式系统全谱系总线协议<br>
> <span class="blue">本模块核心价值：</span>总线协议是设备驱动与硬件通信的基础

---

嵌入式工程师的日常，拆到最后都是总线：看原理图是在确认哪根线走哪种协议，调设备树是在描述总线上的设备地址，写驱动是在按协议的规则收发数据，抓波形是在验证时序是否符合协议约定，评审方案是在权衡几种总线的带宽、实时性与成本。这个扩展就是把"总线"这件事从片内到工厂网络完整讲一遍。

它不是一本要求从头到尾顺读的教科书。不同产品用到的总线差异极大——机器人关节里是 CAN，服务器插槽里是 PCIe，手机摄像头排线上是 MIPI——顺读全本意味着你一定会先学完一堆暂时用不上的东西。所以这一页的职责是帮你搞清楚两件事：**这张地图的全貌是什么，你的路应该怎么走。**

## 全景：从内到外六个板块

```
SoC 封装内部          一块 PCB 上                     设备与设备之间               整机
┌─────────────┐  ┌───────────────────────────┐  ┌───────────────────────┐  ┌────────────┐
│ A. 片内总线  │→ │ B. 低速      C. 中高速     │→ │ D. 专用网络（行业分化）│→ │ E. 综合实战 │
│ AMBA/NoC/CHI │  │ GPIO…I3C   USB/存储/MIPI  │  │ PCIe/CAN/EtherCAT/I2S │  │ 整机架构    │
└─────────────┘  └───────────────────────────┘  └───────────────────────┘  └────────────┘
     通用词汇           开发日常                   按岗位选读                  收口与权衡
                                                              F. 前沿高速（SerDes/CXL…）随时插读
```

顺序本身是一条认知链。A 板块建立"主设备发事务、从设备响应"的通用词汇；B 板块的低速总线是所有协议的母题——I2C 的开漏线与会在 CAN 仲裁里重现，SPI 的片选寻址会在 USB/PCIe 枚举里升级；到了 D 板块，总线开始按行业分化，学习内容由你的岗位决定；E 板块把单点知识组合成整机视角。每组内部统一按 **物理层 → 协议层 → 驱动框架 → 调试排查 → 代码级实战** 展开，实战篇绑定真实量产器件，从数据手册走到联调验证，均带无硬件后备路径。

## 你的路怎么走

先对号入座，再决定读什么。表里"缓读"不是"没用"，是等产品用到时带着真实问题回来读，效率最高。

| 你的产品/岗位 | 主线 | 可以缓读 |
|---------------|------|----------|
| 机器人（关节/控制） | A → B（重点 I2C/SPI/UART）→ D.11 CAN → D.12 EtherCAT → E.15 | C.9 MIPI、D.13 音频 |
| PCIe 卡 / 数通仪器仪表 | A → C.8 存储 → D.10 PCIe 全组 → D.14.5 光模块管理面 | B 概读、D.11~13 |
| 消费电子 / 手机周边 | A → B 全读 → C.7 USB → C.9 MIPI → D.13 音频 | D.11~12 |
| 汽车电子 | A → B → D.11 CAN → D.14 车载与新型 | C.9、D.13 |
| 尚未定向 | A → B 全读，之后按第一份工作进 D 对应组 | C/D 其余 |

两条无论走哪条路都适用的建议：A.1.1 必须读（设备树地址映射和 `/proc/iomem` 是所有人的日常）；C.7.2 USB 枚举值得读（"设备怎么被主机认识"是理解 PCIe 枚举的钥匙，哪怕你不用 USB）。

## 六个板块各自在做什么

**[A. 片内总线认知](A. 片内总线认知/README.md)** — 唯一不教"连线"的板块。总线藏在 SoC 封装里看不见摸不着，但 `ioremap` 的地址、DMA 的一致性、设备树 `reg` 的含义全由它决定。三篇从 AMBA 分层地图讲到 AXI 事务细节，再讲到多核一致性与 Chiplet。偏认知，不直接产生代码，但它是后面一切的词根。

**[B. 低速外设接口](B. 低速外设接口/README.md)** — 开发日常的 80%，全书唯一建议所有人通读的板块。GPIO/PWM/ADC 打底，I2C/SPI/UART 三大件每组五篇闭环（含 AT24C02、W25Qxx、NEO-6M GPS 三个实战），I3C 作为 I2C 的现代化接班人收尾。这里学扎实，后面每个新协议都只需要学"它改了什么"。

**[C. 中高速外设与存储](C. 中高速外设与存储/README.md)** — 数据量超过 Mbps 级之后的世界：USB 的 Host/Gadget 双视角、eMMC/UFS 存储谱系、MIPI 摄像头与显示。这组总线的特征是软件栈比物理协议厚——USB core、MMC、V4L2/DRM 框架各占半边天。带屏带摄像头的产品必读，纯控制类产品可以缓读。

**[D. 专用网络总线](D. 专用网络总线/README.md)** — 行业分化的地方，也是"机器人用 CAN 还是以太网"这类问题的答案所在。PCIe（含 CXL 与 EP 卡实战）刻意排第一组：它的枚举-配置-DMA 模型是高速互连的通用模板。随后 CAN/CANopen、EtherCAT 等工业以太网、I2S 音频、车载与新型总线各成一组。一个能省一半力气的事实：CANopen 的应用层（对象字典、CiA 402）在 CAN 和 EtherCAT（CoE）两个世界通用，学一遍顶两处。

**[E. 综合实战](E. 综合实战/README.md)** — 单总线学会不等于会设计整机。机械臂、AGV、人形机器人、数通整机四个行业案例，加上一张带宽/实时性/成本的选型方法论矩阵。放在最后读——它不再解释协议，只回答"为什么这个产品选这几种总线"。

**知识图谱（B.99）** — 全谱系速查地图：速率/距离/拓扑/选型维度对照。学到任何阶段都可以回来定位"我在哪、旁边还有什么"。

## 与其他部分的分工

读本扩展时会反复跨界，提前说清楚免得找错地方：

- **主线第一部**（启动与运行）：设备树语法、时钟/中断描述——各组"驱动框架"篇的前置。
- **主线第二部第 10~13 章**：中断、设备模型（bus-device-driver）、内核子系统。B 扩展只讲每个总线自己的框架结构，通用机制都在这几章。
- **D 扩展（驱动开发实战）**：回答"驱动怎么写"。B 扩展回答"总线是什么"——实战篇遇到完整驱动写法会指向 D 扩展对应篇，不重复展开。
- **C 扩展（专用技术）**：边缘 AI、功能安全等，是这些总线的下游应用场景。
