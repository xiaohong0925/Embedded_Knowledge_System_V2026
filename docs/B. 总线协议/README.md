# 总线协议

> <span class="blue">BIEM 定位：</span><span class="red">[B→E]</span> 从低速到高速，掌握嵌入式系统全谱系总线协议<br>
> <span class="blue">本模块核心价值：</span>总线协议是设备驱动与硬件通信的基础

---

## 模块概述

总线协议是嵌入式系统的**通信基础设施**：设备之间怎么交换数据、怎么共享资源、怎么协调时序，全部由总线决定。一个嵌入式工程师的日常——看原理图、调设备树、写驱动、抓波形、评审方案——每一件都落在某种总线上。

本扩展覆盖从片内互连到工厂网络的全尺度，共 6 个板块。但**它不是要求你从头到尾顺序读完的教科书**——不同产品用到的总线差异极大，本 README 的职责就是告诉你：每个板块为什么存在、彼此什么关系、你的产品需要哪几块。

---

## 设计逻辑：为什么是这个顺序

六个板块按**由内而外的空间尺度**排列，同时构成认知依赖链：

```
片内（SoC 内部）          板级（一块 PCB 上）              系统级（设备之间）          整机与前沿
┌──────────────┐  ┌─────────────────────────┐  ┌──────────────────────┐  ┌───────────────┐
│ A. 片内总线   │→│ B. 低速 → C. 中高速     │→│ D. 专用网络          │→│ E. 综合实战   │
│ APB/AHB/AXI   │  │ GPIO/I2C/SPI/UART/I3C   │  │ PCIe/CAN/EtherCAT…   │  │ 整机总线架构   │
│ NoC/CHI/UCIe  │  │ USB/eMMC/MIPI           │  │ （行业总线）          │  │ + F. 前沿高速  │
└──────────────┘  └─────────────────────────┘  └──────────────────────┘  └───────────────┘
   一切的地基        嵌入式开发的日常 80%          行业分化的起点            从工程师到架构师
```

这条链的三个设计意图：

1. **先有"总线是什么"的通用认知，再学具体协议**。A 板块用 AMBA 家族建立主/从、地址映射、仲裁这些通用词汇——之后每个板块都在复用它们。
2. **低速是高速的母题**。I2C 的开漏线与、SPI 的片选、UART 的帧同步，会在 I3C、CAN、EtherCAT 里以升级形态反复出现；B 板块学扎实了，后面每个新协议只需要学"它改了什么"。
3. **每组内部统一五段式骨架**：物理层 → 协议层 → 驱动框架 → 调试排查 → 代码级实战（x.5/x.6）。学会一组，其余各组的读法是同样的——实战篇绑定真实量产器件，从数据手册走到联调验证。

## 各板块：为什么包含、讲什么、用在哪

### A. 片内总线认知（3 篇：A.1.1~1.3）

- **为什么包含**：你写的每个驱动都在跟片内总线打交道——`ioremap` 的地址、DMA 的一致性、设备树 `reg` 的含义，答案全在 SoC 内部互连里。不理解它，驱动开发永远隔着一层。
- **讲什么**：APB/AHB/AXI/TileLink 概念 → AXI 深入与 NoC → CHI/UCIe Chiplet 互连。
- **与下游关系**：是 C 板块 PCIe 的"片上镜像"（AXI 与 PCIe TLP 的事务思想同源），也是理解 F 板块 CXL 的前提。
- **对应产品**：所有产品。偏理论认知，不直接产生代码。

### B. 低速外设接口（23 篇：B.2~6）

- **为什么包含**：嵌入式开发的日常 80% 在这里——传感器是 I2C/SPI，调试是 UART，执行器是 PWM。任何岗位都绕不开，也是全书唯一**建议所有人通读**的板块。
- **讲什么**：GPIO/PWM/ADC/DAC → I2C → SPI → UART/RS-485/Modbus → I3C，每组带实战（AT24C02、W25Qxx、NEO-6M GPS）。
- **与下游关系**：I2C 的知识直接迁移到 I3C（演进关系）和 D 板块的光模块管理面 CMIS（I2C 的工业变体）；UART/RS-485 是理解 CAN 差分与 Modbus 寄存器模型的台阶。
- **对应产品**：全部。机器人关节传感器、仪器仪表前面板、消费电子外设，本质都是这组总线的组合。

### C. 中高速外设与存储（规划 15 篇：C.7~9）

- **为什么包含**：当数据量超过 Mbps 级——外接存储、摄像头、显示屏、U 盘——低速总线到顶了，必须理解高速总线的代价：阻抗、协议栈、专用驱动框架。
- **讲什么**：USB（物理层到 Gadget）→ eMMC/UFS/SPI NAND（存储）→ MIPI CSI-2/DSI 与 LVDS/eDP/HDMI（显示摄像）。
- **与下游关系**：USB 的枚举-描述符模型是 PCIe 枚举（D.10）的先修课；MIPI 的差分 PHY 是 F 板块 SerDes 的入门。
- **对应产品**：带屏/带摄像头/带大容量存储的产品（消费电子、仪器仪表人机界面、机器人视觉）。纯控制类产品可整板块选读。

### D. 专用网络总线（规划 26 篇：D.10~14）

- **为什么包含**：过了这块板卡、要连别的设备、别的控制器、别的车——总线开始按行业分化。这是**岗位决定内容**的板块，也是"机器人用 CAN 还是以太网"这类问题的答案所在。
- **讲什么**：PCIe（含 CXL 与 EP 卡实战，提至第一组）→ CAN/CANopen → EtherCAT 等工业以太网 → I2S 音频 → 车载以太网/LIN/CAN XL/SerDes/光模块 CMIS。
- **与下游关系**：E 板块整机实战的直接素材库；CANopen 的应用层（对象字典、CiA 402）在 CAN 和 EtherCAT（CoE）两个世界通用。
- **对应产品**：**按行业选读，不要全读**——PCIe 卡/服务器看 D.10，机器人/汽车看 D.11+D.12+D.14，音频产品看 D.13，数通看 D.14.5。

### E. 综合实战（规划 6 篇：E.15）

- **为什么包含**：单个总线学会不等于会设计整机。真实产品是十几种总线的协同——机械臂、AGV、人形机器人、数通整机各是一堂架构课。
- **讲什么**：行业整机总线方案 + 选型方法论（带宽/实时性/成本权衡矩阵）+ PREEMPT_RT 实时性调优。
- **与下游关系**：B 扩展的收口，也是通往架构师视角的桥。
- **对应产品**：所有人，但建议在对应行业总线读完之后再来。

### 知识图谱（B.99）

全谱系总线的速查地图：选型维度、速率/距离/拓扑对照。学到任何阶段都可以回来定位"我现在在哪、旁边还有什么"。

## 怎么选读：按产品对号入座

| 你的产品/岗位 | 必读 | 选读 | 可跳过 |
|---------------|------|------|--------|
| 机器人（关节/控制） | A → B（重点 I2C/SPI/UART）→ D.11 CAN → D.12 EtherCAT → E.15 | D.14 车载 | C.9 MIPI 显示、D.13 音频 |
| PCIe 卡 / 数通仪器仪表 | A → B（概读）→ C.8 存储 → D.10 PCIe（全部 6 篇）→ D.14.5 CMIS | E.15.5 数通整机 | D.11~13 |
| 消费电子 / 手机周边 | A → B（全读）→ C.7 USB → C.9 MIPI → D.13 音频 | B.6 I3C 深化 | D.11~12 |
| 汽车电子 | A → B → D.11 CAN → D.14 车载（TSN/LIN/CAN XL/SerDes） | D.12 EtherCAT | C.9、D.13 |
| 尚未定向 / 打基础 | A → B（全读）→ 按第一份工作再进 D | C.7 USB | — |

选读原则：**总线知识不过期，但学习时机有成本**。表里"可跳过"不是"没用"，而是"等产品用到时回来读，效率更高"——到时你有真实问题牵引，一天顶现在一周。

## 与主线及其他扩展的关系

- **主线第一部**（启动与运行）：设备树 `reg`、`interrupts`、时钟——读 A/B 板块时会反复回看。
- **主线第二部第 10~13 章**（中断、设备模型、内核子系统）：B 扩展各组"驱动框架"篇只讲该总线的框架结构，通用机制（bus-device-driver、regmap、中断处理）都在那里。
- **D 扩展（驱动开发实战）**：回答"驱动怎么写"。B 扩展回答"总线是什么"——两组的分工是：B 讲协议与框架结构，D 讲驱动写法体系，实战篇里遇到完整驱动写法会指向 D 对应篇，不重复展开。
- **C 扩展（专用技术）**：边缘 AI、功能安全等场景是这些总线的下游应用。
