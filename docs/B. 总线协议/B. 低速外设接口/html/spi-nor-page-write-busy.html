32 字节为什么是两段编程、两次等待

教学顺序模型，不是实测波形。起始地址 0x00F0，长度 32 B，页大小 256 B。

输入：先确定第一段不能超过当前页尾

本步结论：当前页只剩 16 B，所以 32 B 请求必须拆分；此时还没有向 Flash 发出 Page Program。

不看逐步视图时的完整顺序
  1. 由地址 0x00F0 算出当前页剩余 16 B，第一段取 min(16, 32) = 16。
  2. 执行 Write Enable，把第一段写到当前页 0xF0～0xFF；CS 拉高只结束串行命令，内部编程仍在进行。
  3. 调用 spi_nor_wait_till_ready()，BUSY 清除后才把第一段实际长度计入 i。
  4. 第二段重新执行 Write Enable，把余下 16 B 写到下一页 0x00～0x0F。
  5. 再次等待 BUSY 清除，累计第二段实际长度；正常路径到此完成 32 B。
  6. 发送或等待任一步失败都进入 write_err，不能宣称后续数据也已写完。
