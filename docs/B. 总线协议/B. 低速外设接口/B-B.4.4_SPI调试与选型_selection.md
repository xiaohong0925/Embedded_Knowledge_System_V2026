# 速率与接口选择：怎样把调试证据用于决策

> 所属章节：第五部 B. 总线协议 > B-B.4 SPI 总线 > B-B.4.4 SPI 调试与选型
>
> 本组阅读：第 2 页，共 2 页

当前已经在 1 MHz 下正确读到 `EF 40 18`，下一步自然会问：**能否提速，或者改用 QSPI／OSPI，让同类读取更快？**

这时不能直接修改 `spi-max-frequency` 或接口模式。已有结果只证明当前连接、当前速率和当前命令可工作。选择下一套配置要回答三个问题：收益是多少、新增条件是否满足、候选配置怎样复测。

---

## <span class="blue"> 先认接口和时钟关系

普通 SPI 中，**SCLK 由主机 SoC 的 SPI 控制器提供**。从机不需要提前知道频率，也不参与频率协商，只根据时钟边沿采样和移位。频率由主机配置并验证，不是从机固定，也不是双方自动协商。

因此，提速不是“主机自适应从机”，而是主机根据控制器能力、器件手册和板级条件选择一个能够正常工作的时钟。频率过高时，从机可能来不及输出稳定数据，或主机来不及正确采样。

在讨论改变接口之前，先分清它们的物理形态：

| 接口 | 常见信号线 | 硬件上的主要区别 |
|---|---|---|
| SPI | SCLK、MOSI、MISO、每个从机一个 CS | 全双工，主机提供时钟，没有标准 ACK |
| I2C | SDA、SCL | 两线、器件地址、ACK／NACK，多器件共享；从机还可通过时钟拉伸让主机等待 |
| QSPI | SCLK、CS、IO0～IO3 | 4 根双向数据线，部分阶段可按 4 位并行传输 |
| OSPI | SCLK、CS、IO0～IO7 | 8 根双向数据线，部分阶段可按 8 位并行传输 |

QSPI／OSPI 不是只改一个软件字段就能获得全部收益：**原理图上必须实际连接新增数据线**。命令、地址和数据阶段也不一定都使用多线，所以常用 `x-y-z` 分别记录这三个阶段的线数。

判断“支不支持”需要同时看 SoC 手册、Flash 手册、原理图和当前驱动。软件配置不能创造控制器能力或物理连线。

## <span class="blue"> 先算清提速或扩展接口的收益

一笔操作的纯时钟时间由拍数和实际 SCLK 决定：

```text
T_clock = N / f_actual
```

`N` 必须包含命令、地址、dummy 和数据阶段，不能只算有效载荷。以当前 JEDEC ID 读取为例，命令 8 拍、响应 24 拍，共 32 拍。若实际 SCLK 恰好为 1 MHz：

```text
T_clock = 32 / 1,000,000 s = 32 μs
```

这里的 1 MHz 是计算条件，不是由 `spidev_test` 的 `max speed` 证明的实测频率。若控制器分频后的实际速率不同，应代入实际值。

完整操作还可能包含 CS 建立与保持、内核和控制器处理、任务调度，以及编程或擦除命令的内部忙时间。因此，提速首先改变的是 `T_clock`，不能把它直接当作整个系统的响应时间。

**先判断时钟时间在当前操作中是否值得优化，再决定是否需要改变接口。**若主要耗时来自软件调度或 Flash 内部忙过程，提高 SCLK 的收益可能很有限。

## <span class="blue"> 可用配置由控制器、器件和板级条件共同限制

| 约束层 | 选择时要回答的问题 | 需要补的证据 |
|---|---|---|
| 控制器 | 是否支持目标模式？实际分频结果是多少？ | 驱动能力、模式位、时钟配置或实测 SCLK |
| 器件 | 当前命令允许多高速率？各阶段能否使用多数据线？ | 当前命令的手册格式、频率条件和状态位 |
| 板级 | 接收端能否在采样时得到稳定数据？ | 走线、门限、边沿、建立时间和必要的模拟波形 |

只有三层都满足，候选配置才值得进入复测：

```text
f_use ≤ min（控制器可用上限，当前命令的器件上限，板级可验证上限）
```

若上一页出现“降速后恢复”，这只说明故障与频率或时间窗口相关，不能直接指出哪一层就是根因，也不能据此确定一个新的安全频率。

## <span class="blue"> 接口变化带来的新增条件

### SPI 与 I2C：只有真实候选器件可替换时才需要比较

原理图和器件已经确定接口时，软件不能把 SPI Flash 通过 DTS 改成 I2C 器件。若确实在比较不同候选器件，则应比较完整访问路径，而不是只比较“速度”和“线数”：

| 比较项 | SPI | I2C |
|---|---|---|
| 器件选择 | 使用 CS，还要核对多从机时的 MISO 驱动权 | 使用器件地址，需避免地址冲突 |
| 数据路径 | MOSI、MISO 可同时移位 | SDA 双向传输，速率和负载受模式、上拉和电容限制 |
| 应答证据 | 没有标准低层 ACK，必须继续检查有效数据 | ACK 表明相应字节被接收，仍需检查返回内容 |
| 完整成本 | 按命令、地址、dummy 和数据阶段计算 | 按地址、寄存器或命令、数据、ACK/NACK 计算 |

需要较高串行带宽、独立全双工路径或明确片选边界时，SPI 更合适；引脚受限、短事务较多且需要接收确认时，I2C 更有吸引力。最终仍须使用候选器件自己的命令格式和板级条件验证。

### QSPI／OSPI：先看器件证据，再计算阶段收益

以 [W25Q128JV Rev F 手册](images/W25Q128JV_RevF.pdf) 为例，器件支持的是 Standard／Dual／Quad SPI：

| 模式 | 数据引脚 |
|---|---|
| Standard SPI | DI、DO |
| Dual SPI | IO0、IO1 |
| Quad SPI | IO0、IO1、IO2、IO3 |

Quad 不是单纯提高 SCLK，而是数据阶段改用四根线。手册没有证明这颗器件支持 OSPI。

**本例 IQ/JQ 后缀出厂固定 `QE = 1`，IO2、IO3 已启用；IM/JM 后缀默认 `QE = 0`，需要先设置为 1。**QE 位于 Status Register-2，详见手册第 7.1.4 节。QE=1 时，原 `/WP` 引脚复用为 IO2，原 `/HOLD` 引脚复用为 IO3，HOLD 功能不再可用，所以原理图必须核对这四个数据引脚是否全部连接。

`0x9F` 在普通 SPI 下读出正确 ID，**不能证明 QSPI 可用**。手册第 8.2.9 节给出的 `0x6B Fast Read Quad Output` 才是一个具体的四线读取命令：命令和地址仍走单线，数据改用 IO0～IO3，且接受命令前必须满足 QE=1。

```text
0x0B Fast Read：40 拍前导 + 32 拍数据 = 72 拍
0x6B Quad Output：40 拍前导 + 8 拍数据 = 48 拍
```

`0x6B` 只把数据阶段从 32 拍缩为 8 拍，**整笔读取不是直接提速四倍**。命令、地址、dummy、CS 和软件开销也不会自动按线数减少。

因此，使用 QSPI／OSPI 前必须同时确认：

- 器件手册明确支持目标命令和线数，所需 QE 或其他状态位已满足；
- 控制器和当前驱动支持相应模式；
- 原理图实际连接了新增数据线；
- 板级时序满足扩展模式要求。

Flash 页编程、擦除和 BUSY 等待属于内部过程，不会因为数据写入阶段变宽就按同样比例缩短。

## <span class="blue"> 候选配置必须复测

三层约束和接口比较只能给出候选，不能代替验证。实际选择按下面的顺序推进：

1. **固定正常基线**：保留当前能正确读取 ID 的连接和配置。
2. **一次只改一个变量**：只改请求速率或接口模式，记录改动前后的值。
3. **重复目标事务**：重新检查工具返回和有效 ID；取得实际 SCLK 时记录测量条件，不用 `max speed` 代替。
4. **补足必要证据**：提高速率或改变线数后，核对完整数字帧；有时序疑问时检查接收端模拟波形。
5. **限定通过范围**：偶发故障需要有限次数、明确判据和失败记录，不能只循环命令并统计 `exit=0`。
6. **失败就恢复**：回到最后一个正常配置，重新取得正确 ID，不叠加新的改动。

若更换接口或器件，新对象必须重新建立自己的已知正常事务，不能继续沿用 W25Q128JV-IQ/JQ 的 `EF 40 18` 作为预期答案。

## <span class="blue"> 最后把选择落到软件配置

完成硬件与事务验证后，软件上主要核对：

- `spi-max-frequency` 是请求上限，不是实测速率；
- 总线、CS 和 pinctrl 必须与选定的硬件路径一致；
- 调试用 `spidev`，正式 SPI NOR Flash 使用 `jedec,spi-nor` 并接入 MTD；
- QSPI／OSPI 的模式不能只凭 DTS 中的声明启用，必须有前述整条链路支持。

```dts
flash@0 {
    compatible = "jedec,spi-nor";
    reg = <0>;                    // CS0，不是器件寄存器地址
    spi-max-frequency = <1000000>; // 已验证工作点对应的上限
};
```

后续 MTD 分区、烧录和产品级提速验证归 B-B.4.5，不在本页重复展开。

**速查表**

| 当前选择 | 先核对什么 | 怎样验证 |
|---|---|---|
| 提高 SCLK | 实际收益、控制器分频、器件输出有效和板级采样窗口 | 同一事务、实际 SCLK、数字帧和必要的模拟波形 |
| SPI 与 I2C | 是否有真实替代器件，完整事务和 ACK 有何差异 | 使用候选器件自己的命令格式完成验证 |
| 使用 QSPI／OSPI | 各阶段线数、控制器和驱动、状态位、板级连接 | 扩展模式下的完整事务与内部等待 |
| 候选配置失败 | 哪一项证据不足或发生变化 | 恢复最后的正常配置并复测 |

本页计算用于说明选择方法，不构成目标板卡的实测结果。实际 SCLK、MTD 注册、QSPI／OSPI 加速比例和长期稳定性仍需在目标硬件上验证。
