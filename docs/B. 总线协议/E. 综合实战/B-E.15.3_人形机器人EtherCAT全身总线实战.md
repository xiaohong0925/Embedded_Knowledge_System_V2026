# B-E.15.3 人形机器人：EtherCAT 全身总线实战

> 所属章节：第五部 B. 总线协议 > E. 综合实战
>
> 难度：[M] | 预计阅读时间：100 分钟

## <span class="blue"> 本节导读

人形机器人把多总线协同推到当前最极端的形态：30~50 个关节伺服、每个关节要带力矩闭环、全身 IMU 与六维力传感器若干、控制周期 1 kHz 起步且全身轴间同步、还要在躯干里走线。总线方案在人形机器人上不是"选型"问题，是"能不能成立"问题——轴数 × 周期的带宽需求直接把 CAN FD 排除出主运动网，EtherCAT 的线型拓扑与机械结构的走线约束强耦合，安全策略连"停机"这个选项都没有（双足站立是动态平衡，硬抱闸等于直挺挺摔倒）。

本篇以一台典型双足人形（28 关节）为对象，拆解全身总线架构的完整设计。假设你已读过 B-D.12.2/12.3（EtherCAT 协议与 DC）和 B-E.15.1（机械臂多总线协同）——机械臂篇建立的选型表、周期预算、WKC 门禁、域划分方法论在这里全部复用，本篇聚焦人形机器人**独有**的四个问题：轴数规模、躯干走线拓扑、力控带宽、没有停机选项的安全架构。

本节覆盖：需求清单与"主运动网只能 EtherCAT"的定量推导、干线+四肢分支的拓扑设计与机械约束、28 轴 1 kHz 周期预算的完整核算与 2 kHz 升级路径、力控传感器接入的节拍论证、摔倒导向的安全架构（阻尼倒地与分部位降级）、控制周期四层划分、bring-up 工具输出逐段解读、联调顺序与排障表。

## <span class="blue"> 需求清单：先看约束再看方案

| 约束 | 数值 | 对总线的要求 |
|:---|:---|:---|
| 关节数 | 28（腿 6×2、臂 7×2、腰 2） | 单网 28+ 从站，帧长与周期预算紧 |
| 控制周期 | 力控 1 kHz，部分厂商 2~4 kHz | 周期预算只剩几百微秒余量 |
| 轴间同步 | 全身 <1 µs | DC 分布式时钟是前提，不是选项 |
| 力控 | 每关节电流/力矩闭环经主站 | 每轴 PDO 要含力矩指令与电流反馈，字节数翻倍 |
| 走线 | 躯干内穿关节，线缆长度与弯折受限 | 拓扑必须贴合机械结构，线型+分支混合 |
| 安全 | 摔倒保护、关节限位、STO | 安全链路与控制链路分层，且"停机"不可选 |
| 算力 | 主控 x86/ARM + 可选 GPU | 控制网与感知网物理分离 |

第一行和第二行相乘就是主运动网的生死线：**28 轴 × 17 字节过程数据 × 1 kHz ≈ 476 KB/s**。拿这个数去套候选总线——CAN FD 数据段 2 Mbps 下有效吞吐约 1 MB/s 的理论上限，塞进 476 KB/s 的周期数据后负载率直接爆表，且 CAN 系没有轴间硬件同步机制；普通以太网（TCP/IP 栈）的协议栈延迟抖动是百微秒到毫秒级，周期预算过不去。两个候选各自死于不同的指标：CAN FD 死于带宽，普通以太网死于确定性。剩下能同时满足轴数、周期、同步的开放方案只有 EtherCAT——这就是"不是选型问题，是能不能成立问题"的含义。

> EtherCAT G：ETG 定义的千兆变体（EtherCAT G / G10），协议完全兼容，只是物理层升到 1/10 Gbps——线上时间降为 1/10，从站硬件转发延迟不变。它在"轴数 50+ 或周期 2 kHz+"的场景才有意义；当前从站芯片生态远不如 100M 成熟，选型时按"预算实在压不进才升 G"的顺序考虑。

需求清单最后一行（算力）也要展开一句：人形主控通常是"控制 + 感知"双负载同机——x86/ARM 跑 1 kHz 力控，GPU 跑视觉与模型推理。两张网卡物理分离只是第一步，第二步是 CPU 核与内存带宽的隔离：GPU 推理会打满内存总线，力控线程的 cache 命中率因此下跌，周期抖动跟着上升——这是"隔离核都做了还有抖动"的经典根因。整机设计时把感知负载放到独立模组（或接受力控降频到 500 Hz）是两种常见答案，本篇拓扑按前者画。

> 动态平衡：双足站立不是静态稳定结构——质心投影落在两只脚围成的支撑多边形内只是必要条件，行走和受扰时靠持续的关节力矩调整把质心"接住"。含义：控制环断一拍（哪怕 2 ms），机器人不是"停住"，而是开始倒。这条物理事实贯穿本篇——它决定了抖动预算比机械臂苛刻一个量级，也决定了故障降级不能是"抱闸"。

> 支撑多边形 / ZMP（Zero Moment Point，零力矩点）：评估双足稳定性的两个几何量。支撑多边形是足底接触区域围成的凸包；ZMP 是地面反作用力等效作用点——它在支撑多边形内，机器人就有保持平衡的力学条件。WBC/MPC 的约束方程本质就是在每个周期保证"ZMP 不出界"。这两个概念帮读者理解为什么足底力数据直接决定控制律的输入质量。

> 分支器（EtherCAT Junction）：内部就是一颗多端口 ESC，把一条链路分叉成多条物理分支——EtherCAT 逻辑上仍是"一条经过所有站的链"，分支器只是让物理走线可以分叉。它的价值在人形上是决定性的：没有分支器，线型拓扑要求一根线串完全身 28 个关节，线缆得从左腿绕回躯干再去右腿，走线长度和弯折次数都不可接受。代价是每个分支器引入额外传播延迟和一级故障诊断复杂度——分支深度不要超过两级。

拓扑设计的三个机械约束：

1. **穿关节走线用高柔拖链线**：关节处线缆随关节弯折百万次级，选拖链等级线材（如 igus chainflex 这类有弯折寿命标称的系列），每个关节的线长余量按最大行程计算再留 10%。线缆疲劳断裂是人形机器人现场故障的第一名——它的故障形态是先间歇性接触不良（抖动随动作增大），后彻底断开，排障表里两条症状对应这两个阶段。
2. **分支器放腰部**：四肢四个分支的几何中心在腰部，放这里让每根分支线最短。配合主控双端口（Port A/B）做干线冗余：干线腰部断一处时两端分别接管，思想与 15.1 的线缆冗余回环相同。
3. **传感器就近挂载**：足底六维力传感器与小腿 IMU 挂在该腿分支末端——力传感器反正必须在 EtherCAT 网上（理由见传感接入一节），挂在腿分支末端不为它单独拉长线，是走线约束下的自然落点。

连接器的选型与线缆同等重要：关节内部空间按毫米计，连接器必须是带锁扣的圆形接插件（M8/M12 或更小规格），直插式会随振动松脱；每个连接器两端做应力释放（线缆固定点距插头 5~10 cm），让弯折发生在线缆上而不是焊点上。现场返修统计里"连接器松脱/针脚退位"与"线缆疲劳"合计占走线类故障的九成——这两样在图纸阶段都是可防的，防的方式就是把弯折寿命、锁扣形式、应力释放写进布线规范，而不是留给装配工人发挥。

## <span class="blue"> 带宽与 DC 预算：28 轴 1 kHz 是否成立

逐轴 PDO 内容（力控版）：RPDO = 目标力矩（2B）+ 目标位置（4B）+ 控制字（2B）= 8 B；TPDO = 实际位置（4B）+ 实际电流（2B）+ 状态字（2B）+ 温度（1B）≈ 9 B。比 15.1 机械臂的每轴 20 B 略省，但轴数近五倍。

字节分配里有一个值得注意的设计：目标位置与目标力矩**同时**出现在 RPDO 里。这不是冗余——人形的关节控制是"位置为骨、力矩为肉"的混合模式：步态摆动相按位置轨迹走（目标位置生效），支撑相与接触瞬间切力矩主导（目标力矩生效）。CST 模式下驱动器只执行电流环，上层的 WBC 每周期决定这个轴此刻听哪个量。温度字段看似多余，实际是最便宜的热保护：每周期带回的 1 字节温度让主站能做全身热趋势监控，比伺服自己报 EMCY 提前几分钟看到过热——分钟级提前量在演示现场就是"自己走回去待机"和"当场瘫倒"的区别。

```
 过程数据：28 轴 × (8+9) B + 足底力 2 站 ≈ 500 B
 帧结构：每分支一个 LRW 数据报（4~6 个）+ 帧头开销 ≈ 600 B 总量
        （600 B < 1514 B 最大帧，单帧装得下）
 线上时间：600 × 8 / 100 Mbps ≈ 48 µs
 ESC 硬件延迟：31 站 × 0.3 µs ≈ 9 µs
 主站收发+协议栈处理：约 100~200 µs（i210 + IgH 专用驱动）
 控制律计算（WBC/MPC 简化版）：200~400 µs（隔离核）
 ──────────────────────────────────────────────
 合计 ≈ 400~650 µs —— 1 kHz 成立（余量 35~60%），
 2 kHz（周期 500 µs）不成立，需砍内容或升千兆
```

> LRW（Logical Read Write）：EtherCAT 最常用的数据报命令——一次逻辑寻址读写在"边飞边处理"中同时完成所有从站的输出写入与输入读回。过程数据映射到一段逻辑地址区，28 个轴的 PDO 在这条链上各认领一段偏移。按分支拆成多个 LRW 的目的：单分支故障时其余分支的 WKC 依然可辨，定位问题不用猜是哪一段。

主站实现的选择顺带定在这里：IgH（开源，1 ms 周期经 PREEMPT_RT 可达）是学习与多数产品的默认；Acontis 等商业主站在 31 站规模下的协议栈处理时间更短且带厂商支持；部分厂商自研主站绕开 IgH 的 GPL 考量。三者共用同一套预算方法——上表把"主站收发+处理"单列一行，就是为了换主站实现时只动这一行。

**2 kHz 的升级路径**（留给读者作为预算方法的复用练习）：①砍 PDO——温度这类慢变量从每周期 TPDO 移到 10 Hz 低频通道或 SDO 按需读，省出的字节直接减线上时间与主站处理时间；②控制律分层——WBC 全量解算降到 500 Hz，1 kHz 层只做关节插值与力矩分配（多数厂商的实际做法）；③EtherCAT G——ETG 的千兆变体，线上时间从 48 µs 压到 5 µs，但从站生态远不如 100M 成熟。①和②是软件决策，③是供应链决策，预算表的作用就是让这三条路径的收益各自可算。

DC 同步：31 站全 DC 模式，SYNC0 亚微秒对齐无压力。注意分支器引入额外传播延迟，DC 初始化测量会自动补偿，但设计时分支深度不超过两级——时钟链路的诊断复杂度随深度上升。

> ⚠️
> 1 kHz 成立的前提是把"感知流量"完全挡在控制网外。视觉、深度相机、语音走第二张独立网卡（普通以太网），控制网口只跑 EtherCAT。验证方法一行命令：`tcpdump -i <控制网口>` 应该只见 EtherType 0x88A4 的帧——混进任何 IP 流量都说明隔离破了。人形机器人主控翻车案例里，"控制网混入其他流量"是周期抖动的第一大原因。

## <span class="blue"> 传感接入：力控的节拍论证

| 传感器 | 位置 | 接入方式 | 理由 |
|:---|:---|:---|:---|
| 关节力矩/电流 | 每伺服内置 | PDO 自带 | 走 EtherCAT 主循环 |
| 脚底六维力 ×2 | 足底 | EtherCAT IO 从站挂腿分支末端 | 力控直接输入，必须与伺服同节拍 |
| 躯干 IMU | 腰部 | SPI 直连主控（1 kHz 读取）或 EtherCAT IMU 站 | 姿态解算在主控，SPI 延迟最低 |
| 关节绝对编码器 | 每伺服内置 | PDO 自带 | — |
| 视觉/深度相机 | 头部 | USB3 / 千兆网，独立感知网 | 与控制网物理隔离 |
| 麦克风阵列 | 头部 | USB 音频 | 感知域 |

力控的数据流闭环：足底力传感器（EtherCAT TPDO）→ 主控 WBC 算法 → 28 轴力矩指令（RPDO），全程在一个 1 ms 周期内完成。这决定了足底力传感器**必须**在 EtherCAT 网上——用 RS-485 或 CAN 接足底传感器，10 ms 级的到达延迟意味着力控环的反馈滞后十个周期，闭环相位裕度被吃完，表现为站立时的低频摇晃。这是 15.1"参与同一控制律的量必须时间对齐"原则在人形上的极端形态：机械臂上时间戳补偿能救的量，在这里救不回来。

> WBC / MPC（Whole-Body Control / Model Predictive Control）：人形机器人主流的两类全身控制算法。**WBC** 把全身关节力矩分配建模成一个带约束的优化问题（接触力约束、力矩限幅、任务优先级），每个控制周期解一次；**MPC** 在此基础上向前预测未来若干拍的质心演化，提前规划落足点与支撑力。两者对总线的要求相同：所有输入（关节状态、足底力、IMU）必须同节拍且低延迟——算法再先进，迟到 10 ms 的足底力数据只会让它算出一个已经不存在的接触状态。

躯干 IMU 是唯一的例外设计：它可以 SPI 直连主控而不用挂 EtherCAT——条件是主控读取线程与 EtherCAT 周期任务同核同节拍调度，读取时刻锁在周期起点，延迟固定可补偿。这是"可以补偿"与"必须对齐"的边界案例：IMU 数据进姿态解算（微分环节少、对固定延迟不敏感），足底力数据进接触力控制（对延迟一阶敏感）。

> CST（Cyclic Sync Torque，循环同步力矩模式，CiA 402 模式字 = 10）：力控版人形伺服的工作模式——主站每周期直接下目标力矩/电流，伺服只执行电流环，位置环与速度环全部上收到主站的 WBC。与 CSP（位置在主站规划、伺服执行位置环）相比，CST 把最后一级环也交给了主站，换来全身力矩的统一分配能力；代价是主站算力与周期确定性要求再上一档——电流环跨总线闭合，任何抖动直接变成力矩纹波。选型对照：纯点位/轨迹机器人用 CSP 足够，需要与环境发生可控力交互（双足支撑、抓取、人机接触）的必须 CST。

**31 站规模的 ENI 与启动时序**：从站一多，PDO 映射与 DC 配置不再手写——IgH 用 ENI（EtherCAT Network Information，XML 网络描述文件）统一描述全部从站的配置，由配置工具（EC-Engineer 或 IgH 的 `ethercat xml`）生成。启动时序按量级排：链路扫描 ~100 ms → 31 站逐个进 PREOP（PDO/邮箱配置下发）~1~3 s → SAFEOP → OP → DC 收敛（各站 offset 稳定）再花数秒。整机从上电到"全身可控"因此是 5~10 秒量级——这个数字要写进产品的开机体验设计里，也是诊断基线：某站配置漂移会先表现为进 OP 变慢。

## <span class="blue"> 安全架构：没有停机选项的降级设计

```
 硬件安全层（不依赖软件与通信）：
   急停按钮 ── STO 干接点 ── 各伺服 STO 输入（分布式）
   关节机械限位、伺服本体过流保护

 软件安全层（EtherCAT 上）：
   FSoE 安全 PDO：STO/SLS 等安全功能（认证伺服支持时）
   主站监控：WKC 门禁、关节位置/速度软限位、
            摔倒检测（IMU 姿态角突变 + 质心估计发散）
            → 关节切阻尼模式泄力

 策略差异（与机械臂不同）：
   机械臂故障 → 立即抱闸停机
   人形故障   → 分部位降级：单分支掉线切换支撑策略，
                全身断链时关节切阻尼模式（缓慢倒地）
```

> FSoE（Safety over EtherCAT）：EtherCAT 的功能安全协议（IEC 61784-3  profiles 之一），黑色通道实现——安全数据包在不安全的过程数据通道里传输，端到端 CRC + 序列号 + 超时检测兜底，安全完整性由协议保证而不依赖通道。伺服侧支持时，STO/SLS 可以经 FSoE 触发，省去一部分硬件安全回路布线；硬件干接点回路作为兜底层仍然保留。细节在 B-D.14.3。

> SLS（Safely-Limited Speed，安全限速）：IEC 61800-5-2 的安全功能——驱动器内硬件级监控电机速度不超过设定限值，超限触发 STO。人形机器人在人机共域场景用它实现"靠近人时全身降速"，与协作机器人的功率与力限制（PFL）思路同源。

> 阻尼模式（Damping Mode）：伺服切到电流/力矩模式，输出与关节速度反向的力矩（τ = -k·ω，k 为阻尼系数）。效果是让关节像泡在油里一样缓慢运动——失电或失控的机器人以可控速度倒地，而不是僵直砸下或自由甩动。它是"缓慢倒地"策略的执行机构：主站检测到全身断链后，最后一帧有效指令把所有轴切阻尼，随后驱动器本体 watchdog 超时维持该模式。

"故障时缓慢倒地"是人形机器人特有的安全设计：双足站立是动态平衡，硬抱闸把关节锁死等于让几十公斤的刚性体直挺挺翻倒，对旁边的人和机器人本体都更危险。分部位降级写进主站的 WKC 门禁分支——这是 15.1 的 WKC 三行逻辑在人形上的扩展形态：

| 故障范围 | 检测 | 降级动作 |
|:---|:---|:---|
| 单关节掉线 | 该轴 WKC 位缺失 | 该轴切阻尼，全身重分配支撑（能站则站，不能则跪姿着陆） |
| 单分支（一腿）掉线 | 分支 WKC 整体不符 | 切换支撑策略：双臂撑地/蹲伏，切该分支全体阻尼 |
| 全身断链 / 主站失控 | 驱动器 watchdog（PDO 超时） | 各伺服本体自动切阻尼模式——**这条不依赖主站活着** |
| 摔倒进行中 | IMU 姿态角突变 + 质心发散 | 全身阻尼 + 收臂护头（预设保护姿态） |

注意第三行：全身断链时主站可能已经死了，检测责任下沉到每个伺服的 PDO 超时 watchdog——安全链路的每一环都要回答"上一级死了谁接住我"。

降级表在主站侧的落地是 WKC 门禁的分支化——15.1 的单门（整域一个 WKC）在这里拆成按分支核算：

```c
/* 配置期：按分支预算 expected_wkc（左腿 7 站 LRW 一次 ≈ 21，等） */
ecrt_master_receive(master);
ecrt_domain_process(domain1);

int leg_l_ok  = (wkc_leg_l.counter  == EXPECT_LEG_L);   /* 左腿分支 */
int leg_r_ok  = (wkc_leg_r.counter  == EXPECT_LEG_R);
int arms_ok   = (wkc_arms.counter   == EXPECT_ARMS);

if (!leg_l_ok || !leg_r_ok) {
    /* 单腿/双腿分支掉线：该分支全体切阻尼，剩余支撑策略介入 */
    set_branch_damping(leg_l_ok ? NONE : LEFT_LEG);
    set_branch_damping(leg_r_ok ? NONE : RIGHT_LEG);
    support_strategy_fallback();        /* 蹲伏/双臂撑地 */
} else if (!arms_ok) {
    set_branch_damping(ARMS);           /* 臂掉线不影响站立 */
}
/* 全身断链不在此处处理：主站活着才执行到这儿，
   那种情况由伺服本体 PDO watchdog 兜底 */
```

这段代码的每个分支都能在降级表里找到行——表是设计，代码是表的执行体，评审时两者逐行对读。

## <span class="blue"> 周期分层

| 层 | 频率 | 内容 | 调度 |
|:---|:---|:---|:---|
| 力控层 | 1 kHz | EtherCAT 循环 + 逆动力学 + 关节力矩分配 | SCHED_FIFO 最高优先级，隔离核 |
| 运动层 | 100~200 Hz | 步态规划、质心轨迹、落足点规划 | SCHED_FIFO 次优先级 |
| 感知层 | 30~100 Hz | SLAM、目标识别、语音 | 普通调度，独立核/独立网 |
| 任务层 | 事件 | 任务编排、遥操作、云端 | 非实时 |

层间数据交换走无锁环形缓冲（SPSC，见 15.1 的卡片）；上层输出的是参考轨迹（质心、落足点），力控层每周期插值执行。接口的最小形态：

```c
/* 运动层（100 Hz）写，力控层（1 kHz）读——单向 SPSC 环形缓冲 */
struct traj_point {
    double com_x, com_y, com_z;   /* 质心参考轨迹 */
    double foot_l[3], foot_r[3];  /* 落足点轨迹 */
    uint64_t t_mono_us;           /* CLOCK_MONOTONIC 时间戳 */
};

/* 力控层每 1 ms 周期：按时间戳在两个轨迹点间线性插值 */
struct traj_point p = ringbuf_peek_pair(&rb, now_us, &p0, &p1);
double a = (double)(now_us - p0.t_mono_us) / (p1.t_mono_us - p0.t_mono_us);
com_ref = lerp(p0.com, p1.com, clamp(a, 0.0, 1.0));
```

结构与 15.1 机械臂同构，差别在对力控层的抖动要求：机械臂轨迹精度对 100 µs 级抖动不敏感，双足平衡敏感——100 µs 的周期抖动通过微分项放大为力矩纹波，表现为站立时脚底的高频震颤。所以力控层线程的调度配置按 B-E.15.6 的最严档做（隔离核 + 中断绑核 + mlockall + 禁用该核的定时器 tick）。

## <span class="blue"> bring-up：工具输出逐段读

**第一份：`ethercat slaves`（节选）——31 站的体检表**：

```
0   0:0   OP  +  J_L1 Hip Servo (CSP/CST)
1   0:1   OP  +  J_L2 Thigh Servo (CSP/CST)
...
6   0:6   OP  +  Foot Force-Torque Sensor L
7   0:7   OP  +  J_R1 Hip Servo (CSP/CST)
...
30  0:30  OP  +  J_RA7 Wrist Servo (CSP/CST)
```

31 行全 OP 是"总线层通了"的判据。人形场景的特有用法：**掉线时看编号边界**——逻辑链上 position 连续编号，第一个不是 OP 的站就是断点下游方向的第一站。左腿分支整体掉线时，0~6 号消失或停在前一个状态，7 号以后正常——断点在腰部分支器到 J_L1 之间，直接缩小到一段线。

> EtherCAT 状态机：每个从站按 INIT → PREOP → SAFEOP → OP 四级推进——INIT 只认硬件；PREOP 开邮箱通道（SDO 配置、PDO 映射下发都在这层做）；SAFEOP 开始上行过程数据但输出保持安全态；OP 才全双工交换。某站卡在 SAFEOP 的典型原因是 PDO 映射与固件不符（见本节的 ESI ⚠️）；卡在 PREOP 多为邮箱配置失败。排障时先读状态再看日志，状态本身就是故障位置的信息。

**第二份：`ethercat dc`——31 站时钟对齐的分布检查**：

```
Application time: 1234567890123456
System time:      1234567890234567
DC reference clock: slave 0 (J_L1), offset稳定
Slave   1: offset +42 ns, drift OK
Slave   6: offset +380 ns, drift OK        ← 足底力传感器，分支末端延迟略大
Slave  15: offset +95 ns, drift OK
...
```

读法：各站 offset 的绝对值在百纳秒级属正常（分支末端略大是传播延迟的指纹）；要警惕的是某站 offset 持续单向漂移——说明该校正没收敛，通常是该站 ESC 时钟异常或分支层级过深，回到拓扑一节"分支不过两级"的约束上找原因。

**第三份：控制网纯净度验证**：

```bash
tcpdump -i eth1 -c 1000 not ether proto 0x88a4   # 应无输出
```

控制网口抓 1000 帧，非 EtherCAT（EtherType 0x88A4）的帧应为零。抓到 ARP/IP 帧说明有服务把流量打进了控制网——常见元凶是 DHCP client 或零配置网络的 avahi，在系统镜像里对控制网卡全部禁用。

> ⚠️
> 31 站规模下，从站固件与 ESI（EtherCAT Slave Information，从站信息 XML）文件的版本一致性是新的故障面：某轴伺服固件升级后 PDO 映射表变化，而主站侧 ENI 没同步更新，表现为该站进不了 OP 或过程数据错位。产线与售后的固件刷写流程必须把"ENI 重生成"列为强制步骤——配置漂移的故障形态是渐变的，第一次症状往往只是启动变慢（见传感接入一节的启动时序基线）。

## <span class="blue"> 联调顺序

1. **单分支逐个通**：先接腰部分支器 + 一个腿分支（6 站），单分支走通 CSP/CST 模式切换。判据：该分支 72 小时老化零 WKC 错误——分支数少时排查面小，这是人形联调的核心技巧：**不在 31 站上直接调，把问题约束在单分支内**。
2. **全身集成**：四肢分支逐级接入，DC 锁定（`ethercat dc` 各站 offset 收敛），全轴使能后悬挂状态下空载运动。判据：悬挂（吊具离地）状态跑标准动作库 24 小时，周期抖动 P99 < 预算。
3. **落地闭环**：落地站立 → 原地踏步 → 行走，足底力数据逐步进环。判据：静态站立 1 小时质心漂移与震颤幅度达标；推扰恢复测试通过。
4. **故障注入与安全验证**：逐分支拔线、整机断网、急停、推倒测试（保护垫）——对安全降级表逐行验证，重点验证"主站断电时伺服 watchdog 自动切阻尼"这条不依赖软件的路径。判据：全部故障形态的倒地都是可控阻尼倒地，无僵直摔倒；记录进安全评审档案。

第 2 阶段的"悬挂"值得说透：机器人吊在龙门吊具上、脚离地，关节全行程运动但不受地面反力。这个状态把系统切成"总线+控制律"和"接触力学"两个可独立验证的变量——悬挂阶段暴露的是周期抖动、WKC、DC、力矩指令符号错误这类纯控制链问题；如果直接落地调，站立摇晃可能是控制链抖动、也可能是接触参数错误，两个变量耦合时归因全靠猜。悬挂 24 小时动作库跑完，控制链的问题基本清完，第 3 阶段才专心对付接触。

第 3 阶段才落地是经验顺序：悬挂状态排除了接触力学变量，先把"总线+控制"调干净，再把"接触"加进来——两个变量一起调，故障归因会变成猜谜。

## <span class="blue"> 与机械臂方案的对照

| 维度 | 六轴机械臂（15.1） | 人形机器人（本篇） |
|:---|:---|:---|
| 轴数 | 6 | 28~50 |
| 周期 | 1 ms 宽裕（余量 ≥50%） | 1 ms 紧张（余量 35~60%），部分厂商 2~4 kHz |
| 拓扑 | 单条线型+回环冗余 | 干线+四肢分支（机械约束驱动） |
| 力控 | 末端单点（六维力 SPI） | 全身分布式（每关节+足底，全在 EtherCAT 上） |
| 故障降级 | 停机卸力 | 分部位降级、阻尼倒地——停机不可选 |
| 传感器同步 | 时间戳补偿即可 | 足底力必须进 EtherCAT 同节拍 |
| 算力/网络 | 单网口够用 | 控制网/感知网必须物理分离 |

对照 15.2 的 AGV 则是另一极：AGV 连轴间同步都不需要，人形把它推到亚微秒。三台机器、三种总线答案——E 板块前两篇的方法论（约束清单→定量排除→预算核算→降级表→联调判据）在本篇没有新增任何步骤，只是每个步骤的数更紧。

## <span class="blue"> 排障：人形特有问题

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 某分支整体掉线 | 关节走线疲劳断裂 | `ethercat slaves` 看掉线边界站；逐段查关节线 |
| 周期抖动随运动增大 | 线缆弯折引入瞬时接触不良 | 抖动统计与关节角度做相关性分析 |
| 力控振荡/站立摇晃 | 足底力数据延迟或丢帧 | 该从站 WKC 与 PDO 一致性检查；示波器看 SYNC0 |
| DC 锁定慢/漂移告警 | 分支层级过深、参考时钟选取不当 | `ethercat dc` 看各站 offset 分布与漂移方向 |
| 站立时高频小抖动 | 控制周期抖动（感知流量窜网） | 控制网口 tcpdump 应只见 0x88A4 帧 |
| 单轴偶发失控又自愈 | 该轴 PDO 超时 watchdog 触发后恢复 | 驱动器侧错误日志；该轴线缆重点检查 |
| 悬挂正常、落地即振荡 | 接触模型参数（刚度/阻尼）与足底力标定不符 | 足底传感器零位标定复查；接触参数系统辨识 |
| 长时运行后某分支丢帧率上升 | 分支器或该分支首个伺服温度异常 | 各站温度遥测趋势；分支器供电电压测量 |

## <span class="blue"> 本节总结

本篇把 E 板块的方法论压到最紧的约束下又走了一遍：需求清单第一行乘第二行（28 轴 × 1 kHz × 17 B）直接判死 CAN FD 和普通以太网，EtherCAT 成为唯一成立的开放方案；拓扑不再自由选择，是机械结构倒逼的干线加四分支，分支器放腰部是走线几何的答案；周期预算 400~650 µs 说明 1 kHz 成立但余量只有机械臂的一半，2 kHz 需要砍 PDO、控制律分层或 EtherCAT G 三条路径各算各的账；足底力传感器必须挂 EtherCAT 是"参与同一控制律的量必须同节拍"的极端形态。与机械臂最深的一层差异在安全：双足是动态平衡，停机不可选，降级链路的每一环都要回答"上一级死了谁接住我"——主站死了伺服 watchdog 接，分支死了支撑策略接，摔倒进行中阻尼模式接。

| 问题 | 一句话答案 | 详见 |
