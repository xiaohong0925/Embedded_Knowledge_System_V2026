# B-E.15.3 人形机器人：EtherCAT 全身总线实战

> 所属章节：第五部 B. 总线协议 > E. 综合实战
>
> 难度：[M] | 预计阅读时间：45 分钟

## 本节导读

人形机器人把多总线协同推到当前最极端的形态：30~50 个关节伺服、每个关节要带力矩闭环、全身 IMU 与六维力传感器若干、控制周期 1 kHz 起步且全身轴间同步、还要在躯干里走线。总线方案在人形机器人上不是"选型"问题，是"能不能成立"问题——轴数 × 周期的带宽需求直接把 CAN FD 排除出主运动网，EtherCAT 的线型拓扑与机械结构的走线约束强耦合。本篇以一台典型双足人形（28 关节）为对象，拆解全身总线架构的完整设计。

本篇假设你已读过 12.2/12.3（EtherCAT 协议与 DC）、15.1（机械臂多总线协同）；本篇聚焦人形机器人**独有**的问题：轴数规模、躯干走线拓扑、力控带宽、安全架构。

本节覆盖：人形机器人的总线需求清单、EtherCAT 多分支拓扑与走线、带宽与 DC 预算核算（28 轴 1 kHz）、力矩传感器与 IMU 的接入方案、全身安全架构（STO/摔倒保护）、控制周期分层（1 kHz 力控 / 100 Hz 规划）、与机械臂方案的差异对照。

## 需求清单：先看约束再看方案

| 约束 | 数值 | 对总线的要求 |
|:---|:---|:---|
| 关节数 | 28（腿 6×2、臂 7×2、腰 2） | 单网 28+ 从站，帧长与周期预算紧 |
| 控制周期 | 力控 1 kHz，部分厂商 2~4 kHz | EtherCAT 是唯一能同时满足轴数与周期的开放方案 |
| 轴间同步 | 全身 <1 µs | DC 分布式时钟是前提，不是选项 |
| 力控 | 每关节电流/力矩闭环在主站 | 每轴 PDO 要含力矩指令与电流反馈，字节数翻倍 |
| 走线 | 躯干内穿关节，线缆长度与弯折受限 | 拓扑必须贴合机械结构，线型+分支混合 |
| 安全 | 摔倒保护、关节限位、STO | 安全链路与控制链路分层 |
| 算力 | 主控 x86/ARM + 可选 GPU | 控制网与感知网物理分离 |

## 拓扑：让总线贴合身体

```
                    ┌─ 主控（躯干内，x86 + PREEMPT_RT）─┐
                    │  EtherCAT 主端口（Port A）         │
                    └──────┬─────────────────────────────┘
                           │ 干线
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
        左腿分支        躯干/腰          右腿分支
        J_L1..J_L6      腰 J_W1/W2      J_R1..J_R6
        （线型 6 站）    │               （线型 6 站）
                         ▼
                    左臂分支（J_A1..7）经左肩走线
                    右臂分支（J_A5..11 右臂）经右肩走线

 实现方式：腰部放一个多端口 EtherCAT 分支器（4 口 ESC 耦合器，
 如 EK1122 类），把线型干线分叉成四肢四个分支
 端口数：28 伺服站 + 分支器 ≈ 30 个 ESC 节点
```

拓扑设计的三个机械约束：

1. **穿关节走线用细柔线**：关节处的 EtherCAT 线缆要随关节弯折百万次级，选高柔拖链线，且每个关节的线长余量按最大行程计算——线缆拉断是人形机器人现场故障的第一名。
2. **分支器放腰部**：四端口分支器把干线分到四肢，单腿故障（断线）只丢该分支，配合 12.2 的线缆冗余思想，主站侧可以设计成双端口冗余到腰部。
3. **末端 IMU 就近挂载**：脚底六维力传感器与小腿 IMU 挂在该腿分支末端，不为传感器单独拉长线。

## 带宽与 DC 预算：28 轴 1 kHz 是否成立

逐轴 PDO 内容（力控版）：RPDO = 目标力矩（2B）+ 目标位置（4B）+ 控制字（2B）= 8 B；TPDO = 实际位置（4B）+ 实际电流（2B）+ 状态字（2B）+ 温度（1B）≈ 9 B。

```
 过程数据：28 轴 × (8+9) B + 分支器/IO 少量 ≈ 500 B
 帧结构：Datagram 分组（每分支一个 LRW）+ 帧头开销 ≈ 600 B 总量
 线上时间：600 × 8 / 100 Mbps ≈ 48 µs
 ESC 硬件延迟：30 站 × 0.3 µs ≈ 9 µs
 主站收发+处理：约 100~200 µs（I210 + 专用驱动）
 控制律计算（WBC/MPC 简化版）：200~400 µs（隔离核）
 ──────────────────────────────────────────────
 合计 ≈ 400~650 µs —— 1 kHz 成立，2 kHz 需要砍内容或升千兆
```

DC 同步：30 站全 DC 模式，SYNC0 1 µs 级对齐无压力；注意**分支器本身引入额外传播延迟**，DC 初始化测量会自动补偿，但设计时分支深度不要超过两级，避免时钟链路诊断复杂化。

> ⚠️
> 1 kHz 成立的前提是把"感知流量"完全挡在控制网外。视觉、激光雷达、语音走第二张独立网卡（普通以太网/WiFi），控制网口只跑 EtherCAT。人形机器人主控翻车案例里，"控制网混入其他流量"是周期抖动的第一大原因。

## 传感接入方案

| 传感器 | 位置 | 接入方式 | 理由 |
|:---|:---|:---|:---|
| 关节力矩/电流 | 每伺服内置 | PDO 自带 | 走 EtherCAT 主循环 |
| 脚底六维力 ×2 | 足底 | EtherCAT IO 从站挂腿分支末端 | 力控直接输入，必须与伺服同节拍 |
| 躯干 IMU | 腰部 | SPI 直连主控（1 kHz 读取）或 EtherCAT IMU 站 | 姿态解算在主控，SPI 延迟最低 |
| 关节绝对编码器 | 每伺服内置 | PDO 自带 | — |
| 视觉/深度相机 | 头部 | USB3 / 千兆网，独立感知网 | 与控制网物理隔离 |
| 麦克风阵列 | 头部 | USB 音频 | 感知域 |

力控的数据流闭环：脚底力传感器（EtherCAT TPDO）→ 主控 WBC 算法 → 28 轴力矩指令（RPDO），全程在 1 ms 周期内完成。这决定了脚底力传感器**必须**在 EtherCAT 网上——用 RS-485 或 CAN 接足底传感器，10 ms 级的延迟会让 1 kHz 力控环失去意义。

## 安全架构

```
 硬件安全层（不依赖软件与通信）：
   急停按钮 ── STO 干接点 ── 各伺服 STO 输入（分布式）
   关节机械限位、过流保护（伺服本体）

 软件安全层（EtherCAT 上）：
   FSoE 安全 PDO：STO/SLS 安全功能（认证伺服支持时）
   主站监控：WKC 门禁、关节位置/速度软限位、
            摔倒检测（IMU 姿态角突变）→ 阻尼模式泄力

 策略差异（与机械臂不同）：
   机械臂故障 → 立即抱闸停机
   人形故障 → 分部位降级：单腿分支掉线时切换支撑策略，
              全身断链时关节切阻尼模式（缓慢倒地而非僵直摔倒）
```

"故障时缓慢倒地"是人形机器人特有的安全设计：双足站立是动态平衡，硬抱闸等于直挺挺摔倒，对人和机器都更危险。降级策略写进主站的 WKC 门禁分支，这是 15.1 的 WKC 三行逻辑在人形上的扩展形态。

## 周期分层

| 层 | 频率 | 内容 | 调度 |
|:---|:---|:---|:---|
| 力控层 | 1 kHz | EtherCAT 循环 + 逆动力学 + 关节力矩分配 | SCHED_FIFO 最高优先级，隔离核 |
| 运动层 | 100~200 Hz | 步态规划、质心轨迹、落足点规划 | SCHED_FIFO 次优先级 |
| 感知层 | 30~100 Hz | SLAM、目标识别、语音 | 普通调度，独立核/独立网 |
| 任务层 | 事件 | 任务编排、遥操作、云端 | 非实时 |

层间数据交换走无锁环形缓冲；上层输出的是参考轨迹（质心、落足点），力控层每周期插值执行——与 15.1 机械臂的域划分同构，只是层数更多、对力控层的抖动要求更苛刻（双足平衡对 100 µs 级抖动敏感）。

## 与机械臂方案的对照

| 维度 | 六轴机械臂（15.1） | 人形机器人（本篇） |
|:---|:---|:---|
| 轴数 | 6 | 28~50 |
| 周期 | 1 ms 宽裕 | 1 ms 紧张，部分 2~4 kHz |
| 拓扑 | 单条线型 | 干线 + 四肢分支（机械约束驱动） |
| 力控 | 末端单点 | 全身分布式（每关节 + 足底） |
| 故障降级 | 停机 | 分部位降级、阻尼倒地 |
| 传感器同步 | 时间戳补偿即可 | 足底力必须进 EtherCAT 同节拍 |
| 算力/网络 | 单网口够用 | 控制网/感知网必须物理分离 |

## 排障：人形特有问题

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 某分支整体掉线 | 关节走线疲劳断裂 | `ethercat slaves` 看掉线边界站；逐段查关节线 |
| 周期抖动随运动增大 | 线缆弯折引入瞬时接触不良 | 抖动统计与关节角度的相关性分析 |
| 力控振荡 | 足底力数据延迟/丢帧 | 该从站 WKC 与 PDO 一致性检查 |
| DC 锁定慢/漂移告警 | 分支层级过深、参考时钟选取不当 | `ethercat dc` 看各站 offset 分布 |
| 站立时高频小抖动 | 控制周期抖动（感知流量窜网） | 控制网口 tcpdump 应只见 0x88A4 帧 |
