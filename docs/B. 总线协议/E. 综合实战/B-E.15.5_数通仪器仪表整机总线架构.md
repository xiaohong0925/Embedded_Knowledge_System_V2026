# B-E.15.5 数通仪器仪表整机总线架构

> 所属章节：第五部 B. 总线协议 > E. 综合实战
>
> 难度：[M] | 预计阅读时间：45 分钟

## 本节导读

数通测试仪、流量发生器、协议分析仪这类设备，以及广义的机架式仪器，内部是另一种总线形态：前面板插一溜业务卡（每张卡上是 FPGA + PHY + 光模块笼），中间一块背板，后面主控卡。整机的总线架构天然分成三个正交的"面"——数据面跑被测业务流量，管理面跑带内监控（温度/电压/光功率/风扇/电源），控制面跑主控到业务卡的配置下发。三个面的总线选型、隔离、故障域完全不同。本篇以一台 2U 机架式流量测试仪为对象拆解三面架构，这类设备的总线设计方法对 PCIe 卡、交换机、基站等"机箱+背板+插卡"形态的产品普遍适用。

本节覆盖：三平面划分原则、数据面的 PCIe/SerDes 背板互连、管理面的 I2C/PMBus/CMIS 拓扑与器件清单、控制面形态（带内 vs 带外）、背板设计约束、整机 bring-up 顺序、热插拔与故障隔离设计。

## 三平面划分

```
 ┌─────────────────── 2U 机箱 ───────────────────┐
 │                                                │
 │  数据面：业务卡 FPGA ══ SerDes（背板或前面板）    │
 │    被测流量 100G/400G 光口，卡间触发/同步线      │
 │                                                │
 │  控制面：主控卡 ══ PCIe/以太网（背板）══ 业务卡    │
 │    配置下发、状态回收、固件升级                   │
 │                                                │
 │  管理面：BMC/管理 MCU ══ I2C/PMBus 树 ══ 每块卡   │
 │    温度、电压、风扇、电源、光模块 DOM、在位检测    │
 │                                                │
 │  电源：背板 12 V/48 V 主干 + 各卡点载 POL        │
 └────────────────────────────────────────────────┘
```

三面分离的理由：

| 面 | 流量性质 | 失效后果 | 设计原则 |
|:---|:---|:---|:---|
| 数据面 | 被测业务，Tbps 级 | 测试中断 | 与任何软件无关，纯硬件通路 |
| 控制面 | 配置/状态，MB 级 | 无法操作设备 | 可靠优先，可走标准协议栈 |
| 管理面 | 监控遥测，KB 级 | 失去硬件可见性 | **必须独立于主控存活**——主控死机时风扇温控还要继续 |

管理面独立性是最容易被砍掉的 design rule：主控 SoC 跑 Linux 会死机、会重启、会升级；风扇调速和过温保护不能跟着死。所以管理面挂在 BMC/管理 MCU 上，主控通过 BMC 间接访问遥测——服务器行业的 IPMI/BMC 架构就是这个原则的完整形态，仪器仪表只是简化版。

## 数据面：背板 SerDes 与板内 PCIe

数据面的典型互连：

```
 业务卡内部：FPGA ══ PCIe Gen4 x8 ══ 卡上 CPU（或经背板到主控卡 CPU）
 业务卡间：  触发线（背板低速差分对，ns 级同步）、
             参考时钟分发（背板 100 MHz/10 MHz + PLL）
 对外：     QSFP-DD 光模块笼 × 8（前面板）
```

三个设计要点：

1. **触发与同步走专用低速线，不走数据网**。多卡联合测试时，卡间触发偏差要求 ns 级，用背板上的专用差分对 + FPGA 内部时间戳对齐实现；试图用 PTP over 数据网做这件事，精度差三个量级。
2. **参考时钟集中分发**。主时钟卡出 10 MHz/100 MHz 参考，各业务卡 PLL 锁定，全机箱同频——多卡流量测试的时间戳可比性由此而来。
3. **背板通道预算**。背板走 25G/56G SerDes 时，通道预算（插损、串扰、连接器）按 B-F.16.1 的信道预算方法核算，连接器选型（如 VPX 标准件）直接决定能上到哪一代速率。

## 管理面：I2C 树的设计

管理面是一棵以 BMC 为根的 I2C 树，典型器件清单：

| 器件类别 | 协议/标准 | 挂载方式 | 监控内容 |
|:---|:---|:---|:---|
| 温度传感器 | LM75/TMP102 类 | 各卡 I2C | 进/出风口、FPGA 结温邻近点 |
| 电压/电流监控 | INA230/ADM1278 类 | 各卡 I2C | 各电源轨电压电流、功耗 |
| 风扇 | 4 线 PWM + 转速计 | BMC GPIO/PWM | 调速与堵转检测 |
| 电源模块 | PMBus | 背板 I2C | 电源状态、告警、黑盒日志 |
| 光模块 | SFF-8636 / CMIS（14.5） | 各卡 I2C 笼位总线 | DOM 五项、在位、LowPwr 切换 |
| 在位检测 | 卡槽 Present 引脚 | GPIO 扩展器（PCA9555） | 热插拔事件 |
| EEPROM | AT24C 类 | 各卡 I2C 0x50~0x57 | 板卡序列号、校准数据、MAC 地址 |

I2C 树的三个工程问题：

1. **地址冲突**：多卡同型号时，每张卡上的温度传感器地址都一样。解法是用 I2C 多路复用器（PCA9548）按卡位分通道，或者每张卡的 I2C 段挂在该卡自己的 MCU 上做本地汇聚、BMC 只与卡 MCU 对话（背板 I2C 只有 N 个卡 MCU 地址）。后者可维护性更好，是机箱产品的通行做法。
2. **总线锁死恢复**：热插拔中 I2C 时序被打断，从机可能把 SDA 拉死。BMC 侧要有总线恢复逻辑（发 9 个时钟脉冲解锁，或 mux 断电复位），这在热插拔设备上不是可选项。
3. **速率与容性负载**：背板走线的寄生电容大，I2C 跑 100 kHz 起步，别上来就 400 kHz；示波器看上升沿是否超限再提速。

## 控制面：带内与带外

| 形态 | 路径 | 优点 | 缺点 |
|:---|:---|:---|:---|
| 带内 | 主控 ══ PCIe（背板）══ 业务卡 FPGA/卡 CPU | 带宽大，DMA 下发配置快 | 链路训练依赖两边都活着 |
| 带外 | 主控 ══ 以太网交换机芯片（背板）══ 各卡管理口 | 独立于数据面工作状态 | 多一颗交换芯片 |
| 混合 | PCIe 为主 + 以太网兜底 | 两者互补 | 软件要维护双通道 |

仪器仪表的常见形态是混合：正常工作时配置走 PCIe（BAR 访问 + DMA，见 B-D.10.6 的实战），业务卡 FPGA 异常或 PCIe 链路未训练时退回以太网带外通道做恢复。带外通道同时承担固件升级路径——FPGA 在线升级（JTAG over IP 或 SPI Flash 改写）走带外，避免升级失败变砖。

## 整机 bring-up 顺序

```
 1. 电源与时序：背板电压、各卡 POL 时序、PG（Power Good）链
    判据：空载上电各路电压在窗口内，时序图与设计一致
 2. 管理面：BMC 起，扫 I2C 树，读全机箱温度/电压/在位
    判据：BMC 能看到所有卡位状态；风扇闭环调速生效
 3. 控制面带外：各卡管理网口 ping 通
    判据：BMC/主控到每卡的双向通信
 4. 控制面带内：PCIe 枚举（lspci），链路速率/宽度核对
    判据：所有卡按 Gen4 x8 训练成功，AER 无报错（B-D.10.4）
 5. 数据面：光模块管理面确认（CMIS HighPwr 切换），
    SerDes PRBS 自环误码测试，最后接被测设备
    判据：PRBS 零误码 24 小时
 6. 系统级：多卡同步触发精度、长稳测试、热插拔演练
```

这个顺序的原则是"面与面解耦验证"：管理面不通就不上高压大电流，带内不通先用带外定位——每个面的故障域独立，bring-up 时间才不会指数膨胀。

## 排障：整机级故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 某卡时好时坏 | 背板连接器接触、该卡 I2C 段锁死 | 管理面读该卡 MCU 状态；热插拔复现 |
| 全机箱温度告警 | 风扇策略失效、进出风口堵住 | BMC 风扇转速与温度曲线对照 |
| PCIe 降速到 Gen1 | 背板通道损耗、连接器氧化 | lspci -vv 看 LnkSta vs LnkCap；AER 计数 |
| 光模块链路 flap | CMIS 状态机没切 HighPwr、收光不足 | ethtool -m 看 DOM 与模块状态 |
| 卡间触发偏差大 | 参考时钟未锁定、触发线走线不等长 | 示波器测各卡时钟相位与触发线延迟 |
| 升级后某卡失联 | 带外升级通道中断留下半砖 | 带外通道重刷；验证双镜像回退机制 |
