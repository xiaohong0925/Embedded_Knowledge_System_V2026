# B-E.15.1 六轴协作机械臂：多总线协同架构

## 本节导读

单条总线的机制在前面各组都讲过了，真实的整机是七八条总线同时跑。本篇以一台六轴协作机械臂控制器为对象，做的是**总线层面的系统设计**：每条总线分给谁、为什么这么分、带宽和周期预算怎么核算、时钟域怎么隔离、一条总线故障时整机怎么安全降级。IgH 主站的搭建细节在 12.5，本篇不重复安装与完整代码，只保留系统架构相关的骨架。

本篇是 B 扩展 E 板块的开篇，定位是"总线架构设计方法在一个具体整机上的完整演练"；通用方法论的提炼在 15.4。

本节覆盖：六轴机械臂的总线拓扑与选型理由表、实时域划分（硬实时/软实时/非实时）、带宽与周期预算核算、时钟与同步策略、总线故障的安全降级设计、设备树与软件栈的组织方式、整机联调的顺序与排障。

## 拓扑与选型：每条总线分给谁

```
 ┌──────────────── 主控（x86 工控机，PREEMPT_RT）────────────────┐
 │                                                                 │
 │  EtherCAT 口 ── 线型环 ──┬─ J1 伺服 ─ J2 ─ J3 ─ J4 ─ J5 ─ J6 ─┐ │
 │  （IgH 主站，1 kHz）     └───────────────────────────── 回环 ──┘ │
 │                                                                 │
 │  SPI0  ── CS0：六维力矩传感器（末端）                            │
 │         ── CS1~6：各关节绝对编码器                               │
 │  I2C1  ── 底座 IMU（姿态监测）                                   │
 │  UART0 ── 示教器（人机交互）                                     │
 │  RS-485 ── 末端夹爪（Modbus RTU）                                │
 │  GPIO  ── 双通道安全回路（急停/STO 干接点）                       │
 │  MIPI CSI-2 ── 视觉相机（引导定位）                              │
 │  以太网口2 ── 上位机/示教软件（TCP/IP，非实时）                   │
 └─────────────────────────────────────────────────────────────────┘
```

选型理由表——每个分配的"为什么是它"：

| 功能 | 总线 | 选型理由 | 被排除的方案与原因 |
|:---|:---|:---|:---|
| 6 轴伺服闭环 | EtherCAT 1 kHz | 轴间 DC 同步 <100 ns；CoE 复用 CiA 402 | CAN：6 轴状态+指令带宽不够；PROFINET RT：周期到不了 1 ms 稳定 |
| 力矩传感器 | SPI 8 MHz | 板内芯片，SPI 延迟最低、协议最简 | EtherCAT IO：多一个 ESC 成本，无必要 |
| 关节编码器 | SPI 4 MHz ×6 | 同上，6 个 CS 分时复用一根总线 | 每轴独立 SPI 控制器：SoC 没有那么多 |
| 底座 IMU | I2C 400 kHz | 低速率传感器的标准接口，布线两根 | SPI：省不下来什么，IMU 芯片原生 I2C |
| 示教器 | UART | 低速人机交互，UART 最省事 | USB：示教器侧无 USB 栈 |
| 夹爪 | RS-485/Modbus RTU | 夹爪厂商的标准接口，差分抗扰 | CAN：夹爪不支持，要加网关 |
| 安全回路 | GPIO 干接点 | 安全功能独立于所有通信总线（14.3 的黑色通道原则） | 走 EtherCAT PDO：非安全数据驱动安全功能是红灯 |
| 视觉 | MIPI CSI-2 | SoC 原生相机接口 | USB 相机：CPU 占用与延迟都差 |
| 上位机 | 标准以太网 | 非实时管理流量，与控制网物理隔离 | 与控制网共网段：违反确定性前提 |

## 实时域划分

整机的软件按实时性分三域，各域的调度策略、总线访问权不同：

| 域 | 内容 | 周期 | 调度 |
|:---|:---|:---|:---|
| 硬实时 | EtherCAT 周期任务（读反馈→控制律→写指令）、安全回路监控 | 1 ms | SCHED_FIFO 90+，隔离核，mlockall |
| 软实时 | 轨迹规划、力控算法、视觉处理 | 10~30 ms | SCHED_FIFO 中优先级或 SCHED_DEADLINE |
| 非实时 | 示教器 UI、日志、以太网通信、文件 IO | 事件驱动 | 普通调度 |

划域的两个硬规则：

1. **非实时域永远不能阻塞硬实时域**。EtherCAT 周期任务不打印日志、不分配内存、不碰文件系统；与外界的交换走无锁环形缓冲。
2. **总线按域隔离优先级**：EtherCAT 网口专用（12.5 的纪律）；SPI/I2C/UART 的访问由对应域的线程独占，不跨域共享——跨域共享总线意味着互斥锁，互斥锁意味着优先级反转风险。

## 带宽与周期预算

EtherCAT 主干的一次周期预算核算（6 轴，每轴 RPDO 10 B + TPDO 10 B）：

```
 过程数据：6 轴 × (10 + 10) B = 120 B
 帧开销：以太网头 + EtherCAT 头 + Datagram 头 + FCS ≈ 60 B
 单帧线上时间：约 (120+60+64 最小帧补齐) × 8 bit / 100 Mbps ≈ 20 µs
 从站硬件延迟：6 × 0.3 µs ≈ 2 µs
 主站处理 + 控制律计算：实测 200~400 µs（取决于算法）
 ────────────────────────────────────────────────
 总占用 < 500 µs，1 ms 周期留 ≥50% 余量 ← 工程合格线
```

其余总线的负载率都是小菜：SPI 力矩传感器 10 ms 一次几十字节，I2C IMU 20 ms 一次十几字节。真正要核算的是**主站 CPU 时间**和**抖动**，不是总线带宽——机械臂这类系统带宽永远够，时间确定性永远稀缺。

## 时钟与同步策略

```
 DC 参考时钟（首个伺服从站）
      │  EtherCAT DC 机制（12.3）
      ▼
 6 轴伺服 SYNC0 对齐 <100 ns ── 位置环同步执行
      │
 主站周期（1 ms）由 IgH 应用层定时器驱动，与 DC 锁定

 SPI/I2C 传感器：不同步采样，读取时打主站时间戳，
 控制算法侧做时间对齐（外推补偿 10~20 ms 采样延迟）

 视觉：30 fps 自由运行，结果带时间戳进轨迹规划，
 规划器按时间戳做运动学外推
```

原则：参与同一控制律的量必须时间对齐，不对齐的量带时间戳交给算法补偿。不要试图把 IMU、视觉硬塞进 EtherCAT 的同步节拍——成本远超收益。

## 总线故障的安全降级

整机安全设计的总线维度：

| 故障 | 检测手段 | 降级动作 |
|:---|:---|:---|
| EtherCAT 从站掉线 | WKC ≠ 预期值（12.2） | 当周期内触发 Quick Stop + STO，禁止用旧数据驱动 |
| EtherCAT 周期超时 | 主站看门狗（周期 >1.2 ms） | 同上 |
| 编码器 SPI 读数跳变 | CRC/一致性检查（连续两次读比对） | 降速运行并报错；三次不一致停机 |
| 夹爪 Modbus 超时 | 应答超时计数 | 夹爪保持（非安全件），任务报错 |
| 安全回路 GPIO 动作 | 硬件中断 | 硬件级 STO，软件只做记录与上报 |

> ⚠️
> WKC 检查是每周期的必修课，不是可选项。EtherCAT 从站掉线后，过程数据镜像里留的是最后一次旧值——继续拿它做闭环等于盲开。`ecrt_domain_process` 之后立刻 `ecrt_domain_queue` 前核对 WKC，不一致就走安全停机路径，这是协作机器人量产代码里不可删减的三行。

## 软件栈组织

```
 进程/线程布局（单进程多线程，避免 IPC 延迟）：
 ┌─────────────────────────────────────────────────┐
 │ RT 线程（core 2，SCHED_FIFO 90）：EtherCAT 循环   │
 │   ecrt 四段式（12.3），WKC 检查，CiA 402 状态机   │
 │ RT 线程（core 2，SCHED_FIFO 80）：安全回路监控    │
 │ 软实时线程（core 1，SCHED_FIFO 50）：轨迹规划     │
 │ 普通线程（core 0）：视觉 / 示教器 / 网络 / 日志   │
 └─────────────────────────────────────────────────┘
 域间数据交换：无锁环形缓冲（SPSC），方向单向

 设备树：SPI/I2C/UART/GPIO/MIPI 外设节点 + EtherCAT 无节点
 （IgH 走独立网卡驱动，不在设备树里）
```

ecrt 实时循环骨架（与 12.5 相同结构，此处只列多轴组织差异）：

```c
/* 每周期：收 → 处理 → 逐轴控制 → 发 */
ecrt_master_receive(master);
ecrt_domain_process(domain1);

/* WKC 门禁：不一致立即安全停机 */
if (domain1_wkc.counter != expected_wkc) {
    enter_safe_stop();          /* 停 PDO 输出，上报，触发 STO 流程 */
}

for (int ax = 0; ax < 6; ax++) {
    status[ax] = EC_READ_U16(pd + off_status[ax]);
    act_pos[ax] = EC_READ_S32(pd + off_actpos[ax]);
    ctrl[ax] = cia402_next_cw(status[ax]);
    EC_WRITE_U16(pd + off_ctrl[ax], ctrl[ax]);
    if (cia402_enabled(status[ax]))
        EC_WRITE_S32(pd + off_tgt[ax], trajectory_next(ax));  /* 来自规划环形缓冲 */
    else
        EC_WRITE_S32(pd + off_tgt[ax], act_pos[ax]);          /* 跟随当前位置 */
}

ecrt_domain_queue(domain1);
ecrt_master_send(master);
```

## 联调顺序

整机 bring-up 按"先单总线、后集成、再闭环"推进，每阶段有出口判据：

1. **单总线逐个通**：EtherCAT 用 12.5 流程单轴 CSP 走通；SPI/I2C/UART 各自用命令行工具读到数据；安全回路用万用表验证干接点动作。判据：每条总线独立可读写。
2. **六轴 EtherCAT 集成**：六轴同时 OP，DC 锁定（`ethercat dc` 确认），全轴使能后点动。判据：72 小时老化无 WKC 错误。
3. **闭环集成**：轨迹规划接入，跑标准测试轨迹（空载→额定负载）。判据：轨迹跟踪误差与重复定位精度达标。
4. **故障注入**：拔 EtherCAT 网线、堵 SPI、拍急停——验证每条降级路径都按表执行。判据：所有故障注入的结果都是安全停机，无一例外。

## 排障：整机级故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 某轴偶发抖动 | 该轴编码器 SPI 采样与控制周期不同步 | 时间戳对齐检查；控制律输入加延迟补偿 |
| 周期性（每 N 秒）位置跳变 | 非实时线程抢占了硬实时核 | `cat /proc/interrupts` 看中断分布；确认 isolcpus 生效 |
| 视觉引导轨迹漂移 | 视觉时间戳与运动时间不同源 | 统一到 CLOCK_MONOTONIC 并标定延迟 |
| 急停后伺服仍有力矩 | STO 路径被软件逻辑旁路 | 硬件回路审查：STO 必须纯硬件链路 |
| 大负载下周期超时 | 控制律计算时间超预算 | perf 剖周期任务；算法优化或降频到 500 Hz 评估 |
