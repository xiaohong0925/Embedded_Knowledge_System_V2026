## 本节导读

12.1 给出了工业以太网版图，EtherCAT 的结论性优势是集总帧与硬件透传。本节把这个机制拆到字节级：帧怎么封装、经过从站时发生了什么、Datagram 的寻址方式有哪几种、从站芯片（ESC）内部怎么组织、从站状态机怎么管。读完你应该能看懂 Wireshark 抓到的 0x88A4 帧，也能解释"为什么 EtherCAT 的抖动比标准以太网低三个数量级"。

> 本节覆盖：飞读飞写（on-the-fly processing）的完整过程、EtherCAT 帧与 Datagram 结构、APRD/FPRD/LRW 三类寻址方式的分工、WKC 工作计数器、ESC 芯片内部架构（PDM/SyncManager/FMMU/DC）、CoE 邮箱与对象字典的关系、从站 AL 状态机、拓扑与线缆冗余、周期时间估算、IgH 命令行与 Wireshark 两个观察工具、协议层排障。按"帧怎么流 → 帧里装什么 → 地址怎么寻 → 从站芯片怎么接 → 应用数据怎么映射 → 状态怎么管 → 坏了怎么查"展开——这正是你第一次用 IgH 带起一条伺服链时的认知顺序。

读完你应该能独立完成三件事：逐字节解码一个 EtherCAT Datagram 并核对 WKC、用 IgH 的 `ethercat` 命令行确认从站状态与对象字典读写、为给定从站规模估算周期时间下界并说明抖动预算花在哪里。

## 飞读飞写：帧穿过从站时不停车

标准以太网节点收到帧要整帧存储、查目的 MAC、决定是否上送——每个节点的存储转发延迟在 µs 级，且随负载波动。EtherCAT 从站的 ESC 芯片不这么做：帧还在总线上流动时，ESC 的硬件解析逻辑已经在逐字节处理；帧经过从站的几十纳秒内，该从站要读的数据被取出、要写的数据被插入对应位置。帧不减速、不停留、不整帧缓存。

```
 主站发出一个大帧（内含所有从站的数据区）
 ═══════════════════════════════════════════════►
        │                │                │
        ▼                ▼                ▼
   ┌─────────┐     ┌─────────┐     ┌─────────┐
   │ 从站1 ESC│ ──▶ │ 从站2 ESC│ ──▶ │ 从站3 ESC│
   └─────────┘     └─────────┘     └─────────┘
   经过瞬间：       经过瞬间：       经过瞬间：
   写入速度指令     写入力矩指令     读出状态字
   读出实际位置     读出实际电流     （数据塞回帧内）

 帧绕完全网回到主站，一次周期完成全部输入输出交换
 每个从站引入的额外延迟：约 0.3 µs（纯硬件处理时间）
```

这个机制决定了 EtherCAT 的性能特征：周期时间 ≈ 帧传输时间 + Σ从站硬件延迟（每个约 0.3 µs）。延迟是算出来的，不是统计出来的——这就是"确定性"的准确含义。

一笔具体账：100 个从站、每站 8 字节过程数据、100 Mbit/s 线速。帧载荷约 100×(8+10) ≈ 1800 字节（含 Datagram 头开销），传输时间 ≈ 1800×8/100M ≈ 144 µs 双向减半约 72 µs（帧只需走一个来回），从站延迟 100×0.3 = 30 µs，合计周期下界约 100 µs 出头，抖动压在 1 µs 以内。同规模 PROFINET RT 网络典型周期 1~10 ms——两个数量级的差距来自"消灭排队"对"优先级排队"的降维。

抖动预算也要交代去处：帧传输时间是确定量（长度固定），从站硬件延迟的波动在几十 ns 级，真正的抖动来源只剩两个——主站侧发包时刻的抖动（操作系统调度，PREEMPT_RT 补丁解决，见 12.5）和 PHY/线缆引入的物理层偏移（DC 单元负责补偿）。把这两个管住，µs 级抖动就是可重复的工程指标而不是宣传数字。

## 帧结构：以太网壳里的 Datagram 序列

EtherCAT 帧就是标准 IEEE 802.3 以太网帧，Ethertype 固定 0x88A4。帧头之后是 2 字节 EtherCAT 头，然后是一个或多个 Datagram，最后是以太网 FCS：

```
 ┌────────────────────────────────────────────────┐
 │ 以太网头 14 B：目的 MAC | 源 MAC | 0x88A4        │
 ├────────────────────────────────────────────────┤
 │ EtherCAT 头 2 B：长度(11b) | 类型               │
 ├────────────────────────────────────────────────┤
 │ Datagram 1：                                    │
 │   Cmd(1B) | Idx(1B) | 地址(4B) | Len | IRQ(2B)  │
 │   数据(0~1486B)                                  │
 │   WKC(2B) ← 工作计数器                          │
 ├────────────────────────────────────────────────┤
 │ Datagram 2 … Datagram N                         │
 ├────────────────────────────────────────────────┤
 │ FCS 4 B                                         │
 └────────────────────────────────────────────────┘
 总帧长 64~1518 B（小于 64 B 由 MAC 层填充）
```

> WKC（Working Counter，工作计数器）：每个 Datagram 末尾的 2 字节计数，每有一个从站成功执行了该 Datagram 的操作就加一。主站收回帧后核对 WKC 是否等于预期值——不等于就说明有从站没响应，这是 EtherCAT 链路诊断的第一信号。

一个帧里塞多个 Datagram 是常态：一个 LRW 换周期数据、一个 BWR 发广播命令、几个 FPRD 读诊断寄存器，一次往返全部完成。带宽利用率因此远高于"一站一帧"的轮询方案。

> ⚠️
> 以太网最小帧长 64 字节，数据不足时 MAC 层自动填充。解析 EtherCAT 帧必须以头的 Len 字段为准，填充字节不是数据。自己写 ESC 固件或抓包分析时把填充当数据解读，是这一层最常见的误读。

## Datagram 寻址：三种方式的分工

Cmd 字段决定寻址方式，常用的分三类：

| 命令 | 寻址方式 | 用途 |
|:---|:---|:---|
| APRD/APWR（0x01/0x02） | 自动递增地址：帧每经过一个从站，地址计数 −1，数到 0 的从站响应 | 上电扫描：主站不知道网络里有谁，按物理顺序逐个点名 |
| FPRD/FPWR（0x04/0x05） | 配置地址：扫描阶段主站给每个从站写入一个 16 位站地址，之后按站地址访问 | 运行期的寄存器读写（状态、邮箱、DC 寄存器） |
| LRD/LWR/LRW（0x0A/0x0B/0x0C） | 逻辑地址：32 位逻辑地址空间，由 FMMU 映射到各从站的物理内存 | 周期过程数据的主力，LRW 一条命令完成读写交换 |

三类的分工对应设备生命周期的三个阶段：APRD 只在枚举期用；FPRD/FPWR 用于配置与非周期访问；LRW 跑实时循环。

> ⚠️
> APRD 依赖物理顺序：网线把从站 1 和从站 2 对调后，"第 1 个位置"读到的就是原来从站 2 的数据。运行期循环通信绝不用 APRD——枚举完成、配置地址分配完之后，一切访问切到 FPRD/LRW。多轴系统里轴序错位的后果是控制指令发错电机，这条不是风格建议，是安全约束。

## ESC：从站芯片内部

ESC（EtherCAT Slave Controller）是从站的协议硬件，MCU 不用跑协议栈。以 Beckhoff ET1100 为参照，内部四块关键资源：

```
 ┌─────────────────── ET1100 ESC ───────────────────┐
 │                                                    │
 │  Port 0~3（MII/EBUS）── 帧处理单元（解析/插入/WKC） │
 │                              │                     │
 │                    ┌─────────┴─────────┐           │
 │                    │  PDM 8 KB 双口 RAM  │           │
 │                    │  ┌──┬──┬──┬──┬──┐  │           │
 │                    │  │SM│SM│..│SM│SM│  │           │
 │                    │  └──┴──┴──┴──┴──┘  │           │
 │                    └─────────┬─────────┘           │
 │          FMMU × 8 ───────────┘（逻辑→物理地址映射）  │
 │                              │                     │
 │                    PD Interface（SPI / 8/16 位并口） │
 │                              │                     │
 │                     从站 MCU（STM32/FPGA…）          │
 │                                                    │
 │  DC 单元：64 位本地时钟（1 ns）、漂移补偿、SYNC0/1   │
 └────────────────────────────────────────────────────┘
```

- **PDM（Process Data Memory）**：双口 RAM，EtherCAT 帧处理单元从一侧读写，从站 MCU 从另一侧读写。主站与从站程序的数据交换就是对这块内存的双边访问。
- **SyncManager（SM）**：PDM 的通道管理器，把 PDM 划分成邮箱区（SM0/SM1，跑 CoE 的 SDO）和过程数据区（SM2/SM3，跑 PDO），并产生中断通知 MCU"新数据到了"。
- **FMMU**：把主站视角的 32 位逻辑地址映射到本从站 PDM 的物理偏移。LRW 能一帧访问全网从站，靠的就是各从站 FMMU 把同一段逻辑地址区间映射到各自的 PDM。
- **DC（分布式时钟）**：每个 ESC 内置 64 位本地时钟，主站通过专门的 Datagram 测量传播延迟并补偿漂移，全网对齐到亚微秒。DC 是 12.3 的主题。

常见 ESC 选型：ET1100（标杆，8 SM/8 FMMU）、AX58100（低成本、集成 PHY、寄存器兼容）、LAN9252（Microchip，SPI 接口，适合小型 IO 从站）、XMC4300/RZ/T1（MCU 内置 ESC 的单芯片方案）。从站固件侧有开源 SOES 协议栈可评估。

## CoE：CANopen 的应用层借尸还魂

ESC 的邮箱区（SM0/SM1）里跑的主力协议是 CoE（CANopen over EtherCAT）。它的含义非常直白：**11.4 学的对象字典、SDO、PDO 映射、CiA 402 状态机，原封不动搬到 EtherCAT 上**——索引 0x6040 还是控制字、0x6041 还是状态字、0x1018 还是身份条目，SDO 变成走邮箱的读写事务，PDO 映射变成配置 SM2/SM3 过程数据区里摆哪些条目。

> CoE（CANopen over EtherCAT）：把 CANopen 应用层（OD 数据模型 + SDO/PDO 服务 + 设备子协议）承载在 EtherCAT 邮箱与过程数据通道上的协议。帧传输层全换，数据模型与 API 语义全留。

工程上的直接推论：给 CiA 402 伺服换总线（CANopen → EtherCAT），应用层代码几乎不动——改的是主站栈（SocketCAN → IgH）和配置工具链（EDS → ESI 文件），控制逻辑里"写 0x6040=0x06→0x07→0x0F"的使能序列一模一样。这也是 EtherCAT 伺服生态能快速铺开的原因：应用层直接继承了 CANopen 三十年的存量。

邮箱里还住着 CoE 的两个兄弟，认识即可：FoE（File over EtherCAT）走邮箱传文件，从站固件升级的标准通道；EoE（Ethernet over EtherCAT）把标准以太网帧隧道进邮箱，用来给从站开一条 IP 通道做 Web 配置界面——三者共用邮箱，按邮箱协议号区分。周期性能只由 SM2/SM3 的过程数据通道决定，邮箱流量再忙也不影响实时循环，这是 EtherCAT"管理与实时分离"的架构红利。

> ESI 文件（EtherCAT Slave Information）：从站的 XML 设备描述，写清身份、SM/FMMU 默认配置、PDO 映射选项与 DC 能力。主站组态工具（IgH 的 ethercat XML、TwinCAT）靠它理解陌生从站——与 CANopen 的 EDS、PROFINET 的 GSDML 同位同工，三者格式互不兼容但角色一致。

## AL 状态机：从站的四段人生

EtherCAT 从站有一台与 CANopen NMT 神似的状态机，叫 AL（Application Layer）状态机，存在 ESC 的 AL Status 寄存器里。四个状态，通信能力逐级开放：

| 状态 | 邮箱（SDO） | 过程数据 | 语义 |
|:---|:---:|:---:|:---|
| INIT | ✗ | ✗ | 上电/复位态 |
| PRE-OP | ✓ | ✗ | 可配置（写 PDO 映射、参数），无实时数据 |
| SAFE-OP | ✓ | 只进不出 | 输入数据有效，**输出被强制在安全态**——过渡态 |
| OP | ✓ | ✓ | 正常工作 |

主站驱动从站逐级上行（INIT → PRE-OP → SAFE-OP → OP），每级迁移都要从站确认配置无误才放行。SAFE-OP 是最容易困惑的一格：它存在的意义是"先把输入跑起来验证链路，确认无误后再放输出"——从站卡在 SAFE-OP 时，你能读到位置反馈但电机不执行指令，这正是设计行为而不是故障。

状态迁移失败时从站会把拒绝原因写进 AL Status Code 寄存器，主站日志里的 "AL status error 0x001E" 这类行就是从这里来的——查 ETG.1000 的错误码表能直接定位是映射配置错还是同步参数错。高频三个：0x001D/0x001E（SM 配置与从站能力不符，多见于 PDO 映射超出 SM 区大小）、0x001B（看门狗超时，主站停发周期帧后被从站逮到）、0x002C（同步配置致命错）。看到错误码先查表再改配置，不要反过来猜。

从站固件侧的状态机实现不需要自己写——SOES 开源栈和 Beckhoff SSC 工具生成的代码都内置了完整的 AL 状态处理，从站开发者要填的只有"PDO 映射内容"和"状态迁移时的应用回调"两个空洞。

## 拓扑与线缆冗余

ESC 至少两个端口（Port 0 进、Port 1 出），帧自动向"下一个有链接的端口"转发，因此线型（菊花链）是天然拓扑，树型通过多端口 ESC 分叉，星型要经过交换机——交换机的存储转发会破坏飞读飞写，实时段不用星型。

线型冗余靠主站双端口实现：主站两个网口分别接线型链的两端，帧从主端口出发绕链一圈从冗余端口收回。链中间断线时，断点前的从站走正向、断点后的从站走反向，两段都仍然可达：

```
 正常：主端口 ─▶ S1 ─▶ S2 ─▶ S3 ─▶ S4 ─▶ 冗余端口

 断线（S2—S3 之间）：
   主端口 ─▶ S1 ─▶ S2   ✗   S3 ◀─ S4 ◀─ 冗余端口
   S2 检测到下行端口无链接，把帧从 Port 0 原路折返；
   主站两个端口各收半条链，拼接出完整过程数据
```

切换由 ESC 硬件自动完成，主站协议栈感知的是 WKC 变化。这条机制让线型拓扑摆脱"一处断线全链瘫痪"的弱点，是高可用设备的标配设计。

冗余不是所有产品都要上的配置，决策依据很朴素：断线的后果。教学机械臂断线急停即可，冗余是浪费；无人产线上的 24 轴伺服链断一站停全线，双端口冗余的成本远低于一次非计划停机。

## 两个观察工具：IgH 命令行与 Wireshark

IgH 主站自带的 `ethercat` 命令行是协议层的万用表。扫完一条伺服链的典型输出：

```text
# ethercat slaves
0  0:0  PREOP  +  EK1100 EtherCAT-Koppler (2A E-Bus)
1  1:0  PREOP  +  EL2008 8K. Dig. Ausgang 24V, 0.5A
2  2:0  PREOP  +  EL7041-0052 Stepper motor terminal
```

读法：首列是物理位置（APRD 顺序），`0:0` 是别名:位置格式的配置地址（FPRD 用），第三列就是 AL 状态——这里全在 PREOP，说明组态还没下发完成。启动后正常状态应全是 `OP`；哪一站卡在 `SAFEOP` 或带 `E` 错误标记，故障域就锁死了。

对象字典读写用 SDO 上传/下载，格式与 CANopen 完全同构：

```text
# ethercat upload -p 2 0x6041 0 --type uint16
0x0650 1616                          ← 读 2 号站状态字：0x0650
# ethercat download -p 2 0x6040 0 --type uint16 0x000f
                                     ← 写控制字走完使能序列的最后一步
```

抓包侧，Wireshark 内置 EtherCAT dissector，按 `eth.type == 0x88a4` 过滤后直接把帧解到 Datagram 级：每个 Datagram 的 Cmd（`LRW`）、地址、Len、WKC 都是独立字段，WKC 与预期不符的 Datagram 在专家信息里会被标黄——比人工数字节快得多。注意 PC 网卡发出的是完整帧，抓到"主站→从站"方向的帧里 WKC 恒为 0，WKC 的有效值只在环回帧里。

## 排障：协议层故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 主站扫描不到全部从站 | 链路中断、ESC 未上电、端口方向接反 | 主站日志看扫描计数；逐段查链接指示灯 |
| WKC 低于预期 | 有从站未处理该 Datagram（状态不对、映射未配） | `ethercat slaves` 看各站 AL 状态；WKC 差值=缺席站数 |
| 从站卡 SAFE-OP | 过程数据配置未完成或同步参数有误——这是设计行为 | 读 AL Status Code 查迁移拒绝原因 |
| 能读位置但电机不执行 | 在 SAFE-OP（输出被强制安全态），或 CiA 402 状态机没走完 | 查 AL 状态；读 0x6041 对使能序列 |
| 过程数据错位（轴数据串台） | 物理顺序被改动后仍用 APRD 语义理解数据 | 核对实际接线顺序与组态顺序；确认运行期用 FPRD/LRW |
| 抓到 64 字节满帧但有效数据很少 | 以太网最小帧填充被误读 | 按 EtherCAT 头 Len 字段重新解析 |
| 周期数据抖动突然变大 | 网段里混入非 EtherCAT 流量（接了普通交换机/摄像头） | 实时段物理隔离；Wireshark 过滤 0x88A4 以外的帧 |
| AL status error 0x001E 等错误码 | 配置与从站能力不匹配 | 查 ETG.1000 错误码表；比对 ESI 文件与实际从站 |
| 实测周期抖动大于预算 | 主站发包时刻抖动（OS 调度），与从站无关 | 主站打 PREEMPT_RT 补丁并用 cyclictest 验证，见 12.5 |
| 从站固件升级失败 | 邮箱被周期流量挤占或 FoE 块校验失败 | 升级前把节点切到非 OP 态；核对 FoE 传输日志 |

排障总原则：**先 AL 状态、再 WKC、最后抓包**。`ethercat slaves` 一行能把"哪几站不在 OP"直接点名，WKC 差值给出缺席站数，这两步覆盖八成协议层故障；Wireshark 留给字节级的疑难杂症。怀疑主站栈本身有问题时，用 TwinCAT 免费运行时交叉验证——同一条链路两套主站行为不一致，问题在实现；一致，问题在组态或从站。

## 本节总结

EtherCAT 的性能不是调出来的，是机制决定的：飞读飞写让帧穿过从站只花 0.3 µs 且不停车，周期时间因此可以逐站计算而非统计——这就是"确定性"三个字的准确含义，也是它比标准以太网方案抖动低三个数量级的全部原因。围绕这个核心机制，本节的知识其实是一张分工表：三种寻址对应设备生命周期的三个阶段（APRD 枚举、FPRD 配置、LRW 实时循环）；ESC 的四块资源各司其职（PDM 存数据、SM 管通道、FMMU 做逻辑地址映射、DC 对时间）；CoE 把 CANopen 的对象字典与 CiA 402 原样搬进邮箱，换总线不换应用层；AL 状态机按 INIT→PRE-OP→SAFE-OP→OP 逐级放行，SAFE-OP 的"只进不出"是保护不是故障。诊断侧记住三件套：`ethercat slaves` 点名 AL 状态、WKC 差值报缺席站数、Wireshark 解 0x88A4 到 Datagram 级——先状态、再计数、最后才抓包。下一节 12.3 把 DC 分布式时钟单独展开，多轴同步的最后一块拼图在那里。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 飞读飞写 | 帧不停车，每站 ~0.3 µs；延迟可计算=确定性 |
| 帧结构 | 0x88A4 壳内一串 Datagram；Cmd+地址+数据+WKC |
| WKC | 成功站数计数器；不等于预期=有站缺席，差值即缺席数 |
| 三种寻址 | APRD 枚举 / FPRD 配置 / LRW 循环；运行期禁用 APRD |
| ESC 四资源 | PDM 双口 RAM、SM 通道、FMMU 映射、DC 对时 |
| CoE | CANopen 应用层原样上 EtherCAT；0x6040 还是那个 0x6040 |
| AL 状态机 | INIT→PRE-OP→SAFE-OP→OP；SAFE-OP 只进不出是保护 |
| ESI 文件 | 从站 XML 描述；与 EDS/GSDML 同位同工 |
| 诊断顺序 | AL 状态 → WKC → Wireshark 抓包 |
