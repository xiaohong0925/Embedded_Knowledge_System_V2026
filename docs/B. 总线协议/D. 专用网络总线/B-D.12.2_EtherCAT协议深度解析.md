## 本节导读

12.1 给出了工业以太网版图，EtherCAT 的结论性优势是集总帧与硬件透传。本节把这个机制拆到字节级：帧怎么封装、经过从站时发生了什么、Datagram 的寻址方式有哪几种、从站芯片（ESC）内部怎么组织。读完你应该能看懂 Wireshark 抓到的 0x88A4 帧，也能解释"为什么 EtherCAT 的抖动比标准以太网低三个数量级"。

本节覆盖：飞读飞写（on-the-fly processing）的完整过程、EtherCAT 帧与 Datagram 结构、APRD/FPRD/LRW 三类寻址方式的分工、WKC 工作计数器、ESC 芯片内部架构（PDM/SyncManager/FMMU/DC）、拓扑与线缆冗余、协议层的典型误判与排障。

## 飞读飞写：帧穿过从站时不停车

标准以太网节点收到帧要整帧存储、查目的 MAC、决定是否上送——每个节点的存储转发延迟在 µs 级，且随负载波动。EtherCAT 从站的 ESC 芯片不这么做：帧还在总线上流动时，ESC 的硬件解析逻辑已经在逐字节处理；帧经过从站的几十纳秒内，该从站要读的数据被取出、要写的数据被插入对应位置。帧不减速、不停留、不整帧缓存。

```
 主站发出一个大帧（内含所有从站的数据区）
 ═══════════════════════════════════════════════►
        │                │                │
        ▼                ▼                ▼
   ┌─────────┐     ┌─────────┐     ┌─────────┐
   │ 从站1 ESC│ ──▶ │ 从站2 ESC│ ──▶ │ 从站3 ESC│
   └─────────┘     └─────────┘     └─────────┘
   经过瞬间：       经过瞬间：       经过瞬间：
   写入速度指令     写入力矩指令     读出状态字
   读出实际位置     读出实际电流     （数据塞回帧内）

 帧绕完全网回到主站，一次周期完成全部输入输出交换
 每个从站引入的额外延迟：约 0.3 µs（纯硬件处理时间）
```

这个机制决定了 EtherCAT 的性能特征：周期时间 ≈ 帧传输时间 + Σ从站硬件延迟（每个约 0.3 µs），100 个从站带 100 字节过程数据时，周期可压到 100 µs 以内且抖动 <1 µs。延迟是算出来的，不是统计出来的——这就是"确定性"的准确含义。

## 帧结构：以太网壳里的 Datagram 序列

EtherCAT 帧就是标准 IEEE 802.3 以太网帧，Ethertype 固定 0x88A4。帧头之后是 2 字节 EtherCAT 头，然后是一个或多个 Datagram，最后是以太网 FCS：

```
 ┌────────────────────────────────────────────────┐
 │ 以太网头 14 B：目的 MAC | 源 MAC | 0x88A4        │
 ├────────────────────────────────────────────────┤
 │ EtherCAT 头 2 B：长度(11b) | 类型               │
 ├────────────────────────────────────────────────┤
 │ Datagram 1：                                    │
 │   Cmd(1B) | Idx(1B) | 地址(4B) | Len | IRQ(2B)  │
 │   数据(0~1486B)                                  │
 │   WKC(2B) ← 工作计数器                          │
 ├────────────────────────────────────────────────┤
 │ Datagram 2 … Datagram N                         │
 ├────────────────────────────────────────────────┤
 │ FCS 4 B                                         │
 └────────────────────────────────────────────────┘
 总帧长 64~1518 B（小于 64 B 由 MAC 层填充）
```

> WKC（Working Counter，工作计数器）：每个 Datagram 末尾的 2 字节计数，每有一个从站成功执行了该 Datagram 的操作就加一。主站收回帧后核对 WKC 是否等于预期值——不等于就说明有从站没响应，这是 EtherCAT 链路诊断的第一信号。

一个帧里塞多个 Datagram 是常态：一个 LRW 换周期数据、一个 BWR 发广播命令、几个 FPRD 读诊断寄存器，一次往返全部完成。带宽利用率因此远高于"一站一帧"的轮询方案。

> ⚠️
> 以太网最小帧长 64 字节，数据不足时 MAC 层自动填充。解析 EtherCAT 帧必须以头的 Len 字段为准，填充字节不是数据。自己写 ESC 固件或抓包分析时把填充当数据解读，是这一层最常见的误读。

## Datagram 寻址：三种方式的分工

Cmd 字段决定寻址方式，常用的分三类：

| 命令 | 寻址方式 | 用途 |
|:---|:---|:---|
| APRD/APWR（0x01/0x02） | 自动递增地址：帧每经过一个从站，地址计数 −1，数到 0 的从站响应 | 上电扫描：主站不知道网络里有谁，按物理顺序逐个点名 |
| FPRD/FPWR（0x04/0x05） | 配置地址：扫描阶段主站给每个从站写入一个 16 位站地址，之后按站地址访问 | 运行期的寄存器读写（状态、邮箱、DC 寄存器） |
| LRD/LWR/LRW（0x0A/0x0B/0x0C） | 逻辑地址：32 位逻辑地址空间，由 FMMU 映射到各从站的物理内存 | 周期过程数据的主力，LRW 一条命令完成读写交换 |

三类的分工对应设备生命周期的三个阶段：APRD 只在枚举期用；FPRD/FPWR 用于配置与非周期访问；LRW 跑实时循环。

> ⚠️
> APRD 依赖物理顺序：网线把从站 1 和从站 2 对调后，"第 1 个位置"读到的就是原来从站 2 的数据。运行期循环通信绝不用 APRD——枚举完成、配置地址分配完之后，一切访问切到 FPRD/LRW。多轴系统里轴序错位的后果是控制指令发错电机，这条不是风格建议，是安全约束。

## ESC：从站芯片内部

ESC（EtherCAT Slave Controller）是从站的协议硬件，MCU 不用跑协议栈。以 Beckhoff ET1100 为参照，内部四块关键资源：

```
 ┌─────────────────── ET1100 ESC ───────────────────┐
 │                                                    │
 │  Port 0~3（MII/EBUS）── 帧处理单元（解析/插入/WKC） │
 │                              │                     │
 │                    ┌─────────┴─────────┐           │
 │                    │  PDM 8 KB 双口 RAM  │           │
 │                    │  ┌──┬──┬──┬──┬──┐  │           │
 │                    │  │SM│SM│..│SM│SM│  │           │
 │                    │  └──┴──┴──┴──┴──┘  │           │
 │                    └─────────┬─────────┘           │
 │          FMMU × 8 ───────────┘（逻辑→物理地址映射）  │
 │                              │                     │
 │                    PD Interface（SPI / 8/16 位并口） │
 │                              │                     │
 │                     从站 MCU（STM32/FPGA…）          │
 │                                                    │
 │  DC 单元：64 位本地时钟（1 ns）、漂移补偿、SYNC0/1   │
 └────────────────────────────────────────────────────┘
```

- **PDM（Process Data Memory）**：双口 RAM，EtherCAT 帧处理单元从一侧读写，从站 MCU 从另一侧读写。主站与从站程序的数据交换就是对这块内存的双边访问。
- **SyncManager（SM）**：PDM 的通道管理器，把 PDM 划分成邮箱区（SM0/SM1，跑 CoE 的 SDO）和过程数据区（SM2/SM3，跑 PDO），并产生中断通知 MCU"新数据到了"。
- **FMMU**：把主站视角的 32 位逻辑地址映射到本从站 PDM 的物理偏移。LRW 能一帧访问全网从站，靠的就是各从站 FMMU 把同一段逻辑地址区间映射到各自的 PDM。
- **DC（分布式时钟）**：每个 ESC 内置 64 位本地时钟，主站通过专门的 Datagram 测量传播延迟并补偿漂移，全网对齐到亚微秒。DC 是 12.3 的主题。

常见 ESC 选型：ET1100（标杆，8 SM/8 FMMU）、AX58100（低成本、集成 PHY、寄存器兼容）、LAN9252（Microchip，SPI 接口，适合小型 IO 从站）、XMC4300/RZ/T1（MCU 内置 ESC 的单芯片方案）。从站固件侧有开源 SOES 协议栈可评估。

## 拓扑与线缆冗余

ESC 至少两个端口（Port 0 进、Port 1 出），帧自动向"下一个有链接的端口"转发，因此线型（菊花链）是天然拓扑，树型通过多端口 ESC 分叉，星型要经过交换机——交换机的存储转发会破坏飞读飞写，实时段不用星型。

线型冗余靠主站双端口实现：主站两个网口分别接线型链的两端，帧从主端口出发绕链一圈从冗余端口收回。链中间断线时，断点前的从站走正向、断点后的从站走反向，两段都仍然可达：

```
 正常：主端口 ─▶ S1 ─▶ S2 ─▶ S3 ─▶ S4 ─▶ 冗余端口

 断线（S2—S3 之间）：
   主端口 ─▶ S1 ─▶ S2   ✗   S3 ◀─ S4 ◀─ 冗余端口
   S2 检测到下行端口无链接，把帧从 Port 0 原路折返；
   主站两个端口各收半条链，拼接出完整过程数据
```

切换由 ESC 硬件自动完成，主站协议栈感知的是 WKC 变化。这条机制让线型拓扑摆脱"一处断线全链瘫痪"的弱点，是高可用设备的标配设计。

## 排障：协议层故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 主站扫描不到全部从站 | 链路中断、ESC 未上电、端口方向接反 | 主站日志看扫描计数；逐段查链接指示灯 |
| WKC 低于预期 | 有从站未处理该 Datagram（状态不对、映射未配） | `ethercat slaves` 看各站 AL 状态；WKC 差值=缺席站数 |
| 过程数据错位（轴数据串台） | 物理顺序被改动后仍用 APRD 语义理解数据 | 核对实际接线顺序与组态顺序；确认运行期用 FPRD/LRW |
| 抓到 64 字节满帧但有效数据很少 | 以太网最小帧填充被误读 | 按 EtherCAT 头 Len 字段重新解析 |
| 周期数据抖动突然变大 | 网段里混入非 EtherCAT 流量（接了普通交换机/摄像头） | 实时段物理隔离；Wireshark 过滤 0x88A4 以外的帧 |

排障工具：IgH 主站自带的 `ethercat` 命令行（`ethercat slaves` 列从站状态、`ethercat upload/download` 读写对象字典）、Wireshark 的 EtherCAT dissector（直接解 0x88A4 帧到 Datagram 级）、TwinCAT 免费运行时做交叉验证。
