## 本节导读

带音频功能的嵌入式板子——语音对讲、流媒体播放、麦克风采集——SoC 与 Codec 芯片之间的数字音频接口几乎是必答题。I2S 和 PCM/TDM 是这个领域最常见的两种接口形态。

> Codec（编解码器芯片）：音频链路上负责模数/数模转换的专用芯片。内部含 ADC（模拟→数字）、DAC（数字→模拟）、混音器、功放驱动，通过 I2S/PCM 与 SoC 交换数字音频流，通过 I2C/SPI 接受控制（音量、增益、开关）。WM8960、TLV320AIC3104 是嵌入式板卡上的常客。音频链路永远是"两总线"结构：数据走 I2S，控制走 I2C——调试时先分清问题在哪条总线上。

本节回答四个底层问题：信号线有哪几根、各起什么作用；四种 I2S 模式在时序上差在哪；采样率/位深度/主时钟怎么配；TDM 怎样在一根数据线上传多路音频。

> 本节覆盖：I2S 三线+MCLK 的信号定义与频率关系、MCLK 缺席的故障形态、Philips 标准模式的识别签名、左对齐/右对齐/DSP 四模式对比、采样率与位深度的工程取值与动态范围账、PCM 线性编码与 A-law/μ-law 压缩、TDM 时分复用帧结构与走线约束、音频物理层的典型排障。按"信号 → 时序 → 时钟 → 编码 → 多通道 → 排障"展开——这正是你拿到一颗陌生 Codec 手册时的阅读顺序。

读完你应该能对着一份陌生 Codec 的数据手册，把 I2S 接线和时钟配置做对。

## I2S 信号线

I2S（Inter-IC Sound，Philips 1986 年定义）传立体声只需要三根信号线，实际系统通常再加一根主时钟：

| 信号 | 常见别名 | 方向 | 频率 | 作用 |
|:---|:---|:---|:---|:---|
| BCLK | SCLK、SCK | 主 → 从 | Fs × 位深 × 通道数 | 位时钟，每个数据位一个周期 |
| LRCK | WS、FS、WCLK | 主 → 从 | = Fs | 帧/声道时钟，标识左右声道 |
| SD | SDIN/SDOUT、DIN/DOUT | 依方向 | 跟随 BCLK | 串行音频数据，MSB 在前 |
| MCLK | SCKI、SYSCLK | 主 → 从 | 256×Fs 或 384×Fs | Codec 内部 ADC/DAC 的工作时钟 |

> MSB / LSB（Most/Least Significant Bit，最高/最低有效位）：一个二进制数里权重最大/最小的位。I2S 数据 MSB 在前（先传高位），音频模式的全部差异都可以归结为"MSB 出现在什么时刻"这一个问题的不同答案。

厂商命名不统一是常态：BCLK 可能叫 SCLK，LRCK 可能叫 WS，数据线可能拆成 SDIN/SDOUT 两根。接陌生芯片时以数据手册的**时序图**为准，不以引脚名为准——名字是厂商的营销自由，时序图是物理事实。

### 谁当时钟主：方向不是固定的

默认叙事是"SoC 是主、Codec 是从"——BCLK/LRCK 由 SoC 发出。但实际系统里两种角色都存在：

- **SoC 主**（常见）：SoC 的音频控制器产生 BCLK/LRCK/MCLK，Codec 跟随。
- **Codec 主**：Codec 用自己的晶振/PLL 产生 BCLK/LRCK，SoC 跟随。高精度录音链路常这么干——Codec 的低抖动晶振比 SoC 的 PLL 输出干净，让时钟质量最好的那边当主。代价是 SoC 侧采样率只能跟随 Codec，灵活性下降。

设备树里这对应 `bitclock-master` / `frame-master` 属性（D.13.2 展开）。调试时钟类故障前先确认这条链上谁是主——**两边都配成主（互相等对方发时钟）和都配成从（没人发时钟）都是"无声"的经典形态**。

### 为什么音频不用 SPI/UART

一个自然的疑问：SPI 也是时钟+数据线，为什么不能传音频？答案是**时序语义**：SPI 的数据帧是"事务式"的（片选拉起就开始，时钟可以停顿），音频流是"等时"的——BCLK/LRCK 必须永不间断地按精确频率运行，数据流的"时间"本身就是信息（采样间隔）。SPI 时钟停一拍只是慢一拍，I2S 时钟停一拍是一个爆音点。UART 同理（异步、无时钟线）。这也是为什么音频接口独立成标准而不是复用通用串口。

MCLK 不在 I2S 原始标准里，但实际系统几乎都需要：Codec 内部的 Σ-Δ 调制器需要远高于 BCLK 的时钟。

> Σ-Δ 调制器（Sigma-Delta Modulator）：现代音频 ADC/DAC 的核心。它不以 48 kHz 直接采样，而是用高得多的频率（几 MHz）做 1~4 bit 的粗采样，再用数字滤波器把噪声"整形"到可闻频段之外、抽取回标准采样率。这个"过采样"结构要求一颗几十~上百倍 Fs 的高速时钟——MCLK 就是给它喂的。这也解释了为什么 MCLK 的频率精度直接决定底噪与失真：它是整个模拟性能的时钟地基。

> ⚠️
> MCLK 必须是采样率的整数倍，常用 256×Fs（48 kHz → 12.288 MHz）。给一个不整除的时钟（比如随手给 12 MHz），Codec 内部 PLL 锁不住，故障表现是"驱动加载正常、寄存器读写正常、就是不出声"——没有报错信息是它最难查的原因。发现 I2S 一切配置正确却无声，第一件事量 MCLK 频率。

## Philips 标准模式时序

标准模式（I2S 模式）的定义特征：LRCK 低电平期间传左声道、高电平期间传右声道；数据在 BCLK 下降沿变化、上升沿采样；**MSB 比 LRCK 跳变沿延迟 1 个 BCLK 周期**出现。

```text
 BCLK  ─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌
        └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘

 LRCK  ──────────┐                             ┌──────────
                  └──────────────左(低)─────────┘ 右(高)

 SD    ────────┐   ┌───┬───┬─···─┬───┐
               └───┘MSB│D22│     │LSB│
                    ↑
              LRCK 变沿后第 2 个 BCLK 才出现 MSB
              （第 1 个 BCLK 是标志位的"空隙"）
```

"延迟 1 个 BCLK"是 Philips 模式的识别签名，也是它的设计意图：LRCK 跳变当拍，接收方先用一个 BCLK 周期判断"这拍是左还是右"，下一拍才开始收数据——1986 年的逻辑电路需要这个准备时间。后来的模式（左对齐）取消了这个延迟，于是四种模式的分歧点就落在"MSB 与 LRCK 边沿的相对关系"上。

模式配错时，发送方按标准模式发、接收方按左对齐收，结果是数据整体错位 1 位——听感上是严重的杂音或音量异常，波形上看所有采样值都差一个比特位。

## 四种模式对比

| 模式 | LRCK 极性 | 数据对齐 | MSB 出现位置 | 常见于 |
|:---|:---|:---|:---|:---|
| Philips 标准 | 低=左，高=右 | MSB 延迟 1 BCLK | LRCK 变沿后第 2 个 BCLK | 多数 Codec 默认 |
| 左对齐（LJ） | 高=左，低=右 | MSB 对齐 LRCK 变沿 | 变沿当拍 | 部分日系/ADC 芯片 |
| 右对齐（RJ） | 低=左，高=右 | LSB 对齐 LRCK 尾沿 | 由位深决定 | 早期设备，现少用 |
| DSP（PCM A/B） | 短脉冲 | 脉冲触发后连续 | 脉冲后第 1（A）/第 2（B）个 BCLK | TDM 多通道 |

DSP 模式下 LRCK 退化为一个 BCLK 宽的帧同步脉冲，数据从脉冲后紧跟的时隙开始连续排列，不分左右——它是为 TDM 多通道准备的形式。

SoC 侧和 Codec 侧各有一个模式配置寄存器，两边必须一致。Linux 里这个配置在设备树的 `dai-format` 属性（`i2s` / `left_j` / `right_j` / `dsp_a` / `dsp_b`），D.13.2 展开驱动侧的完整配置链。

> 💡
> 读手册时的一个陷阱：有些 Codec 手册的时序图画的是**接收视角**（本芯片何时采样），有些是**发送视角**（本芯片何时驱动）。判断依据是看数据沿标注的是 setup/hold（采样方语言）还是 output delay（发送方语言）。两边都按自己视角配，合起来错一位——"错位 1 位"故障有相当一部分是这么来的。

## 采样率与位深度

| 采样率 | 典型用途 |
|:---|:---|
| 8 kHz | 电话语音、对讲 |
| 16 kHz | 宽带语音、语音识别前端 |
| 44.1 kHz | CD/消费音乐 |
| 48 kHz | 专业音频与嵌入式首选（时钟好分频、DSP 好算） |
| 96/192 kHz | 高解析音频，对时钟抖动敏感，嵌入式少见 |

采样率的物理边界是奈奎斯特定理：可表示的最高频率是采样率的一半（48 kHz → 24 kHz，已覆盖人耳 20 kHz 上限）。选 48 kHz 而不是 44.1 kHz 的工程理由：48 k 的时钟链（12.288 MHz = 48 k×256）在晶振和 PLL 里好分频，专业音频设备全按它设计，时钟抖动容差更友好。

> 时钟抖动（Jitter）：时钟边沿相对理想时刻的随机偏移。音频里抖动的后果直接可听——采样时刻偏移转化为采样值误差，表现为底噪升高与高频细节模糊。96/192 kHz 高解析音频对抖动敏感（同样的时间偏移占采样周期的比例更大），所以高保真场景对 MCLK 晶振和 PLL 质量的要求陡增。嵌入式语音/对讲场景（8/16 kHz）对抖动不敏感，普通晶振够用。

位深度决定动态范围——每多 1 bit 约 6 dB：

| 位深 | 动态范围 | 定位 |
|:---|:---|:---|
| 16 bit | 约 96 dB | 底线，CD 标准 |
| 24 bit | 约 144 dB | 当前主流，余量给到模拟前端 |
| 32 bit | 约 192 dB | 多为内部处理位宽（DSP 防溢出），接口少见 |

> 动态范围（Dynamic Range）：系统能表示的最大不失真信号与底噪之比，单位 dB。人耳的痛阈到可闻下限约 120 dB——16 bit 的 96 dB 对消费播放够用，24 bit 的余量是给录音链路留的（话筒信号幅度不可预知，留足余量防止爆音削波）。

BCLK 频率跟着算：48 kHz × 24 bit × 2 声道 = 2.304 MHz；TDM 8 通道 32 bit 则到 12.288 MHz。

把整条时钟链串起来看一个 48 kHz/24bit/立体声系统的完整算例：

```text
晶振/PLL：12.288 MHz（= 48 kHz × 256，MCLK 基准）
  │
  ├─→ MCLK  = 12.288 MHz ──────→ Codec Σ-Δ 调制器/内部滤波
  ├─→ BCLK  = MCLK ÷ 5.333…? 不对——BCLK 由音频控制器独立分频：
  │           48 kHz × 24 × 2 = 2.304 MHz
  └─→ LRCK  = BCLK ÷ 48 = 48 kHz（每帧 = 一次立体声采样）
```

注意 BCLK 与 MCLK 是**两条独立的分频链**（MCLK 给 Codec 模拟核，BCLK/LRCK 给数字接口），它们之间的比率不必是整数——但都必须从同一个基准导出，否则两边时钟漂移不同步，长时录音会出现周期性的样本丢失/重复（听感是每几秒一声轻"咔"）。这是"两个独立晶振各供各的"方案的隐蔽缺陷。

## PCM 与 A-law/μ-law

I2S 上传的就是 PCM（脉冲编码调制）样本：固定频率采样、线性量化、按时间串行。"线性"指量化台阶均匀——样本值与真实幅度成正比。

PCM 的三步生成过程值得明确定义，后文的参数选择都是对它的取舍：

```text
模拟波形 ──采样──▶ 离散时刻的幅度序列 ──量化──▶ 整数样本流 ──编码──▶ 二进制格式
          （Fs 决定）                    （位深决定台阶数）      （线性/A-law…）
```

- **采样**：每隔 1/Fs 取一次幅度。Fs 决定可表示的频率上限（奈奎斯特）。
- **量化**：把连续幅度取整到最近的台阶。位深 n → 2ⁿ 个台阶；量化误差构成底噪，每 bit 约 6 dB 动态范围就是这么来的。
- **编码**：样本以补码形式按 MSB 在前串行发出——负数样本的最高位是符号位，排障时若波形"半周正常半周乱"，先怀疑符号位解释错了（有符号/无符号配反）。

电话语音场景有一条节省带宽的老优化：语音带宽只有 300~3400 Hz，用对数压缩把 13/14 bit 线性 PCM 压成 8 bit——小信号细分、大信号粗分，恰好匹配人耳对小信号敏感的特性（响度感知本身是对数关系的）：

| 编码 | 输入 | 输出 | 使用地区 |
|:---|:---|:---|:---|
| A-law | 13~14 bit 线性 | 8 bit | 欧洲、中国、国际线路 |
| μ-law | 14 bit 线性 | 8 bit | 北美、日本 |

做电话网关/SIP 终端会遇到这两种格式，ALSA 里对应 `SNDRV_PCM_FMTBIT_A_LAW` / `_MU_LAW`。线性转压缩用查表即可，不需要自己推公式。8 kHz × 8 bit = 64 kbps——这就是经典电话信道"64k"的由来，G.711 标准至今是 VoIP 的保底编码。

## TDM：一根线上的多通道

TDM（时分复用）把一帧分成多个时隙，每个时隙传一个通道，一根 SD 线走 8/16 路音频。帧同步变为脉冲（FSYNC），通道按时隙顺序排列：

```text
 BCLK  ─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌
        └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘

 FSYNC ──┐
         └─┘ ← 每帧一个脉冲，标记时隙 0 开始

 SD    ──┬─ 时隙0：Ch0 MSB···LSB ─┬─ 时隙1：Ch1 MSB···LSB ─┬─···─┬─ Ch7 ─┬─
         └──────────────── 一帧 = 1/Fs ─────────────────────────┘
```

> 时分复用（TDM，Time-Division Multiplexing）：多路信号共享一条物理通道的通用方法——时间切成等长时隙，各路轮流占用。TDM 的概念在通信系统里反复出现（E1/T1 电话干线、车载 SerDes 的反向通道都属此类），I2S 的 TDM 模式是它在音频领域的实例。

常见组合（Fs = 48 kHz）：

| 通道 × 位深 | BCLK | 应用 |
|:---|:---|:---|
| 2 × 16 | 1.536 MHz | 普通立体声 |
| 4 × 16 | 3.072 MHz | 车载四通道 |
| 8 × 16 | 6.144 MHz | 会议麦克风阵列 |
| 8 × 32 | 12.288 MHz | 高端音频接口 |

BCLK 上到 12 MHz 量级后，PCB 走线开始影响信号：DATA 与 BCLK 尽量短（<10 cm）、等长，过长走线的串扰表现为某几个通道低位随机出错——听感是爆裂杂音。解决手段：缩短线长、降低驱动强度、必要时接收端加端接。

多 Codec 共享 TDM 总线是阵列产品的标准做法：4 颗双通道 Codec 挂同一条 TDM 总线，各自只在自己的时隙驱动数据线，其余时隙输出高阻。**时隙分配表（哪颗芯片占哪几个 slot）是这个设计的核心文档**，两边配置错一个 slot，听感就是通道串台。

## 排障：音频物理层故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 完全无声，驱动无报错 | MCLK 未输出或频率不对（PLL 失锁） | 示波器/频率计量 MCLK 引脚 |
| 有声音但全是杂音/音量异常 | 模式不匹配（I2S vs LJ），数据错位 1 位 | 示波器看 LRCK 与 MSB 的相对位置 |
| 左右声道互换 | LRCK 极性理解反了 | 发单声道测试音定位 |
| 声音周期性卡顿 | BCLK 频率错（时钟树分频不对） | 量 BCLK 实际频率对比理论值 |
| 只有特定通道有杂音 | TDM 走线串扰或时隙配置错位 | 降 BCLK 验证；核对两边 slot 配置 |
| 高音内容失真 | 采样率配置与实际流不符（48k 流按 44.1k 播） | aplay -v 看硬件实际参数 |
| 通道间串台 | TDM slot 分配表两边不一致 | 逐通道发测试音定位错位偏移 |
| 底噪大、高频模糊 | MCLK 抖动超标（高采样率场景） | 换低抖动晶振/PLL 对比验证 |

`aplay -v`（放音时打印硬件参数）是软侧第一工具：它显示实际生效的采样率、格式、通道数——**"配置的"和"生效的"不一定是同一组值**，ALSA 会做格式转换，物理层问题定位前要先用它确认链路参数真的落到了硬件上。一份典型输出：

```text
Playing WAVE 'test.wav' : Signed 16 bit Little Endian, Rate 44100 Hz, Stereo
Hardware PCM card 0 'wm8960-audio' device 0 subdevice 0
Its setup is:
  stream       : PLAYBACK
  access       : RW_INTERLEAVED
  format       : S16_LE            ← 实际落到硬件的样本格式
  rate         : 44100             ← 实际生效的采样率
  channels     : 2
  period_size  : 1024              ← 每次硬件中断搬运的帧数
  buffer_size  : 4096              ← 环形缓冲总帧数 = 4 个周期
```

逐字段看三个要点：

- **第一行是文件参数，setup 块才是硬件参数**——两者不同说明 ALSA 中间做了转换（rate 插件重采样）。若文件 44.1 kHz 而硬件不支持该档，转换插件会把 44.1k 重采样到 48k，听起来"快了一点/音调不对"的故障根源就在这里。
- **period_size/buffer_size 决定延迟与欠载余量**：buffer 4096 帧 @44.1 kHz ≈ 93 ms 缓冲。播放出现周期性破音/欠载（underrun）时，第一手段是加大 buffer（`-B` 参数）换稳定性，代价是延迟增大——对讲类实时应用反而要调小。
- **format 与 Codec 位深不匹配会被静默转换**：S24_LE 的流喂给只支持 S16 的 Codec，ALSA 自动截位——不报错，但动态范围悄悄缩水。链路参数"以硬件实际生效为准"，这就是这条纪律的操作含义。

## 本节总结

I2S 的全部知识可以收束成一条主线：**这是一组用三根线+一根主时钟传 PCM 样本流的简单接口，复杂度全在"模式"和"时钟"两处**。模式差异归结为"MSB 相对 LRCK 边沿出现在哪一拍"，四种模式一张表；时钟的纪律是 MCLK 必须为 Fs 整数倍（256×Fs 是基准），它供 Codec 内部 Σ-Δ 调制器，给错频率的典型形态是"一切正常就是无声"。TDM 把一帧切成时隙实现单线多通道，BCLK 频率上去后 PCB 走线开始成为变量。排障三板斧：无声量 MCLK、杂音看模式错位、串台查 slot 分配表。掌握这些，加上 D.13.2 的 ALSA/设备树配置链，音频链路的软硬件就齐了。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 信号 | BCLK/LRCK/SD 三根+MCLK；两总线结构（I2S 数据+I2C 控制） |
| 模式签名 | Philips=MSB 延迟 1 BCLK；LJ=同拍；DSP=窄脉冲+TDM |
| 时钟纪律 | MCLK=256×Fs 起步；无声先量 MCLK |
| 位深账 | 每 bit ≈ 6 dB；16 底线、24 主流、32 内部处理 |
| A-law/μ-law | 电话 64 kbps 的由来；查表转换，中欧 A、美日 μ |
| TDM | 一帧多时隙一线多路；slot 分配表是核心文档 |
