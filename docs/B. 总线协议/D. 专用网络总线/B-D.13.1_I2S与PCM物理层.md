## <span class="blue"> 本节导读

你正在开发一块带音频功能的嵌入式板子——也许是语音对讲机，也许是流媒体播放器，也许是带麦克风的工业网关。板子上的Codec芯片和SoC之间该用什么接口？走几根线？时钟怎么配？采样率选多少？位深度多大？

本节回答这些底层问题。I2S和PCM是嵌入式音频领域最常见的两种数字音频接口。我们会从物理信号线开始，详细拆解I2S的四种工作模式，用ASCII时序图让你直观看到数据怎么在时钟边沿上"流"过去；然后介绍PCM的A-law/μ-law压缩和TDM时分复用——这在电话语音和多通道音频采集场景中非常关键。学完本节，你应该能对着Codec芯片的数据手册， confidently 配出正确的I2S接线，并理解每一根时钟线的作用。

## <span class="blue"> 知识点352 [I] I2S总线：3线标准与四种模式

### I2S信号线

I2S（Inter-IC Sound）是飞利浦在1986年定义的数字音频接口标准。它只需要**3根数据线**就能传输立体声：

| 信号线 | 别名 | 方向 | 频率 | 说明 |
|:---:|:---:|:---:|:---|:---|
| BCLK | SCLK / Bit Clock | 主→从 | Fs × 位深度 × 通道数 | 位时钟，每个数据位一个周期 |
| LRCK | WS / FS | 主→从 | Fs（采样率） | 帧时钟，低=左声道，高=右声道 |
| DATA | SD / DIN/DOUT | 主→从或从→主 | 跟随BCLK | 串行音频数据，MSB在前 |
| MCLK | 主时钟（可选） | 主→从 | 256×Fs 或 384×Fs（常见） | Codec内部DAC/ADC工作时钟 |

> 💡 **提示**：不同厂商叫法不同→BCLK=SCLK，LRCK=WS=FS，DATA=SD→**看时序图确认**！不要只看名字，有些国产Codec会把LRCK标成WS，DATA标成SDIN/SDOUT。最稳妥的方法是打开数据手册的时序图章节，核对边沿关系。

<br>

MCLK虽然不在I2S标准的三线定义内，但实际开发中几乎总是需要。Codec内部的Σ-Δ调制器和数字滤波器需要一个高频主时钟来工作，而BCLK只到几MHz，不够用。

> ⚠️ **陷阱**：MCLK必须是采样率的**整数倍**→常见配置MCLK = 256×Fs。如果MCLK和采样率不对齐，Codec内部PLL无法锁定→I2S**不工作**！比如48kHz采样率对应MCLK = 12.288MHz。如果你拍脑袋给个12MHz，很多Codec会直接罢工，dmesg里可能都看不到报错，就是不出声。

<br>

### I2S标准模式（Philips模式）

标准模式下，LRCK低电平表示正在传输**左声道**，高电平表示**右声道**。数据在BCLK的**下降沿发送**，接收方在**上升沿采样**。注意一个细节：数据比LRCK边沿**延迟1个BCLK周期**，MSB在第2个BCLK周期出现。

```
         ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
BCLK   ──┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───

LRCK   ─────────┐                               ┌──────────────────────────
（WS）            └───────────────────────────────┘
                 └──── 左声道(LOW) ────┘└──── 右声道(HIGH) ────┘

DATA   ────┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
（SD）      └───┘MSB│   │   │   │   │   │   │LSB│   └───┘MSB│   │   │
                   D23 D22 D21 D20 ... D1  D0             D23 D22...
                 ↑                                        ↑
           延迟1个BCLK                               右声道开始

         └── 1个BCLK延迟 →┘
         ├────────── 左声道数据(24bit示例) ────────────┤
```

上图展示了一个24bit位深度、1帧=左声道+右声道的时序。标准模式的关键识别特征是：**LRCK变后，DATA空等1个BCLK才发MSB**。这个延迟是Philips I2S的标志性特征，也是最容易搞错的地方。

<br>

### 四种I2S模式对比

嵌入式Codec通常支持多种I2S变体。你需要根据SoC和Codec的实际支持情况来匹配。

| 模式 | LRCK极性 | 数据对齐 | MSB位置 | 典型应用 |
|:---:|:---:|:---:|:---:|:---|
| **标准模式** (Philips I2S) | 低=左，高=右 | MSB延迟1 BCLK | LRCK变后第2个BCLK | 通用立体声，多数Codec默认 |
| **左对齐模式** (Left Justified) | 高=左，低=右 | MSB与LRCK边沿对齐 | LRCK变的同1个BCLK | 日系Codec，部分ADC |
| **右对齐模式** (Right Justified) | 低=左，高=右 | LSB与LRCK尾部对齐 | 距LRCK变沿N个BCLK | 索尼PDIF接口，早期设备 |
| **DSP模式** (PCM Mode A/B) | 脉冲/电平 | 脉冲触发后连续 | 脉冲后第1/2个BCLK | 多通道TDM，车载音频 |

标准模式和左对齐模式是最常用的两种，它们的主要区别在于：

- **标准模式**：MSB晚1个BCLK出现，有个"空隙"
- **左对齐模式**：MSB紧贴着LRCK边沿，没有延迟，日韩系SoC常用

DSP模式则是一种特殊的类PCM模式，LRCK变为一个**短脉冲**（而不是整个半周期的高/低电平），脉冲出现意味着新一帧开始。这种模式主要用在多通道时分复用（TDM）场景中，后面会讲到。

<br>

### 左对齐模式时序

```
         ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
BCLK   ──┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───

LRCK   ─────────┐                               ┌──────────────────────────
（WS）            └───────────────────────────────┘
                 └──── 左声道(HIGH) ────┘└──── 右声道(LOW) ────┘
                 ↑
DATA   ────┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
（SD）      └───┘MSB│D22│D21│...│D1 │D0 │   └───┘MSB│D22│D21│
                 ↑                                        ↑
           MSB紧贴LRCK边沿                          右声道开始
```

注意左对齐模式LRCK极性跟标准模式**相反**（高=左声道），而且MSB和LRCK边沿之间没有延迟。

<br>

### 采样率与应用

| 采样率 | 应用场景 | 备注 |
|:---:|:---|:---|
| 8 kHz | 电话语音、对讲机、GSM | 人声音质，带宽4kHz |
| 16 kHz | 宽带语音、VoIP、语音识别 | 清晰度优于8kHz |
| 32 kHz | 广播AM质量、部分对讲 | 较少使用 |
| 44.1 kHz | CD音频 | 历史遗留，源自PAL视频行频 |
| 48 kHz | 专业音频、影视制作、大多数嵌入式设备 | 推荐首选，DSP计算方便 |
| 96 kHz | 高解析度音频、录音棚 | USB带宽和CPU开销翻倍 |
| 192 kHz | 发烧级音频、专业录音 | 需要高质量时钟源，线材要求高 |

嵌入式设备最常用的是**8kHz**（语音）和**48kHz**（通用音频）。44.1kHz主要出现在消费类音乐播放器。高于48kHz的采样率在嵌入式场景中较少见，因为对时钟抖动（jitter）要求高，且会增加不小的DSP运算负担。

位深度方面，**16bit**是最基础的支持（CD质量动态范围约96dB），**24bit**是目前主流（动态范围约144dB），**32bit**多为内部浮点处理使用，实际DAC/ADC的有效位一般到不了32bit。

## <span class="blue"> 知识点353 [I] PCM：脉冲编码调制与TDM

### 什么是PCM

PCM（Pulse Code Modulation，脉冲编码调制）是数字音频的**基础编码方式**：把模拟声音信号按固定频率采样，每个样本量化为数字值，按时间顺序串行传输。I2S传输的数据本质上就是PCM编码的音频样本。

在嵌入式语音通信中，有一个关键优化——**压缩编码**。电话语音带宽只有300~3400Hz，但14bit线性PCM每个样本要2字节。为了节省带宽，ITU-T定义了对数压缩：

| 编码方式 | 输入 | 输出 | 动态范围 | 主要应用地区 |
|:---:|:---:|:---:|:---:|:---|
| A-law | 14bit线性PCM | 8bit | 约72dB | 欧洲、中国、国际线路 |
| μ-law | 14bit线性PCM | 8bit | 约72dB | 北美、日本 |

A-law和μ-law用8bit编码实现了14bit线性PCM的动态范围，靠的就是**非线性量化**：对小信号细分（量化步长小），对大信号粗分（量化步长大）。人耳对小信号更敏感，这个策略恰好利用了听觉特性。

> 💡 **提示**：Linux ALSA框架中，A-law对应的格式常量是`SNDRV_PCM_FMTBIT_A_LAW`（MULAW类似）。如果你的设备做电话网关或SIP终端，很可能需要处理这两种格式。在socket发送前用tinycompress或GStreamer做一次格式转换即可。

转换公式（A-law）：
- 对13bit线性值x（归一化到±1），先取绝对值|x|
- 用分段线性近似对数曲线，压缩为8bit（1位符号 + 3位段落 + 4位段内偏移）
- 接收端通过查表或公式还原为13/14bit线性值

<br>

### TDM：时分复用多通道

TDM（Time Division Multiplexing）是I2S的"升级版"——用**一帧内多个数据时隙**来传输多个通道的音频。一根DATA线可以传8路、16路甚至32路音频。

典型TDM帧结构：

```
         ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
BCLK   ──┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───┘   └───

FSYNC  ──┐                                                               ┌─
         └───┘
         ↑帧同步脉冲（每帧1个，标记第0通道开始）

DATA   ────┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
（SD）      └───┘Ch0│Ch0│...│Ch0│Ch1│Ch1│...│Ch1│...│Ch7│Ch7│...│Ch7│
                 MSB      LSB  MSB      LSB      ...  MSB      LSB
         ├── 通道0时隙 ──┤├── 通道1时隙 ──┤...├── 通道7时隙 ──┤
         └──────────────── 1帧(1/BCLK_rate) ──────────────────────────────┘
```

这是一个**TDM 8通道**的时序示例。FSYNC（帧同步）每帧发一个脉冲，脉冲后依次排列8个通道的数据时隙。每个时隙的位深度可以是16bit、24bit或32bit。

TDM常见配置：

| 通道数 | 位深度 | BCLK频率(@48kHz) | 典型应用 |
|:---:|:---:|:---:|:---|
| 2 | 16bit | 1.536 MHz | 标准立体声I2S |
| 4 | 16bit | 3.072 MHz | 车载4通道 |
| 8 | 16bit | 6.144 MHz | 会议麦克风阵列、楼宇对讲 |
| 8 | 32bit | 12.288 MHz | 高端音频接口 |
| 16 | 16bit | 12.288 MHz | 大型会议系统、广播调音台 |

DSP模式（模式A/B）就是为TDM设计的。模式A中数据在FSYNC脉冲后的**第1个BCLK**开始，模式B则**延迟1个BCLK**（类似标准I2S的延迟概念）。选择哪种模式取决于你的SoC I2S控制器和Codec支持什么。

> ⚠️ **陷阱**：TDM 8通道下，BCLK跑到12.288MHz，对PCB走线要求很高。DATA和BCLK线长要尽量短（建议<10cm），最好等长。如果走线过长，BCLK上升沿被DATA线串扰，会导致某几个通道的LSB随机出错——听起来就是"杂音"或"爆裂声"。解决这个问题要么缩短走线，要么降低BCLK驱动强度并在接收端加RC端接。

## <span class="blue"> 本节总结

| 项目 | 要点 |
|:---|:---|
| I2S核心线 | BCLK(位时钟) + LRCK(帧时钟/WS) + DATA(串行数据)，可选MCLK(主时钟) |
| MCLK | 必须是Fs整数倍，常用256×Fs，不对齐则Codec不工作 |
| 标准模式 | MSB延迟1 BCLK，LRCK低=左声道；最常用，多数Codec默认 |
| 左对齐 | MSB紧贴LRCK边沿，日系Codec常用；注意LRCK极性相反 |
| 右对齐 | LSB对齐LRCK尾部，较老旧；LSB位置固定位深度决定 |
| DSP模式 | LRCK为脉冲触发，用于TDM多通道场景 |
| PCM编码 | 8/16/24/32bit线性PCM；A-law/μ-law 8bit压缩用于电话语音 |
| TDM | 一帧内分多个时隙，支持8/16通道；注意高频BCLK走线质量 |
| 关键陷阱 | 模式不匹配→无声音；MCLK不对齐→PLL失锁；TDM走线长→串扰杂音 |
