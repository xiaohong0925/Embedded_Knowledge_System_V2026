# B-D.14.1 车载以太网与 TSN

## 本节导读

汽车电子架构正在从"几十个 ECU 各自挂 CAN"转向"少数几个域控制器 + 车载以太网主干"。驱动力是数据量：激光雷达点云、多路摄像头、OTA 固件包，CAN FD 的 8 Mbps 完全不够看。但车载环境对以太网提出了两个特殊要求：单对双绞线（减重降成本）和确定性时延（控制流量不能被娱乐流量挤占）。前者的答案是 100BASE-T1/1000BASE-T1，后者的答案是 TSN。本节讲清这两条技术线，以及它们与 D.12 工业以太网的关系。

本节覆盖：车载以太网相对工业/商用以太网的差异、100BASE-T1 与 1000BASE-T1 物理层、车载架构演进（分布式→域→中央计算）、TSN 子标准族（时间同步/调度/抢占/整形）、SOME/IP 与 DoIP 应用层、Linux 侧 TSN 支持现状、车载以太网项目的常见认知误区。

## 车载以太网与商用以太网的差异

| 维度 | 商用以太网（1000BASE-T） | 车载以太网（1000BASE-T1） |
|:---|:---|:---|
| 线缆 | 4 对双绞线 | **1 对**双绞线（T1 = single twisted pair） |
| 重量/成本 | 高 | 低——车上一米线束都是成本 |
| EMC | 办公环境标准 | 车规 EMC（发动机舱级） |
| 确定性 | 无 | TSN 保证 |
| 温度范围 | 商业级 | −40~+105 °C 车规 |

标准组织是 OPEN Alliance（One-Pair EtherNet），物理层规范 BroadR-Reach 演进为 IEEE 802.3bw（100BASE-T1，2015）与 802.3bp（1000BASE-T1，2016）。单对线全双工的实现靠回声消除：收发同线，各自从混合信号里减去自己发出的部分。

车载 PHY 芯片选型集中在 Marvell（88Q 系列）、NXP（TJA1100/1101/1103）、TI（DP83TC 系列）。Linux 侧这些是标准 PHY 驱动，`phylink` 框架支持，MAC 侧就是 SoC 的普通千兆 MAC——车载以太网对驱动开发者的可见差异基本只有 PHY 配置（主从角色、线缆诊断）。

## 架构演进：为什么中央计算需要以太网

```
 分布式架构（过去）              域架构（现在）              中央计算（趋势）
 ┌────┐ ┌────┐ ┌────┐        ┌──────────┐               ┌──────────────┐
 │ECU1│ │ECU2│ │ECU3│ …×70   │动力域控制器│              │  中央计算平台  │
 └─┬──┘ └─┬──┘ └─┬──┘        │座舱域控制器│   车载以太网   │  (HPC)        │
   └──────┴──────┘ CAN       │底盘域控制器│ ════════════ │              │
        CAN/LIN 低速网        └────┬─────┘    主干        └───┬──────┬───┘
                                 │                          │      │
                            各域内 CAN/CAN FD           区域控制器  区域控制器
                            （域内不变）                  （挂 CAN/LIN 端点）
```

演进逻辑：功能域集中化减少 ECU 数量；域间与主干用千兆车载以太网传大数据；执行器/传感器端点仍是 CAN/LIN（便宜、够用），通过区域控制器汇聚。CAN 没有消失，是退到末端——D.11 的知识在车里依然全程有效，变的是主干。

## TSN：以太网的实时化子标准族

TSN（Time-Sensitive Networking）不是一个协议，是 IEEE 802.1 的一组子标准，各自解决一个确定性问题：

| 子标准 | 名称 | 解决的问题 | 机制要点 |
|:---|:---|:---|:---|
| 802.1AS | 时间同步（gPTP） | 全网共享时间基准 | PTP 的以太网定制版，µs~ns 级同步 |
| 802.1Qbv | 时间感知整形（TAS） | 实时帧被大帧阻塞 | 每队列开时间门：实时窗口内只放行实时队列 |
| 802.1Qbu / 802.3br | 帧抢占 | 大帧堵住正在等的实时帧 | 允许打断正在发的大帧，先发实时帧再续传 |
| 802.1Qav | 信用整形（CBS） | AV 音视频流量的带宽平滑 | 按信用值限速，防突发 |
| 802.1CB | 帧复制与消除 | 关键帧丢包 | 双路径冗余发送，接收端去重 |
| 802.1Qci | 流过滤与监管 | 故障节点刷屏 | 入口按流限速/丢弃 |

车载与工业对 TSN 的用法不同：车载把 TSN 当底座直接上量（新平台普遍要求 802.1AS + Qbv）；工业是渐进改造（12.1 的 CC-Link IE TSN、PROFINET over TSN）。

工作机制直觉：Qbv 给交换机的每个出端口队列装一个"时刻表"，时间到点才开门放行；Qbu 允许紧急帧打断非紧急帧的传输；CB 给安全关键帧做双发选收。三者叠加，实时帧的最坏延迟变成可计算的定值——这正是车载控制流量需要的。

## 应用层：SOME/IP 与 DoIP

物理层和 TSN 之上，车载有两套常用应用协议：

- **SOME/IP**（Scalable service-Oriented MiddlewarE over IP）：面向服务的 RPC/事件协议，AUTOSAR 标准组件。服务发现（SOME/IP-SD）让节点上线即被找到。座舱域、自动驾驶域内部的进程间通信大量用它。
- **DoIP**（Diagnostics over IP，ISO 13400）：UDS 诊断跑在以太网上，替代 K 线/CAN 诊断。刷写大固件包的必备——OTA 时代诊断带宽就是刷机速度。

与 OPC UA（12.4）的关系：SOME/IP 是车规强实时服务通信，OPC UA 是工厂语义互操作，两者解决的是同一层问题在不同行业的形态。读懂一个，另一个的概念框架直接平移。

## Linux 侧支持现状

- **PHY/MAC**：100BASE-T1/1000BASE-T1 PHY 驱动主线已收录（TJA110x、88Q、DP83TCxx 等），设备树里一个 `phy` 节点的事。
- **时间同步**：linuxptp（`ptp4l`）支持 802.1AS 的 gPTP 配置档。
- **流量整形**：内核 mqprio/taprio qdisc 对应 Qav/Qbv，`tc` 命令配置；TSN 网卡（Intel I210/I225/I226）有硬件 offload。
- **帧抢占、CB 冗余**：支持在演进中，落地以 SoC/交换芯片厂商 BSP 为准。

```bash
# taprio（Qbv 时间门）配置示例：每 250 µs 一个周期，
# 前 100 µs 开队列 1（实时），其余开队列 0
tc qdisc replace dev eth0 parent root handle 100 taprio \
    num_tc 2 map 1 0 queues 1@0 1@1 \
    base-time 0 sched-entry S 02 100000 sched-entry S 01 150000 \
    flags 0x2
```

## 排障与认知误区

| 误区/症状 | 事实 |
|:---|:---|
| 以为车载以太网要换特殊 MAC | 不需要。特殊的是 PHY（单对线）与交换机（TSN）；SoC 侧标准 MAC |
| T1 链路不通 | T1 PHY 分主从角色（master/slave 由 strap 或寄存器定），两端角色必须相反——T1 不通的第一检查项 |
| gPTP 不同步 | 链路上有非 TSN 交换机透传延迟未补偿；确认全网设备 802.1AS 能力 |
| 实时帧仍被挤 | taprio 只配了主站出口，路径上每台交换机的每个端口都要配 |
| 以为 TSN 替代 CAN | 分层关系：TSN 以太网是主干，CAN/LIN 守末端执行器，长期共存 |
