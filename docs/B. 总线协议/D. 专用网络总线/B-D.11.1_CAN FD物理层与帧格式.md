# B-D.11.1 CAN FD 物理层与帧格式

> 所属章节：第五部 B. 总线协议 > B-D.11 CAN 与 CANopen
>
> 难度：[I] Intermediate | 预计阅读时间：40 分钟

## <span class="blue"> 本节导读

CAN 2.0 有两个硬上限：总线速率最高 1 Mbps，单帧数据最长 8 字节。在车载 ECU 固件升级、机器人关节状态高频回传这类场景里，8 字节一帧意味着一次 100 KB 的固件传输要拆成一万两千多帧，帧头和仲裁开销占到总带宽的一半以上。CAN FD（CAN with Flexible Data-Rate，ISO 11898-1:2015 标准化）在保持 CAN 2.0 仲裁机制和物理拓扑不变的前提下，把单帧数据扩展到 64 字节，并允许数据段切换到一个更高的波特率。

本节回答两个问题：CAN FD 帧长什么样、它和 CAN 2.0 帧的差异在哪；CAN FD 的物理层怎么搭、收发器和拓扑怎么选。读完你应该能看懂 candump 抓出来的一帧 FD 报文的每一个字段，也能独立给一个双节点 CAN FD 网络选定波特率、收发器型号和终端电阻。

本节覆盖：CAN FD 帧结构（FDF/BRS/ESI/DLC）、位速率切换的时序与约束、CRC 与填充位计数增强、差分电平与终端电阻、总线拓扑与收发器选型、物理层排障清单。

## <span class="blue"> 为什么 CAN FD 能兼容 CAN 2.0

CAN FD 的兼容性不是靠网关转换，而是靠帧格式上的精心安排：CAN 2.0 帧里有一个保留位 r1（标准帧）或 r0，CAN 2.0 控制器发送时固定写显性 0。CAN FD 把这个保留位定义为 FDF（FD Format）位，FD 帧把它写成隐性 1。

带来的结果是：一条总线上同时挂 CAN 2.0 节点和 CAN FD 节点时，CAN 2.0 节点看到 FDF=1 的帧会判定为格式错误并丢弃（发错误帧），它不会参与 FD 帧的解析，但也不会把 FD 帧误认为合法 2.0 帧。反过来，FD 控制器可以正常收发 CAN 2.0 帧。因此实际组网有一条铁律：

> ⚠️
> CAN FD 帧和 CAN 2.0 节点不能混在同一条总线上跑 FD 报文。CAN 2.0 节点会把每一帧 FD 报文都当成错误帧处理，错误计数持续上涨，最终把自己挂到 Bus-Off。混网方案只有两种：全网升级 FD，或者 2.0 节点所在的网段用网关隔离。

这个结论直接决定了项目选型：如果车上还有老 CAN 2.0 节点无法替换，新节点即使硬件支持 FD，也只能工作在 2.0 兼容模式。

## <span class="blue"> 帧结构

CAN FD 帧沿用 CAN 2.0 的骨架：SOF 起始、仲裁段、控制段、数据段、CRC、ACK、EOF。差异集中在控制段新增的三个位和数据段的扩容。

```
 SOF   仲裁段（仲裁波特率）      控制段           数据段（数据波特率）   CRC        ACK   EOF
 | |---------------------|----------------|--------------------|----------|-----|----|
 | |  ID   |SRR/r1| IDE  |FDF| res|BRS|ESI| DLC  | 数据 0~64 字节 | 填充计数+CRC | ACK | 7b |
 | |11/29b |      |      | 1 | 0  |   |   | 4b   |                | 17/21b      | 2b  |    |
           标准帧 11 位 / 扩展帧 29 位
```

### 各字段与 CAN 2.0 的差异

| 字段 | 位数 | 作用 | 与 CAN 2.0 的差异 |
|:---|:---:|:---|:---|
| SOF | 1 | 帧起始，固定显性位，兼作全网同步沿 | 无差异 |
| 仲裁段 ID | 11/29 | 标识符，同时承担优先级仲裁，ID 越小优先级越高 | 无差异，始终以仲裁波特率传输 |
| SRR / r1 | 1 | 扩展帧为 SRR（固定隐性），标准帧为保留位 r1 | 无差异 |
| IDE | 1 | 标识符扩展位，0=标准帧，1=扩展帧 | 无差异 |
| FDF | 1 | FD 格式标志，1=本帧是 CAN FD | 新增。CAN 2.0 中此位是保留位，固定为 0 |
| res | 1 | FD 保留位，固定显性 | 新增 |
| BRS | 1 | 位速率切换，1=数据段切换到数据波特率 | 新增 |
| ESI | 1 | 错误状态指示，1=发送节点处于错误被动状态 | 新增 |
| DLC | 4 | 数据长度码，编码 0~64 字节 | 扩展。CAN 2.0 仅用 0~8 |
| 数据段 | 0~512 | 数据负载 | 最大 64 字节（CAN 2.0 为 8 字节） |
| 填充位计数 | 4 | 3 位计数值 + 1 位奇偶校验，记录填充位数量 | 新增 |
| CRC | 17/21 | 校验序列，数据 ≤16 字节用 17 位，>16 字节用 21 位 | 增强。CAN 2.0 固定 15 位 |
| ACK | 2 | 应答间隙 + 应答界定符 | FD 中应答间隙长度固定 |
| EOF | 7 | 帧结束，7 个连续隐性位 | 无差异 |

### FDF、BRS、ESI 三个控制位

FDF 在采样时决定接收方按哪套帧格式解析后续字段，这是兼容机制的支点，前文已述。

BRS（Bit Rate Switch）决定是否切换速率。BRS=0 时整帧以仲裁波特率传输，这种帧等价于"数据更长的 CAN 2.0"，常用于对时序确定性要求高、但不需要极限带宽的网络。BRS=1 时，发送器在 BRS 位的采样点之后切换到数据波特率，直到 CRC 界定符的采样点再切回仲裁波特率。

ESI（Error State Indicator）由发送节点的错误状态机自动填写：节点处于错误主动（Error Active）状态时发 0，处于错误被动（Error Passive）状态时发 1。CAN 2.0 里想知道对端节点的错误状态，只能靠协议外的管理报文；FD 把这个信息内嵌进了每一帧，监控端扫一遍总线就能画出全网节点的健康度分布，诊断成本显著降低。

### DLC 编码

DLC 仍是 4 位，但 9~15 不再线性映射，而是跳到 12/16/20/24/32/48/64：

| DLC | 字节数 | DLC | 字节数 |
|:---:|:---:|:---:|:---:|
| 0~8 | 0~8（与 CAN 2.0 相同） | 12 | 24 |
| 9 | 12 | 13 | 32 |
| 10 | 16 | 14 | 48 |
| 11 | 20 | 15 | 64 |

非线性映射的原因：4 位只有 16 个编码，要覆盖到 64 字节就必须跳跃。选这几个值是因为它们对应常见的数据布局——16 字节装 4 个 float，32 字节装 8 个 float 或一组电机矢量状态，64 字节是效率与缓存开销的平衡点。写代码时不要手写 DLC 换算，内核头文件 `include/uapi/linux/can.h` 提供了 `can_fd_dlc2len()` 和 `can_fd_len2dlc()`（在用户态可用 `can-utils` 里的等价宏）。

### candump 输出解码：把一帧 FD 报文拆开

理论落到工具上才算学会。`candump` 抓 FD 帧的输出长这样：

```bash
candump -t a can0
```

```text
 (1736123456.789012)  can0  123   [8]  11 22 33 44 55 66 77 88
 (1736123456.789100)  can0  456##1  01 02 03 04 05 06 07 08 09 0A 0B 0C
 (1736123456.789200)  can0  1ABCDE01##0  A1 A2 A3 A4
```

三行三种形态，逐字段拆：

- **时间戳**：`-t a` 给的绝对时间，括号里秒.微秒。
- **接口**：`can0`，SocketCAN 的网络接口名（11.3 讲配置）。
- **ID**：十六进制标识符。第一行 `123` 是标准帧（11 位）；第三行 `1ABCDE01` 是扩展帧（29 位，显示成 8 位 hex）——扩展与否只看 ID 长度，与 FD 无关。
- **分隔符是 2.0 与 FD 的分水岭**：第一行 ID 后是空格 + `[DLC]`（`[8]` = 8 字节），这是 Classical CAN 格式；第二、三行 ID 后直接跟 `##` + 一个十六进制标志位——**`##` 即 FDF=1 的显示形态**，FD 帧没有 `[DLC]`，数据长度数空格分隔的字节即可（第二行 12 字节、第三行 4 字节）。
- **`##` 后的标志位**：`canfd_frame.flags` 的低 3 位——0x1 = BRS（数据段切高速率），0x2 = ESI（发送节点处于错误被动），0x4 = FDF（内核 5.18+ 收到的 FD 帧会带上）。所以 `456##1` 读作"ID 0x456 的 FD 帧，数据段已切高速率"；`##0` 是 FD 帧但不切速率。

反查练习：`cansend can0 123##31122334455667788`（发送格式同构）——ID 0x123，FD 帧，flags=3 即 BRS+ESI 同时置位，数据 8 字节 `11 22 ... 88`。这一行就是本节全部帧格式知识在命令行里的投影。

> 💡 抓包时区分不了 FD 和 2.0 是新手常见困惑：认准分隔符——空格+`[DLC]` 是 Classical CAN，`##`+标志位是 CAN FD，扩展帧（29 位 ID）只是 ID 显示成 8 位十六进制（如 `1ABCDE01##0 ...`），与 FD 与否无关。

> 💡
> 应用层应该按数据实际长度取 DLC，而不是一律发 64 字节。总线负载率按实际占用位宽计算，发 8 字节数据却用 DLC=15 的帧，会白白多占用 56 字节的传输时间，在节点多、周期短的机器人总线上会直接推高延迟抖动。

## <span class="blue"> 位速率切换的时序与约束

BRS 切换发生在一个位时间之内，时序如下：

```
 仲裁波特率（如 1 Mbps）                数据波特率（如 5 Mbps）
 ──────────────────────╲─────────────────────────────────────────╲────────────
                       ╲                                           ╲
                        ← BRS 位采样点后切换              CRC 界定符采样点后切回 →
 SOF  ID  FDF res BRS ESI   DLC  Data...Data   填充计数 CRC   ACK  EOF
 |--------------------|   |----------------------------|   |--------------|
      仲裁波特率                  数据波特率                    仲裁波特率
```

设计数据波特率时有四条硬约束：

1. **数据波特率必须不低于仲裁波特率**。BRS 位本身在仲裁波特率下传输，切换方向只能是加速；反向切换没有任何标准定义，控制器行为未定义。
2. **数据波特率受全网最弱节点限制**。网络里每个节点的控制器和收发器都有速率上限，数据波特率必须 ≤ 所有节点的最小值。一个用 TJA1050（1 Mbps 上限）的老节点就能把全网数据段锁死在 1 Mbps——而 1 Mbps 的数据段等于没有 FD。
3. **数据波特率受总线物理限制**。速率越高，允许的线长越短、支线越短，见后文拓扑部分。示波器上看到边沿振铃或采样点误判，第一件事就是降数据波特率验证。
4. **仲裁段速率影响最坏延迟**。仲裁段长度决定了一帧的固定开销：64 字节 FD 帧在 1 Mbps 仲裁段 + 5 Mbps 数据段下，仲裁+控制段约占 30 µs，数据段约占 110 µs；若仲裁段降到 500 kbps，固定开销翻倍。节点多、仲裁频繁的总线不要为了省线长而压低仲裁速率。

## <span class="blue"> CRC 增强与填充位计数

CAN 2.0 的 15 位 CRC 对 8 字节数据的检错能力是足够的，但按同样错误率外推到 64 字节，漏检概率会上升到工程上不可接受的水平。FD 的对策是双档 CRC：数据 ≤16 字节用 CRC-17，>16 字节用 CRC-21，对应的生成多项式分别提供 HD=6 和 HD=8 的汉明距离保证。

填充位计数器是 FD 新增的第二道检错。CAN 的位填充规则（连续 5 个同极性位后插入一个反向位）在 FD 里保留，但 FD 额外要求发送器在 CRC 字段之前填入"本帧实际填充位数 mod 8"的 3 位格雷码计数值加 1 位奇偶校验。接收方独立计数填充位并比对，不一致即报填充错误。它防的是一类特殊故障：填充位本身被干扰翻转后，可能恰好让 CRC 计算"将错就错"地对上，15 位 CRC 时代这类复合错误有漏检概率。

```
 数据段末尾 → 填充位计数（3b 格雷码 + 1b 奇偶） → CRC 序列（17/21b） → CRC 界定符

 接收方校验顺序：位填充规则 → 填充位计数比对 → CRC 比对 → 帧格式检查
 任何一步失败：发错误帧，本帧作废
```

## <span class="blue"> 物理层：差分电平与仲裁基础

CAN FD 完全复用 CAN 2.0 的高速物理层（ISO 11898-2）：CAN_H 与 CAN_L 双绞线差分传输。

```
 显性位（逻辑 0）                      隐性位（逻辑 1）
 CAN_H ─────── 3.5 V                   CAN_H ─────── 2.5 V
              差值约 2.0 V                         差值约 0 V
 CAN_L ─────── 1.5 V                   CAN_L ─────── 2.5 V

 收发器主动驱动总线                     收发器释放，终端电阻把两线拉回同电位
```

| 状态 | CAN_H | CAN_L | 差分电压 | 逻辑值 |
|:---|:---:|:---:|:---:|:---:|
| 显性 | ≈3.5 V | ≈1.5 V | ≈+2.0 V | 0 |
| 隐性 / 空闲 | ≈2.5 V | ≈2.5 V | ≈0 V | 1 |

显性覆盖隐性是 CAN 非破坏性仲裁的物理基础：多个节点同时发送时，发隐性的节点在回读总线时看到显性电平，立刻知道自己仲裁失败，转为只听；发显性的节点毫无感知地继续。ID 越小，越早出现显性位，优先级越高——这就是为什么 CAN 的报文 ID 同时承担"地址"和"优先级"两个角色，也是 CANopen 里把紧急报文和同步报文分配小 ID 的原因。

## <span class="blue"> 终端电阻与总线拓扑

总线两端各接一个 120 Ω 终端电阻，两个作用：匹配特性阻抗消除末端反射；隐性位时为 CAN_H/CAN_L 提供直流通路，把两线拉到共同的 2.5 V  recessive 电平。

用万用表在断电状态下量 CAN_H 与 CAN_L 之间的电阻，正常网络应读到约 60 Ω（两个 120 Ω 并联）。读到 120 Ω 说明一端终端缺失，读到 40 Ω 说明多接了一个，读到无穷大说明断路。这是 CAN 排障的第一项检查，30 秒能做完。

```
 干线拓扑：

 120 Ω          节点 1            节点 2            节点 3          120 Ω
 ──●────────────────●─────────────────●─────────────────●──────────────●──
   │              支线≤0.3 m        支线≤0.3 m        支线≤0.3 m        │
   CAN_H/CAN_L 双绞主干线 ────────────────────────────────────────────────

 长度经验值（仲裁段速率）：           CAN FD 数据段的附加约束：
   125 kbps → 最长 500 m              数据段 2 Mbps：干线 ≤25 m，支线 ≤0.3 m
   250 kbps → 最长 250 m              数据段 5 Mbps：干线 ≤10 m，支线 ≤0.1 m
   500 kbps → 最长 100 m              数据段 8 Mbps：干线 ≤10 m 且建议 SIC 收发器
   1 Mbps   → 最长 40 m
```

支线在高速下的危害是信号反射：信号沿支线走到末端反射回干线，与原信号叠加，在采样点附近造成电平误判。数据段速率越高，允许的反射往返时间越短，所以支线限制从 2 Mbps 的 0.3 m 收紧到 5 Mbps 的 0.1 m。拓扑上优先菊链（节点串在干线上），避免星型；必须分支时用带 SIC（Signal Improvement Capability，主动振铃抑制）的收发器可以放宽约束。

## <span class="blue"> 收发器选型

CAN 收发器负责控制器逻辑电平（TXD/RXD）与总线差分电平之间的转换。CAN FD 对收发器的要求是比 2 Mbps 更高的带宽和更对称的传播延迟——老型号 TJA1050、PCA82C250 在 FD 数据段速率下环路延迟不对称性超标，会直接造成位错误，不能用于 FD 网络。

| 型号 | 数据段上限 | 供电 | 关键特性 | 适用 |
|:---|:---:|:---:|:---|:---|
| TJA1051 | 5 Mbps | 5 V | 基础款 FD 收发器，有 VIO 电平移位版本 | 一般车载/工业节点 |
| TJA1043 | 5 Mbps | 5 V | 带 INH 引脚与本地/远程唤醒 | 有休眠唤醒需求的车身节点 |
| TJA1463 | 8 Mbps | 5 V | SIC 主动信号整形，抗振铃 | 复杂拓扑、长支线、高数据段速率 |
| TCAN1042 | 5 Mbps | 5 V | 低功耗待机，工业温度范围 | 工业自动化 |
| TCAN330/334 | 5 Mbps | 3.3 V | 3.3 V 直供，免电平转换 | 3.3 V 主控的嵌入式节点 |
| MCP2542FD | 8 Mbps | 5 V | 高 ESD 等级，低成本 | 成本敏感的大批量节点 |

选型按三个问题收敛：数据段要跑多快（决定速率档）；MCU IO 是 3.3 V 还是 5 V（决定选原生 3.3 V 型号还是带 VIO 引脚的 5 V 型号）；节点要不要休眠唤醒（决定要不要 INH/WAKE 引脚）。

控制器与收发器的连接：

```
 MCU（CAN FD 控制器）         收发器                    总线
 ┌───────────────┐          ┌─────────┐
 │ CAN_TX ───────┼─────────→│ TXD     │        CAN_H ──●──────────
 │ CAN_RX ←──────┼──────────┤ RXD     │        CAN_L ──●──────────
 │ GPIO ─────────┼─────────→│ STB/EN  │                    （双绞至其他节点）
 │ （休眠控制）    │          │ VIO/VCC │
 └───────────────┘          └─────────┘
```

## <span class="blue"> 排障：物理层与帧格式相关故障

排障表里有两个术语需要先立住，它们是 CAN 波特率配置的实质内容：

> 采样点（Sample Point）：一个位时间不是瞬时判决，而是被控制器分成若干时间份额（time quantum），接收方在位时间的某个比例处采样电平——这个位置就是采样点，常用 75%~87.5%。采样点越靠后，对信号传播延迟和振铃的容忍越大，但对时钟偏差的容忍越小。

<!-- -->

> SJW（Synchronization Jump Width，同步跳转宽度）：控制器在收发过程中动态微调位时间的最大幅度，用于补偿各节点时钟偏差。它与仲裁段速率、数据段速率、采样点合称波特率四参数——全网每个节点的这四项必须逐项一致，靠协商是做不到的，CAN 没有波特率协商机制。

CAN FD 网络的故障大多落在物理层和速率配置上，按下表从快到慢排查：

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 全网无任何帧 | 终端电阻缺失/断路、收发器未使能 | 断电测 CAN_H-CAN_L 电阻（应 ≈60 Ω）；查 STB/EN 引脚电平 |
| 只有部分节点能通 | 支线过长反射、某节点收发器速率不够 | 示波器看该节点处波形边沿与振铃；换 SIC 收发器对比 |
| FD 帧全报错误、2.0 帧正常 | 总线上混有 CAN 2.0 节点 | 逐个下电节点定位；确认全网控制器均为 FD 模式 |
| BRS=1 的帧出错、BRS=0 正常 | 数据波特率超过某节点上限或线长超标 | 数据波特率降到 2 Mbps 验证；量干线长度与支线长度 |
| 偶发位错误、随温度/时间变化 | 振铃、接触不良、收发器环路延迟不对称 | candump 开 CAN FD 错误帧统计；示波器差分探头看采样点附近波形 |
| 单节点反复进入 Bus-Off | 该节点波特率配置与全网不一致 | 对比各节点仲裁段/数据段/采样点三组参数 |

波特率配置不一致是最常见的软件侧故障：CAN 的波特率不是靠协商，而是每个节点各自用分频器配出来的，标称值相同但采样点（sample point）设置不同（如 75% vs 87.5%）时，短距离低速下可能侥幸能通，FD 高速数据段下必然出错。全网统一仲裁段速率、数据段速率、采样点、SJW 四组参数，写入设计文档而不是口头约定。

## <span class="blue"> 本节总结

CAN FD 的全部设计可以用一句话收拢：**仲裁和拓扑这两个 CAN 最值钱的资产原样保留，只把"慢"和"短"两个短板换掉**。帧格式上 FDF 位借用了 2.0 的保留位实现兼容判定，BRS/ESI 两个新控制位分别解决速率切换和错误状态可视化；DLC 的非线性编码是用 16 个编码覆盖 64 字节的工程妥协。这套设计的高明在于升级路径清晰，但它的边界也同样清晰——FD 帧和 2.0 节点不能混网，这条铁律直接决定项目选型。

物理层侧要建立的是"参数纪律"而非"参数知识"：CAN 没有波特率协商，仲裁段速率、数据段速率、采样点、SJW 四组参数靠每个节点各自配置，全网一致性只能靠设计文档和 review 保证。排障的反射动作有两个：断电测 CAN_H-CAN_L 电阻（≈60 Ω 正常，30 秒做完）；FD 帧全错而 2.0 帧正常，直接怀疑总线上混入了 2.0 节点。

candump 的分隔符读法（空格+[DLC] = Classical，`##`+标志位 = FD）是把本节帧格式知识变现的接口——抓到任何一帧都能反推出 FDF/BRS/ESI 的状态。

### 速查表

| 项 | 要点 |
|----|------|
| 兼容机制 | FDF 位=原保留位；2.0 节点见 FD 帧必报错，混网铁律不可破 |
| 三新位 | FDF=FD 标志；BRS=数据段切速率；ESI=发送方错误被动 |
| DLC | 9~15 跳到 12/16/20/24/32/48/64；按实际长度取值，别一律 64 |
| 速率约束 | 数据段 ≥ 仲裁段；≤ 全网最弱节点；越高线越短（5 Mbps 干线 ≤10 m） |
| 终端 | 两端各 120 Ω，断电测 ≈60 Ω；支线 ≤0.3 m（5 Mbps 时 ≤0.1 m） |
| 收发器 | 老型号（TJA1050）不能上 FD；高速率/长支线选 SIC 型号 |
| 波特率四参 | 仲裁速率/数据速率/采样点/SJW，全网逐项一致，无协商机制 |
| candump | 空格+[DLC]=Classical；`##`+flags=FD（0x1 BRS / 0x2 ESI / 0x4 FDF） |

### 本节自查

读完本节，你应能独立完成以下动作：

- 给定一帧 candump 输出（如 `123##31122334455667788`），指出 ID、FDF/BRS/ESI 状态、数据字节数
- 解释为什么 CAN 2.0 节点不能与 FD 帧共存于同一总线，以及混网时错误计数的变化过程
- 为一个 6 节点、干线 8 m、数据段 5 Mbps 的网络选定仲裁/数据波特率、采样点、收发器型号和终端电阻阻值
- 用万用表电阻测量法在 1 分钟内判断终端电阻是否正常
- 根据"FD 帧全错、2.0 帧正常"这一症状定位到总线上混入了 2.0 节点
- 说明数据波特率不能低于仲裁波特率的原因
