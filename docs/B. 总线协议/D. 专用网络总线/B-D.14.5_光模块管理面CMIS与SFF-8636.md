# B-D.14.5 光模块管理面：CMIS 与 SFF-8636

> 所属章节：第五部 B. 总线协议 > D. 专用网络总线
>
> 难度：[I] | 预计阅读时间：45 分钟

## 本节导读

数通设备和 PCIe 卡上的光模块、AOC/DAC 线缆，业务面跑的是几百 Gbps 的 SerDes 信号（F.16 组的领域），但工程师日常打交道的是它的**管理面**：一个 400 kHz 的 I2C 从机，挂着一张几百字节的内存映射表。光模块的温度、电压、发射功率、接收功率、告警标志、固件版本，全部通过这张表读写。

这张表的格式是行业标准：老的是 SFF-8636（SFP+/QSFP+ 时代），新的是 CMIS（QSFP-DD/OSFP，400G/800G 时代）。对数通和 PCIe 卡工程师来说，这是嵌入式低速总线知识在岗位上的最直接应用——B-B.3 组的 I2C 驱动加上这张内存映射表，就是光模块管理的全部软件基础；反过来说，本节也是 B 扩展里"低速总线在高端产品里干什么"的最佳样本。

> 本节覆盖：管理面与业务面的系统分工、模块内 MCU 的角色、SFF-8636 内存映射结构与分页机制、DOM 定点数格式与 dBm 换算的完整算例、ethtool -m 输出逐行解读、CMIS 相对 SFF-8636 的五个变化（状态机/Bank 寻址/lane 组/固件升级/增强诊断）、模块状态机的上电时序影响、DAC/AOC/光模块的管理面差异、Linux 四条访问路径、自研板卡的模块笼拓扑与 GPIO 时序、典型排障。按"系统位置 → 老标准读表 → 新标准变化 → Linux 落地 → 排障"的顺序展开——这也是你在岗位上从第一次接触光模块到独立排障的能力路径。

## 管理面与业务面：两条互不依赖的通路

```text
 业务面（数据通路）                    管理面（控制/监控）
 ─────────────────                    ──────────────────
 SerDes 高速信号 ══ 光模块 ══ 光纤      I2C（400 kHz）── 模块 EEPROM/MCU
                                            │
                                     SoC/BMC 的 I2C 控制器
                                     Linux：i2c-dev / phylink / ethtool
```

> 管理面 / 业务面（Management Plane / Data Plane）：数通设备的标准分层。业务面跑用户数据（几百 Gbps），管理面跑设备监控与控制（400 kHz I2C）。两面物理独立、故障域独立：业务面链路断了，管理面通常还活着。整机架构上这套"快慢双平面"思想与 B-E.15.5 数通整机的背板管理面（I2C/IPMI）同源。

模块内部有一枚小 MCU：采集 ADC（温度/电压/光功率）、维护告警阈值比较逻辑、跑固件、响应 I2C 读写。那张内存映射表就是这颗 MCU 的寄存器窗口——**你读的不是存储器，是一颗活着的 MCU 的实时采样结果**（温度会随时间变，告警位会随光功率变）。

这个结构决定了排障的第一原则：**"模块认不认、光功率多少"这类问题，第一步永远读管理面，而不是看 SerDes**。管理面活着而业务面不通，问题在线缆/光路/SerDes 配置；管理面都不通，问题在模块供电、GPIO 时序或 I2C 本身。

### 模块形态速览：从 SFP 到 OSFP

读规范前先建立形态坐标——SFF-8636 与 CMIS 的分界本质上是模块形态的代际分界：

| 形态 | 速率/模块 | 通道 | 管理标准 | 时代 |
|:---|:---|:---|:---|:---|
| SFP / SFP+ | 1G / 10G | 1 | INF-8074 / SFF-8472 | 2000s |
| QSFP+ / QSFP28 | 40G / 100G | 4 | **SFF-8636** | 2010s |
| QSFP-DD / OSFP | 400G / 800G | 8 | **CMIS** | 2020s |

命名规律：Q = Quad（4 通道），DD = Double Density（8 通道），OSFP 是另一阵营的 8 通道形态（体积略大、散热裕量更好）。速率翻倍的另一条暗线是**每通道速率**（10G → 25G → 50G → 100G → 200G per lane），这部分是业务面 SerDes 的事，见 F.16 组；管理面需要关心的只是 lane 数翻倍导致诊断数据量翻倍——这正是 CMIS 引入 Bank 的原因。

## SFF-8636：QSFP+ 时代的内存映射

SFF-8636 定义的 I2C 内存映射（地址固定 0x50，部分功能在 0x51）分两个区域：

```text
 地址 0x50，256 字节窗口

 Lower Page（0x00~0x7F，无需选页，直接读）：
   0x00~0x02   模块标识与类型（SFP/QSFP+/QSFP28…）
   0x03~0x21   告警与状态标志位
   0x22~0x29   温度、电压（2 字节定点数）
   0x34~0x41   每通道 RX/TX 光功率

 Upper Page（0x80~0xFF，先写 0x7F 选页）：
   Page 00h    厂商信息：厂商名、型号、序列号、日期码、波长
   Page 01h    扩展标识与选项位
   Page 02h    用户可写 EEPROM / 部分厂商密码区
   Page 03h    告警阈值上下限（与 Lower Page 实测值比较用）
   Page 20h/21h 厂商自定义
```

> 分页（Paging）：用一个小地址窗口（0x80~0xFF，128 字节）访问远大于窗口的存储空间的技术。先往页选择寄存器（0x7F）写页号，窗口就"切换"到那一页的内容。SPI NOR flash 的 Bank 切换、eMMC 的扩展寄存器都是同一思想。分页的最大坑：**忘记选页直接读，读到的是上一次选中的页**——管理面读数"对不上手册"的第一嫌疑。

### DOM 定点数：手算一遍

> DOM（Digital Optical Monitoring，数字光监控）：光模块内置的实时诊断量集合——温度、供电电压、激光器偏置电流、发射光功率、接收光功率五项为核心。SFF-8472/8636 定义了它们的定点数格式，告警判定逻辑是"实测值与 Page 03h 的阈值表比较"。

手册上的定点格式要会用。以温度为例：16 位有符号数，分辨率 1/256 °C，高字节是整数部分、低字节是小数部分。

```text
读到 0x1A80（地址 0x22~0x23）：
  0x1A = 26（整数），0x80 = 128 → 128/256 = 0.5
  温度 = 26.5 °C

电压：单位 100 µV。读到 0x8234 = 33332 → 33332 × 100 µV ≈ 3.33 V
光功率：单位 0.1 µW。RX 功率读到 0x03E8 = 1000 → 100 µW
  dBm 换算：dBm = 10·log10(mW) = 10·log10(0.1) = −10 dBm
```

−10 dBm 是个值得记住的参照点：数据中心多模光链路的典型收光范围在 −1 ~ −10 dBm 之间，−10 已接近灵敏度边缘。读到 −20 dBm 以下基本等于没光。

这些换算与阈值比较，`ethtool` 已经替你做完：

```bash
ethtool -m eth0
```

输出样本（QSFP28 模块，截取关键行）逐行判读：

```text
Identifier                                : 0x11 (QSFP28)      ← 模块类型码
Vendor name                               : FINISAR            ← Page 00h 厂商信息
Vendor PN                                 : FTLC1151RDPL
Temperature                               : 41.2 degrees C     ← Lower Page 实测值
Voltage                                   : 3.31 V
Laser rx power                            : -2.3 dBm           ← 收光：正常区间
Laser output power                        : 1.8 dBm            ← 发光：正常
Module temperature high alarm threshold   : 75.0 degrees C     ← Page 03h 阈值
```

读法：前半是标识（认模块对不对），中段是实测值（与后半的阈值比对），末尾是告警/警告标志位（有告警时会列出 `high alarm` 等）。**实测值正常但告警位置位**的组合也是存在的——阈值表本身可能被厂商设得很保守。

## CMIS：QSFP-DD / OSFP 时代的管理面

400G/800G 模块引入了 lane 组（8×50G → 8×100G）、可插拔固件、功耗分级、显式状态机，SFF-8636 的扁平页表装不下这些概念，CMIS（Common Management Interface Specification，QSFP-DD/OSFP MSA 制定）取而代之：

| 维度 | SFF-8636 | CMIS 5.x |
|:---|:---|:---|
| 模块形态 | SFP+/QSFP+/QSFP28 | QSFP-DD / OSFP / QSFP112 |
| 分页 | 扁平页表 | Bank+Page 二维寻址 |
| 状态机 | 无显式定义 | 模块状态机（LowPwr → HighPwr 等） |
| Lane 管理 | 简单通道开关 | 按 lane 组的映射、速率协商、数据路径状态机 |
| 固件 | 不可升级/厂商私有 | 标准化固件升级（CDB 命令区） |
| 诊断 | 基础 DOM | 增强 DOM、每 lane 告警、性能监控计数器 |

对工程师最有实际影响的三个变化，逐个展开。

### 变化一：上电默认 LowPwr 的模块状态机

CMIS 模块插上电处于低功耗态（LowPwr），业务面不工作，主机必须通过管理面写控制位显式切到 HighPwr。状态机的简化视图：

```text
 插入上电 → LowPwr（默认）──主机写控制位──▶ HighPwr（业务面激活）
                │                                │
                │  LPMode 引脚也可拉低           │ 故障/告警事件
                ▼                                ▼
           （引脚与寄存器双重门控）          Fault 态 → 需主机干预恢复
```

**"模块插了、温度能读、链路就是不起来"——先查模块状态**。这是 CMIS 时代最高频的新手坑：SFF-8636 时代模块上电即工作（LPMode 引脚拉低就行），CMIS 时代多了一步软件门控，老经验会误导你直接去查光路。

### 变化二：Bank+Page 二维寻址

CMIS 把分页扩成二维：先选 Bank 再选 Page。Bank 存在的理由是 lane 数翻倍——8 条 lane 的每 lane 诊断数据一页装不下，按 lane 组分 Bank（如 Bank 0 = lane 1~4，Bank 1 = lane 5~8）。读错 Bank 得到的是另一组 lane 的数据，数值看起来"合理但不对"，是最阴的误读形态。写脚本解析 CMIS dump 时，把 Bank/Page 选择当成**每次读操作的前置动作**，不要假设模块停在你上次选的位置。

### 变化三：标准化固件升级（CDB）

> CDB（Command Data Block）：CMIS 定义的模块命令接口区——主机往指定寄存器块写命令（查固件版本、开始传输、写分块、提交激活），模块 MCU 执行并回状态。固件升级由此从"各厂商私有流程"变成标准流程。升级有断电风险窗口，产线流程里要给升级动作配供电保持与失败回滚策略。

CDB 升级的流程骨架（实现带外升级功能时对照 CMIS 规范细化）：

```text
1. 读模块能力：确认支持固件升级与分块大小
2. 发"开始传输"命令，模块进入升级态（业务面可能中断——升级要在维护窗口做）
3. 循环：写固件分块 → 查询状态 → 等待完成，逐块推进
4. 发"提交/激活"，模块校验镜像完整性
5. 复位模块（或等下次上电），新固件生效；读回版本号确认
```

两个工程注意点：**升级期间断电 = 模块变砖风险**（部分模块有双镜像回滚，部分没有——选型时问清楚）；升级后要用管理面读回固件版本号做闭环确认，不能只信升级命令的返回码。

### DAC/AOC/光模块的管理面差异

三类"线缆形态"在管理面上的差异：

| 形态 | 内部有源器件 | 管理面内容 | DOM |
|:---|:---|:---|:---|
| DAC（无源铜缆） | 无（或仅有 EEPROM） | 只有标识信息 | 无或仅温度电压 |
| AOC（有源光缆） | 有（激光器+驱动） | 等同光模块 | 完整 |
| 光模块 | 有 | 完整 + 波长/距离标识 | 完整 |

`ethtool -m` 输出里 `Identifier`/`Module type` 字段能区分这三类。DAC 上报"无光功率数据"不是故障，是形态使然——别把 DAC 当坏光模块返修。

## Linux 访问路径

| 路径 | 适用 | 用法 |
|:---|:---|:---|
| `ethtool -m` | 网卡挂光模块 | 最常用，内核 phylink/sfp 框架读好并解析 |
| 内核 SFP 框架 | 设备树声明 `sfp` 节点 | SoC MAC + 可插拔模块的嵌入式板卡 |
| i2c-dev 直接读 | 自研板卡、PCIe 卡上的模块笼 | `i2ctransfer` 或自写脚本按 SFF-8636/CMIS 解析 |
| EEPROM 驱动 | 只读标识信息 | `at24` 类驱动把 0x50 挂成 eeprom sysfs |

自研 PCIe 卡上的常见拓扑：BMC 或主控的 I2C 挂 4~8 个模块笼（cage），每个笼还有几根控制 GPIO：

```text
 BMC/主控
   │ I2C（0x50 地址全一样，靠 mux 或 ModSelL 分时选通）
   ├─────┬─────┬─────┬─────┐
  笼 0  笼 1  笼 2  笼 3  …
   │     │     │     │
  每笼三根 GPIO：ModSelL（选通）、LPMode（功耗门控）、ModPrsL（在位检测→中断）
```

所有模块的 I2C 地址都是 0x50——**地址冲突是多笼拓扑的结构性问题**，两种解法：I2C mux（如 PCA9548，B-B.3.4 讲过的老面孔）把各笼分到不同子总线，或用 ModSelL 逐笼选通（同一时刻只有一个笼应答）。选型考量：mux 方案软件简单、BOM 多一颗芯片；ModSelL 方案省芯片但 GPIO 数量和时序复杂度上升。

管理面软件 = I2C 读写 + GPIO 时序 + 表解析，三者缺一不可：

> ModSelL / LPMode / ModPrsL：QSFP 族模块的三根关键控制引脚。ModSelL（模块选择，低有效）——不拉低，模块不应答 I2C；LPMode（低功耗模式）——拉高强制低功耗，上电时序里要在读表前释放；ModPrsL（模块存在，低有效）——热插拔检测输入，通常接中断，触发后重新读表刷新 DOM。带外管理软件的标准动作就是围着这三根脚转。

i2c-dev 直读示例（QSFP-DD 读温度，CMIS 5.x 的温度在 Lower Page 0x16~0x17）：

```bash
# 总线 3，选 Page 0（写 0x7F = 0x00），再读 Lower 区前 32 字节
i2ctransfer -y 3 w2@0x50 0x7f 0x00 r32@0x50
# 返回字节流里第 0x16/0x17 字节即温度定点数，按 1/256 °C 解码
```

> ⚠️
> 上电时序纪律：模块 MCU 从得电到能应答 I2C 有初始化时间（规范量级为秒级），上电后立刻读表会拿到全 0xFF/0x00——排障表里的"读数全 F"第一条就是读太早。带外软件在 ModPrsL 中断后应延时 ≥2 s 再读表。

## 排障：管理面故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| i2cdetect 看不到 0x50 | ModSelL 未拉低、模块未插到底、I2C 总线被模块拉死 | 量 ModSelL/LPMode 电平；换笼位交叉验证 |
| 读到全 0xFF/0x00 | 上电时序太早读、选页错 | 延时 ≥2 s 再读；显式写页寄存器后复读 |
| DOM 数值离谱 | 定点解析公式错、读错 Bank/Page | 与 `ethtool -m` 输出交叉验证 |
| 模块温度可读但链路不起 | CMIS 模块停在 LowPwr | 读模块状态字段；写控制位切 HighPwr |
| 光功率 -inf | 激光器未使能（Tx Disable）或对端无光 | 查 Tx Disable 控制位；对端看发光功率 |
| 收光功率低告警 | 对端发光弱、光纤端面脏、弯折半径过小 | 对端 `ethtool -m` 看发光；清洁端面后复测 |
| 多笼位读数串扰 | I2C 地址冲突（0x50 撞车）需经 mux 或 ModSelL 分时 | 核对 I2C mux/开关拓扑与 ModSelL 使能逻辑 |
| 固件升级后模块异常 | CDB 流程中断（断电窗口） | 查模块状态机是否 Fault；按厂商流程恢复 |

## 本节总结

光模块管理面是"低速总线干大事"的样本：业务面几百 Gbps，管理面只是一条 400 kHz I2C 加一张内存映射表，但监控、告警、固件、状态控制全在这张表上。SFF-8636 的核心技能是分页（先选页再读）与定点数解码（温度 1/256 °C、dBm 换算）；CMIS 在它之上加了三个必须知道的变化——上电默认 LowPwr（链路不起先查状态）、Bank+Page 二维寻址（读错 Bank 拿到"合理但不对"的数据）、CDB 标准化固件升级。Linux 侧 `ethtool -m` 解决 90% 的日常读取，自研板卡走 i2c-dev + GPIO 时序（ModSelL/LPMode/ModPrsL 三根脚）。排障的总纲是一条：管理面与业务面故障域独立，先读表再查光路。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 管理面本质 | 模块内 MCU 的 I2C 寄存器窗口，读的是实时采样 |
| SFF-8636 核心 | 0x50 + Lower/Upper 分页，忘选页是第一嫌疑 |
| DOM 换算 | 温度 1/256 °C、电压 100 µV、功率 0.1 µW；−10 dBm 是灵敏度边缘 |
| CMIS 三变化 | 默认 LowPwr 要软件激活；Bank+Page 二维寻址；CDB 标准固件升级 |
| Linux | `ethtool -m` 为主，自研板卡 i2c-dev + 三根 GPIO 脚 |
| 排障总纲 | 先读管理面再查光路；上电读表延时 ≥2 s |
