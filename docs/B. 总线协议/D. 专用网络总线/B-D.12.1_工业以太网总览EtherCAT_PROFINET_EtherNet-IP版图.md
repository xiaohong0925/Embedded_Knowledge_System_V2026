> 所属章节：第五部 B. 总线协议 > D. 专用网络总线
>
> 难度：[B] | 预计阅读时间：50 分钟

## 本节导读

CAN 解决了可靠性和确定性，但有两个天花板：1 Mbps（FD 下 8 Mbps）的带宽和逐帧仲裁带来的规模上限。当一条产线要挂几百个伺服和 IO、控制周期压到 250 µs 以下、还要同时传诊断数据和参数时，工程师把视线转向以太网——带宽大三个量级、布线标准化、IT 基础设施可复用。

但标准以太网是非确定性的：交换机排队、TCP 重传，每一样都和实时控制冲突。**工业以太网就是"在以太网上重做确定性"的一组方案**——而且不止一种：EtherCAT、PROFINET、EtherNet/IP、POWERLINK、CC-Link IE、Sercos III 各自走了不同的技术路线。这些路线的差异不是细节，是哲学：有的改从站硬件，有的改交换机，有的只靠网络规划。

本节是 D.12 组的总览：不深入任何一个协议的帧格式（那是 12.2~12.4 的事），而是建立版图认知——每个方案怎么解决确定性、硬件代价是什么、生态被谁把持、选型按什么维度收敛。

> 本节覆盖：标准以太网缺的三项能力（确定性/同步/共存）、四大主流方案的技术路线与横向对比、从站芯片与主站协议栈的生态格局、CANopen 应用层的跨协议复用（CoE）、TSN 作为收敛方向、按行业与约束的选型矩阵、选型层面的高频误判。按"问题 → 各家的答案 → 横向对比 → 应用层复用 → 演进方向 → 选型"的顺序展开——先理解问题再看方案，各家的"怪设计"才有来由。

读完你应该能给出一个项目"该用哪种工业以太网"的初步判断，并说清理由。

## 标准以太网缺什么：三个缺口

把标准以太网搬进控制回路，要补三个缺口。先说清楚缺口，后面每家方案的"怪设计"就都有来由了。

1. **确定性时延**：控制帧必须在可预期的窗口内到达。标准以太网的交换机用存储转发——收完整帧、查表、排队、再发，队列深度随网络负载变化，时延抖动轻松超过一个控制周期。

   > 存储转发（Store-and-Forward）：标准以太网交换机的工作方式——把整个帧完整收进缓冲区，查转发表，再从目标端口发出。它带来灵活组网能力，代价是每跳增加"帧长 + 排队"两级延迟，且排队深度取决于瞬时负载，不可预测。EtherCAT 的"帧经过从站时边传边处理"（cut-through 的极致形态）正是对着存储转发打的。

   > 抖动（Jitter）：同一条链路上通信延迟的波动范围。实时系统里抖动比延迟本身更致命——100 µs 的固定延迟可以被控制算法吸收，±50 µs 的抖动会让控制环参数失配。E.15.6 的实时性量化方法里，抖动测量是核心动作。

   > 确定性（Determinism）：通信延迟有**可证明的上界**的性质。注意不是"快"，是"可预测"——1 ms 固定延迟的系统是确定性的，平均 0.1 ms 但偶发 10 ms 的系统不是。实时控制要的是前者：控制算法按最坏情况设计，抖动比延迟本身更致命。这个概念与 B-E.15.6 的"最坏延迟"口径一脉相承。

2. **全网同步**：多轴运动要求所有从站在同一时刻采样、同一时刻输出（20 轴同步起动的机械臂，轴间时间差会直接变成轨迹误差），需要全网时钟同步到 µs 甚至 ns 级。标准以太网的协议栈里根本没有"时间"这个概念。
3. **与 IT 流量共存**：工厂网络里控制流量和诊断、视频监控、MES 上报跑在同一套布线里。标准以太网对所有流量一视同仁，实时流量会被一个大文件传输冲垮。部署层面的解法（网段隔离/IGMP/QoS）在后文"部署纪律"一节展开。

顺带澄清一个历史包袱：教科书里以太网"不确定性"的经典原因是 CSMA/CD（载波监听冲突检测）——多节点共享介质、冲突后随机退避重发，延迟天然无界。**全双工交换式以太网普及后 CSMA/CD 事实上已消亡**（点对点链路无冲突可言），今天的不确定性来源只剩交换机排队这一项。但"以太网 = CSMA/CD = 不确定"的过时认知仍广泛流传，面试和评审里要能把这层说清楚。

## 四大方案的技术路线

### EtherCAT：集总帧，一帧过全网

EtherCAT（IEC 61158/61784，ETG 协会）的机制最激进：主站发一个大的以太网帧，帧里按顺序塞着所有从站的过程数据；帧像火车一样依次穿过每个从站，从站硬件（专用 ESC 芯片）在帧经过自己的瞬间读出写给它的输出数据、插入它的输入数据——"processing on the fly"，全程不存储转发。帧绕完一圈回到主站，一次通信周期完成。

> 集总帧（Summation Frame）：EtherCAT 的核心机制。传统以太网通信是"一个设备一个帧"，EtherCAT 是"一帧装所有设备"——帧内按从站顺序划分数据区段，每个从站只读写属于自己的那几字节。带宽利用率因此极高（帧头开销被上百个从站分摊），且每周期帧数恒定，延迟可精确计算。

一个量化实例感受它的确定性：100 个从站、每站 8 字节过程数据，集总帧载荷约 800 字节，千兆线上传输约 8 µs；每站 ESC 硬件透传延迟约 0.3 µs，100 站共 30 µs；加上主站协议栈处理，**整个周期可压到 100 µs 以内，且每分每秒都是这个数字**——延迟是从站数量和帧长的函数，不是负载的函数。

拓扑与冗余也值得一提：EtherCAT 天然是线形/菊花链（帧顺次穿过每站），分支用 ESC 的多端口或专用分支器实现树形；首尾相接可成环——**环冗余**下主站从两个方向同时发帧，线缆单点断开时两个半环各自继续工作，设备层不停机。这是 EtherCAT 在"线缆被机械臂拖链磨断"这类真实工况下的高可用答案，D.12.3 的驱动配置里会看到冗余端口的对应参数。

- 确定性来源：没有交换机排队（线形/树形拓扑下交换机根本不存在）；从站处理延迟是固定的几十 ns 级。
- 同步：分布式时钟（DC）机制，主站测量并补偿各从站的时钟漂移与传播延迟，全网同步到 <1 µs，轴间 <100 ns（机制详解见 D.12.3）。
- 硬件代价：从站必须用 ESC 专用芯片（Beckhoff ET1100/ET1200、Microchip LAN9252、亚信 AX58100 等）——**普通 PHY 做不了集总帧透传**；主站是纯软件的，普通网卡即可。
- 生态：ETG 会员制，从站芯片由 Beckhoff 授权体系控制；主站侧有商业栈（Acontis、KPA）和开源 IgH EtherCAT Master（Linux，D.12.5 实战用它）。
- 典型地盘：运动控制、机器人关节、半导体设备——轴多、周期快、拓扑呈线/树形的场景。

### PROFINET：交换机里做优先级

PROFINET（IEC 61158，PI 协会）走标准以太网兼容路线，分三档实时等级，按需选档：

- **PROFINET NRT**：标准 TCP/UDP，非实时，跑参数和诊断——和办公网流量平起平坐。
- **PROFINET RT**：实时帧用以太网类型 0x8892 直发，跳过 TCP/IP 协议栈（省掉栈处理延迟），靠 VLAN 优先级（IEEE 802.1Q 的 PCP 字段）在交换机队列里插队。周期 1~10 ms，不需要特殊硬件——标准交换机都认识 VLAN 优先级。
- **PROFINET IRT**：等时同步实时。网络时间被切成"实时通道"和"开放通道"两种时间片，实时帧在自己的时间片里独享链路，需要带 IRT 功能的专用交换机芯片（西门子 ERTEC）。周期可到 250 µs 以下，抖动 <1 µs。

> 时间片调度（Time-slot Scheduling）：把链路时间划分为固定时槽，不同类别的流量各用各的槽。IRT 的时间片思想与 TSN 的 802.1Qbv 时间门（D.14.1）是同一棵技术树上的两个分支——前者是 PROFINET 私有实现，后者是 IEEE 标准化版本。

- 确定性来源：RT 靠优先级排队（软保证），IRT 靠时间片+硬件（硬保证）。

  IRT 的时间片结构（一个周期内的链路时间分配）：

  ```text
  |◀────────── 一个 IRT 周期（如 500 µs）──────────▶|
  ┌────────────────┬───────────────────────────────┐
  │  实时通道       │  开放通道                      │
  │  IRT 帧独享     │  RT 帧 + 标准 TCP/IP 流量      │
  │  （硬实时）     │  （按优先级排队）               │
  └────────────────┴───────────────────────────────┘
   交换机硬件按时刻表切换通道，实时通道内绝无其他流量
  ```

  对照 D.14.1 的 TSN Qbv 时间门看，机制几乎同构——差别在 IRT 需要专用交换机芯片，Qbv 是标准能力。这也是 PROFINET 向"PROFINET over TSN"演进毫无概念障碍的原因。

- 生态：西门子主导，PLC 世界的事实标准；从站按档位选 ERTEC 专用芯片或标准 MAC。
- 典型地盘：汽车产线、流程工业、以 PLC 为中心的工厂自动化。

### EtherNet/IP：标准以太网上的 CIP

EtherNet/IP（ODVA 协会）是"标准以太网 + CIP 应用层"的组合，名字里的"IP"是 Industrial Protocol 不是 Internet Protocol——工业以太网史上最容易误导的命名。

消息分两类通道：**隐式消息**（Implicit Messaging）跑实时 IO 数据，UDP 多播，连接建立后周期性发送，低开销；**显式消息**（Explicit Messaging）跑参数读写和诊断，TCP，按需触发。不加硬件加速时确定性在 1~10 ms 级，靠工程手段保证：专用网段、IGMP snooping 管理多播、QoS 优先级、网络负载规划。

> CIP（Common Industrial Protocol）：EtherNet/IP 承载的应用层协议，用"对象模型"组织设备功能（与 CANopen 对象字典思想相通）：设备由若干对象（Object）组成，对象有属性（Attribute）与服务（Service），按"类—实例—属性"三级寻址。"连接"（Connection）是 CIP 的核心资源：隐式消息建立在周期性连接上，多播让一条 IO 数据可被多个消费者同时接收。CIP 是跨介质的——DeviceNet（CAN 上）与 EtherNet/IP 共用同一套对象模型，这就是"存量 DeviceNet 升级应用层可保留"的机理。

- 确定性来源：协议本身不改 MAC 层，全靠网络工程；时钟同步用 CIP Sync（IEEE 1588 PTP），µs 级。
- 硬件代价：零——纯标准以太网芯片，这是它对 EtherCAT 阵营的卖点。
- 生态：罗克韦尔（Rockwell）主导，北美市场强势；CIP 应用层与 DeviceNet（CAN 上）同源，存量 DeviceNet 网络升级有连续性。
- 典型地盘：北美工厂自动化、过程控制、离散制造的 PLC 网络。

### POWERLINK 与 CC-Link IE：另外两条路线

- **Ethernet POWERLINK**（EPSG 协会）：标准以太网硬件，主站轮询制——一个周期内主站依次点名从站发数据，从站只在自己被点名的时隙发送，冲突被机制性地消除（与 LIN 调度表同思想，速率快五万倍）。主站开源（openPOWERLINK）。奥地利 B&R 主导，欧洲机械装备常见。
- **CC-Link IE**（CLPA 协会）：三菱主导的千兆工业以太网；其 TSN 版本（CC-Link IE TSN）是**第一批商用的 TSN 方案**——新设计用标准 TSN 交换机芯片即可，不再依赖私有硬件。日系设备与亚洲市场常见。
- **Sercos III**：运动控制老牌总线 Sercos 的以太网版本，主从线形拓扑+时分调度，在欧洲机床行业有存量。遇见概率低于前几家，知道它存在即可。

五条路线摆在一起，一个模式浮现了：**消灭不确定性的手段只有三类**——硬件透传（EtherCAT）、时间隔离（IRT/POWERLINK/TSN）、工程规划（EtherNet/IP RT 档）。任何新冒出来的"工业以太网方案"，都可以先归到这三类之一再细看。

### 横向对比

| 维度 | EtherCAT | PROFINET RT/IRT | EtherNet/IP | POWERLINK |
|:---|:---|:---|:---|:---|
| 最小周期 | ~12.5 µs（实用 100 µs） | RT ~1 ms / IRT ~250 µs | ~1 ms | ~200 µs |
| 抖动 | <1 µs（DC 同步 <100 ns） | IRT <1 µs | ms 级 | <1 µs |
| 确定性机制 | 集总帧+硬件透传 | 优先级 / 时间片 | QoS+网络规划 | 主站轮询 |
| 从站硬件 | 必须 ESC 专用芯片 | RT 标准 MAC / IRT 专用芯片 | 标准以太网 | 标准 MAC（FPGA 可选） |
| 主站硬件 | 标准网卡 | RT 标准网卡 / IRT 专用 | 标准网卡 | 标准网卡 |
| 开放性 | ETG 授权，IgH 开源主站 | PI 会员 | ODVA 会员 | 开源主站 |
| 强势生态 | 运动控制、机器人 | 西门子系产线 | 罗克韦尔系（北美） | B&R 系机械 |

表中最值得咀嚼的是"从站硬件"一行：要不要专用芯片，决定了 BOM 成本、供应商锁定和自研可行性的全部差异。

## 生态格局：芯片、协议栈与授权

总览视角下还要看清"谁掌握什么"——这决定项目里哪些东西能自研、哪些必须买：

**从站芯片**（以 EtherCAT 为例，其他阵营同构）：ESC 芯片三选一——Beckhoff ET1100/ET1200（原生）、Microchip LAN9252（集成 PHY，常见）、亚信 AX58100（亚洲供应链友好）。芯片需要 Beckhoff 授权（随芯片采购含授权费），从站设备还要过 ETG 一致性认证才能打 EtherCAT 标。从站开发的真实成本大头不在芯片价格，在**协议栈移植（SSC 代码）+ 认证测试**。

**主站协议栈**：主站侧没有专用硬件约束，竞争在软件栈——商业栈（Acontis EC-Master、KPA）卖性能指标、支持与认证包；开源 IgH EtherCAT Master 免费、Linux 主线之外维护、D.12.5 实战用它。选商业栈还是 IgH 的决策轴是：要不要 vendor 支持、要不要跑在非 Linux 的 RTOS 上、性能要求是否苛刻到要榨干网卡。

**授权与协会**：ETG（EtherCAT）、PI（PROFINET）、ODVA（EtherNet/IP）、EPSG（POWERLINK）——加入协会拿规范与一致性测试资格是从站开发的入场券。协会年费与认证费用要进项目预算，这部分在小团队立项时经常被漏算。

## 与 IT 流量共存的部署纪律

第三个缺口（共存）落到工程上是一组网段纪律：

- **控制网与办公网物理/逻辑隔离**：控制流量走独立网段或 VLAN，与办公网之间只经防火墙/网关互通。EtherNet/IP 多播流量泛滥拖垮办公网是经典事故形态。
- **IGMP snooping 必须开**：不开时多播退化为广播，每个端口都收到视觉相机的视频流，实时流量被冲垮。
- **实时网段不接互联网**：OT 安全（D.14.3 的功能安全是防失效，网络安全是防攻击）的底线；远程维护走跳板机。
- **拓扑文档化**：每条网段的设备清单、IP 规划、交换机端口映射写进竣工文档——十年后维修的人就靠它。

## 应用层的跨协议复用：CoE

有一个能省一半学习成本的事实：**CANopen 的对象字典、PDO/SDO、CiA 402 伺服行规被 EtherCAT 原样继承**。

> CoE（CANopen over EtherCAT）：把 CANopen 应用层装进 EtherCAT 数据报的适配协议。伺服驱动器的对象字典（0x6040 控制字、0x6064 实际位置这些 D.11.4 见过的索引）在两条总线上完全一致——同一个 CiA 402 状态机，同一份 PDO 映射逻辑，只是传输层从 CAN 帧换成了 EtherCAT 数据报。

PROFINET 侧对应的运动行规是 PROFIdrive，概念同构（状态机 + 标准报文），索引不同但思想一致。

所以学习顺序有讲究：先把 D.11.4~11.5 的 CANopen 吃透，D.12 里就只剩"帧怎么跑"是新知识；反过来先在 EtherCAT 项目里摸过 CoE，再回头做 CAN 的伺服控制也只是换传输层。**对象字典这套"用索引寻址设备功能"的抽象，是跨总线迁移能力最强的知识资产**。

## TSN：收敛方向

TSN（Time-Sensitive Networking，IEEE 802.1 族，机制详解见 D.14.1）是以太网标准自身的实时化：802.1AS 时间同步、802.1Qbv 时间感知调度、802.1Qbu 帧抢占等子标准，目标是把"确定性"从各家私有方案变成以太网的标配能力。OPC UA over TSN（D.12.4）被寄望成为统一的应用层。

对工程师的现实意义分两档：车载以太网已经把 TSN 当底座直接上量；工业领域 CC-Link IE TSN 已商用、PROFINET over TSN 在推进，但存量网络的私有方案会长期共存——**TSN 是新设计和预研的必选项，不是替换现有 EtherCAT 网络的紧迫理由**。判断一个工业网络方案有没有未来，看它有没有 TSN 演进路线即可。

## 真实产线的混合组网

单一协议打天下的产线几乎不存在。一条典型的新能源电池产线长这样：

```text
                    ┌─────────────┐
                    │ SCADA / MES  │  OPC UA / 数据库接口
                    └──────┬──────┘
                    ───────┼─────── 工厂骨干（标准以太网/光纤环网）
              ┌────────────┼────────────┬─────────────┐
        ┌─────┴─────┐ ┌────┴─────┐ ┌────┴─────┐ ┌─────┴────┐
        │ 主控 PLC   │ │ 机器人    │ │ 视觉检测  │ │ 仪表/温控 │
        │ PROFINET  │ │ 控制器    │ │ 工位      │ │ Modbus   │
        └─────┬─────┘ │ EtherCAT │ │EtherNet/IP│ │ TCP      │
              │       └────┬─────┘ └──────────┘ └──────────┘
        分布式 IO 岛        │
        （RT 级）      六轴伺服+附加轴
                      （CoE/CiA 402，周期 1 ms）
```

这张图的读法：

- **协议按工位特性分布**：机器人控制器内部用 EtherCAT（多轴同步刚需），主控 PLC 用 PROFINET（西门子体系），视觉工位是罗克韦尔相机就走 EtherNet/IP——每种协议出现在它生态最强的位置。
- **协议之间不直连**：跨协议数据全部经主控 PLC 或 SCADA 汇聚（PLC 同时跑 PROFINET 主站和 EtherCAT 网关），或靠 OPC UA 在上层做语义统一。这就是为什么选型矩阵里"生态锁定"比技术指标权重高——**你的产线协议版图，往往在你入职前十年就被供应商名单决定了**。
- **网关是第一类常见外购件**：EtherCAT↔PROFINET、CAN↔EtherCAT 这类网关是成熟商品（HMS Anybus、Hilscher netX 系列芯片），自研网关几乎总是不划算的。

## 选型矩阵

| 项目约束 | 收敛方向 | 理由 |
|:---|:---|:---|
| 多轴伺服，周期 ≤1 ms，轴间同步 | EtherCAT | 集总帧+DC 为此设计；机器人/半导体设备事实标准 |
| 西门子 PLC 为中心的产线 | PROFINET | 生态锁定，与 TIA Portal 工具链一体 |
| 北美项目、罗克韦尔体系 | EtherNet/IP | 同上，生态锁定 |
| 预算敏感、IO 为主、周期 ≥1 ms | PROFINET RT / EtherNet/IP / Modbus TCP | 标准硬件即可，不必为性能过剩付费 |
| 日系设备对接 | CC-Link IE（TSN） | 生态锁定 |
| 新架构预研、跨厂商统一 | OPC UA over TSN | 标准演进方向 |
| 与 CAN 节点混存 | EtherCAT + CAN 网关，或 CANopen | CoE 复用应用层，网关成熟 |

> 💡
> 选型矩阵里"生态锁定"出现的次数比技术指标多——这是工业总线选型的真实常态：技术指标决定"能不能做"，生态决定"做得起做不起"。产线设备的维护周期是十年起步，选型的头号问题是十年后还能不能买到备件、找到会修的人。

## 排障：总览层的误判

总览篇的"故障"是选型层面的误判，列四个高频的：

| 误判 | 后果 | 纠正 |
|:---|:---|:---|
| 以为 EtherCAT 从站可以用普通 PHY | 设计打回：集总帧透传必须 ESC 芯片 | 立项时确认从站芯片供货与授权 |
| 以为 PROFINET RT 能做 250 µs 多轴同步 | 性能不达标：RT 是软实时档 | 需要 IRT 档+专用交换机，或直接换 EtherCAT |
| 以为工业以太网之间可以直连互通 | 现场集成失败 | 协议互不相同，跨协议必须网关或上层 SCADA 汇聚 |
| 以为上了 EtherCAT 就有硬实时 | 主站在标准 Linux 上抖动失控 | 实时性在主站操作系统——配 PREEMPT_RT（E.15.6），总线只管传输确定性 |
| 控制网段直接挂办公交换机 | 视频/备份流量冲垮实时帧；OT 安全事故 | 网段隔离+VLAN，IGMP snooping 必开，实时网段不接互联网 |

## 本节总结

工业以太网的版图用一条主线就能记住：**每个方案都是"确定性三缺口"（时延/同步/共存）的一种解法，差异全在改哪层**。EtherCAT 改从站硬件（ESC 集总帧透传，延迟是帧长的函数而非负载的函数），PROFINET 改交换机（RT 优先级、IRT 时间片），EtherNet/IP 哪层都不改（全靠网络工程，卖点是零专用硬件），POWERLINK 改通信纪律（主站轮询）。应用层有意外之喜：CANopen 的对象字典和 CiA 402 经 CoE 原样迁移到 EtherCAT，学完 CANopen 再学 EtherCAT 只剩传输层。长期方向是 TSN——判断方案有没有未来，看它有没有 TSN 演进路线。选型时记住矩阵里出现最多的词是"生态锁定"：技术决定能不能做，生态决定做得起做不起。最后别忘总览层最常见的那条误判：EtherCAT 保证的是**传输**确定性，主站 Linux 的调度实时性要另配 PREEMPT_RT——总线和操作系统各管一半，缺哪一半都不是硬实时。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 三缺口 | 确定性时延、全网同步、IT 流量共存 |
| EtherCAT | 一帧过全网；从站必须 ESC 芯片，主站纯软件 |
| PROFINET | 三档选档：NRT 办公、RT 优先级、IRT 时间片 |
| EtherNet/IP | 零专用硬件，确定性靠网络工程；北美罗克韦尔系 |
| CoE | CANopen 对象字典跨总线复用，学习成本减半 |
| TSN | 新设计必选；判断方案未来的试金石 |
| 三类确定性手段 | 硬件透传 / 时间隔离 / 工程规划，新方案先归类再细看 |
| 共存纪律 | 控制网段隔离、IGMP snooping 必开、实时网段不上互联网 |
| 隐性成本 | 协会年费+一致性认证+协议栈移植，立项预算别漏 |
