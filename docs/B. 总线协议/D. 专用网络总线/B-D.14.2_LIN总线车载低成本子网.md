# B-D.14.2 LIN 总线：车载低成本子网

> 所属章节：第五部 B. 总线协议 > D. 专用网络总线
>
> 难度：[B] | 预计阅读时间：25 分钟

## 本节导读

车身里大量节点根本不需要 CAN：车窗升降、座椅调节、雨刷、氛围灯——数据量小、速度无所谓、成本敏感。LIN（Local Interconnect Network）就是为这类节点设计的：单线、UART 物理层、主从轮询、最高 20 kbps，节点成本压到 CAN 的几分之一。机器人行业里 LIN 用得少，但"低成本单主子网"的设计思想——以及它与 CAN 的边界划分——值得每个做整机总线规划的工程师建立认知。

本节覆盖：LIN 的物理层与帧结构、主从调度表机制、LIN 与 CAN 的分工边界、Linux 下的 LIN 接入方式、典型故障。

## 物理层：一根线的 UART

LIN 用单根信号线（相对地），电平沿用 12 V 车规逻辑：显性（0）拉到接近 0 V，隐性（1）靠上拉到电池电压（VBAT）。物理层本质是带车规电平转换的 UART——19200 bps 以内，8N1 格式。

```
 主机节点                          从机节点 ×N（最多 16）
 ┌──────────┐                      ┌──────────┐
 │ UART_TX/RX│                     │ UART      │
 │ LIN 收发器│──── LIN 线 ─────────┤ LIN 收发器 │
 │ （上拉 1kΩ+二极管）             │（上拉 30kΩ）│
 └──────────┘                      └──────────┘

 主机上拉 1 kΩ（强），从机上拉 30 kΩ（弱）
 显性时任意节点拉低总线 → 线与特性，与 CAN 同思想
```

主机/从机上拉电阻的不对称（1 kΩ vs 30 kΩ）是 LIN 电气规范的关键点：主机主导总线电平能力，从机只在其应答时隙驱动。收发器芯片如 TJA1021、MCP2003，把 MCU 的 UART 电平转成 LIN 总线电平。

## 帧结构与调度表

LIN 帧固定两段：主机发帧头（Header），指定节点回应答（Response）。从机永远不允许主动发——这是 LIN 与 CAN 仲裁制的根本区别，冲突在机制上不存在。

```
 一帧 = 帧头（主机发） + 应答（指定从机或主机自己发）

 帧头：  Break 场（≥13 位显性，唤醒+帧起始）
         Sync 场（0x55，从机用它自动校准波特率）
         PID（保护标识符：6 位 ID + 2 位奇偶校验）

 应答：  数据 1~8 字节 + 校验和
         校验和两档：经典校验（仅数据）/ 增强校验（数据+PID，LIN 2.x）
```

主机的**调度表（Schedule Table）**决定总线上发生什么：调度表是一张静态的时间表，定义了依次发出哪些帧头、每帧间隔多少槽位时间。网络行为完全可预测——LIN 的确定性不是靠仲裁赢来的，是靠"一切都在表里"得来的。诊断帧、事件触发帧（多个从机共享一个应答时隙，有数据才抢答，冲突时回退到逐个点名）是标准轮询之外的补充机制。

> LIN 与 CAN 的设计哲学对照：CAN 把智能放在每个节点（仲裁），LIN 把智能集中在主机（调度表）。前者灵活抗单点，后者便宜可预测。总线选型里"集中 vs 分布"这条轴线，LIN 和 CAN 是两端的教科书样本。

## LIN 与 CAN 的分工

| 维度 | LIN | CAN / CAN FD |
|:---|:---|:---|
| 速率 | ≤20 kbps | 1 M / 8 Mbps |
| 线数 | 1 | 2（差分） |
| 节点成本 | 极低（UART + 便宜收发器） | 中 |
| 节点数 | ≤16 | ~110（电气限制） |
| 冲突机制 | 无（主机轮询） | 非破坏仲裁 |
| 实时性 | 由调度表保证 | 由优先级保证 |
| 典型节点 | 车窗、座椅、雨刷、灯光、空调面板 | 动力、底盘、安全、诊断 |

分工规则：安全相关、跨域通信、诊断主干一律 CAN；单功能执行器、人机界面小件用 LIN。一辆车里 LIN 子网通常有十条以上，各由车身域控制器或对应 ECU 当主机。

## Linux 下的 LIN 接入

Linux 没有原生 LIN 子系统，工程上三条路：

1. **UART + 外部 LIN 收发器**：LIN 帧就是 UART 字节流，用 tty 直接收发；Break 场的产生依赖 UART 的 break 控制（`TIOCSBRK` 或自定义波特率技巧）。适合主机角色的简单实现，时序精度一般。
2. **USB-LIN 适配器**：以 slcan 兼容或厂商私有协议接入，应用层走串口或 SocketCAN 风格接口。
3. **MCU 协处理**：实时性敏感的主机调度放 MCU 上跑，Linux 通过 SPI/UART 与 MCU 交互。量产车身控制器的主流形态。

多数嵌入式工程师与 LIN 的交集是第二条或第三条——理解协议帧格式足够你做网关转发和诊断，不必在 Linux 里自己实现调度表。

## 排障：LIN 常见故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 从机全部无应答 | 主机 Break/Sync 场时序不对；上拉电阻错 | 示波器看 Break ≥13 位显性、Sync=0x55 |
| 单个从机不应答 | PID 分配错；从机 NAD（地址）配置 | 换已知好的从机交叉验证 |
| 偶发校验错 | 经典/增强校验混用（LIN 1.x 与 2.x 节点混网） | 核对各节点 LIN 版本与校验类型 |
| 波特率漂移丢帧 | 从机内部 RC 振荡器精度差 | Sync 场自动校准是否使能；温度范围复测 |
| 休眠唤不醒 | 唤醒信号时长不够（显性 250 µs~5 ms） | 示波器量唤醒脉冲宽度 |
