# B-D.13.3 SPDIF 与音频接口选型

> 所属章节：第五部 B. 总线协议 > D. 专用网络总线
>
> 难度：[I] | 预计阅读时间：45 分钟

## 本节导读

I2S 解决的是板内几厘米的音频传输。设备到设备——电视到功放、播放器到音响——就要换接口。SPDIF 是消费级设备间数字音频的事实标准，用一根线（光纤或同轴）把数字音频原样送达对端，中途不做数模转换。本节讲清 SPDIF 的物理介质、帧结构与双相标记编码，在 Linux 上把 SPDIF 输出实际跑通，然后把 I2S/SPDIF/TDM/USB Audio 四种接口放在一起，给出按场景收敛的选型方法。

> 本节覆盖：SPDIF 的定位与两种物理介质、子帧/帧/块三级结构与三种同步头、BMC 编码与时钟恢复、PCM 与压缩码流两种载荷、Linux 上的 IEC958 设备与 AC3 透传、线速率速算、四种音频接口的量化对比、按场景的选型决策、硬件实现路径与排障。按"线长什么样 → 帧怎么组织 → 时钟怎么恢复 → Linux 上怎么用 → 四种接口怎么选 → 坏了怎么查"展开——这正是你给产品加一路数字音频输出时的实际顺序。

读完你应该能独立完成三件事：为产品选定音频接口并说出被否决方案的理由、在 Linux 上把 SPDIF 声卡配置出来并完成 PCM 放音与 AC3 透传、对着示波器波形判断 SPDIF 链路故障出在哪一段。

## SPDIF 定位与物理介质

SPDIF（Sony/Philips Digital Interface，IEC 60958-3）从专业音频的 AES3 简化而来：阻抗从 110 Ω 降到 75 Ω，连接器从 XLR 换成 RCA/TOSLINK，帧结构基本继承。消费设备上你会同时见到两种物理形态：

| 维度 | 光纤（TOSLINK） | 同轴（RCA） |
|:---|:---|:---|
| 介质 | 塑料光纤，光脉冲 | 75 Ω 同轴电缆 |
| 距离 | <10 m（塑料光纤衰减大，典型 <5 m） | <10 m |
| 抗电磁干扰 | 完全隔离（无电气连接） | 一般 |
| 弯曲半径 | ≥25 mm，过度弯折断光路 | 无约束 |
| 载荷 | PCM / AC3 / DTS | 相同 |
| 成本 | 需光电收发器 | RCA 插座即可 |

两种介质的协议层完全一致，选哪个看距离与干扰环境：强干扰环境（功放电源旁、电机旁）用光纤——电气隔离同时切断了地环路，共模噪声随之一刀两断；其余用同轴省钱。同轴线要认准 75 Ω 阻抗，拿普通音频 RCA 线代替是"声道里混着噪声"的经典来源。

## 帧结构：子帧、帧、块

SPDIF 帧继承 AES3 结构，分三级组织：

> 子帧（Subframe）：一个声道一个采样点的运输单元，32 bit——4 bit 同步头 + 24 bit 音频数据 + 4 bit 状态位（V/U/C/P）。
>
> 帧（Frame）：左右两个子帧拼成一帧，对应一个采样时刻的立体声数据。
>
> 块（Block）：192 帧为一块，块起始处换用特殊同步头 Z——接收端靠它对齐声道状态数据的起点。

```
 子帧 32 bit：
 ┌────────┬──────────────────────┬───┬───┬───┬───┐
 │ 同步头  │    音频数据 24 bit    │ V │ U │ C │ P │
 │ 4 bit  │                      │有效│用户│状态│校验│
 └────────┴──────────────────────┴───┴───┴───┴───┘

 帧 = 子帧 A（左声道，头 X）+ 子帧 B（右声道，头 Y）
 块 = 192 帧，首帧左声道用头 Z（标识声道状态块起点）
```

三种同步头 X/Y/Z 是**故意违反 BMC 编码规则**的跳变图案——正常数据位周期边界必跳变，同步头在某些边界不跳，接收端因此能绝无歧义地认出"这里是一帧的开头"。这是所有自时钟串行协议通用的 framing 手法：用编码违规当逗号。三者分工固定：X 头 = 普通帧左声道、Y 头 = 右声道、Z 头 = 块首帧的左声道（192 帧块起点）。

X/Y/Z 的具体图案用"8 个半位时隙的跳变序列"区分（1=有跳变、0=无跳变）：

| 同步头 | 图案 | 语义 |
|:---|:---|:---|
| X | 11101000 | 普通帧左声道 |
| Y | 11100100 | 右声道 |
| Z | 11100010 | 块首帧左声道（声道状态块对齐点） |

正常数据位的图案只可能是 1100 或 1110 两种（边界必跳、中间可选），上面三种图案都落在合法集合之外——这就是违规编码能当帧界的数学基础。用协议分析仪抓 SPDIF 流时，帧边界标注靠的就是认出这三个图案。

末尾的 C 位（Channel Status）容易被忽略但排障常用：连续 192 帧的 C 位拼成 192 bit 声道状态块，里面写着采样率、位宽、是否预加重、以及"数据是 PCM 还是压缩码流"的 non-audio 标志位。接收端功放显示"48 kHz PCM"靠的就是它——AC3 透传时源端必须把这个位置成 non-audio，否则功放会把压缩数据当 PCM 解，输出一耳朵噪声。

与专业版 AES3 的关系顺带理清，遇到调音台、广播机房场景用得上：

| 维度 | SPDIF（IEC 60958-3） | AES3（AES3 / IEC 60958-4） |
|:---|:---|:---|
| 电平/阻抗 | 0.5 Vpp / 75 Ω 不平衡 | 2~7 Vpp / 110 Ω 平衡 |
| 连接器 | RCA / TOSLINK | XLR 卡侬 |
| 距离 | <10 m | <100 m |
| 状态块含义 | 消费级位定义 | 专业级位定义（部分位含义不同） |

帧结构与 BMC 编码两者完全相同，差别全在电气层与状态块语义。互接需要电平转换（变压器或专用收发芯片），直连轻则噪声重则不识码。

## BMC 编码：为什么一根线够

SPDIF 没有时钟线，时钟从数据流里恢复，靠的是双相标记编码（BMC）：

> BMC（Biphase Mark Code，双相标记编码）：每个位周期边界必有一次电平跳变；数据 1 在位周期中间再跳一次，数据 0 不跳。等价于用跳变密度换时钟——跳变永不缺席，接收端 PLL 就有东西可锁。

```
 数据:     0       1       0       1
        ┌────┐  ┌──┐┌──┐  ┌────┐  ┌──┐┌──┐
 信号:  │    └──│  └┘  └──┘    └──│  └┘  └──
        ↑       ↑  ↑  ↑   ↑       ↑  ↑  ↑
        边界跳变  边界+中间两次跳变
```

BMC 的两个直接收益：跳变密度有下界（每位至少一次），长串 0 也不会失锁，所以单线传输成立；信号无直流分量，可以变压器隔离、AC 耦合。代价是线速率为音频数据率的两倍，以及接收端 PLL 会引入少量时钟抖动。

> jitter（抖动）：恢复时钟边沿相对理想位置的微小偏移。音频场景里 jitter 直接调制 DAC 的采样时刻，转换成底噪与失真。发烧音频场景嫌弃 SPDIF 的 jitter，根源就是 BMC 必须靠 PLL 恢复时钟——而 I2S 主从共用时钟线，没有这一层。这是"时钟质量"成为选型维度的原因。

jitter 的工程对策也有标准答案，按成本从低到高：缩短链路并换好线（减少 PLL 输入侧的抖动源）；用带高质量 PLL 的 DIR 芯片（如 DIR9001）做恢复，它的片内 PLL 环路带宽决定了对输入抖动的抑制能力；终极方案是 ASRC（异步采样率转换）——用本地低抖动时钟重新采样，代价是引入微小采样率误差与额外延迟。HiFi DAC 产品里"SPDIF 输入级"宣传的低 jitter 设计，指的就是后两条的组合。

## 载荷：PCM 与压缩码流

载荷分两类，由声道状态块的 non-audio 位区分：

- **无压缩 PCM**：最高 24 bit / 192 kHz，但**只有立体声两个声道**——帧结构里就两个子帧，这是硬上限。
- **压缩码流**：AC3（Dolby Digital 5.1，约 640 kbps）、DTS（5.1）。SPDIF 只当管道不解码，压缩数据原样装进 24 bit 数据域送到功放的解码器。

> 💡
> 要传 5.1 声道的无压缩 PCM，SPDIF 做不到。三个出路：压缩成 AC3/DTS 走 SPDIF；换 HDMI（8 声道 LPCM）；板内多声道走 TDM。选型时先数声道数，再定接口。

## 线速率速算

线速率 = Fs × 64 bit（帧长）× 2（BMC 翻倍）。常用档位：

| 采样率 | 线速率 | 备注 |
|:---|:---|:---|
| 44.1 kHz | 5.645 Mbps | CD 格式 |
| 48 kHz | 6.144 Mbps | 视频/嵌入式最常见 |
| 96 kHz | 12.288 Mbps | 高解析 |
| 192 kHz | 24.576 Mbps | 上限，塑料光纤衰减下裕量紧张 |

排障时这个表是示波器带宽的依据：192 kHz 档信号边沿已到 24 MHz 基波，示波器带宽至少 5 倍基波即 120 MHz 起，否则看到的圆角波形不能作为判决依据。高速档掉锁先查光纤质量与长度，再怀疑收发器。

## Linux 上的 SPDIF：IEC958 设备

SoC 内置 SPDIF 控制器的平台（RK3568、全志 H6 等）注册出的声卡在 ALSA 里就是普通 PCM 设备，传统别名是 IEC958。确认与放音：

```text
# aplay -l
card 0: rkspdif [rk-spdif], device 0: ffxx0000.spdif-dit-hifi dit-hifi-0 []
  Subdevices: 1/1

# aplay -D plughw:0,0 -v test48k.wav
Playing WAVE 'test48k.wav' : Signed 16 bit Little Endian, Rate 48000 Hz, Stereo
Hardware PCM card 0 'rk-spdif' device 0 subdevice 0
Its setup is:
  format       : S16_LE
  rate         : 48000            ← SPDIF 对采样率敏感，必须与源匹配
```

两个 SPDIF 特有的注意点：

- **采样率必须严格匹配**。SPDIF 没有重采样余地——接收端 PLL 按状态块里的采样率锁相，源端发 44.1 kHz 内容而系统按 48 kHz 配置，结果就是无声或音调不对。`plughw` 会做重采样转换，`hw` 直开则要求文件与设备参数一致。
- **AC3/DTS 透传是另一个用法**：应用把压缩帧原样写入 IEC958 设备，同时驱动把状态块的 non-audio 位置位。ALSA 侧对应 `iec958` 的 AES 控制接口（`iecset` 工具可查看/修改状态位）；Kodi 这类播放器里的"passthrough"开关最终落在这里。

```text
# iecset -c 0
... 
Data: audio                    ← audio=PCM；non-audio=AC3/DTS 透传
Rate: 48000                    ← 状态块里声明的采样率
```

排障时 `iecset` 输出是第一现场：功放端不识码先核对 `Data` 位与 `Rate` 是否与源内容一致。

## 四种音频接口对比

| 维度 | I2S | SPDIF | TDM | USB Audio |
|:---|:---|:---|:---|:---|
| 信号线 | 3~4 根 | 1 根 | 2~3 根 | 2 根（D+/D−） |
| 距离 | <30 cm（板内） | <10 m | <30 cm（板内） | <5 m |
| 通道数 | 2 | 2（PCM）/5.1（压缩） | 4~16+（时隙复用） | 带宽内任意 |
| 时钟 | 专用时钟线，主从同源 | 接收端 PLL 恢复 | 同 I2S | 异步/同步/自适应三种模式 |
| 额外芯片 | 无（SoC 自带控制器） | 收发器/内置 SPDIF 控制器 | 无 | USB 控制器 + UAC 驱动 |
| 典型应用 | 板内 Codec | 电视→功放 | 麦克风阵列 | USB 声卡/耳机 |

四个维度的取舍逻辑：

1. **距离**：板内用 I2S/TDM；跨设备用 SPDIF 或 USB。I2S 的 BCLK 在 48 kHz/32 bit/2ch 下已到 3 MHz 量级，走线一长就串扰，不出板是它的物理边界。
2. **通道数**：2 声道以内 I2S 或 SPDIF；4~16 声道 TDM 一根数据线复用，是麦克风阵列的标准做法；任意通道数 USB Audio 带宽兜底。
3. **时钟质量**：I2S/TDM 主从同源，jitter 最小；SPDIF 的 PLL 恢复引入 jitter；USB Audio 异步模式让设备端做主时钟、主机跟随，是 USB 音频音质最好的模式。
4. **开发量**：I2S/TDM 用 SoC 自带控制器加设备树即可；SPDIF 需要 SoC 内置控制器或外挂收发芯片；USB Audio 设备端走 Gadget（见 B-C.7.4），主机端 UAC2 免驱。

## 按场景收敛

| 场景 | 收敛 | 理由 |
|:---|:---|:---|
| 板内 SoC ↔ Codec | I2S | 零额外芯片，ASoC 框架直接支持 |
| 电视/盒子 → 功放 | SPDIF 光纤优先 | 长距、抗扰、消费设备标配 |
| 4~8 麦克风阵列 | TDM | 一线多通道，走线最少 |
| 外置声卡/HiFi DAC | USB Audio 异步 | UAC2 免驱，jitter 低 |
| 车载多声道板间 | TDM | 短距多声道，车规 Codec 普遍支持 |
| 专业调音台/录音 | AES3 / MADI | 专业标准，距离与通道数上限高 |

真实产品里是组合的：智能音箱内部"PDM 麦克风 → DSP（TDM 汇总）→ I2S → 板载 Codec → 模拟功放"，对外再留一个 SPDIF 输出接用户音响。选型不是选一个协议，是给每段链路各选一个。

## SPDIF 硬件实现路径

```
 路径 A：SoC 内置 SPDIF 控制器（RK3568、全志 H6 等）
   SoC SPDIF_TX 引脚 ──► TOSLINK 发射器（如 DLR1150）──► 光纤

 路径 B：外挂转换芯片（SoC 只有 I2S 时）
   SoC ── I2S ──► WM8804/CS8406（I2S→SPDIF）──► TOSLINK/RCA 缓冲
```

内核里路径 A 对应 SoC 的 SPDIF DAI 驱动，路径 B 对应 `sound/soc/codecs/wm8804.c` 这类收发器驱动，两者对上层都呈现为普通声卡，ASoC 配置方式与 13.2 相同。接收方向同理：DIR9001 这类 SPDIF→I2S 恢复芯片把光/同轴信号还原成 I2S 进 SoC，同时完成时钟恢复——它的 PLL 质量直接决定这一路的 jitter 水平。

硬件侧还有两个常被漏掉的细节：TOSLINK 发射器（如 DLR1150）是 5 V 供电的有源器件，SoC 的 SPDIF_TX 是 3.3 V 逻辑，中间要确认电平兼容或加缓冲；同轴输出端必须按 75 Ω 端接（串联电阻 + 插座端并联），省掉端接电阻的电路在短线上"能工作"，长线和温度变化下就是间歇性失锁的来源。

## 排障：SPDIF 故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 光纤无信号 | TOSLINK 防尘盖未拨开；发射器未供电 | 看发射端是否有红光（Class 1，人眼安全）——SPDIF 排障第一步永远是看光 |
| 有声但断续/爆音 | 接收端 PLL 失锁：线过长、弯折、连接器松动 | 换短线对比；量接收端恢复时钟稳定性 |
| 声道里混着噪声 | 同轴阻抗不匹配（用了非 75 Ω 线） | 换 75 Ω 同轴线 |
| 5.1 输出变成立体声 | 源端输出的是 PCM 而非 AC3/DTS 透传 | 源端设置开 bitstream/透传；`iecset` 核对 Data 位 |
| 功放显示采样率不对 | 状态块 Rate 与实际不符 | `iecset -c 0` 看 Rate；`aplay -v` 看协商采样率 |
| 功放把 AC3 放成噪声 | non-audio 位未置位，压缩数据被当 PCM 解 | `iecset` 确认 Data: non-audio |
| 示波器看不到干净波形 | 线速率是 Fs×128，示波器带宽不足 | 48 kHz 对应 6.144 Mbps，用 ≥100 MHz 带宽示波器 |
| 192 kHz 高采样率掉锁 | 塑料光纤衰减在高频下急剧恶化 | 换短光纤或玻璃光纤；或改用同轴介质 |
| 间歇性失锁（温度相关） | 同轴端未按 75 Ω 端接 | 补端接电阻；换合格线缆 |

排障顺序和 13.4 一脉相承：先软件（采样率、状态位、透传开关）后物理（光、线、端接）——SPDIF 的软件状态全浓缩在 `aplay -v` 和 `iecset` 两条命令里，三十秒就能排除一整层嫌疑。

## 本节总结

SPDIF 的存在回答了"板间/设备间音频怎么走"：用一根线、自时钟、原样送达。三个机制撑起这个定位——BMC 编码用强制跳变密度换来无时钟线（代价是两倍线速率与 PLL jitter，这是它音质天花板的根源）；X/Y/Z 同步头用编码违规实现无歧义帧对齐；192 帧的声道状态块携带采样率与 non-audio 标志，接收端的显示与 AC3 透传全靠它。工程上要带走的硬数字是：PCM 双声道是硬上限、5.1 必须压缩、48 kHz 线速率 6.144 Mbps、光纤排障第一步看红光。选型维度收敛为四个——距离、通道数、时钟质量、开发量，真实产品是 I2S/TDM/SPDIF/USB 按链路分段组合，而不是单选其一。Linux 侧没有新概念：IEC958 就是普通声卡，`aplay -v` 看采样率、`iecset` 看状态位，两处对上了再怀疑物理层。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 定位 | 设备间数字音频管道；中途不做数模转换 |
| 介质选择 | 强干扰/要隔离→光纤；其余→75 Ω 同轴 |
| BMC | 位边界必跳变、1 中间再跳；无时钟线的根基，jitter 的来源 |
| 帧结构 | 子帧 32 bit（头+24 数据+V/U/C/P）；192 帧一块 |
| 声道上限 | PCM 只有 2 声道；5.1 走 AC3/DTS 压缩透传 |
| 状态块 | C 位拼成 192 bit；采样率与 non-audio 标志在此 |
| 线速率 | Fs × 128：48 kHz = 6.144 Mbps |
| Linux | IEC958=普通声卡；aplay -v 查率、iecset 查状态位 |
| 排障 | 光纤先看红光；断续查 PLL 失锁；噪声查 75 Ω |
