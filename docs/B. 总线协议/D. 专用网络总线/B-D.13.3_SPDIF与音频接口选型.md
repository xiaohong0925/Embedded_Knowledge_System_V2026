# B-D.13.3 SPDIF 与音频接口选型

> 所属章节：第五部 B. 总线协议 > D. 专用网络总线
>
> 难度：[I] | 预计阅读时间：25 分钟

## 本节导读

I2S 解决的是板内几厘米的音频传输。设备到设备——电视到功放、播放器到音响——就要换接口。SPDIF 是消费级设备间数字音频的事实标准，用一根线（光纤或同轴）把数字音频原样送达对端，中途不做数模转换。本节讲清 SPDIF 的物理介质、帧结构与双相标记编码，然后把 I2S/SPDIF/TDM/USB Audio 四种接口放在一起，给出按场景收敛的选型方法。

本节覆盖：SPDIF 的定位与两种物理介质、PCM 与压缩码流两种载荷、BMC 编码与时钟恢复、四种音频接口的量化对比、按场景的选型决策、SPDIF 的硬件实现路径与排障要点。

## SPDIF 定位与物理介质

SPDIF（Sony/Philips Digital Interface，IEC 60958-3）从专业音频的 AES3 简化而来：阻抗从 110 Ω 降到 75 Ω，连接器从 XLR 换成 RCA/TOSLINK，帧结构基本继承。

| 维度 | 光纤（TOSLINK） | 同轴（RCA） |
|:---|:---|:---|
| 介质 | 塑料光纤，光脉冲 | 75 Ω 同轴电缆 |
| 距离 | <10 m（塑料光纤衰减大，典型 <5 m） | <10 m |
| 抗电磁干扰 | 完全隔离（无电气连接） | 一般 |
| 弯曲半径 | ≥25 mm，过度弯折断光路 | 无约束 |
| 载荷 | PCM / AC3 / DTS | 相同 |
| 成本 | 需光电收发器 | RCA 插座即可 |

两种介质的协议层完全一致，选哪个看距离与干扰环境：强干扰环境（功放电源旁、电机旁）用光纤，其余用同轴省钱。

## 载荷：PCM 与压缩码流

SPDIF 帧继承 AES3 结构：每帧两个子帧（左/右声道），子帧 32 bit——4 bit 同步头（preamble，X/Y/Z 三种变体标识声道与块边界）+ 24 bit 音频数据 + 4 bit 状态位（V/U/C/P）。线速率 = Fs × 64 bit × 2（BMC 编码翻倍）：48 kHz 时 6.144 Mbps。

载荷分两类：

- **无压缩 PCM**：最高 24 bit / 192 kHz，但**只有立体声两个声道**——帧结构里就两个子帧，这是硬上限。
- **压缩码流**：AC3（Dolby Digital 5.1，约 640 kbps）、DTS（5.1）。SPDIF 只当管道不解码，压缩数据原样送到功放的解码器。

> 💡
> 要传 5.1 声道的无压缩 PCM，SPDIF 做不到。三个出路：压缩成 AC3/DTS 走 SPDIF；换 HDMI（8 声道 LPCM）；板内多声道走 TDM。选型时先数声道数，再定接口。

## BMC 编码：为什么一根线够

SPDIF 没有时钟线，时钟从数据流里恢复，靠的是双相标记编码（BMC）：

```
 规则：每个位周期边界必有一次电平跳变；
       数据 1 在位周期中间再跳一次，数据 0 不跳。

 数据:     0       1       0       1
        ┌────┐  ┌──┐┌──┐  ┌────┐  ┌──┐┌──┐
 信号:  │    └──│  └┘  └──┘    └──│  └┘  └──
        ↑       ↑  ↑  ↑   ↑       ↑  ↑  ↑
        边界跳变  边界+中间两次跳变

 接收端 PLL 锁定跳变沿 → 恢复位时钟 → 解出数据
```

BMC 的两个直接收益：跳变密度有下界（每位至少一次），长串 0 也不会失锁，所以单线传输成立；信号无直流分量，可以变压器隔离、AC 耦合。代价是线速率为音频数据率的两倍，以及接收端 PLL 会引入少量时钟抖动——发烧音频场景嫌弃 SPDIF 的 jitter，根源就在这里。

## 四种音频接口对比

| 维度 | I2S | SPDIF | TDM | USB Audio |
|:---|:---|:---|:---|:---|
| 信号线 | 3~4 根 | 1 根 | 2~3 根 | 2 根（D+/D−） |
| 距离 | <30 cm（板内） | <10 m | <30 cm（板内） | <5 m |
| 通道数 | 2 | 2（PCM）/5.1（压缩） | 4~16+（时隙复用） | 带宽内任意 |
| 时钟 | 专用时钟线，主从同源 | 接收端 PLL 恢复 | 同 I2S | 异步/同步/自适应三种模式 |
| 额外芯片 | 无（SoC 自带控制器） | 收发器/内置 SPDIF 控制器 | 无 | USB 控制器 + UAC 驱动 |
| 典型应用 | 板内 Codec | 电视→功放 | 麦克风阵列 | USB 声卡/耳机 |

四个维度的取舍逻辑：

1. **距离**：板内用 I2S/TDM；跨设备用 SPDIF 或 USB。I2S 的 BCLK 在 48 kHz/32 bit/2ch 下已到 3 MHz 量级，走线一长就串扰，不出板是它的物理边界。
2. **通道数**：2 声道以内 I2S 或 SPDIF；4~16 声道 TDM 一根数据线复用，是麦克风阵列的标准做法；任意通道数 USB Audio 带宽兜底。
3. **时钟质量**：I2S/TDM 主从同源，jitter 最小；SPDIF 的 PLL 恢复引入 jitter；USB Audio 异步模式让设备端做主时钟、主机跟随，是 USB 音频音质最好的模式。
4. **开发量**：I2S/TDM 用 SoC 自带控制器加设备树即可；SPDIF 需要 SoC 内置控制器或外挂收发芯片；USB Audio 设备端走 Gadget（见 B-C.7.4），主机端 UAC2 免驱。

## 按场景收敛

| 场景 | 收敛 | 理由 |
|:---|:---|:---|
| 板内 SoC ↔ Codec | I2S | 零额外芯片，ASoC 框架直接支持 |
| 电视/盒子 → 功放 | SPDIF 光纤优先 | 长距、抗扰、消费设备标配 |
| 4~8 麦克风阵列 | TDM | 一线多通道，走线最少 |
| 外置声卡/HiFi DAC | USB Audio 异步 | UAC2 免驱，jitter 低 |
| 车载多声道板间 | TDM | 短距多声道，车规 Codec 普遍支持 |
| 专业调音台/录音 | AES3 / MADI | 专业标准，距离与通道数上限高 |

真实产品里是组合的：智能音箱内部"PDM 麦克风 → DSP（TDM 汇总）→ I2S → 板载 Codec → 模拟功放"，对外再留一个 SPDIF 输出接用户音响。选型不是选一个协议，是给每段链路各选一个。

## SPDIF 硬件实现路径

```
 路径 A：SoC 内置 SPDIF 控制器（RK3568、全志 H6 等）
   SoC SPDIF_TX 引脚 ──► TOSLINK 发射器（如 DLR1150）──► 光纤

 路径 B：外挂转换芯片（SoC 只有 I2S 时）
   SoC ── I2S ──► WM8804/CS8406（I2S→SPDIF）──► TOSLINK/RCA 缓冲
```

内核里路径 A 对应 SoC 的 SPDIF DAI 驱动，路径 B 对应 `sound/soc/codecs/wm8804.c` 这类收发器驱动，两者对上层都呈现为普通声卡，ASoC 配置方式与 13.2 相同。

## 排障：SPDIF 故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 光纤无信号 | TOSLINK 防尘盖未拨开；发射器未供电 | 看发射端是否有红光（Class 1，人眼安全）——SPDIF 排障第一步永远是看光 |
| 有声但断续/爆音 | 接收端 PLL 失锁：线过长、弯折、连接器松动 | 换短线对比；量接收端恢复时钟稳定性 |
| 声道里混着噪声 | 同轴阻抗不匹配（用了非 75 Ω 线） | 换 75 Ω 同轴线 |
| 5.1 输出变成立体声 | 源端输出的是 PCM 而非 AC3/DTS 透传 | 源端设置开 bitstream/透传 |
| 示波器看不到干净波形 | 线速率是 Fs×128，示波器带宽不足 | 48 kHz 对应 6.144 Mbps，用 ≥100 MHz 带宽示波器 |
