## <span class="blue"> 本节导读

EtherCAT（Ethernet for Control Automation Technology）是由德国倍福（Beckhoff）于2003年推出的工业以太网协议，现已成为IEC 61158标准家族的核心成员。如果你见过一条以太网线把所有伺服驱动器、I/O模块、传感器像串糖葫芦一样串在一起，同时还能在微秒级完成全部数据交换——那就是EtherCAT的魔法。

本节将深入EtherCAT的两项核心机制：一是**"飞读飞写"（on-the-fly processing）**，理解从站如何在帧经过的纳秒级时间内完成数据读写而不存储整帧；二是**分布式拓扑与ESC硬件架构**，掌握线型、树型、星型拓扑的适用场景以及ESC芯片的选型要点。学完本节，你会明白为什么EtherCAT能在100个从站、100μs周期下依然保持低于1μs的抖动。

<br>

## <span class="blue"> 知识点340：EtherCAT架构与核心机制 [E][M]

### EtherCAT总体架构

EtherCAT采用经典的主从（Master-Slave）架构。整个网络中**只有一个主站**（Master），负责发起所有通信；**所有从站**（Slave）都是被动响应的，不能主动发送数据。这种设计看似简单，但配合"飞读飞写"机制后，通信效率远超其他工业以太网协议。

主站通常是一台运行EtherCAT主站协议栈的工控机或嵌入式控制器。常见的开源主站协议栈包括：**IgH EtherCAT Master**（Linux内核模块）、**SOEM**（Simple Open EtherCAT Master，倍福官方开源）、**TwinCAT**（倍福商业方案）。从站则由专用的**ESC芯片**（EtherCAT Slave Controller）实现协议处理，MCU只需通过SPI/并行总线与ESC交互即可。

<br>

### "飞读飞写"原理（On-the-Fly Processing）

这是EtherCAT最核心的创新。标准以太网中，每个节点收到完整帧后解析目的MAC地址，决定是否接收——这意味着每个从站都要**存储整帧**再处理。EtherCAT彻底颠覆了这个思路。

EtherCAT从站的ESC芯片内置了硬件解析逻辑。当以太网帧的**前导码（Preamble）**还在物理层传输时，ESC就已经在识别帧头；当帧数据**流经过**从站时，ESC在帧通过的极短时间内（约几十纳秒）完成数据读写，帧不减速、不停留、不整帧存储。

来看看帧经过三个从站时的飞读飞写过程：

```
时间轴 →

[主站发送帧] ════════════════════════════════════════════════════════►
              │              │              │
              ▼              ▼              ▼
         ┌─────────┐   ┌─────────┐   ┌─────────┐
         │ 从站1   │   │ 从站2   │   │ 从站3   │
         │  ESC    │──▶│  ESC    │──▶│  ESC    │
         └─────────┘   └─────────┘   └─────────┘
              │              │              │
              ▼              ▼              ▼
         读取温度值     读取位置值     读取状态字
         (覆盖为旧值)   写入速度指令   写入力矩指令
              │              │              │
帧内容变化: [Temp=25]──▶[Pos=1000]──▶[Status=0x1234]
                        [Spd=500]    [Torq=200]
                        
关键: 每个从站只处理属于自己的那几个字节,
      帧以全速(100Mbps/1Gbps)通过,无缓冲延迟!
```

看明白了吗？帧像一列高铁穿过站台，每个从站只"上下"自己的几字节数据，列车本身几乎不减速。这就是EtherCAT能做到**<1μs抖动**的秘密。

<br>

### EtherCAT帧结构

EtherCAT帧被封装在标准IEEE 802.3以太网帧中，Ethertype字段固定为 **0x88A4**，这是IANA分配给EtherCAT的专属类型码。任何识别此Ethertype的网络设备都会将其视为EtherCAT帧。

```
+----------------+----------------+----------------+----------------+
|  Ethernet Header (14 bytes)                                    |
+----------------+----------------+----------------+----------------+
| 目的MAC (6B)   | 源MAC (6B)     | Ethertype      | = 0x88A4       |
| (广播/单播)    | (主站MAC)      | (2B)           |                |
+----------------+----------------+----------------+----------------+
|  EtherCAT Header (2 bytes)                                     |
+----------------+----------------+----------------+----------------+
|  Len (11bit)   | R (1bit)       | Res (4bit)    | Type (1=DAT)  |
+----------------+----------------+----------------+----------------+
|  EtherCAT Datagram #1                                          |
+----------------------------------------------------------------+
|  Cmd (1B) | Idx(1B) | Addr(4B/8B) | Len(11bit) | R(3bit)| IRQ  |
|  (APRD/   |         | (ADP/ADO    |             |       | (2B) |
|  FPRD/    |         |  or         |             |       |      |
|  BRD/LRD) |         |  逻辑地址)  |             |       |      |
+----------------------------------------------------------------+
|  Data (0~1486 bytes, 由Len指定)                                |
+----------------------------------------------------------------+
|  WKC (Working Counter, 2B)  ← 从站处理次数计数                 |
+----------------------------------------------------------------+
|  EtherCAT Datagram #2 (可选，可包含多个)                        |
+----------------------------------------------------------------+
|  ... Datagram #N ...                                           |
+----------------------------------------------------------------+
|  Ethernet FCS (Frame Check Sequence, 4 bytes)                   |
+----------------------------------------------------------------+

总帧长度: 64 ~ 1518 bytes (含FCS, 符合以太网标准)
```

帧内可以包含**多个Datagram**，每个Datagram独立指定目标从站和操作类型。这意味着一个EtherCAT帧能同时完成对不同从站的读、写、读写操作，效率极高。

<br>

### Datagram类型详解

每个Datagram的**Cmd字段**（1字节）定义了寻址方式和操作类型。你需要熟悉以下四种核心类型：

| 类型 | 代码 | 功能 | 适用场景 |
|------|------|------|----------|
| **APRD** | 0x01 | Auto Increment Physical Read，自动递增物理地址读 | 扫描阶段检测从站数量，按物理顺序读取 |
| **APWR** | 0x02 | Auto Increment Physical Write，自动递增物理地址写 | 初始化阶段按顺序配置从站 |
| **FPRD** | 0x04 | Configured Address Physical Read，配置地址物理读 | 正常运行阶段读取指定从站（推荐） |
| **FPWR** | 0x05 | Configured Address Physical Write，配置地址物理写 | 正常运行阶段写入指定从站（推荐） |
| **BRD** | 0x07 | Broadcast Read，广播读 | 同时读取所有从站相同偏移地址的数据 |
| **BWR** | 0x08 | Broadcast Write，广播写 | 同时向所有从站写入相同数据 |
| **LRD** | 0x0A | Logical Read，逻辑读 | 基于Process Data Image的逻辑地址读取 |
| **LWR** | 0x0B | Logical Write，逻辑写 | 基于Process Data Image的逻辑地址写入 |
| **LRW** | 0x0C | Logical Read Write，逻辑读写 | 同步交换输入/输出数据（最常用） |

**寻址方式的本质区别**：
- **APRD/APWR**：使用16位自动递增计数器。帧经过第1个从站时计数器为0，经过第2个变为1……从站匹配自己的位置序号。这要求从站物理顺序**绝对固定**。
- **FPRD/FPWR**：每个从站初始化时被主站分配一个16位**固定配置地址**（0x0001~0xFFFF），后续通信通过此固定地址访问，与物理位置无关。
- **BRD/BWR**：所有从站都响应，用于广播同步指令。
- **LRD/LWR/LRW**：通过32位逻辑地址访问**Process Data Memory（PDM）**，这是周期性数据交换的主力。主站通过EtherCAT PDO（Process Data Object）映射，将逻辑地址与物理从站的内存区域绑定。

> ⚠️ **陷阱**：EtherCAT从站顺序改变→自动递增地址（APRD）读取错位→必须用配置地址（FPRD）
>
> 现场维护时如果把从站1和从站2的网线对调了位置，APRD帧仍然按物理经过顺序读取——原来"从站1的位置"现在读的是从站2的数据！这在多轴伺服系统中极其危险。工程实践中，**初始化扫描阶段用APRD发现从站并分配配置地址后，正常运行必须切换到FPRD/FPWR或LRD/LRW**。记住：APRD只用于上电枚举，绝不用于运行期循环通信。

<br>

### ESC（EtherCAT Slave Controller）芯片

ESC是EtherCAT从站的核心硬件，负责处理EtherCAT协议栈的物理层和数据链路层，解放主控MCU的计算资源。

| 型号 | 厂商 | PDM大小 | 特点 |
|------|------|---------|------|
| **ET1100** | Beckhoff（倍福） | 8KB | 业界标杆，8个同步管理器（SM），8个FMMU，支持分布式时钟，工业级可靠性 |
| **AX58100** | ASIX（亚信） | 8KB | 台湾厂商，低成本替代方案，集成PHY，兼容ET1100寄存器接口 |
| **LAN9252** | Microchip | 4KB | 集成2/3端口PHY，SPI接口为主，适合小型I/O从站 |
| **ET1200** | Beckhoff | 16KB | 高性能版本，更大的PDM，支持更复杂的从站应用 |
| **XMC4300** | Infineon（英飞凌） | 内置 | ARM Cortex-M4 + 内置ESC，单芯片解决方案 |
| **RZ/T1** | Renesas（瑞萨） | 内置 | R-IN引擎 + 内置ESC，适合运动控制 |

PDM（Process Data Memory）是ESC内部的RAM区域，主站通过EtherCAT帧读写PDM，MCU则通过本地总线（SPI/并行）访问同一块PDM——这是主站与从站MCU之间数据交换的双端口机制。

<br>

### EtherCAT vs 标准以太网

| 维度 | EtherCAT | 标准以太网（TCP/IP） | 差异 |
|------|----------|----------------------|------|
| **通信模型** | 主从架构，主站轮询所有从站 | 对等架构，任意节点主动发送 | EtherCAT确定性更高，无CSMA/CD冲突 |
| **帧处理方式** | 飞读飞写（on-the-fly），不存储整帧 | 存储-转发（store-and-forward） | EtherCAT延迟降低2~3个数量级 |
| **周期抖动** | < 1μs（典型） | 毫秒级，不可预测 | EtherCAT适合高精度运动控制 |
| **最小周期** | 50μs（100从站）/ 25μs（少量从站） | 通常 > 10ms | EtherCAT快100~200倍 |
| **Ethertype** | 0x88A4 | 0x0800（IP） | EtherCAT不经过IP协议栈 |
| **拓扑支持** | 线型、树型、星型任意混合 | 星型为主 | EtherCAT布线更灵活 |
| **硬件要求** | 从站需ESC芯片 | 通用以太网控制器 | EtherCAT从站成本略高 |
| **实时性** | 硬实时，确定性保证 | 软实时，尽力而为 | 工业控制场景的本质差异 |
| **数据负载效率** | >90%（单帧多Datagram） | ~30-40%（含TCP/IP头） | EtherCAT带宽利用率极高 |

> 💡 **提示**：EtherCAT帧最小长度64字节→如果数据太少会填充→不要误解填充数据为有效数据
>
> 以太网标准要求最小帧长64字节（含FCS）。如果你发送的EtherCAT帧数据区很小，底层会自动填充到64字节。**在从站接收端，必须以EtherCAT Header中的Len字段为准解析有效数据，不能把填充字节当作有效数据解读**。很多初学者在调试自定义ESC固件时犯这个错误——看到64字节满帧就以为数据区全满，实际上可能只有8字节有效载荷。

<br>

## <span class="blue"> 知识点341：拓扑结构与ESC内部架构 [E][M]

### 三种拓扑结构

EtherCAT支持任意拓扑组合，这是因为它采用了类似交换机的**集成式集线器**机制：每个ESC芯片至少有两个EtherCAT端口（Port 0和Port 1），高端型号有四个端口（Port 0~3）。帧从Port 0进入，ESC处理完数据后自动转发到下一个有连接的端口，形成自动路由。

```mermaid
graph LR
    subgraph 线型拓扑（最常用）
        M[EtherCAT主站<br/>工控机] --> S1[从站1<br/>伺服驱动器]
        S1 --> S2[从站2<br/>伺服驱动器]
        S2 --> S3[从站3<br/>I/O模块]
        S3 --> S4[从站4<br/>传感器]
        S4 --> M
    end
    
    style M fill:#e1f5e1,stroke:#333,stroke-width:2px
    style S1 fill:#e3f2fd,stroke:#333,stroke-width:1px
    style S2 fill:#e3f2fd,stroke:#333,stroke-width:1px
    style S3 fill:#e3f2fd,stroke:#333,stroke-width:1px
    style S4 fill:#e3f2fd,stroke:#333,stroke-width:1px
```

<br>

**线型（菊花链）**：最常用。主站→从站1→从站2→……→从站N→回主站。优点是布线简单、电缆用量最少；缺点是单点故障会断开后续从站（除非启用冗余）。

**树型**：主站通过多个分支连接不同区域的从站群。适合大型设备分区布局，如一条生产线分为左/中/右三个工位。

**星型**：多个从站通过交换机或集线器连接。EtherCAT支持标准以太网交换机，但会丧失飞读飞写的纳秒级处理优势（交换机通常引入微秒级延迟），**不推荐用于实时控制段**。

<br>

### 线型冗余机制

EtherCAT的线型冗余是一个巧妙设计。高端主站（如倍福的FC9001网卡）有两个独立的EtherCAT端口。正常工作时，帧从主端口发出，经过整条链路后从最后一个从站返回，接入冗余端口。

```
正常模式:                    故障模式（从站2-3间断线）:
                              
    主端口 ──▶S1──▶S2──▶S3──▶S4──▶ 冗余端口      主端口 ──▶S1──▶S2  X  S3──▶S4
              ↑___________________________↑                              ↑___________↑
              （帧沿正向路径流动）                                         （自动切换反向路径）
                                                                          
断线后: S2检测到Port1无连接,自动将Port0收到的帧
       从Port2反向回传,主站通过冗余端口仍可访问S3/S4
```

当某处电缆断开时，断点之前的从站仍通过正向路径可达，断点之后的从站通过**反向路径**（帧从原返回方向进入）仍然可达。主站同时从两个端口收发，自动整合完整数据。切换时间通常 **< 50μs**，对大多数应用无感。

<br>

### ESC内部结构

以业界标杆ET1100为例，ESC内部包含以下核心模块：

```
┌──────────────────────────────────────────────────────┐
│                    ET1100 ESC 内部架构                  │
├──────────────────────────────────────────────────────┤
│                                                      │
│  ┌──────────────┐    ┌──────────────────────────┐   │
│  │ EtherCAT     │    │    Process Data Memory    │   │
│  │ Processing   │◄──▶│         (PDM) 8KB        │   │
│  │ Unit (ECAT)  │    │                          │   │
│  │              │    │  ┌────┬────┬────┬────┐  │   │
│  │ ·帧解析      │    │  │SM0 │SM1 │... │SM7 │  │   │
│  │ ·Datagram处理│    │  └────┴────┴────┴────┘  │   │
│  │ ·WKC计数     │    │  8个Sync Manager通道      │   │
│  │ ·FMMU映射    │    │                          │   │
│  └──────┬───────┘    └──────────────────────────┘   │
│         │                                            │
│  ┌──────┴───────┐    ┌──────────────────────────┐   │
│  │   Port 0~3   │    │   Distributed Clock (DC)  │   │
│  │  (MII接口)   │    │                          │   │
│  │              │    │ ·本地时钟 (64位, 1ns精度) │   │
│  │ ·Port0=IN    │    │ ·时钟同步 (DC漂移补偿)    │   │
│  │ ·Port1~3=OUT │    │ ·同步信号输出 (SYNC0/1)   │   │
│  │ ·自动路由    │    │ ·主站参考时钟分发          │   │
│  └──────────────┘    └──────────────────────────┘   │
│                                                      │
│  ┌──────────────┐    ┌──────────────────────────┐   │
│  │   FMMU × 8   │    │     PD Interface          │   │
│  │              │    │  (SPI/8bit/16bit并行)     │   │
│  │ 逻辑地址→物理 │    │                          │   │
│  │ 地址映射单元  │    │ 连接外部MCU (STM32/FPGA)  │   │
│  └──────────────┘    └──────────────────────────┘   │
│                                                      │
└──────────────────────────────────────────────────────┘
```

**关键组件解析**：

**PDM（Process Data Memory）**：8KB的双端口RAM。一端连接EtherCAT处理单元（由主站通过以太网帧访问），另一端连接PD Interface（由本地MCU通过SPI/并行总线访问）。8个**Sync Manager（SM）通道**将PDM划分为不同的邮箱区域和过程数据区域，实现有序的数据交换。

**FMMU（Fieldbus Memory Management Unit）**：EtherCAT的"MMU"。FMMU将32位逻辑地址（主站视角）映射到PDM内的16位物理地址（从站视角）。一个ET1100有8个FMMU，意味着最多支持8段独立地址映射。主站通过配置FMMU寄存器，就能决定"逻辑地址0x1000~0x1003对应从站1的PDM 0x0F01~0x0F04"。

**分布式时钟单元（DC）**：每个ESC内置一个64位本地时钟（分辨率1ns），通过EtherCAT特殊Datagram与主站参考时钟同步。DC机制能让所有从站的SYNC0/1信号在亚微秒级对齐，这是多轴同步运动的基础。我们将在下一节详细展开。

## <span class="blue"> 本节总结

| 项目 | 要点 |
|------|------|
| **核心架构** | 单主多从，主站轮询，从站被动响应，ESC硬件处理协议栈 |
| **飞读飞写** | ESC在帧流经时不存储整帧，实时读写数据，延迟极低（<1μs抖动） |
| **帧格式** | 标准以太网帧 + Ethertype 0x88A4 + EtherCAT Header + N个Datagram + FCS |
| **Datagram寻址** | APRD/APWR（自动递增，仅枚举用）→ FPRD/FPWR（配置地址）→ LRD/LRW（逻辑地址，运行期主力） |
| **ESC选型** | ET1100为标杆，AX58100为低成本替代，LAN9252适合小型从站 |
| **拓扑** | 线型最常用，支持树型/星型混合；线型冗余可在断线时自动切换反向路径 |
| **ESC内部** | PDM（8KB双端口RAM）+ 8个Sync Manager + 8个FMMU + DC时钟单元 |
| **关键陷阱** | ① 从站顺序改变导致APRD错位→运行期必须用FPRD/LRW ② 最小帧64字节填充→以Len字段为准 |
| **性能指标** | 100从站/100μs周期，抖动<1μs；数据负载效率>90% |
