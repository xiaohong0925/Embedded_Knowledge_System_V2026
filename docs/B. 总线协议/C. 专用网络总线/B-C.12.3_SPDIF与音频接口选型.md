# B-C.12.3 SPDIF与音频接口选型

## <span class="blue"> 本节导读

你搞定了I2S，觉得数字音频也就那么回事？别急。当你的设备需要把音频信号传到另一台设备——比如从电视传给音响，从播放器传给功放——I2S那点距离完全不够看。这时候就该**SPDIF**出场了。本节带你搞清楚SPDIF的光纤和同轴两种物理介质、它独特的双相标记编码方式，以及面对I2S/SPDIF/TDM/USB Audio这四种常见音频接口时，如何根据场景做出最优选型。读完你会明白：为什么客厅影音设备普遍用SPDIF，而智能音箱里却根本看不到它的影子。

## <span class="blue"> 知识点356 SPDIF数字音频接口 [I]

### 什么是SPDIF

**SPDIF**（Sony/Philips Digital Interface，索尼/飞利浦数字接口）是一种消费级数字音频传输标准，由这两家公司在1980年代联合推出。它的设计目标很简单：用一根线把数字音频从一台设备传到另一台，全程保持数字域不经过数模转换，避免模拟信号传输带来的噪声和失真。

SPDIF脱胎于专业音频领域的**AES/EBU**（AES3）标准，但做了简化——阻抗从110Ω降到75Ω，连接器从XLR改成RCA或TOSLINK，电压电平也做了调整。本质上它继承了AES/EBU的帧结构和子帧格式，只是物理层不同。

### 两种物理介质

SPDIF支持两种传输介质，各有脾气：

| 参数 | 光纤（TOSLINK） | 同轴（RCA） | 说明 |
|------|----------------|------------|------|
| 传输介质 | 塑料光纤（PMMA） | 铜缆+屏蔽层 | 光纤用光脉冲，同轴用电信号 |
| 阻抗 | 无（光传输） | 75Ω | 同轴需匹配75Ω终端阻抗 |
| 最大距离 | <10m（典型<5m） | <10m（典型<1m） | 塑料光纤衰减较大，距离受限 |
| 连接器 | 方形TOSLINK | RCA莲花头 | TOSLINK带弹簧防尘盖 |
| 抗电磁干扰 | 极佳（完全隔离） | 一般 | 光纤不受EMI/RFI影响 |
| 弯曲半径 | ≥25mm | 任意 | 光纤过度弯折会断光路 |
| 支持格式 | PCM/AC3/DTS | PCM/AC3/DTS | 两者协议层完全相同 |
| 成本 | 中等（收发器约¥2-5） | 低（RCA插座¥0.5） | 光纤需要光电转换器件 |

<br>

### 音频格式支持

SPDIF的协议层可以承载两类数据：

**无压缩PCM**：这是最常见的用法。SPDIF的PCM通道支持最高**24bit/192kHz**的立体声信号。在子帧结构中，每个音频样本被封装为32bit的子帧（4bit同步 preamble + 24bit音频数据 + 4bit辅助/V/U/C/状态位），两个子帧（左右声道）组成一帧。

**压缩比特流**：SPDIF还可以封装压缩的多声道音频，主要是**AC3**（Dolby Digital，最高5.1声道，约640kbps）和**DTS**（最高5.1声道，约1.5Mbps）。注意：SPDIF本身不解码这些格式，它只是个"管道"——压缩数据原封不动传给接收端的解码器（通常是功放或音响）。

> 💡 **提示**：SPDIF的PCM最高只支持**立体声**（2声道）。如果你想传5.1声道的PCM，对不起，带宽不够。要么用压缩格式（AC3/DTS），要么换接口（HDMI、TDM、USB Audio）。

<br>

### 协议层：双相标记编码（BMC）

SPDIF在电气层使用**双相标记编码**（Biphase Mark Code，BMC），也叫双相空间编码。这是SPDIF的核心机制，理解它你就理解了SPDIF的时钟恢复原理。

BMC的规则很简单：

- 每个数据位周期内，信号**必定有一次跳变**（保证足够的翻转密度供接收端恢复时钟）
- 数据为**0**：只在位周期边界跳变**一次**
- 数据为**1**：在位周期边界**和**中间各跳变**两次**

ASCII示意图：

```
SPDIF 双相标记编码（BMC）时序图

原始数据:    0     1     0     0     1     1     0     1
           ____  __    ____  ____  __    __    ____  __
BMC编码:  |    ||  | |    ||    ||  |  |  | |    ||  |
         _|    ||  |_|    ||    ||  |__|  |_|    ||  |_
           ^  ^  ^  ^  ^  ^  ^  ^  ^  ^  ^  ^  ^  ^  ^
           跳变  跳变 跳变    跳变  跳变 跳变 跳变  跳变 跳变
           
位边界:    |--0--|--1--|--0--|--0--|--1--|--1--|--0--|--1--|

图例:
  0 = 仅位边界处单跳变
  1 = 位边界处跳变 + 位中间额外跳变
  
时钟恢复: 接收端用锁相环(PLL)从跳变沿提取位时钟
          即使长时间传0，每个位周期仍有跳变，保证PLL锁定
```

BMC编码有两个巨大的好处：

1. **自带时钟信息**：跳变沿密度足够高，接收端不需要独立的时钟线，直接从数据流中恢复时钟。这也解释了为什么SPDIF只需要一根信号线。
2. **无直流分量**：信号始终在高低电平间跳变，平均直流分量接近零，方便变压器隔离和AC耦合。

SPDIF的帧结构继承自AES/EBU。每帧包含两个子帧（左声道+右声道），每个子帧32bit，所以一帧是64bit。帧的头部有一个特殊的**preamble**（同步头，3种变体：X/Y/Z），接收端靠这个识别帧边界和声道归属。采样率48kHz时，线速率 = 48k × 64 × 2（BMC加倍） = **6.144Mbps**。

> 🔴 **危险**：SPDIF的BMC编码让数据速率是音频采样率的128倍（64bit/帧 × 2倍BMC开销）。如果你的示波器带宽不够，可能看不到干净的跳变沿，误以为信号质量差。看SPDIF波形建议示波器带宽≥100MHz。

<br>

### ⚠️ 陷阱：SPDIF光纤接口的盖子没打开

这是最经典的SPDIF调试陷阱，没有之一。

TOSLINK接口上有个**弹簧防尘盖**——很多设备出厂时盖着，或者你自己推回去防尘后忘了打开。盖子一盖，LED发出的光被塑料片挡住，光纤接收端一片漆黑，自然没有信号。

```
错误排查过程（血的教训）：
  1. 用户报告"音响没声音"                          ← 现象
  2. 检查播放器输出设置 → 已选SPDIF                  ← 没问题
  3. 检查功放输入源 → 已选OPTICAL IN                 ← 没问题
  4. 换光纤线 → 问题依旧                           ← 线材没问题
  5. 怀疑播放器SPDIF口坏了 / 功放解码器坏了           ← 误判方向
  6. 准备拆机/返修...                               ← 浪费半天
  
正确操作：
  1. 看一眼TOSLINK接口的防尘盖 → 果然盖着
  2. 拨开盖子 → 问题解决
  
教训：SPDIF光纤 troubleshooting 第一步永远是——看光。
      对着光纤头发射端看，应该看到明亮的红光（Class 1激光，
      对人眼安全）。看不到光？要么是盖没开，要么是发射器坏了。
```

这个陷阱之所以常见，是因为TOSLINK的盖子设计得很隐蔽，刚好和接口平齐，不仔细看根本发现不了。而且"没声音"的故障现象太泛，很容易让人往复杂的方向想。

## <span class="blue"> 知识点357 音频接口选型 [I]

### 四种接口的横向对比

嵌入式音频系统里有四个主流选择：I2S、SPDIF、TDM、USB Audio。它们不是竞争关系，而是各有"舒适区"。

| 维度 | I2S | SPDIF | TDM | USB Audio |
|------|-----|-------|-----|-----------|
| 引脚数 | 3-4（BCLK/LRCK/DATA[+MCLK]） | 1（同轴）或1+光路（光纤） | 2-3（BCLK/FS/DATA，多声道复用） | 2（D+/D-） |
| 典型传输距离 | <30cm（板级） | <10m（光纤/同轴） | <30cm（板级） | <5m（USB线缆） |
| 最大音频通道 | 2（立体声） | 2（PCM）或5.1（压缩） | 4-16+（时隙复用） | 任意（带宽允许） |
| 时钟同步 | 主从模式，需专用时钟线 | 接收端从数据流恢复时钟 | 同I2S，共享BCLK/FS | USB异步/同步/自适应 |
| 抗EMI能力 | 差（多根未屏蔽PCB走线） | 优（光纤完全隔离） | 差（同I2S） | 良（差分对+屏蔽） |
| 成本 | 极低（GPIO直连） | 中（需收发芯片+连接器） | 低（GPIO直连） | 中（需USB PHY/控制器） |
| 是否需专用控制器 | 否（大多数MCU自带I2S外设） | 是（需SPDIF TX/RX芯片或SOC内置） | 否（I2S外设支持TDM模式） | 是（需USB控制器+Audio Class驱动） |
| 典型应用 | 板内Codec连接 | 电视→功放、播放器→音响 | 多麦克风阵列、会议系统 | USB耳机、外置声卡 |

<br>

### 各维度的深入分析

**引脚数与布线复杂度**

I2S最省心也最费引脚——3根线是底线，如果Codec不是BCLK slave还得加MCLK，变成4根。TDM聪明地把多声道数据复用到一条DATA线上，8声道也只需要2-3根线。SPDIF和USB Audio都是"一线走天下"，但代价是两端各需要一颗专用收发芯片做协议转换。

**距离：决定因素往往不是协议，而是物理层**

I2S和TDM的信号完整性在PCB上只能保证几十厘米——BCLK频率通常很高（64×采样率，48kHz时就是3.072MHz），走线一长就开始出现串扰和反射。SPDIF的光纤版本是距离冠军，10米内基本随便拉，而且完全不怕电机、电源等干扰源。USB Audio理论上5米，但超过3米建议用带中继的有源线。

**多通道能力**

I2S天生 stereo，扩展多声道需要多组I2S线（比如4组I2S传8声道）或者上TDM。TDM是真正的多声道利器——通过时分复用，一条数据线可以承载4、8、甚至16个声道的数据。SPDIF的PCM只有2声道，传5.1必须走压缩流，这是它的硬限制。USB Audio没有理论上限，2.0版本全速模式带宽足够支持多声道高清音频。

**时钟同步：一个容易被忽略的大坑**

I2S和TDM的时钟同步依赖硬件连线（BCLK/LRCK），源端和接收端必须时钟同源或者一方明确做slave。SPDIF的时钟恢复靠接收端PLL，会有少量抖动（jitter），高端发烧友会嫌弃这个。USB Audio的异步模式让设备端做主时钟，主机自适应，这是目前音质最好的USB音频方案。

<br>

### 常见音频场景的推荐方案

| 场景 | 推荐接口 | 理由 |
|------|---------|------|
| 板内MCU ↔ Audio Codec | I2S | 引脚少、几乎所有MCU都支持、无需额外芯片 |
| 电视/机顶盒 ↔ 功放/音响 | SPDIF（光纤优先） | 长距离、抗干扰、行业标准、消费级设备标配 |
| 智能音箱多麦克风阵列（4-8麦） | TDM | 多通道复用、减少PCB走线、主流方案 |
| USB外置声卡/HiFi DAC | USB Audio（异步模式） | 即插即用、带宽大、主机端无需额外驱动（UAC2） |
| 车载音响主机 ↔ 功放 | TDM或I2S | 板间短距离、多声道、车载Codec普遍支持TDM |
| 专业音频设备（调音台、录音棚） | AES/EBU或MADI | 专业级标准、距离远（AES）、通道极多（MADI） |
| 低功耗IoT音频（门铃、传感器） | I2S或PDM→I2S | 简单、功耗低、PDM麦克风直接进DSP |

<br>

### 💡 选型决策口诀

> 💡 **提示**：记住这个口诀，选型不纠结——
> - **板内短距** → **I2S**（简单直接，零额外成本）
> - **长距抗扰** → **SPDIF光纤**（10米随便拉，EMI免疫）
> - **多通道** → **TDM**（一线上8声道，阵列音频首选）
> - **即插即用** → **USB Audio**（兼容性无敌，主机端零开发）

实际项目中往往是组合使用：智能音箱的内部链路可能是 **麦克风PDM → DSP TDM输入 → 处理后的I2S → 板载Codec → 模拟功放**，而对外扩展接口则可能留一个SPDIF输出供用户外接音响。

<br>

### 典型硬件方案参考

SPDIF发射端的典型实现有两种路径：

1. **SOC内置SPDIF控制器**（如全志H6、瑞芯微RK3568、AM335x）→ 直接引脚输出 → 加光耦/TOSLINK收发器或RCA缓冲
2. **外挂SPDIF发射芯片**（如DIR9001/WM8804做接收，WM8804/CS8406做发射）→ I2S输入转SPDIF输出

```
方案1：SOC内置SPDIF控制器
  +--------+    SPDIF信号    +------------------+    光脉冲    +--------+
  |  SOC   |--------------->| TOSLINK收发器     |---------->| 光纤   |
  |(内置TX)|   (电信号)      | (如DLR1150)      |            | 输出   |
  +--------+                 +------------------+            +--------+

方案2：I2S转SPDIF外挂芯片
  +--------+    I2S    +-----------+    SPDIF    +------------------+
  |  MCU   |--------->| WM8804    |----------->| TOSLINK收发器     |
  |        |          |(I2S→SPDIF)|   (电信号)  |                  |
  +--------+          +-----------+             +------------------+
```

## <span class="blue"> 本节总结

| 要点 | 内容 |
|------|------|
| SPDIF是什么 | Sony/Philips消费级数字音频接口，从AES/EBU简化而来 |
| 物理介质 | 光纤（TOSLINK）和同轴（RCA 75Ω）两种，协议层完全相同 |
| 音频格式 | PCM最高24bit/192kHz（立体声）；压缩AC3/DTS（5.1环绕声） |
| 编码方式 | BMC双相标记编码，数据流中恢复时钟，单线传输 |
| 选型原则 | 板内I2S / 长距SPDIF光纤 / 多通道TDM / 即插即用USB Audio |
| 经典陷阱 | TOSLINK防尘盖没打开 → 无光信号 → "设备故障"假象 |

SPDIF可能是你日常使用最多的数字音频接口——家里的电视、机顶盒、功放、游戏机背后都有那个发着红光的小方口。理解了它的BMC编码和时钟恢复原理，你就理解了为什么SPDIF只需要一根线。而在嵌入式产品内部，I2S和TDM仍是绝对主力。
