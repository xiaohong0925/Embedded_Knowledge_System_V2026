# B-C.9.1 CAN FD物理层与帧格式

> 所属章节：第五部 B. 总线协议 > B-C.9 CAN FD总线
>
> 难度：[I] Intermediate | 预计阅读时间：35分钟

## <span class="blue"> 本节导读

还记得上一节我们提到的那个老问题吗？CAN 2.0的最高速率只有1Mbps，数据段最长8字节，在当前车载网络动辄百KB的固件升级场景下简直捉襟见肘。CAN FD（Flexible Data Rate，灵活数据速率）正是为此而生——它在兼容CAN 2.0的基础上，让数据段跑上8Mbps甚至更高，同时把单帧payload扩展到64字节。本节先搞定"物理送电"和"帧长什么样"这两个基础问题。放心，CAN FD跟CAN 2.0的血缘关系很近，很多概念直接复用。

<br>

## <span class="blue"> 知识点327 CAN FD帧结构详解 [I][M]

CAN FD帧整体沿袭了CAN 2.0的骨架，但塞进了几个关键新位。理解这几个位的分工，就能理解CAN FD"灵活变速"的本质。

<br>

### CAN FD帧结构一览

先上一张全景图，看看一帧CAN FD报文从头到尾都包含什么。

```
  SOF      仲裁段(1Mbps)        控制段          数据段(最高8Mbps)      CRC        ACK   EOF
  |  |----------------------|------------|----------------------|-----------|-----|----|
  |  |  ID  | RTR→SRR | IDE |  r1 | FDF |      | DLC | 数据0~63 | CRC17/21 | ACK |    |
  |  |11/29b|  0  |   0   |  0  |  0  |  1  | BRS | ESI | 4b |  字节    |  17/21b  | 2b  | 7b |
  |  |------Base格式---------|----FD扩展控制---|----------------------|-----------|-----|----|
  
         ↑                                                          ↑
       固定1Mbps（或500k）                                      BRS=1时切换
                                                              仲裁段波特率 ←→ 数据段波特率
                                                              (如1Mbps → 8Mbps)
```

<br>

### 各字段详解

| 字段 | 位数 | 说明 | 与CAN 2.0差异 |
|:---|:---:|:---|:---|
| SOF | 1 | 起始帧位（Start of Frame），固定显性位（0） | 无差异 |
| 仲裁段 ID | 11/29 | 标识符，标准帧11位/扩展帧29位，ID越小优先级越高 | 无差异，速率固定为仲裁波特率 |
| SRR/r1 | 1 | 标准帧保留位r1（0）；扩展帧SRR位（1），占RTR位置 | CAN FD中标准帧r1始终为0 |
| IDE | 1 | 标识符扩展位（0=标准帧，1=扩展帧） | 无差异 |
| FDF | 1 | **FD格式标志位（1=CAN FD帧，0=CAN 2.0帧）** | ⭐ CAN FD新增，CAN 2.0此位为r1(0) |
| BRS | 1 | **位速率切换位（1=数据段提速，0=全程同速）** | ⭐ CAN FD新增，决定数据段是否切高速 |
| ESI | 1 | **错误状态指示位（1=错误被动节点，0=主动节点）** | ⭐ CAN FD新增，CAN 2.0无此显性提示 |
| DLC | 4 | 数据长度码，0-15编码0-64字节 | ⭐ CAN FD扩展，CAN 2.0仅0-8 |
| 数据段 | 0-512 | 实际数据负载，0~64字节 | ⭐ 最大64字节（CAN 2.0仅8字节） |
| CRC | 17/21 | CRC校验序列，≤16字节用17位CRC，>16字节用21位CRC | ⭐ CAN FD增强，CAN 2.0固定15位 |
| ACK | 2 | 应答间隙+应答界定符 | ACK间隙在CAN FD中固定为1位（CAN 2.0可延长） |
| EOF | 7 | 帧结束，7个连续隐性位（1） | 无差异 |

FDF、BRS、ESI这三个位，是CAN FD的"灵魂三件套"。FDF让接收方知道"这是一帧FD报文"；BRS负责"踩油门"——如果BRS=1，从数据段开始切换到高速波特率；ESI则像一个故障指示灯，当一个节点进入Error Passive状态时，它发出的帧ESI=1，让其他节点心里有数。

<br>

### DLC编码表

CAN FD把DLC从3位扩到4位，但0-8的编码保持兼容，9-15采用非线性映射来覆盖12/16/20/24/32/48/64这几个关键字节数。

| DLC值 | 数据字节数 | 说明 |
|:---:|:---:|:---|
| 0 | 0 | 空帧，常用于同步或心跳 |
| 1 | 1 | 单字节数据（兼容CAN 2.0） |
| 2 | 2 | 双字节数据（兼容CAN 2.0） |
| 3 | 3 | 三字节数据（兼容CAN 2.0） |
| 4 | 4 | 四字节数据（兼容CAN 2.0） |
| 5 | 5 | 五字节数据（兼容CAN 2.0） |
| 6 | 6 | 六字节数据（兼容CAN 2.0） |
| 7 | 7 | 七字节数据（兼容CAN 2.0） |
| 8 | 8 | 八字节数据（兼容CAN 2.0） |
| 9 | 12 | ⭐ CAN FD扩展，跳4字节到12 |
| 10 | 16 | ⭐ CAN FD扩展，适合uint32x4数组 |
| 11 | 20 | ⭐ CAN FD扩展 |
| 12 | 24 | ⭐ CAN FD扩展 |
| 13 | 32 | ⭐ CAN FD扩展，适合浮点数组传输 |
| 14 | 48 | ⭐ CAN FD扩展 |
| 15 | 64 | ⭐ CAN FD扩展最大payload，固件升级利器 |

注意DLC=9以后不是线性增长！这是有意设计的，用4位二进制最多表示16种状态，要在16种编码里覆盖到64字节，就必须在关键节点做跳跃。实际编程时别自己算，直接用`canfd_dlc2len()`和`canfd_len2dlc()`这样的内核辅助函数转换。

<br>

### BRS位速率切换详解

BRS（Bit Rate Switch）是CAN FD最具魔力的设计。来看时序图：

```
  仲裁段波特率 (如1Mbps)                    数据段波特率 (如8Mbps)
  ──────────────────────╲────────────────────────────────────────
                        ╲
                         ╲  ← BRS位之后采样点切换
                          ╲
  SOF  ID  FDF  BRS  ESI   DLC  Data0..DataN   CRC    ACK  EOF
   |   |    |    ↑    |    |      |            |      |    |
   |   |    |    |    |    |      |            |      |    |
   └─────────────┘    └────────────────────────────────────────┘
   固定仲裁速率              提速运行（如果BRS=1）
   
   BRS=0: 全程一个速率，CAN FD退化为"加速版CAN 2.0"
   BRS=1: 仲裁段慢速保冲突，数据段高速传大payload
```

> ⚠️ **陷阱**：CAN FD的数据段波特率必须 ≥ 仲裁段波特率，绝对不能反过来。原因是BRS位本身是在仲裁段波特率下传输的，接收节点需要根据BRS=1这个"切换指令"来准备采样率的变更。如果数据段速率低于仲裁段，BRS位之后的位宽反而变长，采样点逻辑会完全错乱，整帧报废。牢记：**BRS只能"加速"，不能"减速"**。

> 💡 **提示**：设计CAN FD网络时，不要急着把每个节点都飙到最高速。正确的流程是：先确定网络中**所有节点的最大支持速率**（看各自MCU的CAN FD控制器规格和收发器规格），然后取最小公约数作为网络的数据段波特率。例如节点A支持最高5Mbps，节点B支持最高8Mbps，节点C用的老收发器只支持2Mbps——那整个网络的数据段波特率必须 ≤ 2Mbps。仲裁段通常设500k或1Mbps即可，兼顾距离和兼容性。

<br>

### CRC增强机制

CAN FD的CRC有两档：数据段 ≤ 16字节时用17位CRC，> 16字节时升级到21位CRC。相比CAN 2.0的固定15位CRC，这个增强很必要——毕竟64字节的payload出错概率比8字节高多了。

另外CAN FD还引入了**填充位计数器（Stuff Bit Counter）**，位于CRC序列之前，用来记录帧中填充位的数量，自身也有校验保护。这是为了防止"填充错误"被漏检。

```
  数据段末尾 → 填充位计数器(3位数据+1位奇偶校验) → CRC序列(17或21位) → CRC界定符
  
  填充位计数器的作用：
  - 记录本帧仲裁段+控制段+数据段中实际出现的填充位数量 mod 8
  - 接收方独立计数填充位，跟计数器值比对
  - 不匹配说明填充规则被破坏，立即报错
```

<br>

## <span class="blue"> 知识点328 CAN FD物理层 [I]

物理层是CAN FD的"公路系统"，负责把0和1变成真实的电压差在双绞线上跑。好消息：CAN FD复用了CAN 2.0的物理层拓扑，只是对收发器提出了更高的带宽要求。

<br>

### 差分信号电平

CAN总线用两根线——CAN_H和CAN_L——的电压差来传数据。这种差分设计的妙处在于抗共模干扰：噪声同时作用于两根线，差值不变。

```
  显性位(Dominant, 逻辑0)              隐性位(Recessive, 逻辑1)
  
  CAN_H ─────┐    3.5V                CAN_H ─────┐    2.5V
             │     ↑                             │     ↑
             │    2V差值                         │   0V差值
             │     ↓                             │     ↓
  CAN_L ─────┘    1.5V                CAN_L ─────┘    2.5V
  
  收发器输出驱动电流，强行拉开电压          收发器释放总线，两根线被电阻拉到同一电平
  
  总线逻辑：显性位(0)会覆盖隐性位(1)，这就是"线与"机制，仲裁的基础
```

| 状态 | CAN_H | CAN_L | 差值(Vdiff) | 逻辑值 | 说明 |
|:---|:---:|:---:|:---:|:---:|:---|
| 显性位 | 3.5V | 1.5V | ≈ +2.0V | 0 | 主动驱动，优先级高，可覆盖隐性 |
| 隐性位 | 2.5V | 2.5V | ≈ 0.0V | 1 | 被动上拉，所有节点释放时总线状态 |
| 空闲态 | 2.5V | 2.5V | ≈ 0.0V | 1 | 无节点发送，同隐性位 |

仲裁机制就建立在"显性覆盖隐性"这个硬件特性上：多个节点同时发，发0（显性）的节点会把总线拉到2V差值，发1（隐性）的节点检测到这个差值就知道自己输了，自动退出发送。这就是CAN非破坏性仲裁的物理基础。

<br>

### 终端电阻与总线拓扑

CAN总线必须在两端各接一个120Ω终端电阻，作用有两个：

1. **消除信号反射**：高频信号在总线末端遇到阻抗不连续会反射回来，造成信号振铃
2. **建立正确的直流偏置**：隐性位时靠终端电阻分压把CAN_H和CAN_L拉到2.5V

```
  典型拓扑：干线+支线结构
  
  120Ω              节点1              节点2              节点3             120Ω
  ━━━━●━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━
     CAN_H          收发器           收发器            收发器
  ━━━━●━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━━●━━━━━━━━━━━━━━━━
  ━━━━┛             │                  │                 │                ━━━━┛
  终端电阻          支线<0.3m          支线<0.3m         支线<0.3m         终端电阻
  
  总线长度 vs 速率经验值（仲裁段速率，CAN FD数据段速率更高时需更短）：
  
  ┌─────────────┬──────────────┬─────────────────────────┐
  │ 仲裁段波特率  │ 最大总线长度  │ 建议主干线类型            │
  ├─────────────┼──────────────┼─────────────────────────┤
  │   125 kbps   │    500m      │  双绞线/屏蔽双绞线        │
  ├─────────────┼──────────────┼─────────────────────────┤
  │   250 kbps   │    250m      │  双绞线/屏蔽双绞线        │
  ├─────────────┼──────────────┼─────────────────────────┤
  │   500 kbps   │    100m      │  屏蔽双绞线               │
  ├─────────────┼──────────────┼─────────────────────────┤
  │   1 Mbps     │    40m       │  屏蔽双绞线，严格控支线   │
  └─────────────┴──────────────┴─────────────────────────┘
  
  CAN FD数据段速率>2Mbps时：建议总线长度<10m，支线<0.1m，用高质量屏蔽双绞线
```

支线的长度控制很关键。高速下支线就像一根天线——信号跑到支线末端反射回来，跟原信号叠加造成波形畸变。CAN FD跑到5Mbps以上时，建议支线控制在10cm以内，必要时用菊链拓扑替代星型。

<br>

### CAN FD收发器选型

不是所有CAN收发器都能跑FD。经典的老收发器如TJA1050/PCA82C250，带宽只到1Mbps，BRS切速后信号直接糊掉。CAN FD需要收发器有足够的输出摆率来跟上高速边沿。

| 型号 | 最高速率 | 供电电压 | 关键特点 | 典型应用场景 |
|:---|:---:|:---:|:---|:---|
| TJA1051 | 5 Mbps | 5V | 高速CAN FD，基本款，VIO版本可选 | 一般车载ECU通信 |
| TJA1057 | 5 Mbps | 5V | 改进EMI性能，符合CiA 601-4 | 对EMC要求高的车身控制 |
| TJA1043 | 5 Mbps | 5V | **带本地/远程唤醒功能**，INH引脚 | 需要休眠唤醒的节点（如车门模块） |
| TJA1463 | 8 Mbps | 5V | 信号改善（SIC），抗振铃能力强 | 复杂拓扑/长支线/高速场景 |
| TCAN1042 | 5 Mbps | 5V | TI出品，低功耗待机模式 | 工业自动化/通用CAN FD |
| TCAN330 | 8 Mbps | 3.3V | **3.3V供电**，直接对接3.3V MCU | 3.3V主控的IoT/嵌入式设备 |

选收发器时要重点看三个参数：最大数据速率（决定能不能跑FD）、供电电压（5V还是3.3V跟你MCU匹配）、有没有唤醒功能（休眠场景必备）。TJA1463的SIC（Signal Improvement Capability）技术特别值得一提——它在收发器内部做了主动信号整形，能把振铃压下去，让复杂拓扑也能稳定跑高速。

<br>

### 物理层设计要点

```
  收发器与控制器连接：
  
  MCU CAN FD控制器          CAN收发器               总线
  ┌──────────────┐         ┌──────────┐          ┌──────┐
  │              │   TXD   │          │  CAN_H   │      │
  │  CAN_TX ─────┼────────→│ TXD      ├────────→●──────●────→
  │              │         │          │  CAN_L   │      │    其他节点
  │  CAN_RX ←────┼─────────│ RXD      ├────────→●──────●────→
  │              │   RXD   │          │          └──────┘
  │  STB_N ←─────┼─────────│ STB      │
  │  (休眠控制)   │         │  (INH)   │←── 唤醒/使能控制
  └──────────────┘         └──────────┘
  
  连线要点：
  - TXD和RXD直连MCU的CAN FD控制器引脚（注意3.3V/5V电平匹配）
  - CAN_H和CAN_L用双绞线引出，线束绞距约33turns/m
  - 两个120Ω终端电阻分别在最远的两个节点处
  - 收发器的VIO引脚（如果有）接MCU同电压，保证电平兼容
```

## <span class="blue"> 本节总结

| 主题 | 关键要点 |
|:---|:---|
| FDF位 | 控制段第一位，=1表示CAN FD帧，兼容CAN 2.0识别 |
| BRS位 | 速率切换开关，=1时数据段切到高速波特率，必须≥仲裁段速率 |
| ESI位 | 错误状态指示器，被动错误节点发1，方便网络健康监控 |
| DLC扩展 | 4位DLC支持0-64字节payload，9-15非线性映射12/16/20/24/32/48/64 |
| CRC增强 | ≤16字节用17位CRC，>16字节用21位CRC，新增填充位计数器 |
| 差分信号 | 显性0（Vdiff≈2V）覆盖隐性1（Vdiff≈0V），仲裁的物理基础 |
| 终端电阻 | 总线两端各120Ω，消除反射+建立直流偏置 |
| 收发器选型 | 必须选CAN FD专用收发器（≥5Mbps），看速率/电压/唤醒三要素 |
| 拓扑限制 | 高速场景严控支线长度，>2Mbps建议支线<0.1m，总线<10m |
| 速率设计 | 网络数据段速率 ≤ 所有节点（控制器+收发器）最小支持速率 |
