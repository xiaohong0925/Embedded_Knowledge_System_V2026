# B-C.9.1 MIPI D-PHY 物理层

> 所属章节：第五部 B. 总线协议 > C. 中高速外设与存储
>
> 难度：[I] | 预计阅读时间：35 分钟

## 本节导读

手机摄像头拍的照片、显示屏上刷的画面，在 SoC 与传感器/屏幕之间跑的都是 MIPI 接口。MIPI 不是一个协议，而是一族协议：物理层有 D-PHY / C-PHY / A-PHY，协议层有 CSI-2（摄像头进）和 DSI（显示出）。本篇讲其中最经典的物理层 D-PHY。

D-PHY 的核心设计是**双模式**：同一对物理线，低速时当单端控制通道用（LP 模式，配置寄存器、状态切换），高速时当差分数据通道用（HS 模式，跑图像流）。摄像头 99% 的时间在 LP 模式省电，出图的一瞬间切 HS 突发传输。理解这套"平时省电、用时爆发"的机制，就理解了 MIPI 为什么统治了移动设备。

本节覆盖：D-PHY 的 Lane 构成与源同步架构、LP/HS 双模式的电气差异、LP 状态机与 LP→HS 切换时序、各版本速率演进、Lane 数与带宽的换算方法（含分辨率选型速算）、C-PHY 与 A-PHY 的定位差异。

## 信号构成：1 对时钟 + N 对数据

D-PHY 采用**源同步**架构——发送方随数据一起发出时钟，接收方用这根时钟采样数据，双方不需要共享全局时钟：

```
   发送端（CSI-2：摄像头 / DSI：SoC 显示侧）        接收端（SoC / 屏幕）
   ┌─────────────────────────┐                  ┌─────────────────┐
   │                         │   CLK+ ────────► │                 │
   │      数据源              │   CLK- ────────► │   D-PHY 接收器   │
   │    （Sensor/GPU）        │                  │                 │
   │                         │   D0+ ────────►  │                 │
   │                         │   D0- ────────►  │                 │
   │                         │   D1+ ────────►  │                 │
   │                         │   D1- ────────►  │                 │
   │                         │   （D2/D3 同理）   │                 │
   └─────────────────────────┘                  └─────────────────┘
       1×CLK 差分对 + 1~4×Data 差分对
```

- **CLK+/-**：一对差分时钟，HS 模式下所有 Data Lane 共用它做边沿采样
- **D0~D3+/-**：最多 4 对差分数据线。D0 特殊：LP 模式下它是双向的，支持 BTA（Bus Turn-Around，总线反转）——接收方可以借 D0 回传应答，比如 DSI 读屏幕寄存器

## 双模式：LP 与 HS 的电气差异

同一对线在两套完全不同的电气规则下工作：

| 特性 | LP 模式（Low Power） | HS 模式（High Speed） |
|------|---------------------|----------------------|
| 信号方式 | 单端（每根线独立判断电平） | 差分（两线反相摆动） |
| 电压摆幅 | 1.2V（0~1.2V） | 约 ±200mV |
| 速率 | < 10 Mbit/s | 80 Mbit/s ~ 2.5 Gbit/s/lane |
| 用途 | 控制、配置、状态切换 | 图像/显示数据传输 |
| 功耗 | 极低 | 较高 |
| 线路状态 | LP-00/01/10/11 | HS-0/HS-1 |

LP 的四状态由两根线的单端电平组合而成；HS 则是标准低压差分。摆幅从 1.2V 压到 200mV 是高速的必要条件——摆幅越小，翻转越快、功耗越低、EMI 越小，这是所有高速差分接口（USB、PCIe、SerDes 同理）的共同选择。

> ⚠️ MIPI 链路的大量现场问题出在 PCB 而不是芯片。硬约束三条：Lane 间走线等长（长度差 < 0.2mm 量级）、差分阻抗 100Ω ±10%、远离开关电源等噪声源。示波器上看到眼图闭合、消隐期错位，先量走线再怀疑配置。

## LP 状态机与 HS 切换

### LP 四状态

| 状态 | Dp | Dn | 含义 |
|------|----|----|------|
| LP-11 | 1 | 1 | Stop：空闲态，链路的默认与复位态 |
| LP-00 | 0 | 0 | HS 请求 / Escape 入口 |
| LP-01 | 0 | 1 | 中间过渡态 |
| LP-10 | 1 | 0 | 中间过渡态 |

（LP 电平：1 = 1.2V，0 = 0V，单端判断。）

### LP → HS 切换时序

每次进入高速传输都要走一遍固定序列，任何违规跳变都会被接收端拒绝：

```
CLK Lane:  LP-11 ──→ LP-00 ──→ HS-Rqst ──→ HS 差分时钟连续输出
Data Lane: LP-11 ──→ LP-01 ──→ LP-00 ──→ HS-Rqst ──→ HS 突发数据
           (Stop)    (过渡)    (请求)      (准备)     (preamble+同步字0xB8+载荷)

关键时序参数：
  T_LPX        LP 状态最短持续时间（~50ns）
  T_HS-PREPARE HS 准备时间（38~95ns + 2UI）
  T_HS-ZERO    HS 零态持续（105ns + 6UI）
  T_HS-TRAIL   结尾拖尾（最大 105ns + 12UI）
```

逐步分解：

1. **LP-11（Stop）**：链路空闲，差分驱动器关闭，功耗最低
2. **LP-11 → LP-01 → LP-00**：Data Lane 上的这个序列是"我要进 HS"的请求签名；CLK Lane 走自己的 LP-00 请求路径先行启动
3. **HS-Rqst → HS 突发**：驱动器从单端切差分，先发一串 0 的 preamble 让接收端锁定，再发同步字 0xB8 对齐字节边界，随后才是 CSI-2/DSI 的数据包
4. **HS-TRAIL → LP-11**：传完发拖尾位，关闭差分驱动，回 LP-11 继续省电

> ⚠️ HS 是**突发传输**架构：链路的典型节奏是 LP → HS → LP → HS 循环，每次切入都有几百纳秒的固定开销（唤醒序列 + preamble + 同步字）。推论是**小包传输效率极低**——MIPI 适合图像这种大包连续流，不适合稀疏的小数据包。这也是为什么传感器的寄存器配置走 LP/Escape 或干脆走 I2C，只有像素流走 HS。

## 版本演进

| 参数 | v1.1 | v1.2 | v2.x |
|------|------|------|------|
| 最高速率/lane | 1.5 Gbit/s | 2.5 Gbit/s | 4.5 Gbit/s |
| Data Lane 数 | 1~4 | 1~4 | 1~4 |
| HS 差分摆幅 | 200mV | 200mV | 200mV |
| 典型应用 | 720p 摄像头 | 1080p/4K 摄像头 | 4K/8K 显示 |

嵌入式领域目前最常见的是 v1.2：4 Lane 共 10 Gbit/s，带 4K@30fps 摄像头刚好够用。要 4K@60fps 或多路高帧率，上 v2.x 或转 C-PHY。

## 带宽速算：选型第一笔账

总带宽 = Lane 数 × 每 lane 速率。D-PHY 本身没有 8b/10b 这类重编码（这点不同于 PCIe/USB3），开销主要来自数据包头和行/帧消隐，工程估算按 85% 有效载荷率：

| Lane 数（v1.2 @ 2.5G/lane） | 物理带宽 | 有效带宽估算 | 适用 |
|------|---------|------------|------|
| 1 Lane | 2.5 Gbit/s | ~260 MB/s | 小分辨率传感器 |
| 2 Lane | 5.0 Gbit/s | ~530 MB/s | 720p@60 / 1080p@30 |
| 4 Lane | 10 Gbit/s | ~1.06 GB/s | 1080p@120 / 4K@30 / 2K 屏 |

实战速算——1080p（1920×1080）摄像头、RAW10 输出、30fps：

```
像素率   = 1920 × 1080 × 30 = 62.2 Mpixel/s
数据率   = 62.2M × 10bit ≈ 622 Mbit/s
加 15% 行/帧消隐开销：622 × 1.15 ≈ 715 Mbit/s

结论：1 Lane v1.1（1.5G）理论够但裕量不足；
     2 Lane 是稳妥选择，还给 ISP 后处理留了空间。
```

同 sensor 提到 60fps，数据率翻倍到约 1.43 Gbit/s，2 Lane 起步。这个速算方法（像素率 × 位宽 × 消隐系数 → 对照 Lane 带宽）对 DSI 屏幕同样适用，把"摄像头分辨率"换成"屏幕分辨率 × 色深"即可。

## C-PHY 与 A-PHY：两条进化路线

D-PHY 之后 MIPI 推出了两个不同方向的 PHY：

**C-PHY——提升引脚效率。** 取消独立时钟对，三根线一组构成一个 lane，用线间电平跳变编码符号，时钟从跳变中恢复。16bit 数据映射为 7 个符号（约 2.28 bit/symbol），每 lane 等效约 5.7 Gbit/s。注意 C-PHY 的 "1 lane" 是 **3 根线**，与 D-PHY 的 2 根线不同，算总线数时别混。

**A-PHY——拉长传输距离。** 为车载设计：同轴线或屏蔽双绞线传 15 米，内置 FEC 前向纠错与重传，单链路最高 16 Gbit/s。典型拓扑是"摄像头端短距 D-PHY 接 sensor，经加串器（serializer）转 A-PHY 跑长距，到网关经解串器（deserializer）还原成 CSI-2 进 SoC"——TI 的 FPD-Link、ADI（Maxim）的 GMSL 是这一生态的主流芯片。

```
摄像头模组                          中央网关/SoC
┌────────────┐                    ┌──────────────────┐
│ CSI-2 传感器│──D-PHY(短距)──► 加串器 │══A-PHY(≤15m)══► 解串器 │──CSI-2──► SoC
└────────────┘                    └──────────────────┘
```

三者对比：

| 维度 | D-PHY | C-PHY | A-PHY |
|------|-------|-------|-------|
| 线结构 | 1 CLK 对 + 1~4 Data 对 | 3 线组，无独立 CLK | 同轴/屏蔽双绞线 |
| 每 lane 线数 | 2 | 3 | 1~2 |
| 最高速率 | 2.5 Gbit/s/lane（v1.2） | ~5.7 Gbit/s/lane | 16 Gbit/s |
| 距离 | < 30cm（板内/FPC） | < 30cm | **15m** |
| 典型应用 | 手机/嵌入式摄像头与屏 | 高像素多摄手机 | 车载 ADAS 摄像头 |

选型逻辑：板内连接、成本敏感 → D-PHY；手机 SoC 原生支持且追求高像素 → C-PHY；摄像头离主控超过一米（车载、机器人远端视觉）→ A-PHY 或 FPD-Link/GMSL 加串方案。

## 本节总结

| 自查项 | 读完本节你应能独立做到 |
