# B-C.7.1 USB 物理层与拓扑

> 所属章节：第五部 B. 总线协议 > C. 中高速外设与存储
>
> 难度：[I] Intermediate | 预计阅读时间：40 分钟

## <span class="blue"> 本节导读

USB 是嵌入式系统里出现频率最高的外设接口：键盘鼠标、U 盘、4G 模组、摄像头、调试烧录口，都挂在它上面。与 I2C/SPI 这类板级总线不同，USB 是为"用户随手插拔、线缆几米长、设备千奇百怪"的场景设计的——它的物理层和拓扑规则处处体现这个设计目标。

本篇是 USB 系列的物理层与拓扑篇，回答两个底层问题：信号怎么在两根线上稳定跑到 480 Mbps 乃至 10 Gbps，以及一台主机怎么把上百个设备组织成一棵树。不要求任何 USB 背景，术语就地解释。枚举与描述符（协议层）在 B-C.7.2，Linux 驱动在 7.3/7.4，USB4 的隧道化演进在 B-F.16.5。

本节覆盖：D+/D- 差分物理层与阻抗要求、四种速率等级与编码演进（NRZI/位填充、8b/10b、128b/132b）、上拉电阻连接检测与 High-speed 握手、OTG 双角色机制、星型拓扑的层级与设备数限制、嵌入式三种工作模式。

## <span class="blue"> 物理层：一对差分线的二十年

### D+/D- 差分对

USB 1.x/2.0 的全部数据都走一对差分线：D+ 和 D-。数据不由单根线对地的电平表示，而由**两根线之间的电压差**表示——差分传输的原理（共模干扰在取差时相消）在 B-F.16.1 已完整展开，这里直接用它与低速单端总线对照：I2C 的单根开漏线在几米长线缆上会被干扰淹没，差分对则天然扛得住线缆环境。

USB 2.0 规范要求这对线的**差分特性阻抗 90 Ω（±15%）**——这是 PCB 布线的硬性指标：D+/D- 等长、等距、同层、紧耦合走线，用阻抗计算器（如 Si9000）按板材参数验证后再投板。阻抗失配导致信号反射，示波器上表现为眼图闭合（眼图概念见 F.16.1），现场症状是设备时断时续。

### 速率等级与编码演进

| 版本 | 等级 | 数据速率 | 信号通道 | 编码 | 年份 |
|:----:|------|:--------:|----------|------|:----:|
| USB 1.1 | Low-Speed（LS） | 1.5 Mbps | D+/D- | NRZI + 位填充 | 1998 |
| USB 1.1 | Full-Speed（FS） | 12 Mbps | D+/D- | NRZI + 位填充 | 1998 |
| USB 2.0 | High-Speed（HS） | 480 Mbps | D+/D- | NRZI + 位填充 + Chirp 握手 | 2000 |
| USB 3.0（3.1 Gen1） | SuperSpeed（SS） | 5 Gbps | **新增** SSTX±/SSRX± | 8b/10b | 2008 |
| USB 3.1 Gen2 | SuperSpeed+ | 10 Gbps | SSTX±/SSRX± | 128b/132b | 2013 |
| USB4 | — | 20/40 Gbps | Type-C 多通道复用 | 隧道化架构 | 2019 |

USB 2.0 时代的编码值得讲透，因为它的设计动机和 PCIe 的 8b/10b 完全不同：

> NRZI（Non-Return-to-Zero Inverted）：USB 的线路编码——**数据 0 使电平翻转，数据 1 保持电平不变**。接收端从翻转沿提取时钟（USB 2.0 没有独立时钟线）。问题在于一长串连续的 1 意味着电平长时间不动，接收端时钟就会漂——于是有了位填充：发送端在连续 6 个 1 之后强制插入一个 0（制造一次翻转），接收端识别并丢弃填充位。这套"编码保跳变"的思路与 SerDes 的跳变密度铁律（F.16.1）同源，只是实现手段原始得多。

**High-Speed 的 480 Mbps 是在同一对 D+/D- 上跑出来的**——FS 时代的 3.3V 摆幅在 HS 模式切换到 400 mV 低压摆幅以降低跳变时间。设备插入时先以 FS 身份出现，随后与主机进行 **Chirp 握手**（双方互发 K/J 序列确认 HS 能力），谈成才切入 HS 模式。抓不到 Chirp 序列，说明线缆或阻抗有问题——设备会以 FS 12 Mbps 龟速工作，这是"USB 设备慢"的第一排查点。

**USB 3.0 的结构性变化**是新增了两对独立差分线 SSTX±/SSRX± 组成全双工高速通道，D+/D- 原样保留给 USB 2.0 兼容——一根 USB 3.0 线缆里实际是两套互不相干的通道。编码也换成了 SerDes 谱系：8b/10b（5 Gbps）→ 128b/132b（10 Gbps），与 PCIe 同宗。USB4 之后物理层复用 Type-C 通道并走向隧道化，详见 B-F.16.5。

> ⚠️ High-Speed 线缆超过 5 m 信号衰减就会失控，设备表现为时断时续、枚举随机失败。这类问题别在软件侧花时间——换短线、用带中继的有源延长线（active extension cable），或者干脆换接口形态。长距离从来不是 USB 的设计目标。

## <span class="blue"> 连接检测：电阻告密

USB 没有热插拔控制器这类复杂机制，设备插入的检测全靠几个电阻的分压关系：

- **Host 侧**：D+、D- 各接 15 kΩ 下拉到地，平时两根线都是低电平；
- **Device 侧**：在自己所属速率的那根线上接 1.5 kΩ 上拉到 3.3 V——FS/HS 设备上拉 D+，LS 设备上拉 D-。

设备插入后，上拉与下拉构成分压，对应数据线被抬到高电平——Host 检测到"哪根线被拉高"就同时知道了两件事：**有设备来了** + **它是什么速度等级**（HS 设备先以 FS 上拉出现，Chirp 握手后再切高速）。

这个机制对调试的实用价值：设备插上毫无反应时，万用表量 D+/D- 电平就能区分"设备没上电"（两根都低）与"上拉在了错的线上"（硬件设计错误）。

## <span class="blue"> OTG：双角色协商

传统 USB 角色固定：Host 恒为主，Device 恒为从。嵌入式产品经常要双角色——平板既要接 U 盘（当 Host），又要连 PC 被识别（当 Device）。**USB OTG（On-The-Go）**为此而生：

> OTG（On-The-Go）：允许同一个 USB 口在 Host 与 Device 角色间切换的扩展规范。Micro-USB 接口的第 5 脚 ID 引脚决定上电初始角色：ID 接地 = Host（A-Device），ID 悬空 = Device（B-Device）。连接后还可用 HNP（Host Negotiation Protocol）动态交换角色、用 SRP（Session Request Protocol）让 Device 请求 Host 恢复 VBUS 供电（省电场景）。

Linux 里 OTG 角色由控制器驱动管理，sysfs 可见可改：

```bash
cat /sys/class/udc/*/current_speed           # 当前 Device 侧速度
echo host   > /sys/.../usb_role/role         # 强制 Host（部分平台）
echo device > /sys/.../usb_role/role         # 强制 Device
```

Type-C 普及后，角色切换改由 CC 线配置通道完成（USB PD 协议的 DRP 模式），OTG 的 ID 引脚方案只存在于 Micro-USB 时代的产品——维护老设备时才需要碰它。

嵌入式的三种 USB 工作形态与内核配置：

| 模式 | 场景 | 关键 CONFIG | 典型产品 |
|:----:|------|-------------|----------|
| Host | 接 U 盘、键盘、4G 模组 | `USB_XHCI_HCD`/`USB_EHCI_HCD` | 工业网关 |
| Device（Gadget） | 被 PC 识别为 U 盘/串口/网卡 | `USB_CONFIGFS`+`USB_GADGET` | 开发板烧录口、智能手表 |
| OTG | 动态双角色 | `USB_OTG` + 控制器驱动 | 平板、双角色工控机 |

> 💡 Gadget 模式的一个高价值应用是产线烧录：DFU（Device Firmware Update）模式配合 `dfu-util`，一台 PC 经 Hub 可同时给几十块板子烧固件，效率远超逐块接 UART。Gadget 的完整配置方法在 B-C.7.4，实战在 7.5。

## <span class="blue"> 星型拓扑：127 个设备与 6 层深

USB 是**分层星型拓扑**：所有设备经 Hub 级联到 Root Hub，设备之间不许直连，不许成环。限制参数：

| 参数 | 限制 | 由来 |
|------|:----:|------|
| 最大设备数 | 127 | 7 位地址字段共 128 个，地址 0 保留给未枚举的新设备 |
| 最大层级 | 6 层（含 Root Hub） | 协议对延迟预算的硬性规定 |
| Hub 级联 | 最多 5 级 | 层级限制的推论 |
| 线缆长度 | HS 5 m / FS 5 m / SS 3 m | 信号衰减与传播延迟预算 |

```text
Root Hub (Tier 1)
├── Hub #1 (Tier 2)
│    ├── Hub #3 (Tier 3)
│    │    └── …最深可到 Tier 6
│    └── Keyboard
├── Hub #2 (Tier 2)
│    └── 4G 模组
└── Mouse（设备可直插 Root Hub，Hub 只是扩展端口用）
```

工程视角下这些极限参数很少成为约束——真实产品里超过两级 Hub 就要审视设计了。它们的价值在兼容性测试：USB-IF 认证会验证 6 层深度与 127 设备的极限场景。排查"设备接在 Hub 后面不认、直插就认"的问题时，方向是 Hub 供电与兼容性，不是层级数。

## <span class="blue"> 方案对比（Trade-off）

| 维度 | 评价 |
|------|------|
| 差分 vs 单端 | 抗干扰、可长线；代价是双倍的走线与等长约束 |
| NRZI+位填充 vs 8b/10b | 零开销、实现简单 vs 系统化保证跳变与直流平衡——速率上 Gbps 后前者退场 |
| 保留 D+/D- 兼容通道 | 二十年老设备即插即用；代价是连接器与线缆复杂度 |
| OTG 双角色 | 一个口两种用法，省物料；代价是角色协商的协议与调试复杂度（Type-C/PD 时代已被 CC 线方案取代） |
| Hub 级联扩展 | 理论上 127 设备；代价是共享带宽与供电分摊，级联越深越脆弱 |

## <span class="blue"> 本节总结

| 自查项 | 读完应能独立完成的动作 |
|--------|------------------------|
| 差分物理层 | 说出 90 Ω 阻抗的布线含义；把"设备时断时续"症状关联到眼图闭合 |
| 速率体系 | 背出 LS/FS/HS/SS 四档速率与通道构成；解释 USB 3.0 线缆里为什么是两套通道 |
| NRZI | 正确复述编码规则（0 翻转、1 保持）与位填充针对长串 1 的动机 |
| Chirp 握手 | 解释 HS 协商过程；"设备慢"先查是否回落到 FS |
| 连接检测 | 用 D+/D- 电平判断无反应设备的故障域 |
| OTG | 说出 ID 引脚/HNP/SRP 各自的角色；知道 Type-C 时代由 CC 线接管 |
| 拓扑 | 解释 127 与 6 层的出处；Hub 后不识别的排查方向 |
| 工作模式 | 按产品需求选对 Host/Gadget/OTG 模式与对应内核配置 |
