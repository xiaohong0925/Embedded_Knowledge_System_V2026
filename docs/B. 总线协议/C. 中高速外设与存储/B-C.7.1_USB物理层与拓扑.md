# B-C.7.1 USB 物理层与拓扑

> 所属章节：第五部 B. 总线协议 > C. 中高速外设与存储
>
> 难度：[I] | 预计阅读时间：50 分钟

## 本节导读

USB 是嵌入式系统里出现频率最高的外设接口：键盘鼠标、U 盘、4G 模组、摄像头、调试烧录口，都挂在它上面。与 I2C/SPI 这类板级总线不同，USB 是为"用户随手插拔、线缆几米长、设备千奇百怪"的场景设计的——它的物理层和拓扑规则处处体现这个设计目标。读 USB 的物理层，本质上是在读一份"消费级插拔场景"的工程答卷。

本篇是 USB 系列的物理层与拓扑篇，回答两个底层问题：信号怎么在一对差分线上稳定跑到 480 Mbps 乃至 10 Gbps，以及一台主机怎么把上百个设备组织成一棵树。不要求任何 USB 背景，术语就地解释。枚举与描述符（协议层）在 C.7.2，Linux 驱动在 C.7.3/7.4，USB4 的隧道化演进在 F.16.5。

> 本节覆盖：D+/D- 差分对与 J/K/SE0 线路状态、90 Ω 阻抗的布线含义、四种速率等级与编码演进（NRZI/位填充、8b/10b、128b/132b）、Chirp 高速握手全过程、VBUS 供电与电流预算、上拉电阻连接检测、OTG 双角色机制、星型拓扑的 127 设备与 6 层限制、嵌入式三种工作模式与物理层排障。按"信号 → 速率 → 供电 → 插拔检测 → 角色 → 拓扑 → 排障"展开——这正是你从零点亮一个 USB 口时实际走通的顺序。

读完你应该能独立完成三件事：把 USB 接口的 PCB 布线约束讲给硬件同事听、用万用表和 `lsusb` 区分物理层故障域、为产品选对 Host/Gadget/OTG 模式。

## 物理层：一对差分线的二十年

### D+/D- 差分对与线路状态

USB 1.x/2.0 的全部数据都走一对差分线：D+ 和 D-。数据不由单根线对地的电平表示，而由**两根线之间的电压差**表示——差分传输的原理（共模干扰在取差时相消）在 F.16.1 已完整展开，这里直接用它与低速单端总线对照：I2C 的单根开漏线在几米长线缆上会被干扰淹没，差分对则天然扛得住线缆环境。

这对线除了传数据，还兼任**状态信令**——协议用几种特殊的电平组合表达"空闲、复位、挂起"等语义：

> J 状态 / K 状态：差分对的两种相反极性——J 是 D+ 高 D- 低，K 反之（低速设备定义相反，以空闲态为 J）。数据传输就是在 J/K 之间按编码规则翻转；**空闲（Idle）就是持续的 J 状态**，主机据此判断总线上当前无事发生。
>
> SE0（Single-Ended Zero）：D+ 和 D- **同时**为低的异常组合——正常数据永远一高一低，双低只用于信令：持续 2.5 µs 以上是包结束（EOP）标志，持续 10 ms 以上是**复位**命令。设备上电后被主机复位用的就是它。SE1（双高）是非法态，出现即线路故障。

记住"双低=复位"这一条，示波器排查"设备不停掉线重连"时就有抓手：抓到周期性 SE0，说明主机在反复复位设备——往下查供电或信号完整性，而不是驱动。

### 90 Ω 阻抗：PCB 布线的硬性指标

USB 2.0 规范要求这对线的**差分特性阻抗 90 Ω（±15%）**。这是投板前必须验证的数字，不是参考值：D+/D- 等长（长度差 <1 mm 量级）、等距、同层、紧耦合走线，用阻抗计算器（如 Si9000）按板材参数（介电常数、铜厚、线宽线距）算好再投板。阻抗失配导致信号反射，示波器上表现为眼图闭合（眼图概念见 F.16.1），现场症状是设备时断时续、高速回落低速。

> 特性阻抗（Characteristic Impedance）：传输线对高频信号呈现的等效阻抗，由走线几何与板材决定，与线长无关。它的工程含义是"阻抗连续"——信号在走线、过孔、连接器、线缆的每一跳都看到相同的 90 Ω 才无反射。这就是为什么 USB 走线要远离参考平面开槽、少打过孔：每一处几何突变都是一次阻抗不连续。

## 速率等级与编码演进

| 版本 | 等级 | 数据速率 | 信号通道 | 编码 | 年份 |
|:----:|------|:--------:|----------|------|:----:|
| USB 1.1 | Low-Speed（LS） | 1.5 Mbps | D+/D- | NRZI + 位填充 | 1998 |
| USB 1.1 | Full-Speed（FS） | 12 Mbps | D+/D- | NRZI + 位填充 | 1998 |
| USB 2.0 | High-Speed（HS） | 480 Mbps | D+/D- | NRZI + 位填充 + Chirp 握手 | 2000 |
| USB 3.0（3.2 Gen1） | SuperSpeed（SS） | 5 Gbps | **新增** SSTX±/SSRX± | 8b/10b | 2008 |
| USB 3.2 Gen2 | SuperSpeed+ | 10 Gbps | SSTX±/SSRX± | 128b/132b | 2013 |
| USB4 | — | 20/40 Gbps | Type-C 多通道复用 | 隧道化架构 | 2019 |

> 命名混乱是 USB 生态的长期公害：USB 3.0 先后被改名为 USB 3.1 Gen1、USB 3.2 Gen1——同一个 5 Gbps 三个名字。选型认速率不认名字，规格书上找 "5 Gbps / 10 Gbps / 20 Gbps" 字样，别数 Gen 几。

USB 2.0 时代的编码值得讲透，因为它的设计动机和 PCIe 的 8b/10b 完全不同：

> NRZI（Non-Return-to-Zero Inverted，反向不归零编码）：USB 的线路编码——**数据 0 使电平翻转，数据 1 保持电平不变**。接收端从翻转沿提取时钟（USB 2.0 没有独立时钟线）。问题在于一长串连续的 1 意味着电平长时间不动，接收端时钟就会漂——于是有了位填充：发送端在连续 6 个 1 之后强制插入一个 0（制造一次翻转），接收端识别并丢弃填充位。这套"编码保跳变"的思路与 SerDes 的跳变密度铁律（F.16.1）同源，只是实现手段原始得多。

### High-Speed 与 Chirp 握手

**High-Speed 的 480 Mbps 是在同一对 D+/D- 上跑出来的**——FS 时代的 3.3 V 摆幅在 HS 模式切换到 400 mV 低压摆幅以降低跳变时间，等效于在同一条路上换了一辆快得多的车。

设备插入时先以 FS 身份出现（D+ 上拉），随后与主机进行 **Chirp 握手**确认双方都有 HS 能力：

```text
主机先复位设备（SE0 ≥ 10 ms）
  → 设备回应 Chirp K（约 1 ms 的 K 状态）：“我能跑高速”
  → 主机连发 3 对 K-J 交替序列：“收到，切换”
  → 设备断开 FS 上拉、启用 HS 端接，双方切入 480 Mbps
```

抓不到 Chirp 序列，说明线缆或阻抗有问题——设备会以 FS 12 Mbps 龟速工作，这是"USB 设备慢"的第一排查点。`lsusb -t` 里设备速度显示 12M 而不是 480M，就是握手失败的软侧证据（排障节展开）。

Chirp 谈成后还有一个常被忽略的动作：设备**断开 1.5 kΩ 上拉、启用 45 Ω HS 端接**。物理层意义上，这是一次"换司机"——FS 的驱动器和端接全部退场，HS 收发器接管同一对线。示波器上能看到信号摆幅从 3.3 V 坍缩到 400 mV，这个坍缩瞬间就是切换成功的物理证据。

### USB 3.0 的结构性变化

USB 3.0 不是在旧路上提速，而是**新增两对独立差分线** SSTX±/SSRX± 组成全双工高速通道（一发一收，物理上分离），D+/D- 原样保留给 USB 2.0 兼容——一根 USB 3.0 线缆里实际是两套互不相干的通道，老的插老的、新的跑新的。编码也换成了 SerDes 谱系：8b/10b（5 Gbps）→ 128b/132b（10 Gbps），与 PCIe 同宗同源，均衡/眼图/抖动那套分析手段完全通用（F.16.1）。USB4 之后物理层复用 Type-C 通道并走向隧道化，详见 F.16.5。

> LFPS（Low Frequency Periodic Signaling，低频周期信令）：SS 通道的"门铃"。SuperSpeed 差分对平时断电休眠，链路唤醒、链路训练、热复位都靠在线对上发一段低频方波来发起——它故意不用高速编码，保证对端在最低功耗状态下也能检测到。示波器抓 SS 链路问题时，先看到的往往是 LFPS 方波而不是数据——认得出它，就知道链路训练进行到了哪一步。

SS 连接器也有辨识度极强的物理特征：Type-A 母口里 5 根新增触点藏在深处，插入时先接通 USB 2.0 的 4 根、再接通 SS 的 5 根——这就是为什么 USB 3.0 设备"插一半"时能以 480M 工作，插到底才是 5 Gbps。现场遇到"同一只 U 盘这次 480M 下次 5G"的玄学问题，先怀疑插座弹片磨损导致的接触时序。

## 供电：VBUS 与电流预算

USB 的第一功能其实是供电——VBUS 恒为 5 V，设备没枚举完也有电。但"能取多少电流"有明确的分级纪律，不是插上就能放开取：

| 阶段 | 允许电流 | 说明 |
|------|:--------:|------|
| 插入未枚举 | 100 mA（一个 unit load） | 设备自检、等待枚举期间的预算 |
| 枚举完成后 | 描述符申报值，USB 2.0 上限 500 mA | 主机按申报值批准或拒绝 |
| USB 3.x 口 | 上限提高到 900 mA | 协议层机制相同 |
| USB PD（Type-C） | 协商至 5 A / 100 W+ | 独立协议，见 C.7.x 与 F.16.5 |

> unit load（单位负载）：USB 2.0 定义的电流计量单位，1 unit = 100 mA。设备在描述符里申报自己需要几个 unit，主机按端口的供电预算决定批准或拒绝（拒绝即枚举失败）。电池充电（BC 1.2）与 PD 是另外两套协商，手机"插电脑充电慢"就是只拿到默认 500 mA 的实例。

工程后果常被低估：**嵌入式板子的 USB Host 口供电是设计出来的，不是免费的**。4G 模组发射瞬间电流可到 2 A，VBUS 走线细、滤波电容小，模组一注册网络就掉电复位——"4G 模组时好时坏"的经典根因是供电不是射频。接大功率设备前，核对板子 USB 口的 VBUS 限流开关/电源路径规格。

## 连接检测：电阻告密

USB 没有热插拔控制器这类复杂机制，设备插入的检测全靠几个电阻的分压关系：

- **Host 侧**：D+、D- 各接 15 kΩ 下拉到地，平时两根线都是低电平；
- **Device 侧**：在自己所属速率的那根线上接 1.5 kΩ 上拉到 3.3 V——FS/HS 设备上拉 D+，LS 设备上拉 D-。

设备插入后，上拉与下拉构成分压，对应数据线被抬到约 3 V——Host 检测到"哪根线被拉高"就同时知道了两件事：**有设备来了** + **它是什么速度等级**（HS 设备先以 FS 上拉出现，Chirp 握手后再切高速）。检测电平超过约 2 ms 有效，随后主机发 SE0 复位，枚举流程（C.7.2）开始。

这个机制对调试的实用价值：设备插上毫无反应时，万用表量 D+/D- 电平就能三分天下——两根都低是设备没上电；上拉出现在了错的线上是硬件设计错误；电平正常但主机无反应，问题在主机侧（Hub 供电、控制器、驱动）。

### 挂起与远程唤醒

连接检测的反面是省电：USB 2.0 规定总线空闲（持续 J 状态）超过 3 ms，设备必须进入**挂起（Suspend）**，总电流压到 2.5 mA 以下——这是物理层状态机的另一档，VBUS 仍在、数据停止。唤醒有两个方向：主机发复位/恢复信号（Resume，K 状态驱动 20 ms），或设备自己驱动 K 状态发起**远程唤醒（Remote Wakeup）**——键盘按一下唤醒睡眠中的电脑，走的就是后者。

工程意义在电池产品：挂起电流超标是待机功耗失控的常见根因（某个端点没配好、设备就是不进挂起）。用 `cat /sys/bus/usb/devices/*/power/...` 配合功耗仪逐个设备核对，能把"待机一晚掉电 20%"归因到具体设备。

USB 3.x 把这档省电细化成了 U0~U3 四级链路状态（U0 工作、U3 挂起，U1/U2 是更快的浅睡档），由链路双方自动协商进出——机制升级，排查思路不变：先确认链路停在哪一档，再谈功耗归因。

## OTG：双角色协商

传统 USB 角色固定：Host 恒为主，Device 恒为从。嵌入式产品经常要双角色——平板既要接 U 盘（当 Host），又要连 PC 被识别（当 Device）。**USB OTG（On-The-Go）**为此而生：

> OTG（On-The-Go）：允许同一个 USB 口在 Host 与 Device 角色间切换的扩展规范。Micro-USB 接口的第 5 脚 ID 引脚决定上电初始角色：ID 接地 = Host（A-Device），ID 悬空 = Device（B-Device）。连接后还可用 HNP（Host Negotiation Protocol）动态交换角色、用 SRP（Session Request Protocol）让 Device 请求 Host 恢复 VBUS 供电（省电场景下 Host 会关 VBUS 休眠）。

Linux 里 OTG 角色由控制器驱动管理，sysfs 可见可改：

```bash
cat /sys/class/udc/*/current_speed           # 当前 Device 侧速度
echo host   > /sys/.../usb_role/role         # 强制 Host（部分平台）
echo device > /sys/.../usb_role/role         # 强制 Device
```

Type-C 普及后，角色切换改由 CC 线配置通道完成（USB PD 协议的 DRP 模式），OTG 的 ID 引脚方案只存在于 Micro-USB 时代的产品——维护老设备时才需要碰它。

嵌入式的三种 USB 工作形态与内核配置：

| 模式 | 场景 | 关键 CONFIG | 典型产品 |
|:----:|------|-------------|----------|
| Host | 接 U 盘、键盘、4G 模组 | `USB_XHCI_HCD`/`USB_EHCI_HCD` | 工业网关 |
| Device（Gadget） | 被 PC 识别为 U 盘/串口/网卡 | `USB_CONFIGFS`+`USB_GADGET` | 开发板烧录口、智能手表 |
| OTG | 动态双角色 | `USB_OTG` + 控制器驱动 | 平板、双角色工控机 |

> 💡
> Gadget 模式的一个高价值应用是产线烧录：DFU（Device Firmware Update）模式配合 `dfu-util`，一台 PC 经 Hub 可同时给几十块板子烧固件，效率远超逐块接 UART。Gadget 的完整配置方法在 C.7.4，实战在 C.7.5。

## 星型拓扑：127 个设备与 6 层深

USB 是**分层星型拓扑**：所有设备经 Hub 级联到 Root Hub，设备之间不许直连，不许成环。限制参数：

| 参数 | 限制 | 由来 |
|------|:----:|------|
| 最大设备数 | 127 | 7 位地址字段共 128 个，地址 0 保留给未枚举的新设备 |
| 最大层级 | 6 层（含 Root Hub） | 协议对延迟预算的硬性规定 |
| Hub 级联 | 最多 5 级 | 层级限制的推论 |
| 线缆长度 | HS 5 m / FS 5 m / SS 3 m | 信号衰减与传播延迟预算 |

```text
Root Hub (Tier 1)
├── Hub #1 (Tier 2)
│    ├── Hub #3 (Tier 3)
│    │    └── …最深可到 Tier 6
│    └── Keyboard
├── Hub #2 (Tier 2)
│    └── 4G 模组
└── Mouse（设备可直插 Root Hub，Hub 只是扩展端口用）
```

工程视角下这些极限参数很少成为约束——真实产品里超过两级 Hub 就要审视设计了。它们的价值在兼容性测试：USB-IF 认证会验证 6 层深度与 127 设备的极限场景。排查"设备接在 Hub 后面不认、直插就认"的问题时，方向是 Hub 供电与兼容性，不是层级数。

> ⚠️
> 拓扑里还藏着一条带宽纪律：同一棵子树上的所有 HS 设备**共享 Root Hub 的 480 Mbps**。Hub 不提速、只扩展端口数——4 个摄像头挂同一个 Hub 各要 100 Mbps，第四路帧率必崩。多高速设备场景要核对它们在 `lsusb -t` 里挂在哪棵子树下，必要时分散到不同控制器。

## 排障：物理层故障

| 症状 | 优先怀疑 | 验证方法 |
|:---|:---|:---|
| 插上毫无反应 | 设备未上电 / VBUS 缺失 | 万用表量 VBUS 与 D+/D- 电平 |
| 电平正常但主机无反应 | 主机侧 Hub/控制器/驱动问题 | 换口、换机交叉验证 |
| 设备被识别但速度只有 12M | Chirp 握手失败，回落 FS | `lsusb -t` 看速度字段 |
| 设备周期性掉线重连 | 主机在反复发 SE0 复位——供电跌落或信号完整性 | 示波器抓 D+/D- 看周期 SE0；量 VBUS 跌落 |
| 4G/摄像头上负载就掉 | VBUS 供电不足，瞬态电流击穿预算 | 示波器/电流探头看 VBUS 波形 |
| 高速设备时断时续 | 阻抗失配/线缆过长，眼图闭合 | 换短线验证；查走线阻抗报告 |
| 多高速设备同时用就卡 | 同子树共享 480 Mbps 带宽超预算 | `lsusb -t` 核对拓扑分布 |
| 待机功耗超标 | 某设备未进挂起（Suspend），挂起电流超 2.5 mA | 功耗仪 + `/sys/.../power/` 逐设备核对 |
| U 盘这次 480M 下次 5G | USB 3.0 插座弹片磨损，SS 触点接触时序不稳 | 换插座/线缆交叉验证 |

软侧第一工具是 `lsusb -t`（拓扑+速度一把抓）。一份典型输出：

```text
/:  Bus 02.Port 1: Dev 1, Class=root_hub, Driver=xhci_hcd/4p, 5000M
    |__ Port 2: Dev 3, If 0, Class=Mass Storage, Driver=usb-storage, 5000M
/:  Bus 01.Port 1: Dev 1, Class=root_hub, Driver=xhci_hcd/12p, 480M
    |__ Port 3: Dev 5, If 0, Class=Communications, Driver=cdc_acm, 12M
    |__ Port 4: Dev 6, If 0, Class=Vendor Specific, Driver=option, 480M
```

逐字段看三个要点：

- **每行末尾的速度字段是第一证据**——5000M/480M/12M 直接告诉你协商结果。HS 设备显示 12M，Chirp 失败实锤，去查线缆和阻抗，别在驱动里翻。
- **Bus 分组反映物理控制器**——Bus 02 挂在 5000M root hub（SS 通道），Bus 01 是 480M（HS 通道）。前文"带宽共享"纪律就在这里核实：两个高带宽设备是否挤在同一 Bus 下。
- **Driver 列说明枚举走到了哪一步**——有 `usb-storage`、`cdc_acm` 说明枚举成功且驱动已绑定；Class 正常但 Driver 列空，是枚举成功但驱动没配上（协议层/驱动问题，不是物理层）——这条分界线能省掉一半排查时间。

## 方案对比（Trade-off）

| 维度 | 评价 |
|------|------|
| 差分 vs 单端 | 抗干扰、可长线；代价是双倍的走线与等长约束 |
| NRZI+位填充 vs 8b/10b | 零开销、实现简单 vs 系统化保证跳变与直流平衡——速率上 Gbps 后前者退场 |
| 保留 D+/D- 兼容通道 | 二十年老设备即插即用；代价是连接器与线缆复杂度 |
| OTG 双角色 | 一个口两种用法，省物料；代价是角色协商的协议与调试复杂度（Type-C/PD 时代已被 CC 线方案取代） |
| Hub 级联扩展 | 理论上 127 设备；代价是共享带宽与供电分摊，级联越深越脆弱 |

## 本节总结

USB 物理层的全部复杂度来自一个设计目标：**让用户随便插、随便拔、插什么都能用**。差分对+90 Ω 阻抗保证几米线缆上的信号完整；J/K/SE0 把信令和数据压在同一对线上；速率演进走"同路换车（HS）→ 加开新路（SS）→ 隧道化（USB4）"三步，编码随之从 NRZI 换到 SerDes 谱系；连接检测用两个电阻的分压完成，优雅但把故障域划给了硬件；VBUS 供电分级是工程上最容易栽的坑——4G 模组掉线先量电压。拓扑的 127/6 层是认证参数，真正要记的是带宽共享纪律：Hub 只扩端口不提速。带着"软侧先 `lsusb -t`、硬侧先量电平"的分界意识，USB 物理层故障的排查就是收敛的过程而不是发散的猜测。

| 关键结论 | 一句话记忆 |
|:---|:---|
| 线路状态 | J=空闲，SE0 双低=复位；反复复位查供电/信号 |
| 阻抗 | 90 Ω±15%，投板前算，不是参考值 |
| HS 握手 | 先 FS 上拉，Chirp K-J 序列谈成才切 480M |
| 编码 | NRZI：0 翻转 1 保持；连 6 个 1 插 0 保跳变 |
| 供电 | 未枚举 100 mA，枚举后申报值；大功率设备先核对 VBUS 路径 |
| 连接检测 | 设备 1.5 kΩ 上拉，主机 15 kΩ 下拉；量电平三分故障域 |
| 拓扑 | 127 设备/6 层是认证参数；Hub 共享带宽才是工程约束 |
| 排障分界 | `lsusb -t` 看速度与 Driver 列；万用表量 VBUS/D+/D- |
| 省电 | 3 ms 空闲进挂起（2.5 mA）；SS 细化为 U0~U3 链路状态 |
| 命名陷阱 | USB 3.0=3.1 Gen1=3.2 Gen1 全是 5 Gbps；认速率不认名字 |
| 触点时序 | SS 口先通 2.0 后通 SS——"插一半 480M"的物理解释 |
