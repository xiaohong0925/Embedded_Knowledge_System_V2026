## 开篇决策场景：机器人控制器项目的SoC选型之争

2025年初，某机器人公司的硬件团队会议室里，一场激烈的争论已经持续了三周。

项目经理老王把两叠datasheet拍在桌上："我们新控制器选NXP i.MX8M Plus还是Rockchip RK3588？下周必须定！"

硬件工程师小李力挺NXP："i.MX8M Plus的BSP成熟度高，Yocto层完善，NXP是Linux基金会成员，长期支持有保障。我们上个项目用i.MX6，BSP质量有目共睹。"

采购部张总皱着眉头："NXP模组$85一颗，RK3588模组只要$45，成本差一倍！而且RK3588四核A76性能更强，还有6 TOPS NPU。"

软件负责人老周插话："RK3588的BSP我调研过了——主线内核6.12已经支持大部分功能，GPU有Panthor开源驱动，Collabora在推上游化。但VPU编解码和NPU驱动还是半成品。NXP的Vivante GPU虽然闭源，但GStreamer插件成熟，Hantro VPU库稳定。"

质量工程师小陈提出了关键问题："产品生命周期8年。NXP承诺10年供货，RK3588呢？Rockchip的BSP维护周期多长？他们的参考设计质量如何？"

会议室沉默了。

**这就是本章要解决的问题**：面对市场上数十种SoC和参差不齐的BSP支持，如何建立一套**科学的评估体系**，在成本、功能、风险、长期维护之间做出最优决策？

> 💡 本章节将为你提供一套完整的BSP评估方法论，涵盖五大主流SoC厂商的BSP策略深度分析、主线内核与厂商内核的权衡、20项BSP评估检查清单，以及内核升级路径规划。这不是一篇产品宣传稿，而是基于真实工程经验和社区数据的决策指南。

### 1.1 厂商选择的市场格局

嵌入式Linux SoC市场呈现出清晰的分层结构。根据2025年的市场数据和社区活跃度，我们将主要厂商分为三个梯队：

| 梯队 | 厂商 | 主力系列 | 市场定位 | 典型价格区间（模组） |
|------|------|---------|---------|-------------------|
| 第一梯队（工业/汽车级） | NXP、TI、Renesas | i.MX6/8/9、AM6x/Jacinto、RZ/G/V | 工业自动化、汽车电子、医疗 | $60-$200+ |
| 第二梯队（消费/商用级） | Rockchip、Amlogic、MediaTek | RK3568/3588/3576 | 商显、IoT网关、教育平板、SBC | $15-$60 |
| 第三梯队（高端IoT/AI） | Qualcomm、NVIDIA Jetson | QCS6490/8550、Orin Nano | 机器人、Edge AI、高端IoT | $100-$500+ |

**选型的核心trade-off**：第一梯队厂商提供**长期支持承诺**和**完善的文档/参考设计**，但价格较高、性能/功耗比相对保守；第二梯队厂商提供**极高的性价比**和**强大的多媒体能力**，但BSP成熟度和长期支持承诺相对较弱；第三梯队厂商提供**顶级的AI/计算能力**，但闭源组件多、生态锁定风险大。

以下我们逐一深入分析五大厂商的BSP策略。

### 1.2 NXP — i.MX系列的工业标杆

#### 1.2.1 产品矩阵与定位

NXP的i.MX系列是嵌入式Linux市场**最成熟、覆盖最广**的产品线之一，从入门级i.MX6ULL（Cortex-A7，$5级别）到高端i.MX95（6x Cortex-A55 + Mali-G310，$50+级别），形成了完整的产品阶梯 [^2943^][^2991^]。

| 系列 | 架构 | 制程 | 典型内核 | GPU | NPU | 目标市场 |
|------|------|------|---------|-----|-----|---------|
| i.MX6ULL | Cortex-A7 | 40nm | NXP 5.10/6.1 | 无 | 无 | 低成本IoT、网关 |
| i.MX8M Mini | 4x Cortex-A53 | 14nm | NXP 5.15/6.1 | Vivante GC4000 | 无 | 通用嵌入式、HMI |
| i.MX8M Plus | 4x Cortex-A53 | 14nm | NXP 6.1/6.6 | Vivante GC7000ULX | 2.3 TOPS | 工业视觉、AI边缘 |
| i.MX8M Nano | 4x Cortex-A53 | 14nm | NXP 6.1 | Vivante GC7000 | 无 | 低功耗多媒体 |
| i.MX93 | 2x Cortex-A55 | 16nm | NXP 6.6 | Arm Ethos U-65 | 0.5 TOPS | 工业控制、能源管理 |
| i.MX91/95 | 1-6x Cortex-A55 | 16nm | NXP 6.6+ | Mali-G310 | 内置NPU | 汽车V2X、工业4.0 |

#### 1.2.2 官方BSP架构

NXP的BSP体系围绕**Yocto Project**构建，是其最大的优势之一 [^2943^][^2948^]：

**官方Yocto层结构**：

```
├── recipes-bsp/              # U-Boot、ATF、固件
│   ├── u-boot-imx/           # 基于NXP lf_v2024.04
│   ├── imx-atf/              # Arm Trusted Firmware
│   └── firmware-imx/         # DDR PHY、VPU固件
├── recipes-kernel/
│   └── linux-imx/            # NXP内核 lf-6.6.y
├── recipes-graphics/
│   ├── imx-gpu-viv/          # Vivante GPU驱动
│   └── imx-gpu-sdk/          # GPU示例程序
├── recipes-multimedia/
│   ├── imx-vpuhantro/        # Hantro VPU库
│   └── imx-vpuwrap/          # VPU封装层
└── recipes-ml/
    └── ethosu-driver/        # Arm Ethos-U NPU驱动
```

**NXP Yocto快速启动** [^2956^]：
```bash

mkdir ${MY_YOCTO} && cd ${MY_YOCTO}
repo init -u https://github.com/nxp-imx/imx-manifest \

```

#### 1.2.3 主线支持状态

NXP对**主线内核 upstreaming**的投入在嵌入式SoC厂商中**名列前茅**。这得益于NXP是Linux基金会长期成员，拥有专职的上游化团队。

| i.MX系列 | 主线内核支持 | 评价 |
|---------|------------|------|
| i.MX6全系 | Linux 3.x+ 完全支持 | 最成熟，社区驱动完善 |
| i.MX7 | Linux 4.x+ 完全支持 | 成熟 |
| i.MX8M Mini/Nano/Plus | Linux 5.x+ 基本支持 | GPU需闭源blob，VPU主线支持不完整 |
| i.MX8M Quad | Linux 5.x+ 支持 | HDMI/DP需固件 |
| i.MX8X | Linux 5.x+ 支持 | 较好 |
| i.MX93 | Linux 6.1+ 支持 | 主线支持快速增长 |
| i.MX91/95 | Linux 6.6+ 初期支持 | 新系列，主线化进行中 |

**NXP主线化的独特优势**：
1. **U-Boot主线化最彻底**：i.MX6/7/8系列的U-Boot支持几乎全部由NXP工程师维护在主线上
2. **内核驱动积极提交**：电源管理（PFUZE）、以太网（FEC）、CAN、GPIO等驱动持续上游化
3. **Device Tree质量高**：NXP的DTS/DTSI遵循主线规范，版本控制清晰

#### 1.2.4 长期维护承诺

NXP对工业客户的长期支持承诺是其**核心竞争力**：

- **产品 longevity 承诺**：i.MX工业级芯片**10-15年**供货保证（通过Product Longevity Program）
- **BSP季度发布**：每年4次BSP更新，包含安全补丁和bug修复 [^2991^]
- **LTS内核跟踪**：紧跟CIP SLTS版本，确保内核安全补丁覆盖产品全生命周期
- **Yocto LTS跟随**：Scarthgap (5.0) 是当前NXP主推的Yocto版本 [^2948^][^2951^]

> 💡 NXP的BSP质量在行业内口碑最好——文档完整、参考设计可靠、社区活跃。但代价是模组价格较高（i.MX8M Plus模组$60-$120），且部分IP（如Vivante GPU、Hantro VPU）依赖闭源二进制blobs。

#### 1.2.5 NXP BSP的不足之处

- **GPU闭源**：Vivante GPU的用户态驱动（libGL/libGLES）是闭源的，虽然有基于Gallium的开源etnaviv驱动，但功能覆盖不如闭源版本完整
- **VPU固件闭源**：Hantro VPU需要加载闭源firmware
- **NPU生态还在建设中**：i.MX93的Ethos-U NPU支持相对基础，与Rockchip/NVIDIA的NPU生态有差距
- **i.MX95尚未大规模出货**：作为2024年底发布的新系列，i.MX95的BSP成熟度需要时间验证 [^2992^]

#### 1.3.1 产品矩阵与定位

TI在嵌入式处理器领域有**超过30年的积累**，其处理器产品分为两个主要方向：AM系列（Sitara，通用工业）和Jacinto系列（汽车ADAS/网关） [^2888^][^2958^]。

| 系列 | 架构 | 制程 | Linux SDK | GPU | 加速器 | 目标市场 |
|------|------|------|----------|-----|--------|---------|
| AM62x | 1-4x Cortex-A53 | 16nm | Processor SDK 6.1 | PowerVR AX1 | 无 | 工业HMI、PLC |
| AM64x | 2x A53 + 4x R5F | 16nm | Processor SDK 6.1 | 无 | PRU-ICSS | 工业实时控制 |
| AM67x | 1x A53 + GPU | 16nm | Processor SDK 8.x | IMG BXS-4-64 | 无 | 工业视觉 |
| TDA4VM (J721E) | 2x A72 + 6x R5F | 16nm | Processor SDK 8.x | PowerVR AX2 | C7x DSP, DMPAC | ADAS L2+ |

#### 1.3.2 Processor SDK架构

TI的Processor SDK是一个**多处理器、多操作系统**开发平台，这是其区别于其他厂商的核心特点 [^2888^]：

```
Processor SDK/
├── processor-sdk-linux/        # Linux A核主系统
│   ├── ti-linux-kernel/        # TI维护的内核（通常6.1/6.6 LTS）
│   ├── ti-u-boot/              # U-Boot
│   ├── ti-arm-firmware/        # 固件
│   └── filesystem/             # 根文件系统
├── processor-sdk-rtos/         # RTOS核心（Cortex-R5F/DSP）
│   ├── tidl/                   # TI Deep Learning库
│   ├── ti-openvx/              # OpenVX加速
│   ├── vision-apps/            # 视觉处理应用
│   └── pdk/                    # 平台开发套件
└── processor-sdk-qnx/          # QNX支持（汽车级）
    └── ...
```

**异构计算架构**是TI的独特优势。以TDA4VM为例：
- **Cortex-A72**：运行Linux，负责系统管理和决策
- **Cortex-R5F**：运行RTOS，负责实时控制（100us级响应）
- **C7x DSP**：负责信号处理和AI推理
- **DMPAC**：专用图像处理硬件

**SDK构建流程**：
```bash
# 克隆SDK
git clone https://github.com/TexasInstruments/ProcessorSDK.git
cd ProcessorSDK

# 设置目标SoC
export SOC=j721e
export TISDK_IMAGE=adas

# 下载依赖
./setup.sh

# 构建SDK
cd sdk_builder
make sdk -j $(nproc)

# 制作启动SD卡
sudo ./sdk_builder/scripts/mk-linux-card.sh /dev/sdX
```

#### 1.3.4 主线支持状态

TI在**主线支持方面投入巨大**，特别是K3架构（AM6x/Jacinto系列的基础）：

| SoC | 主线U-Boot | 主线Linux | 评价 |
|-----|-----------|----------|------|
| AM62x | 完整 | Linux 6.1+ 完整 | 工业HMI首选主线方案 |
| AM64x | 完整 | Linux 6.1+ 完整 | 实时控制强大 |
| TDA4VM (J721E) | 完整 | Linux 6.1+ 基本支持 | 复杂异构需TI SDK |

**TI upstreaming的亮点**：
1. **K3平台统一架构**：AM6x和Jacinto共享K3架构，主线化工作可复用
2. **TI SCI（System Controller Interface）**：主线内核已支持TI的固件通信协议
3. **PRU-ICSS主线化**：可编程实时单元驱动已进主线
4. **工业协议栈**：EtherCAT、Profinet等工业通信协议有TI官方支持

#### 1.3.5 工业/汽车生态

TI的BSP生态**深度绑定工业和汽车应用场景**：

- **工业通信**：PRU-ICSS支持EtherCAT、Profinet IRT、EtherNet/IP等实时工业以太网协议
- **功能安全**：部分芯片支持SIL 2/ASIL B等级，提供安全手册
- **汽车认证**：Jacinto系列针对AEC-Q100和ISO 26262设计
- **参考设计完整**：每个SoC都有EVM评估板、原理图、PCB设计文件、BOM清单

> 💡 TI的Processor SDK是**业界最复杂但功能最全面**的嵌入式SDK之一。如果你需要异构多核（Linux+RTOS）、硬实时控制、工业通信协议，TI几乎是唯一选择。但学习曲线陡峭，SDK构建时间长达数小时。

#### 1.4.3 GPU驱动：Panthor的里程碑

RK3588集成的**Mali-G610 MP4**是ARM Valhall架构（第三代）GPU。主线支持经历了从Panfrost到Panthor的演进 [^2953^][^2955^]：

```
Panfrost驱动（旧） → 支持Bifrost架构（Mali-G52/G57/G72等）
Panthor驱动（新） → 支持Valhall CSF架构（Mali-G610/G310/G710等）
```

**关键里程碑**：
- **Linux 6.9**：Panthor DRM驱动合入主线
- **Mesa 24.1+**：PanVK（Vulkan驱动）通过Vulkan 1.4一致性测试 [^2953^]
- **Mesa 24.1+**：Panfrost（OpenGL ES驱动）通过OpenGL ES 3.1一致性测试
- **Wayland支持**： Weston/Wayland在RK3588上运行稳定

```bash
# 检查Panthor驱动状态
dmesg | grep panthor
# [drm] Initialized panthor 1.3.0 for fb000000.gpu on minor 0

# 检查Vulkan支持
vulkaninfo | grep deviceName
# deviceName        = Mali-G610 (PanVK)
```

#### 1.4.4 NPU驱动：Rocket的新征程

RK3588的**6 TOPS NPU**（基于NVDLA衍生设计）在2025年获得了主线支持 [^2953^][^2957^]：

- **内核驱动**：Rocket（DRM_ACCEL子系统），由Tomeu Vizoso编写
- **用户空间**：Teflon TensorFlow delegate，集成在Mesa中
- **支持情况**：RK3588优先，RK3568/RK3576等需要额外工作
- **注意**：主线NPU驱动功能尚不如Rockchip厂商内核的RKNPU完善

#### 1.4.5 BSP评估：优势与风险

**Rockchip BSP的优势**：
1. **极高的性价比**：RK3588模组$30-$60，性能超越$100+的竞品
2. **主线化速度惊人**：从Linux 6.1到6.18，RK3588主线支持几乎从零到完整
3. **开源生态活跃**：Collabora、Armbian、Radxa、Joshua Riek等社区持续贡献
4. **多媒体能力强大**：4K编解码、多屏输出、GPU加速
5. **多个Linux发行版支持**：Armbian、Debian、Ubuntu、Arch Linux ARM

**Rockchip BSP的风险**：
1. **长期支持承诺不明确**：Rockchip不提供像NXP/TI那样的10+年供货保证
2. **参考设计质量参差不齐**：官方EVB设计相对简单，部分外围电路有bug
3. **文档不够完整**：TRM不完整，很多寄存器信息缺失，驱动开发依赖逆向
4. **ISP无主线支持**：摄像头ISP只有厂商内核支持，质量调试困难 [^2952^]
5. **闭源固件**：部分功能（如HDMI PHY）仍需要闭源firmware

> ⚠️ **陷阱**：Rockchip的厂商内核（通常是4.19或5.10的深定制版本）与主线差异巨大。如果你选择了厂商内核进行产品开发，后期迁移到主线的成本可能非常高——Driver API完全不同，Device Tree结构不一致，用户空间库（如MPP、RGA）依赖特定内核版本。

#### 1.4.6 社区生态评估

Rockchip的社区生态是评估其BSP成熟度的重要维度：

| 社区 | 活跃度 | 贡献内容 |
|------|--------|---------|
| linux-rockchip ML | 高 | 主线补丁讨论、技术支持 |
| Collabora | 高（全职） | GPU/VPU/视频捕获/NPU上游化 |
| Armbian | 高 | 发行版维护、补丁集合 |
| Radxa | 中-高 | 硬件设计、DTS维护 |
| Rockchip官方 | 中 | 补丁提交（Andy Yan等）、固件发布 |
| Heiko Stübner | 高（主线维护者） | 主线代码review、merge |
| Joshua Riek (unmaintained) | 低（已停止） | 之前维护ubuntu-rockchip |

### 1.5 Renesas — 工业CIP内核的坚定拥护者

#### 1.5.1 产品矩阵与定位

Renesas（瑞萨电子）是日本最大的半导体公司，其RZ系列MPU在工业HMI、汽车电子领域有很强的市场地位 [^2917^][^2919^][^2923^]。

| 系列 | 架构 | GPU | AI加速器 | 目标市场 |
|------|------|-----|---------|---------|
| RZ/G2L | 2x Cortex-A55 + M33 | Mali-G31 | 无 | 入门级工业HMI |
| RZ/G2LC | 1x Cortex-A55 + M33 | Mali-G31 | 无 | 低成本HMI |
| RZ/G2UL | 1x Cortex-A55 | 无 | 无 | 超低成本工业 |
| RZ/G3S | 2x Cortex-A55 | Mali-G31 | 无 | 中端工业HMI |

| RZ/V2N | 4x Cortex-A76 | Mali-G57 | DRP-AI (13 TOPS) | 高端AI边缘 |

#### 1.5.2 Verified Linux Package (VLP) — CIP内核的典范

Renesas的BSP策略核心是**Verified Linux Package (VLP)**——一个基于**CIP SLTS内核**的完整软件包 [^2919^][^2923^]。

```
VLP架构:
├── CIP SLTS Linux Kernel     # 超长期支持内核
│   ├── VLP v5: Linux 6.12    # 最新，支持RZ/T2H, RZ/N2H
│   ├── VLP v4: Linux 6.1     # 支持RZ/G2L/G2LC/G2UL/G3S
│   ├── VLP v3: Linux 5.10    # 广泛支持多系列
│   ├── VLP64:  Linux 4.19    # 老系列维护
│   └── VLP v2: Linux 4.4     # 遗留系统
├── Yocto BSP
│   └── meta-renesas/          # 官方Yocto层
├── 多媒体包
│   ├── H.264/H.265 编解码器
│   └── OpenGL ES (Mali GPU)
├── HMI SDK / AI SDK
└── 安全补丁（10年+）
```

**VLP版本矩阵** [^2919^]：

| VLP版本 | CIP内核 | 支持设备 | 维护终止 |
|---------|---------|---------|---------|
| VLP v5 | 6.12 (SLTS) | RZ/T2H, RZ/N2H | 2035年6月 |
| VLP v4 | 6.1 (SLTS) | RZ/G2L/G2LC/G2UL/G3S | 2033年8月 |
| VLP v3 | 5.10 (SLTS) | 全部RZ/G1/G2系列 | 2031年1月 |
| VLP64 | 4.19 (SLTS) | RZ/G2H/G2M/G2N/G2E | 2029年1月 |

#### 1.5.3 CIP内核的工业级承诺

Renesas是**CIP项目的核心发起成员**之一（与西门子、东芝并列），这使得其BSP具有独特的长期维护优势 [^2917^]：

- **10年+安全补丁**：每个VLP版本对应一个CIP SLTS内核，获得10年安全维护
- **5年功能backport**：Renesas承诺在5年内将最新内核的功能backport到VLP版本
- **工业级验证**：所有软件包经过完整测试验证，降低产品化风险
- **免费许可**：点击式许可协议，无额外费用

#### 1.5.4 主线与社区支持

Renesas在主线支持方面**稳步推进**：

| SoC | 主线Linux | 评价 |
|-----|----------|------|
| RZ/G2L/G2LC/G2UL | Linux 6.1+ 支持 | 基本功能完整，GPU用Panfrost |
| RZ/G2H/G2M/G2N/G2E | Linux 5.10+ 支持 | 成熟稳定 |
| RZ/V2L | Linux 6.1+ 部分支持 | DRP-AI需厂商库 |
| RZ/FIVE | Linux 6.1+ 支持 | RISC-V架构 |

**Renesas社区BSP** [^2931^]：
```bash
# RZ Community BSP快速启动
 git clone https://github.com/renesas-rz/rz-community-bsp.git
 cd rz-community-bsp

# 支持多内核版本切换

# - CIP SLTS内核
```

> 💡 Renesas的独特价值主张是**"工业级可靠性 + 超长期支持"**。如果你在做工业HMI、工厂自动化、医疗设备，且产品生命周期>10年，Renesas的VLP + CIP内核组合是**最省心的选择**。但缺点是性能相对保守（最高仅4x Cortex-A76），价格较高，且AI生态不如NVIDIA/Rockchip丰富。

### 1.6 Qualcomm — 高端IoT与AI的闭源巨人

#### 1.6.1 产品矩阵与定位

Qualcomm（高通）凭借其在移动处理器市场的霸主地位，将Snapdragon处理器延伸到嵌入式IoT和Edge AI领域 [^2889^][^2989^][^3000^]。2025年，高通将IoT处理器品牌统一为**Dragonwing**。涵盖从低功耗控制器QCS2290到高性能QCS8550的完整阶梯。产品矩阵中，QRB2210/QRB4210面向机器人应用，而QCS6490/QCS7230/QCS8550则分别针对中端和旗舰级Edge AI场景。最新发布的QCS6490和IQ9系列分别采用Kodiak和SoC架构，支持工业级应用和先进功能 [^3001^]。

各系列处理器在AI算力、视频编解码能力和网络连接方面表现突出。例如，QCS6490支持最高12 TOPS的AI性能，具备4K@60fps视频解码能力，并集成Wi-Fi 6E和5G连接选项。这些处理器广泛应用于机器人、智能相机、工业边缘计算和高端IoT领域 [^2997^]。

#### 1.6.2 BSP策略：完整但封闭

高通的BSP策略与NXP/TI截然不同——**提供极其完整但高度封闭**的解决方案：

**支持的操作系统**：
- **Android**：完整的AOSP + 高通HAL，GMS认证路径清晰
- **Linux (Yocto/Ubuntu)**：通过meta-qcom层支持，但功能受限 [^2993^][^2994^]
- **Windows IoT**：部分高端芯片支持

**Yocto支持**：
```bash
# meta-qcom快速构建
repo init -u https://github.com/qualcomm-linux/meta-qcom -b scarthgap
repo sync
# 构建QCS6490镜像
MACHINE=qcs6490-rb3gen2 bitbake qcom-multimedia-image
```

**闭源组件清单**：
| 组件 | 开源状态 | 说明 |
|------|---------|------|
| Adreno GPU驱动 | 闭源（freedreno部分开源） | 用户态闭源，内核有开源替代 |
| Hexagon DSP固件 | 闭源 | 语音/音频/AI加速 |
| 摄像头ISP | 闭源 | Spectra ISP |
| Wi-Fi/蓝牙固件 | 闭源 | 需签署许可获取 |
| 安全启动链 | 闭源 | XBL + TrustZone |
| NPU/AI加速 | 闭源 | 通过SNPE SDK访问 |

#### 1.6.3 主线支持状态

高通在主线内核支持方面**有明显改善但仍落后于NXP/TI**：

- **基础SoC支持**：SM8450/SC8280XP等较新平台已有主线DTS
- **GPU**：freedreno驱动在主线上支持部分Adreno GPU，但功能不如闭源驱动
- **启动链**：RB3 Gen2支持TF-A + U-Boot + OP-TEE，但需闭源QTISECLIB [^2993^][^2994^]
- **通信**：Modem/Wi-Fi/蓝牙依赖闭源firmware

#### 1.6.4 高端定位的优势与风险

**Qualcomm的核心优势**：
1. **顶级的AI性能**：Hexagon DSP + NPU提供业界领先的AI推理能力
2. **完整的通信集成**：Wi-Fi 6E/7、5G、蓝牙5.3、GNSS等高度集成
3. **ISP/Spectra摄像头处理**：移动级ISP质量，远超工业竞品
4. **品牌溢价**：在高端IoT和机器人市场，Qualcomm品牌有客户认可度

**核心风险**：
1. **生态锁定严重**：从bootloader到AI推理栈都依赖高通封闭生态
2. **获取门槛高**：BSP需要签署NDA和许可协议，小团队难以获取
3. **定制化困难**：硬件规格固定，不能像NXP/TI那样灵活裁剪
4. **长期支持不确定**：高通IoT产品线的longevity承诺不如NXP/TI/Renesas

> ⚠️ **陷阱**：高通平台的闭源组件意味着你无法自行修复底层问题。如果Hexagon DSP固件有bug，你只能等高通发布更新——没有时间表可控。对于需要10年维护的工业产品，这是一个重大风险。

## 本节总结

### 核心要点回顾

1. **NXP i.MX系列**：BSP质量行业最佳，Yocto层完善，主线化投入最大，10-15年供货保证。适合工业/汽车/医疗产品。缺点是价格较高，GPU/VPU部分闭源。

2. **TI Sitara/Jacinto**：异构多核（Linux+RTOS）独一无二，工业通信协议支持最强。适合需要硬实时控制、功能安全认证的场景。学习曲线陡峭。

3. **Rockchip RK系列**：性价比之王，主线化速度惊人（Collabora推动），开源GPU驱动（Panthor）领先。适合消费/商用产品。长期支持承诺不明确，文档不完整。

4. **Renesas RZ系列**：CIP内核核心成员，VLP提供10年+安全维护。适合生命周期>10年的工业HMI/自动化产品。性能相对保守。

5. **Qualcomm Snapdragon/Dragonwing**：顶级AI性能和通信集成，但闭源生态严重，获取门槛高。适合高端IoT和机器人，不适合长生命周期工业产品。
