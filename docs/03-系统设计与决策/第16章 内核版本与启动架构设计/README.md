## 核心问题

选什么内核版本？启动链怎么设计？

## 本章简介

“选哪个内核版本？启动链怎么设计？” 你的产品需要用哪个内核分支（主线/LTS/SLTS/厂商BSP）？启动链从BootROM到Kernel的每个环节如何取舍安全、速度和复杂度？设备树在多产品线场景下如何组织？这些问题在项目启动时如果不回答清楚，将在维护期产生指数级放大的技术债务。有经验工程师通常已经会移植内核、会配置U-Boot、会写设备树。

但当你面临以下场景时，“会用工具”远远不够：一个工业控制器需要10年生命周期，内核支持只有6年怎么办？团队决定从厂商BSP迁往上主线，但驱动适配工作量未知——如何评估？一条产品线有8个板卡变体，每个变体的设备树差异越来越大，如何重构？这些决策的共性是：它们的影响跨越整个产品生命周期，回退成本极高，且没有标准答案。

本章的目标不是告诉你”用5.15内核”，而是给你一个决策框架，让你的选择有清晰的rationale。你是一家工业自动化公司的BSP负责人。产品基于NXP i.MX8M Plus，需要支持10年。NXP提供的BSP基于5.15 LTS，但你注意到CIP项目有5.10 SLTS支持到2031年。同时，团队要求3秒内从断电到应用就绪。

你需要做出三个决策：内核版本选哪个？启动链怎么优化？设备树怎么组织才能覆盖未来可能的产品变体？...
