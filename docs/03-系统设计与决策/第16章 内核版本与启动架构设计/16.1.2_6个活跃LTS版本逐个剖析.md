### 2.2 Linux 6.18 LTS（2025年最新LTS）

#### 2.2.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2025-11-30 |
| 上游LTS EOL | 2028-12（约3年） |
| CIP SLTS | 预计2026年启动，EOL约2035 |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| Yocto对应 | walnascar (YP 5.2) |

#### 2.2.2 关键特性

Linux 6.18是2025年的年度LTS版本，引入了一系列重要的基础设施改进 [^phoronix-618^][^linuxjournal-618^]：

**Sheaves内存管理**：6.18引入了名为"Sheaves"的新型per-CPU slab缓存层。传统的SLUB分配器在所有CPU之间共享slab缓存，高并发场景下产生显著的锁竞争。Sheaves为每个CPU核心分配独立的内存对象缓存，减少处理器争夺共享内存池的冲突，**在高负载多线程场景下可提升10–20%的内存分配性能** [^ithome-618^]。

**dm-pcache**：Device-mapper新的持久缓存目标，允许使用NVDIMM/CXL等持久内存作为块设备的缓存层。这对需要高性能存储的工业边缘计算设备有潜在价值。

**XFS online fsck默认启用**：XFS文件系统现在支持在线文件系统检查（fsck），无需卸载文件系统即可检测和修复问题。对于要求7×24运行的工业网关，这意味着可以在不中断服务的情况下进行文件系统健康检查。

**Signed BPF程序**：内核现在支持加密签名的BPF（eBPF）程序。这一安全强化措施对使用eBPF进行网络过滤和监控的设备很重要——只有经过签名的BPF程序才能加载到内核。

#### 2.2.3 BSP支持状态

作为最新LTS，6.18的BSP支持还在完善中：

- **NXP i.MX**：Yocto walnascar分支提供linux-imx 6.18支持，但GPU/VPU驱动可能不如6.12成熟
- **TI**：TI的linux-ti-staging树正在向6.18迁移，预计2025年Q3达到生产质量
- **Rockchip**：RK3588/RK3568的mainline支持在6.18中持续完善，GPU（Mali G610）的Panfrost驱动支持较好

#### 2.2.4 实时能力

6.18继承了6.12的PREEMPT_RT主线化成果，支持`CONFIG_PREEMPT_RT=y`。但作为新版本，RT路径上的某些驱动（尤其是GPU和专用加速器）可能存在稳定性问题。

#### 2.2.5 推荐场景与风险评估

| 场景 | 推荐度 | 理由 |
|------|--------|------|
| 新产品开发（2025年启动） | ⭐⭐⭐ 高 | 最长维护窗口、最新特性 |
| 需要10年+生命周期的产品 | ⭐⭐☆ 中 | 需等待CIP SLTS启动 |
| 保守的工业应用 | ⭐☆☆ 低 | 太新，未经充分验证 |

> ⚠️ **陷阱（版本太新）**:  选择6.18意味着你是"早期采用者"。虽然内核本身经过RC阶段验证，但BSP（Board Support Package）生态需要3–6个月才能成熟。如果你计划在2025年Q1–Q2量产，6.18的NXP/TI BSP可能还不够稳定。建议至少等到2026年Q2再基于6.18启动量产项目。

### 2.3 Linux 6.12 LTS（⭐ 2025年嵌入式首选）

#### 2.3.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2024-11-17 |
| 上游LTS EOL | 2028-12（约4年） |
| **CIP SLTS EOL** | **2035-06（10年+）** |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| CIP维护者 | Nobuhiro Iwamatsu & Pavel Machek |
| Yocto对应 | walnascar (YP 5.2) |

#### 2.3.2 关键特性：为什么6.12是嵌入式工程师的"梦中情核"

Linux 6.12 LTS之所以被绝大多数嵌入式工程师视为2025年的首选，不是因为某一项特性，而是因为它在**多个关键维度上同时达到了里程碑** [^phoronix-612^][^tuxcare-612^]：

**① PREEMPT_RT主线化（最核心的特性）**

经过20年的开发，PREEMPT_RT实时补丁终于在Linux 6.12中**完整合并到主线**。这意味着：
- 不再需要打外部RT补丁（以前每个内核升级都要重新适配RT补丁集）
- 只需一个配置项即可启用实时：`CONFIG_PREEMPT_RT=y`
- 所有内核驱动现在必须在RT环境下编译通过，RT兼容性成为上游标准
- 支持ARM64、x86_64、RISC-V架构

我们将在第5节深入讨论PREEMPT_RT的技术细节。

**② sched_ext：BPF可编程调度器**

6.12引入了`sched_ext`，一个基于BPF（Berkeley Packet Filter）的可编程调度类。这使得开发者可以用BPF程序定义自己的调度策略，而无需修改内核代码 [^kernelnewbies-66^]。

```c
// sched_ext示例：一个简单的优先级提升调度器
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>

SEC("sched_ext/example")
int BPF_PROG(sched_init)
{
    // 自定义调度逻辑：为标记为RT的任务提供额外CPU时间
    return 0;
}
```

对于工业设备，sched_ext的潜在应用包括：
- 为Modbus/PLC通信线程创建专用调度策略
- 根据I/O负载动态调整任务优先级
- 实现"确定性的"任务执行时间片分配

**③ ARM64 Permission Overlay Extension (POE)**

支持ARM的Permission Overlay Extension，允许用户空间对特定内存区域施加细粒度权限控制。这是实现更安全的用户空间内存管理的基础。

**④ RISC-V架构扩展**

继续完善RISC-V架构支持，添加多个CPU ISA扩展。对于评估RISC-V SoC的嵌入式项目，6.12提供了比6.6更好的硬件兼容性。

#### 2.3.3 BSP支持状态

**NXP i.MX系列** [^nxpbsp^]：
- Yocto walnascar分支的`meta-imx-bsp`提供`linux-imx 6.12.49+git`
- i.MX6/i.MX7/i.MX8/i.MX93全系支持
- GPU（Vivante）和VPU驱动完整
- 注意：NXP的BSP包含大量out-of-tree补丁，需评估向上游移植的成本

| NXP SoC | 6.12 BSP状态 | 关键驱动 | 备注 |
|---------|-------------|----------|------|
| i.MX6ULL | ✅ 完整 | GPU(ECDC), UART, Ethernet, SD | 成熟平台 |
| i.MX8M Mini | ✅ 完整 | GPU(Vivante), VPU, CSI | 推荐 |
| i.MX8M Plus | ✅ 完整 | GPU, VPU, NPU(Ethos-U) | AI推理 |
| i.MX93 | ✅ 完整 | GPU, Ethernet, CSI | 新平台首选 |

**TI AM62x/AM335x系列** [^tibsp^]：
- TI的`linux-ti-staging`树提供6.12支持
- AM625/AM623/AM6442的Device Tree完善
- PRU（Programmable Real-Time Unit）支持保留
- 注意：TI的6.12 BSP相对较新，建议验证具体外设驱动

**Rockchip RK3588/RK3568** [^rockchip-bsp^]：
- RK3588的mainline支持在6.12中**大幅完善**
- GPU（Mali G610）Panfrost驱动支持OpenGL ES 3.1
- 视频编解码器（H.264/H.265/VP9）支持较好
- NPU支持通过RKNN-Toolkit2（out-of-tree）

#### 2.3.4 实时能力：PREEMPT_RT在6.12上的表现

PREEMPT_RT在6.12中的延迟表现（基于社区测试数据）[^imd-rt^]：

| 架构 | 典型延迟 | 最坏情况延迟 | 测试条件 |
|------|----------|-------------|----------|
| x86_64 | 5–15 µs | 30–50 µs | Intel i7, 无负载 |
| ARM64 (Cortex-A72) | 10–25 µs | 50–100 µs | Raspberry Pi 4, 轻负载 |
| ARM64 (Cortex-A55) | 15–30 µs | 80–150 µs | i.MX93, 中等负载 |

> ⚠️ **陷阱（RT延迟≠一切）**:  很多工程师看到"15µs延迟"就认为PREEMPT_RT满足所有实时需求。实际上，**延迟只是实时性能的一个维度**。还需要考虑：
> - 中断抖动（irq latency）
> - 调度抖动（scheduling jitter）
> - 内存分配延迟（kmalloc在RT路径上的行为）
> - 驱动程序的RT兼容性（某些驱动在中断线程化后性能下降）
>
> 我们将在第5节详细讨论如何正确评估和调优PREEMPT_RT。

#### 2.3.5 已知问题与限制

1. **PREEMPT_RT在某些SoC上的稳定性**：虽然RT代码已主线化，但某些SoC的厂商驱动可能未在RT环境下充分测试。特别是GPU和VPU驱动，在RT内核上可能出现死锁。

2. **sched_ext的成熟度**：BPF调度器是可编程的，但API可能在未来版本中变化。用于生产环境需要锁定API版本。

3. **Rust驱动的可用性**：6.12支持Rust编写内核驱动，但实际可用的Rust驱动仍然很少。不要指望用Rust替代C编写设备驱动。

#### 2.3.6 推荐场景

| 场景 | 推荐度 | 核心依据 |
|------|--------|----------|
| 工业网关/PLC | ⭐⭐⭐ **最高** | PREEMPT_RT + CIP SLTS到2035 |
| 医疗设备 | ⭐⭐⭐ 最高 | 长维护期 + RT支持 |
| 汽车信息娱乐 | ⭐⭐⭐ 高 | RT支持 + 良好BSP |
| 物联网边缘设备 | ⭐⭐⭐ 高 | 低功耗 + 长维护 |
| 通信基础设施 | ⭐⭐☆ 中高 | 网络性能优化 |

### 2.4 Linux 6.6 LTS（稳定通用平台）

#### 2.4.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2023-10-29 |
| 上游LTS EOL | 2027-12（约4年） |
| CIP SLTS | 暂无（未入选CIP） |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| Yocto对应 | scarthgap (YP 5.0, LTS) |

#### 2.4.2 关键特性

**EEVDF调度器**：6.6最大的变革是用**EEVDF**（Earliest Eligible Virtual Deadline First）替代了服役16年的CFS（Completely Fair Scheduler）[^kernelnewbies-66^]。

EEVDF的核心改进在于**延迟感知**：CFS使用启发式方法猜测哪些进程需要更多关注，而EEVDF通过算法化的方式确保"被忽视"的进程自动获得下一次调度机会。实际效果：
- 交互式任务（如UI响应）延迟降低15–30%
- 批处理任务（如编译、数据处理）吞吐量保持或略有提升
- 去除了CFS中大量可调参数，调度行为更可预测

> ⚠️ **陷阱（EEVDF的边界情况）**:  EEVDF在某些特定工作负载下可能出现调度退化。2023年底6.6发布后，有用户报告在特定游戏场景下出现UI卡顿。虽然这些问题在后续stable更新中已修复，但如果你从5.15/6.1升级，建议进行全面性能回归测试。

**Intel Shadow Stack**：支持Intel的Shadow Stack硬件特性，防止ROP（Return-Oriented Programming）攻击。对安全敏感的应用场景（如金融终端、安全网关）有价值。

**可配置unbound workqueue**：改进无绑定workqueue的执行局部性，对多L3缓存的现代处理器（如AMD Zen 4、Intel Alder Lake）性能提升明显。

#### 2.4.3 BSP支持状态

6.6的BSP生态非常成熟——它已经被多个Yocto和Buildroot版本采用：

- **NXP i.MX**：scarthgap分支的linux-imx 6.6.23+git，经过充分验证
- **TI**：linux-ti-staging 6.6支持AM62x/AM335x/AM437x全系
- **Rockchip**：RK3588/RK3568支持良好，但不如6.12完善（部分GPU特性缺失）
- **Raspberry Pi**：Raspberry Pi OS基于6.6内核

#### 2.4.4 实时能力

6.6发布时PREEMPT_RT尚未完整主线化。要使用RT，需要打外部补丁（RT补丁集）。CIP项目维护6.6-cip分支，但不包含RT版本。

#### 2.4.5 推荐场景

| 场景 | 推荐度 | 理由 |
|------|--------|------|
| 通用嵌入式平台 | ⭐⭐⭐ 高 | 成熟稳定，BSP完善 |
| Debian 13基础 | ⭐⭐⭐ 高 | Debian trixie基于6.6 |
| 不需要RT的设备 | ⭐⭐⭐ 高 | EEVDF调度器优秀 |
| 需要10年+维护的设备 | ⭐☆☆ 低 | 无CIP SLTS支持 |

> ⚠️ **陷阱（无CIP SLTS）**:  6.6没有被CIP选为SLTS版本。如果你的产品生命周期超过4年（即2027年后仍在运行），6.6将在EOL后失去安全补丁支持。这种情况下，建议考虑6.12 CIP SLTS或商业支持（如Timesys、Lynx）。

### 2.5 Linux 6.1 LTS（成熟嵌入式经典）

#### 2.5.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2022-12-11 |
| 上游LTS EOL | 2027-12（约5年） |
| **CIP SLTS EOL** | **2033-08（10年+）** |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| CIP维护者 | Nobuhiro Iwamatsu & Pavel Machek |
| Yocto对应 | mickledore (YP 4.2) |

#### 2.5.2 关键特性

**Rust支持（初始）**：6.1是Linux内核**首次正式支持Rust编程语言**的版本 [^9to5linux-61^][^phoronix-61^]。虽然当时的支持非常基础（仅能编译最简单的Rust驱动），但它标志着一个新时代的开启。

到2025年，Rust在内核中的支持已经显著增强：
- Rust可以编写块设备驱动、网络驱动和PCI驱动
- Android Binder驱动有Rust实现版本
- USB Gadget驱动框架支持Rust绑定

**多代LRU（MGLRU）**：6.1引入了MGLRU（Multi-Gen LRU），一种革命性的页面回收算法。传统LRU在判断哪些内存页面真正"活跃"时准确率有限，导致：
- 桌面系统下Chrome等应用被不公正地回收
- 嵌入式系统下关键进程的工作集被错误地换出

MGLRU通过多代（generation）机制更精确地识别活跃页面，在Google的测试中**减少了40%的kswapd CPU使用率**，同时降低了页面错误率 [^phoronix-61^]。

**io_uring改进**：支持缓冲写入（buffered writes）的io_uring，以及fs-verity保护文件的发送操作。

#### 2.5.3 BSP支持状态

6.1是2023–2024年间嵌入式行业使用最广泛的LTS版本，BSP生态极其成熟：

- **NXP i.MX**：mickledore/scarthgap分支都有完善的6.1支持
- **TI**：linux-ti-staging 6.1.y是TI官方推荐的LTS基础
- **Rockchip**：RK3568支持完善，RK3588基础支持可用
- **Raspberry Pi**：Debian 12 (bookworm) 基于6.1内核

#### 2.5.4 实时能力

6.1有CIP维护的RT版本（`6.1.y-cip-rt`），由Pavel Machek专门维护。RT补丁需要单独应用，但CIP提供了预打补丁的树：

```bash
# 克隆CIP 6.1 RT内核
git clone https://git.kernel.org/pub/scm/linux/kernel/git/cip/linux-cip.git
cd linux-cip
git checkout linux-6.1.y-cip-rt
```

#### 2.5.5 推荐场景

| 场景 | 推荐度 | 理由 |
|------|--------|------|
| 保守的工业应用 | ⭐⭐⭐ 高 | 经过2年验证，极其稳定 |
| Debian 12设备 | ⭐⭐⭐ 高 | Debian bookworm基础 |
| 需要RT + 长期维护 | ⭐⭐⭐ 高 | CIP SLTS到2033 |
| 产品生命周期5–8年 | ⭐⭐⭐ **推荐** | CIP覆盖整个生命周期 |

### 2.6 Linux 5.15 LTS（即将EOL，存量维护）

#### 2.6.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2021-10-31 |
| **上游LTS EOL** | **2026-12（不到1.5年！）** |
| CIP SLTS | 暂无（未入选） |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| Yocto对应 | kirkstone (YP 4.0, LTS) |

#### 2.6.2 关键特性

**NTFS3文件系统**：5.15引入了Paragon Software贡献的全新NTFS驱动，支持完整的读写操作、日志重放、ACL和压缩文件 [^kernelnewbies-515^]。在此之前，Linux用户只能依赖只读的内核NTFS驱动或用户空间的ntfs-3g。

**ksmbd（内核SMB服务器）**：三星贡献的内核态SMB3服务器，提供比Samba更高的性能和更低的资源占用 [^linuxmag-ksmbd^]。

**DAMON（数据访问监控）**：Amazon贡献的内存访问模式监控框架，支持主动内存回收优化 [^kernelnewbies-515^]。

#### 2.6.3 为什么5.15是"危险区"

> 🔴 **危险**:  **5.15将在2026年12月EOL**。如果你在2025年开始一个新项目，5.15的剩余寿命不到1.5年。产品还没量产，内核就不维护了。

即使Yocto kirkstone（基于5.15）是Yocto LTS版本，Yocto社区的LTS支持也不能替代内核LTS——Yocto kirkstone的内核安全补丁最终依赖上游5.15.y的stable发布。

**5.15的唯一适用场景**：你的硬件BSP锁定在5.15（如某些老旧的i.MX6平台），且产品生命周期很短（<2年），或者有明确的升级路径。

### 2.7 Linux 5.10 LTS（最后警告：2026年底EOL）

#### 2.7.1 基本信息

| 属性 | 详情 |
|------|------|
| 发布日期 | 2020-12-13 |
| **上游LTS EOL** | **2026-12（不到1.5年！）** |
| CIP SLTS EOL | **2031-01** |
| 维护者 | Greg Kroah-Hartman & Sasha Levin |
| CIP维护者 | Nobuhiro Iwamatsu & Pavel Machek |

#### 2.7.2 关键特性

5.10是Linux内核历史上维护时间最长的LTS之一（整整6年），这得益于它被Android GKI（Generic Kernel Image）选为基础版本 [^kernelnewbies-510^]。

**Ext4 Fast Commit**：5.10引入了Ext4的快速提交模式，显著提升了`fsync()`性能——对于需要频繁数据持久化的嵌入式设备（如日志记录、数据库），这是一个重要优化。

**Static Calls**：引入静态调用机制，用直接调用替代间接调用，改善Spectre缓解后的性能。

**Android GKI基础**：Google选择5.10作为Android Generic Kernel Image的基础，意味着5.10获得了大量来自Android生态的测试和补丁投入。

#### 2.7.3 5.10+CIP SLTS：一个特殊选项

虽然5.10的上游LTS将在2026年12月结束，但**CIP SLTS将继续维护到2031年1月**。这意味着：
- 如果你已经在使用5.10（存量产品），可以迁移到CIP SLTS获得额外4年支持
- 但不建议新设计选择5.10——6.12/6.1提供更长的维护期和更好的特性

> ⚠️ **陷阱（CIP SLTS ≠ 上游LTS）**:  CIP SLTS的补丁发布频率（每月1–2次）远低于上游stable（每周1次）。对于安全关键应用，你需要评估CIP的响应速度是否满足需求。此外，CIP主要backport安全修复和重要bug修复，新硬件驱动通常不会被backport到老版本。

### 2.8 版本选择速查卡

综合以上分析，这里提供一个快速决策参考：

```
新产品（2025年）内核选择决策：
│
├─ 产品生命周期 ≤ 3年？
│  ├─ 需要最新硬件（如RK3588完整支持）→ 6.18 LTS
│  └─ 需要成熟稳定 → 6.12 LTS（推荐）
│
├─ 产品生命周期 3–8年？
│  ├─ 需要PREEMPT_RT实时 → 6.12 LTS + CIP SLTS
│  └─ 不需要实时 → 6.6 LTS（BSP成熟）或 6.12 LTS
│
├─ 产品生命周期 8–15年？
│  ├─ 工业/基础设施 → 6.12 CIP SLTS（到2035）
│  └─ 保守选择 → 6.1 CIP SLTS（到2033，更成熟）
│
└─ 存量产品维护？
   ├─ 当前5.15 → 计划2026年底前升级到6.12
   ├─ 当前5.10 → 可迁移到CIP SLTS（到2031）
   └─ 当前4.x/5.4 → 立即升级（已EOL，安全风险极高）
```

## 本节总结与下一步

### 核心要点回顾

1. **Linux 6.18 LTS（2025年最新）**：Sheaves内存管理、dm-pcache、Signed BPF，但BSP生态尚不成熟，建议2026年Q2后再考虑量产。

2. **Linux 6.12 LTS（⭐ 2025年嵌入式首选）**：PREEMPT_RT主线化 + CIP SLTS到2035 + 成熟BSP生态，三者交汇使6.12成为工业/嵌入式设备的最高推荐。

3. **Linux 6.6 LTS（稳定通用平台）**：EEVDF调度器、Intel Shadow Stack，BSP成熟但无CIP SLTS支持，不适合生命周期>4年的产品。

4. **Linux 6.1 LTS（成熟嵌入式经典）**：Rust支持、MGLRU、CIP SLTS到2033，经过2年验证极其稳定，适合保守工业应用。

5. **Linux 5.15 LTS（即将EOL）**：2026年12月EOL，仅剩不到1.5年。仅适用于存量维护或有明确短期升级路径的场景。

6. **Linux 5.10 LTS（最后警告）**：2026年12月上游EOL，但CIP SLTS维护到2031年。存量产品可迁移到CIP SLTS，新设计不建议选择。

### 必须避开的2个陷阱

> ⚠️ **陷阱1：选了快EOL的版本**。5.15和5.10在2026年底EOL，2025年开始新项目应避免选择。
>
> ⚠️ **陷阱2：只看版本号新，忽略BSP支持**。6.18虽然最新，但NXP/TI的BSP可能不如6.12成熟。先确认BSP，再选内核。
