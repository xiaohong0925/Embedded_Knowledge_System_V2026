## 2. SPL（Secondary Program Loader）：DDR的唤醒者

### 2.1 SPL的本质与必要性

SPL是BootROM加载的第一阶段加载器，它的核心使命只有一个：**初始化DDR内存，然后把U-Boot完整版加载到DDR中执行**。

为什么需要SPL？因为存在一个**鸡生蛋问题**：

- U-Boot完整版通常需要**数百KB到数MB**的内存来运行
- 但SoC上电时只有**几十KB到几百KB**的内部SRAM
- DDR控制器需要复杂的初始化序列才能工作（PHY训练、ZQ校准、write leveling等）
- 这个初始化序列本身就需要代码来执行
- 但代码不能放在DDR里——DDR还没初始化

SPL就是解决这个悖论的关键：它足够小（通常<128KB），可以放在SRAM中运行；但它又足够聪明，能完成DDR的初始化。

```
┌─────────────────────────────────────────────────────────┐
│                    内存布局（SPL阶段）                     │
├─────────────────────────────────────────────────────────┤
│  0x0000_0000 - 0x008F_FFFF │  BootROM区域（只读）       │
│  0x0090_0000 - 0x0091_FFFF │  OCRAM 128KB（SPL运行于此） │
│  0x0092_0000 - 0x009F_FFFF │  OCRAM 保留区域            │
│  0x1000_0000 - 0x4FFF_FFFF │  DDR（1GB，未初始化时不可用）│
└─────────────────────────────────────────────────────────┘

SPL的典型大小限制：
- i.MX6 SPL: ~60-100KB（SRAM 128KB，预留栈和堆）
- Rockchip SPL/TPL: ~80-120KB
- TI AM335x MLO（即SPL）: ~50-80KB（SRAM 109KB）
- Allwinner SPL: ~24-32KB（SRAM 32KB）
```

SPL不是独立的软件，它是U-Boot源码树的一部分，通过特定的Kconfig选项启用：


### 2.3 SPL的执行流程（代码级）

SPL的入口代码位于`arch/arm/cpu/armv7/start.S`，是启动链中最底层的汇编代码之一：

```asm
/* arch/arm/cpu/armv7/start.S — SPL入口 */

/* 复位向量表 */
.globl _start
_start:
    b   reset           /* 复位入口 */
    b   _undefined_instruction
    b   _software_interrupt
    b   _prefetch_abort
    b   _data_abort
    b   _not_used
    b   _irq
    b   _fiq

/* 复位后的第一条指令 */
.globl reset
reset:
    /* 1. 设置CPU为SVC模式，关中断 */
    mrs r0, cpsr
    bic r0, r0, #0x1f
    orr r0, r0, #0xd3         /* SVC模式 + 关IRQ/FIQ */
    msr cpsr, r0
    
    /* 2. 关闭MMU、D-cache、I-cache（如果之前开启了） */
    mrc p15, 0, r0, c1, c0, 0 /* 读取SCTLR */
    bic r0, r0, #0x00002300   /* 清V、I、C位 */
    bic r0, r0, #0x00000005   /* 清D、M位 */
    bic r0, r0, #0x00001000   /* 清I位（I-cache） */
    mcr p15, 0, r0, c1, c0, 0 /* 写回SCTLR */
    
    /* 3. 设置临时栈指针（在SRAM中） */
    ldr sp, =(CONFIG_SPL_STACK) /* 如 0x0091_FFF0 */
    
    /* 4. 跳转到C代码 */
    bl  board_init_f            /* SPL的板级初始化 */
    
    /* 注意：SPL的board_init_f与U-Boot完整版的board_init_f不同！ */
    /* SPL版本位于 common/spl/spl.c */
```

SPL的C代码入口`spl.c`：

```c
/* common/spl/spl.c — SPL主流程 */

void board_init_r(gd_t *new_gd, ulong dest_addr)
{
    gd = new_gd;
    
    /* 1. 初始化全局数据指针 */
    memset(gd, '\0', sizeof(gd_t));
    
    /* 2. 初始化驱动模型（DM）基础 */
    dm_init_and_scan(true);
    
    /* 3. 初始化串口（如果能）——这是我们看到SPL日志的起点 */
    preloader_console_init();
    printf("SPL: board_init_r starting...\n");
    
    /* 4. 初始化存储设备 */
    spl_board_init();
    
    /* 5. 根据启动模式加载下一阶段 */
    boot_device = spl_boot_device();
    
    switch (boot_device) {
    case BOOT_DEVICE_MMC1:
    case BOOT_DEVICE_MMC2:
        spl_mmc_load_image();
        break;
    case BOOT_DEVICE_NAND:
        spl_nand_load_image();
        break;
    case BOOT_DEVICE_SPI:
        spl_spi_load_image();
        break;
    case BOOT_DEVICE_USB:
        spl_usb_load_image();
        break;
    case BOOT_DEVICE_ETH:
        spl_net_load_image();
        break;
    default:
        hang(); /* 未知启动设备，死循环 */
    }
    
    /* 6. 跳转到加载的镜像 */
    spl_image.entry_point(); /* 通常是U-Boot的_entry */
}
```

### 2.4 SPL的DDR初始化（关键代码）

DDR初始化是SPL最重要的任务，也是最复杂的部分。以i.MX6为例，DDR初始化通过DCD（Device Configuration Data）表格实现：

```c
/* arch/arm/mach-imx/spl.c — i.MX6的DDR初始化 */

/* DCD表格定义了需要写入的寄存器地址和值 */
/* 这些值来自DDR芯片的数据手册和PCB layout参数 */

/* 典型的DCD配置（DDR3-1066, 1GB, 2片x16） */
static struct mx6_ddr3_cfg ddr_cfg = {
    .mem_speed = 1066,           /* DDR3-1066 (533MHz clock) */
    .density = 4,                /* 4Gb per chip */
    .width = 16,                 /* x16 */
    .banks = 8,                  /* 8 banks */
    .rowaddr = 15,               /* 15 row bits */
    .coladdr = 10,               /* 10 column bits */
    .pagesz = 2,                 /* 2KB page size */
    .trcd = 1375,                /* tRCD = 13.75ns → 1375ps */
    .trcmin = 4875,              /* tRC = 48.75ns */
    .trasmin = 3500,             /* tRAS = 35ns */
    /* ... 更多时序参数 */
};

/* DDR PHY（MMDC）寄存器配置 */
static void spl_ddr_init(void)
{
    /* 1. 使能MMDC时钟 */
    enable_mmdc_clock();
    
    /* 2. 配置I/O引脚驱动强度和 slew rate */
    /* ⚠️ 这个参数直接影响低温下的信号完整性！ */
    writel(0x30, IOMUXC_SW_PAD_CTL_PAD_DRAM_SDCLK0);
    writel(0x30, IOMUXC_SW_PAD_CTL_PAD_DRAM_SDCLK1);
    /* drive strength = 0x30 (240 Ohm / 7 = ~34 Ohm) */
    /* 低温下可能需要提高drive strength到0x38或更高 */
    
    /* 3. 执行ZQ校准 */
    /* ZQ校准使用外部240Ω电阻校准输出驱动器阻抗 */
    /* 低温下ZQ校准结果会偏移！ */
    mmdc_do_zq_calibration();
    
    /* 4. Write Leveling — 补偿DQ/DQS与CLK的skew */
    /* 这是DDR3的关键校准步骤 */
    mmdc_do_write_leveling();
    
    /* 5. Read DQS Gating校准 */
    mmdc_do_dqs_gating();
    
    /* 6. 最终时序配置 */
    mmdc_set_timing_params(&ddr_cfg);
    
    /* 7. 使能DDR控制器 */
    mmdc_enable();
}
```

> ⚠️ **陷阱 — SPL的DDR初始化参数不正确（低温下DDR不稳定）**：本文开篇的决策场景就是典型案例。DDR PHY的ZQ校准在低温下会产生偏差，因为外部240Ω参考电阻的温度系数不为零（典型±50 ppm/°C，-40°C时偏差约2.4%）。同时，PCB走线的阻抗也会随温度变化。解决方案：(1) 在DDR初始化代码中加入温度补偿；(2) 提高I/O drive strength的裕量（从最小值调到中值）；(3) 降低DDR频率（从533MHz降到400MHz）增加时序裕量；(4) 使用工业级DDR芯片（-40°C~+105°C spec）。最严重的情况下，需要在SPL中加入DDR训练（training）的retry机制——如果第一次训练失败，调整参数重试。

## 本节总结

### 核心要点回顾

```
SPL关键认知：
1. SPL解决"鸡生蛋"问题——太小放不进SRAM，太大需要DDR，但DDR还没初始化
2. SPL核心使命：初始化DDR → 加载U-Boot到DDR → 跳转执行
3. DDR初始化是关键且最复杂的步骤（ZQ校准、write leveling、DQS gating）
4. 低温下DDR PHY的ZQ校准会产生偏差，需要温度裕量
5. SPL的启动日志级别通过CONFIG_SPL_LOGLEVEL控制
```

### 关键决策清单

1. **DDR参数温度裕量**：ZQ校准和write leveling必须覆盖整个温度范围
2. **SPL大小控制**：确保SPL + 栈/堆 < SRAM容量，预留20%裕量
3. **DCD表格正确性**：每个寄存器值必须有DDR数据手册依据
4. **低温调试**：在-40°C下使用工业级DDR芯片，必要时降低DDR频率
