## 核心问题

OTA怎么设计？

## 本章简介

“OTA怎么做？A/B分区还是单分区？” OTA已从”锦上添花”变为法规要求（欧盟CRA 2027年起强制执行）。但OTA方案的选择影响存储布局、启动链设计、安全架构和用户体验。本章的目标是让你基于产品特征选择正确的OTA方案，并设计出”更新失败不会变砖”的可靠更新系统。有经验工程师通常已经做过某种形式的固件更新——可能是简单的scp替换文件，或者是基于U-Boot的手动更新。

但当你需要设计一个产品级的OTA系统时，问题变得复杂得多：每天10万台设备同时更新，怎么避免服务器被压垮？更新到一半断电，设备怎么恢复？恶意固件怎么防范？回滚策略怎么设计才能不让用户感知？存储只有128MB，怎么做A/B更新？本章的核心洞察是：OTA不是一个功能，而是一个分布式系统——它涉及设备端、云端、传输通道、存储布局、启动链的协同设计。

你正在设计一款工业网关的OTA系统，计划部署5000台到全球各地的工厂。设备基于Yocto，使用RAUC做OTA。需求：更新包大小约200MB（rootfs），工厂网络带宽不稳定（可能只有几百kbps），设备不能长时间停机（工厂24x7运行），有些设备可能离线数周，更新失败率必须<0.1%。你怎么设计更新流程？A/B分区怎么布局？差分更新怎么做？离线设备怎么处理？...
