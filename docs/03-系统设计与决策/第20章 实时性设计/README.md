# 第20章：实时性设计

> 所属：第三部 系统设计与决策
>
> 难度：[I] ~ [E] | 核心问题：系统需要实时吗？怎么实现？

## 核心问题

系统需要实时吗？——需要硬实时吗？PREEMPT_RT 够了吗？

## 本章简介

实时性决策是嵌入式 Linux 中最容易过度设计或设计不足的地方。误区从定义开始：**实时 ≠ 快，实时 = 确定性**——在截止时间前完成才算正确，设计目标是压低并证明最坏情况（WCET），不是优化平均值。

本章的方法论一句话：**先测量，再决策；按关键性分域，各付各的确定性成本**。大多数声称"需要硬实时"的系统，用 cyclictest 在真实负载下量一遍之后，会发现 PREEMPT_RT（2024 年起已全量并入主线内核）已经足够——而真正的硬实时需求，答案往往是让关键任务不依赖 Linux。

## 学习目标

- 能把"要实时"的呼声改写成三要素规格（截止时间/抖动/miss 率）
- 能识别伪实时需求并指出各自的真实解法
- 能用决策树按需求收敛到 RT/Xenomai/双系统/卸载，并记录被否决路线
- 能建延迟预算表并按段调优（IRQ 亲和/CPU 隔离/电源锁定/内存纪律）
- 能按 SoC 形态选择混合关键性分割路线，并执行通道纪律
- 能把架构承诺翻译成验收测试矩阵
