## 核心问题

存储介质和文件系统怎么选？

## 本章简介

“文件系统怎么选？存储怎么分区？怎么防断电丢数据？” 存储架构是嵌入式系统中最容易设计失误的部分——不是因为技术难，而是因为决策后果滞后显现。断电丢数据通常在产品量产半年后才开始暴露，存储介质寿命问题可能在1-2年后爆发。

本章的目标是让你在设计阶段就能回答：什么文件系统匹配你的存储介质？分区策略如何平衡安全与灵活？断电保护的真正代价是什么？有经验工程师对文件系统不陌生——你知道ext4、听过UBIFS、可能用过SquashFS。

但当你需要为一个工业设备设计存储架构时，以下问题不会自动有答案：NAND闪存用UBIFS还是F2FS？eMMC上ext4的barrier设置对性能影响多大？原子更新（A/B分区）与原地更新的断电安全性差异如何量化？分区大小如何预留才能撑过5年的OTA升级？本章的核心洞察是：存储架构设计不是选文件系统，而是设计一个数据生命周期管理系统——每个数据有不同的写入频率、不同的持久化要求、不同的恢复策略。

你正在设计一款户外工业网关，工作环境-40°C到85°C，使用8GB eMMC存储。设备每天写入约100MB日志数据，运行5年。要求：断电不能损坏系统（每天可能断电数次），OTA更新必须可回滚，设备在存储接近满时仍能保持基本功能。你会怎么设计存储分区？用什么文件系统？怎么保证断电安全？...


## 子节清单

- 存储介质选型（NAND/eMMC/SD/NVMe）
- 文件系统选型矩阵（ext4/f2fs/UBIFS/SquashFS/EROFS）
- 分区策略设计（只读rootfs+可写数据区+备份区）
- 断电安全架构（barrier/journal/原子更新）
