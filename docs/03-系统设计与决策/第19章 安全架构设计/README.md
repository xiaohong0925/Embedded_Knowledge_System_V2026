## 核心问题

系统安全怎么设计？

## 本章简介

“安全要做什么程度？TrustZone值得投入吗？” 嵌入式安全不是开关——不是”做安全”或”不做安全”，而是选择投入的程度。每一层安全都有成本：BOM成本、启动时间、性能开销、开发时间、维护复杂度。本章的目标是让你基于威胁模型做有rationale的安全投资决策，而不是盲目堆砌安全功能。

有经验工程师对嵌入式安全通常有模糊认知——你知道安全启动的概念、听过TrustZone、可能配置过SELinux。

但当你面临以下问题时，“听过”和”能决策”之间有巨大鸿沟：产品要通过ETSI EN 303 645认证，具体需要做哪些安全加固？加了TrustZone后开发复杂度增加多少？OP-TEE的维护成本如何评估？加密密钥存在eFuse还是外部安全元件？运行时安全选SELinux还是AppArmor？这些决策的共同点是：安全投入必须匹配产品风险profile，过度投入浪费资源，投入不足可能导致产品召回或法律责任。

你正在设计一款智能门锁，基于ARM Cortex-A53，有WiFi连接、指纹传感器、触摸屏。产品售价$200，BOM成本需要控制在$80以内。安全要求：指纹数据不能被提取、OTA不能被劫持、物理拆机不能获取密钥、通过ETSI EN 303 645认证。你的安全预算只有$3（硬件安全元件+额外的BOM成本）。你会怎么分配这$3？哪些安全措施用软件实现？哪些必须用硬件？...
