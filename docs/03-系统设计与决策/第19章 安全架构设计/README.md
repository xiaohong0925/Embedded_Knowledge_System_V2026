# 第19章：安全架构设计

> 所属：第三部 系统设计与决策
>
> 难度：[I] ~ [E] | 核心问题：系统安全怎么设计？

## 核心问题

系统安全怎么设计？——安全要做什么程度？TrustZone 值得投入吗？

## 本章简介

嵌入式安全不是开关——不是"做安全"或"不做安全"，而是选择投入的程度。每一层安全都有成本：BOM、启动时间、性能开销、开发时间、维护复杂度。本章的主线只有一条：**安全投入必须匹配产品风险 profile**——每一项支出能指回威胁清单上的具体条目，每一处留白都明示了接受的残留风险。

产品要通过 ETSI EN 303 645 认证需要做哪些加固？OP-TEE 的维护成本怎么评估？密钥存 eFuse 还是安全元件？SELinux 还是 AppArmor？这些决策的共同点是不能靠"听过"回答——本章给你的是从威胁模型到预算表的完整推导方法。

## 学习目标

- 能为一个产品做出威胁模型（资产/对手/向量/分级）并写出对手档位辩护
- 能设计安全启动信任链，判断全链/半链/不上的档位
- 能按决策树选择运行时安全组合，并为服务落地最小权限配置
- 能为密钥选择存储载体（eFuse/OP-TEE/SE/TPM）并设计生命周期流程
- 能分清 Safety 与 Security，说明 Linux 在功能安全产品里的位置
- 能把硬性安全要求推导成预算分配表，每笔支出指回威胁清单
