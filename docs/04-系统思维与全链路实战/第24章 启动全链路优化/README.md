# 第24章：启动全链路优化

> 所属：第 四 部 系统思维与全链路实战
>
> BIEM：[E] | 核心问题：每一毫秒启动时间去了哪里？你愿不愿意付出代价来消灭它？

## 核心问题

不是"启动链是怎么工作的"——那是第 1 部（bring-up）和第 7 章（启动链深度解析）已经回答过的问题。本章回答的是：**从上电到用户可用这条链上，每一毫秒花在了哪一段、用什么工具量出来的、消灭它要付什么代价（功能、调试能力、可维护性），以及哪些"毫秒"其实根本不用消灭——因为用户可以感知不到它。**

## 为什么需要这一章

启动时间是嵌入式产品最直观的体验指标：安防摄像头要求冷启动 2 秒内出预览，仪表盘要求点火后 3 秒内亮屏，机器人要求急停恢复后快速回到可控状态。但"启动慢"是个糊涂账——5 秒里 BootROM 占多少、内核占多少、你的应用占多少？不知道比例就动手，大概率是在最贵的段上省最少的钱。

有经验的工程师通常都会几招：换 lz4、裁剪驱动、关串口打印。但"会几招"和"会做启动优化"之间隔着方法论：**先建立测量基础设施让每一毫秒显形，再按"性价比 × 代价"排序逐项消灭，最后接受一个反直觉的真相——用户感知到的启动时间，不等于系统真正就绪的时间**。大纲给的智能摄像头案例里，省掉最多"感知时间"的一招（先出预览、后初始化 AI）根本不在任何启动优化清单上。
