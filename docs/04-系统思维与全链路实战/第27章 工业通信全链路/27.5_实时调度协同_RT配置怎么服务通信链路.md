# 27.5 实时调度协同：RT 配置怎么服务通信链路

> 所属章节：第27章 工业通信全链路
>
> 难度：[E] | 预计阅读时间：25分钟

## <span class="blue">本节导读

27.2~27.4 解决的是"线上"的确定性——帧在总线上的传输与同步。但 27.2 末尾留了个口子：**定时与唤醒不归总线管**。IGH 主站不负责叫醒你，`cyclic_task` 能不能每 1ms 准时醒来、醒来之后能不能不被打扰地跑完，全在调度器和系统配置手里。27.1 的抖动源清单就是这一节的任务书：SMI、page fault、中断抢占、DVFS、tick、缓存争抢——每一项都对应一项配置，配齐了调度段的确定性才算闭环。

边界先划清：**选不选 PREEMPT_RT、要不要 Xenomai，是第 20 章的选型题**；本节假设你已选定 PREEMPT_RT（2026 年 Linux 工业控制的主流答案），讲的是选定之后围绕通信链路的完整配置。

> 本节覆盖：内核配置三件套（PREEMPT_RT/HZ_1000/NO_HZ_FULL）、CPU 隔离为什么是三兄弟（isolcpus/nohz_full/rcu_nocbs）、中断亲和与 irqbalance、RT 线程的优先级分配原则、mlockall 与栈预触碰、定频与 DVFS 的取舍、一份可照抄的完整配置清单，以及 x86 平台最后的漏网之鱼 SMI。

## <span class="blue">配置的总依据：抖动源消灭表 [E]

先立本节的主线——每一项配置都要能回答"它消灭 27.1 清单里的哪个抖动源"：

| 抖动源 | 消灭它的配置 | 所在小节 |
|:---|:---|:---|
| tick 中断（HZ 周期打扰） | `HZ_1000` + `NO_HZ_FULL` + `nohz_full=` | 内核配置 / CPU 隔离 |
| 中断抢占（网卡/磁盘打到 RT 核） | irq affinity + 关 irqbalance | CPU 隔离 |
| 缓存争抢（其他核跑内存密集任务） | `isolcpus=` + 线程绑定 | CPU 隔离 / 线程侧 |
| page fault（未锁内存） | `mlockall` + 栈预触碰 | 线程侧 |
| DVFS 频率切换 | performance governor / 定频 | 定频 |
| RCU 回调、定时器迁移 | `rcu_nocbs=` | CPU 隔离 |
| SMI | BIOS 层处理（OS 管不到） | SMI 与 27.6 |

配完每一项都要回到 cyclictest 验证——**配置不是信仰，是逐项验收的工程**。清单执行完，Max 列没有明显下降的那一项，要么没配生效，要么抖动源判断错了。

## <span class="blue">内核配置三件套 [E]

```
CONFIG_PREEMPT_RT=y        # 完全可抢占内核
CONFIG_HZ_1000=y           # tick 频率 1000Hz
CONFIG_NO_HZ_FULL=y        # 全动态 tick（配合启动参数生效）
```

- **PREEMPT_RT**：把内核里"不可抢占"的窗口压到最小——自旋锁变可睡眠锁、中断处理线程化、软中断线程化。效果是 27.1 说的"最坏延迟有界化"：普通内核里一次几百微秒的关中断临界区，RT 内核里缩短到微秒级。代价是吞吐下降 5~15%（锁变贵了）——这是拿平均值换最坏值，工业控制里永远划算。
- **HZ_1000**：tick 频率决定定时器分辨率的地板。RT 线程用 hrtimer/`clock_nanosleep` 本可亚毫秒定时，但系统的超时、调度记账仍以 tick 为节拍——1000Hz 让地板足够低。
- **NO_HZ_FULL**：编译时打开能力，运行时还要靠启动参数指定哪些核"免打扰"——下一节讲。

## <span class="blue">CPU 隔离：为什么是三兄弟 [E]

4 核控制器上划 CPU 2、3 给实时任务（CPU 0、1 跑 Linux 业务），启动参数长这样：

```
isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3 irqaffinity=0,1
```

四个参数各堵一条"打扰通道"，漏一个隔离就不完整：

| 参数 | 堵什么 | 不配的漏气方式 |
|:---|:---|:---|
| `isolcpus=2,3` | 调度器不再往 2、3 上放普通任务 | 普通任务被调度上去，缓存与流水线争抢 |
| `nohz_full=2,3` | 2、3 上只有一个任务时停 tick | 每 1ms 一次的 tick 中断打断 RT 线程（1~10μs 抖动） |
| `rcu_nocbs=2,3` | RCU 回调挪到其他核执行 | RCU 软中断在 RT 核上触发（偶发几微秒） |
| `irqaffinity=0,1` | 默认中断亲和排除 RT 核 | 网卡/磁盘中断随机打到核 2、3（5~50μs 抖动） |

隔离生效后还要收尾两件：**关掉 irqbalance**（它运行时会周期性地"重新平衡"中断，把你精心排的亲和表冲掉——发行版默认开着，是隔离配置最常见的翻车点）；**逐中断核对** `/proc/irq/*/smp_affinity_list`，特别是网卡与存储中断，确认没有漏网之鱼指向核 2、3。

> 💡 EtherCAT 用专用 MAC 驱动时是例外：它的中断（如果用的话）**应该**绑到 RT 核上——主站收帧中断本来就是实时路径的一部分。隔离的对象是"与实时无关的打扰"，不是"所有中断"。

## <span class="blue">线程侧：优先级、锁内存、绑定 [E]

隔离的核上是空舞台，放什么演员、谁站 C 位，是应用层的三件事。

**优先级分配**。SCHED_FIFO 范围 1~99，分配原则不是"越高越好"，是**按周期紧迫度排序、且互斥关系想清楚**：

| 优先级 | 线程 | 理由 |
|:---|:---|:---|
| 90 | EtherCAT 主站收发线程 | 周期最短（1ms 甚至 250μs），迟到全盘皆输 |
| 80 | 控制算法线程 | 等主站数据，让主站先跑 |
| 50 | CAN/IO 事件处理 | 事件型，上界毫秒级 |
| 1~10 | 状态上报、日志 | 27.1 说的"可被挤占" |

> 优先级反转：低优先级线程持锁时被高优先级线程等，等于高优先级被降级——27.1 抖动源清单里的隐藏款。PREEMPT_RT 内核的互斥锁默认带优先级继承（PI mutex）：持锁的低优先级线程临时继承等待者的优先级，尽快放锁。应用侧用 `pthread_mutexattr_setprotocol(PTHREAD_PRIO_INHERIT)` 对用户态互斥锁做同样设置——RT 线程间共享数据的所有 mutex 都要加这一行，不加就是给自己埋 spike。

**锁内存与栈预触碰**（27.2 已见代码，这里补原理）：`mlockall(MCL_CURRENT | MCL_FUTURE)` 把进程所有页钉在物理内存，防止运行中被换出或惰性分配。两个配套动作缺一个都不算完：**栈预触碰**（循环前 `memset` 一段栈空间，把栈页提前 fault 进来）和**堆预分配**（RT 路径上禁止 `malloc`——分配器有锁、可能触发缺页，控制循环里的内存必须循环前备好）。

**线程绑定**：`pthread_setaffinity_np` 把每个 RT 线程钉到指定核。主站线程与控制线程放同一个核还是分开？预算够（合计 < 单核算力的 70%）就放同核——省去核间同步的 cache line 乒乓；不够再分核，分核后共享数据改走无锁环形缓冲。

## <span class="blue">定频：DVFS 的取舍 [E]

DVFS（动态调频）为省电让频率随负载浮动，频率切换本身有 5~20μs 的过渡期抖动——RT 系统直接关掉：

```bash
# 全部 CPU 锁在最高频
echo performance > /sys/devices/system/cpu/cpu2/cpufreq/scaling_governor
# Intel 平台更彻底的做法：启动参数 intel_pstate=disable + BIOS 锁频
```

代价是实打实的功耗与温度——第 28 章会算这笔账。工程折中是：**只给 RT 核定频，业务核保留 schedutil**——实时性和电费各拿一半。

## <span class="blue">完整配置清单：可照抄的一页 [E]

把全节收拢成部署时的三个落点：

```bash
# ① 内核启动参数（bootloader 命令行）
isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3 irqaffinity=0,1 intel_pstate=disable
```

```bash
# ② 系统初始化脚本（systemd service / rc.local）
systemctl stop irqbalance
echo performance > /sys/devices/system/cpu/cpu2/cpufreq/scaling_governor
echo performance > /sys/devices/system/cpu/cpu3/cpufreq/scaling_governor
# 网卡与磁盘中断逐个绑到 0,1（按 /proc/interrupts 实际 IRQ 号）
echo 0,1 > /proc/irq/24/smp_affinity_list
echo 0,1 > /proc/irq/25/smp_affinity_list
sysctl -w kernel.sched_rt_runtime_us=-1   # 放开 RT 带宽节流，见下注
```

```c
/* ③ 应用线程启动时（每个 RT 线程） */
mlockall(MCL_CURRENT | MCL_FUTURE);          /* 在任何 RT 动作之前 */
/* 栈预触碰 */
char stack_prefault[256 * 1024];
memset(stack_prefault, 0, sizeof(stack_prefault));
/* 绑定 + 优先级（SCHED_FIFO 90 示例见 27.2 的 rt_thread） */
```

> ⚠️ `sched_rt_runtime_us=-1` 这条要讲清楚：内核默认给 RT 任务留了 5% 带宽兜底（防止 RT 死循环锁死系统）。控制线程算力需求超过 95% 时会莫名被限流——症状是"算法偶发超时，查不出原因"。放开意味着接受"RT 死循环 = 整机死"，所以配套纪律是控制线程里**禁止任何不确定循环**，并且留一个更高优先级的看门狗线程兜底。

## <span class="blue">SMI：OS 管不到的最后一条鱼 [E]

配置全部到位、cyclictest 的 Max 列仍然偶发 50~200μs——x86 平台上这通常意味着 SMI（System Management Interrupt，系统管理中断）。它由 BIOS/芯片组直接触发，进入 SMM 模式执行固件代码，**对操作系统完全不可见、不可屏蔽、不可测量**——OS 视角就是"那段时间凭空消失了"。常见来源：BIOS 的温度轮询、USB 传统模式仿真、EC（嵌入式控制器）事件。

它是 x86 平台最大的实时性杀手，也是 ARM 工控平台崛起的原因之一（ARM 无此机制）。处置只有 BIOS 层一条路：关闭能关的 SMI 源（温度监控、USB legacy），关不掉的接受它、评估周期与时长是否在预算余量内——27.6 的综合实战就是围绕一次真实的 SMI 猎杀展开的，排查链在那里完整走一遍。

## <span class="blue">验证：回到预算表 [E]

配置工程的收尾永远是测量。标准动作：

```bash
# 在隔离核上跑 cyclictest，周期1ms，过夜
taskset -c 2 cyclictest -p 99 -m -i 1000 -l 86400000 -h 100
```

`taskset -c 2` 故意用普通调度工具把测试放到隔离核——它模拟的就是你的控制线程的处境。验收口径对照 27.1：Max 列稳定低于预算（1ms 周期通常要求 <30μs），且负载注入（stress-ng 打满 CPU 0、1）后不退化。**隔离的试金石恰恰是不隔离那边越忙越好**——CPU 0、1 上编译内核、跑数据库，核 2 的 Max 纹丝不动，隔离才算真成立。

## <span class="blue">本节总结

调度段的确定性靠逐项消灭 27.1 的抖动源清单：内核三件套（PREEMPT_RT 把最坏延迟有界化，代价是 5~15% 吞吐——拿平均换最坏，永远划算）、CPU 隔离四参数各堵一条打扰通道（漏 irqbalance 是最常见翻车点）、线程侧三件事（按周期紧迫度排优先级、PI mutex 防优先级反转、mlockall 配栈预触碰与堆预分配）、定频换功耗（折中是只给 RT 核定频）。

配置清单的三个落点：启动参数、初始化脚本、应用线程启动代码，`sched_rt_runtime_us=-1` 的放开必须有"RT 线程禁止不确定循环 + 看门狗兜底"的配套纪律。SMI 是 OS 管不到的最后一条鱼，只有 BIOS 层一条路——它的完整猎杀过程就是下一节。验证口径：隔离核上 cyclictest 的 Max 列，在"不隔离那边越忙越好"的压力下纹丝不动才算数。
