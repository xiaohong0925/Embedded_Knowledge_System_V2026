# 第27章：工业通信全链路

> 所属：第 四 部 系统思维与全链路实战
>
> BIEM：[E] | 核心问题：确定性怎么从传感器一路保证到执行器？

## 核心问题

不是"EtherCAT/CAN/TSN 协议是什么"——那是 B 扩展已经回答过的问题。本章回答的是：**一个运动控制周期（1ms，甚至 125μs）里，数据从传感器锁存到执行器动作要经过总线、驱动、调度器、控制算法层层转手，每一层都在花时间、引入抖动——怎么设计这条链路，使得"第 100 万次循环"和"第 1 次循环"一样准时。**

## 为什么需要这一章

工业通信的核心特征是大纲的原话：**确定性——不是"多快"，而是"保证在规定时间内完成"**。这句话的反直觉之处在于：平均延迟 50μs 的系统可能完全不可用（最坏一次 2ms，电机就抖了），平均延迟 200μs 的系统反而可能是好系统（最坏 210μs，永远准时）。评估单位不是均值，是最坏情况。

有经验的工程师通常已经能调通 CAN 收发、搭起 IgH 主站、让伺服转起来。但"能通"和"确定"之间的问题不会自动有答案：控制周期定 1ms 还是 500μs，依据是什么？偶发的周期超时，该怀疑总线、调度器还是 BIOS？PREEMPT_RT 打了补丁为什么还有 100μs 的 spike？EtherCAT 和 TSN 都号称确定性以太网，替换关系是什么？这些问题的答案分散在协议、内核调度、时间同步、硬件平台四个领域里——本章把它们串成一条链。
