## 核心问题

出了问题怎么系统调试？

## 本章简介

本章不调试某个具体子系统，而是调试”整个系统”——建立从症状到根因的系统化方法论。核心思想是：高级工程师的调试能力不在于他知道多少个工具，而在于他能在复杂系统中建立假设-验证的思维链条。

问题现象层

```
    │
    ├── 性能异常（CPU 100%、延迟抖动、吞吐量下降）
    ├── 功能异常（崩溃、挂死、数据错误）
    └── 偶发异常（Heisenbug、时序问题、竞争条件）
              │
    ┌─────────┴─────────┐
    ▼                   ▼
信息收集层          假设构建层
    │                   │
    ├── 全局概览        ├── 从症状反推可能原因
    ├── 子系统定位      ├── 构建假设树（多个互斥假设）
    └── 事件关联        └── 设计实验验证每个假设
              │
              ▼
        根因确认层
              │
    ├── 复现 → 隔离 → 确认
    ├── 交叉验证（多个工具指向同一结论）
    └── 修复验证 + 回归测试
```


## 子节清单

- 调试思维：从症状到根因的系统方法
- 信息收集：日志、Tracing、监控
- 假设-验证法：缩小问题范围
- 常见陷阱：看似是A问题实际是B问题

## 学习目标

掌握本章核心知识，能够在实际项目中应用相关技术。
