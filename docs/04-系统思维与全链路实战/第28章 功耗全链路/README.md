# 第28章：功耗全链路

> 所属：第四部 系统思维与全链路实战
>
> 难度：[M] ~ [E] | 核心问题：每一毫瓦功耗从哪里来，怎么以最小的性能损失消灭它？

## 核心问题

电池供电产品的续航指标、工业设备的散热与电费成本、芯片结温的可靠性红线——背后都是同一个问题：功耗。但"功耗高"不是一个可以下手的问题，必须先把每一毫瓦分解到具体的电源域、具体的外设、具体的引脚，才能逐项消灭。本章回答：功耗怎么测、怎么分解、分解表对不上的账去哪找、优化手段各自付出什么性能代价、最后怎么验收。

## 本章简介

功耗优化和性能优化最大的区别是：性能问题往往有明确的热点函数，功耗问题却经常"分解表加不拢"——理论分解之和与实测整机功耗之间差着几百毫瓦。这个差值不是误差，是破案方向：引脚漏电、未关断的 always-on 电源域、PMIC 工作模式选错，全都藏在这里。本章的主线就是这套**分解—对账—归因**的方法论。

本章的定位是**链路实战层**，与第 15 章（电源管理：Runtime PM 引用计数、cpuidle/cpufreq、schedutil、DVFS 模型、Thermal、suspend 机制、15.7.1 功耗排查实战）分工明确：第 15 章讲机制是什么，本章讲在真实产品上怎么用这些机制把功耗打下来，以及每一步的性能代价怎么算账。全章以 WRM247LTE（电池供电工业物联网终端，suspend 功耗指标 <200mW）收口：720mW 起步，分解表差值 323mW 逼出引脚漏电，四步优化压到 199mW，验收时 +55℃ 高温反弹用温度自适应策略收口，续航 4.2 天提升到 11.6 天。

## 学习目标

- 能建立整机功耗分解表，并用"分解之和 vs 实测总功耗"的差值作为排查入口
- 能按场景选用测量手段：万用表定性、功耗分析仪定量、片上传感器在线监控
- 能用 cpuidle 驻留分布与 cpufreq 统计分解 CPU 功耗，识别异常驻留
- 能执行外设 Runtime PM 补全与引脚态审计，定位引脚漏电
- 能按唤醒延迟与功耗收益选型 suspend 档位，配置唤醒源并审计 always-on 域
- 能为每项功耗优化写明性能代价与回滚条件，设计含温度边界的验收标准
- 能完整复盘一次功耗优化项目：指标、分解、对账、逐项消灭、验收
