## 三、待诊断确认的篇目契约

以下均为**候选项**，低档模型必须用正文证据确认、修正或否定，不得直接当成已批准方案。

### 1. 篇目类型

协议层／帧格式／时序篇。核心是把一笔传输的位流、状态边界、数据有效位置和观测证据讲清楚，不默认要求 Linux 驱动代码、DTS 或完整上板教程。

### 2. 候选唯一主问题

一笔 W25Q128JV Fast Read 怎样从 CS 有效开始，依次经过命令、24 位地址和 dummy clocks，到达有效数据；软件怎样在明确的传输模型下定位返回字节，并用波形或日志验证自己没数错？

### 3. 候选贯穿实例

- 指令：`0x0B`；
- 地址：`0x001234`；
- 前导：8 拍命令＋24 拍地址＋8 拍 dummy，共 40 拍；
- 随后：连续读出数据；
- 读取长度、具体教学数据和预期 RX 内容：由诊断提出，并说明为什么足以暴露字节边界和位序问题。

若构造 `EF 40 18` 之外的新数据，必须明确标为“教学假设数据”，不得写成板卡或仪器实测。若沿用正文抽象 `D0 D1 D2 ...`，必须说明读者怎样验证自己找到了第一个有效数据字节。

### 4. 必要交付物候选

1. 从 CS 有效到释放的完整事务边界，以及 Flash 内部状态与主机缓冲状态的区别。
2. `0x0B 00 12 34 + 8 dummy` 的逐段帧序列、累计拍号和有效数据起点。
3. TX／RX 同时发生时，主机缓冲区为何出现偏移；`RX[5]` 只适用于哪种全双工、等长缓冲模型。
4. 位序、字节边界和连续读之间是什么关系，读者怎样手工推演出第一个有效数据字节。
5. dummy clocks、ADC 转换等待和 Flash 内部 busy 的异同；若保留多器件比较，各自证据必须齐全。
6. AC 时序参数怎样沿“控制器边沿→走线与器件→采样点”影响有效数据，不和 B-B.4.1 的电气基础重复。
7. 同一笔实例怎样用软件预期、逻辑分析仪或示波器交叉验证；哪些只是手册或教学推导，哪些尚未实测。
8. 多线 SPI 只在能推进主问题时保留；需要交代与单线 Fast Read 的差异及移交边界，不能堆指令名。

### 5. 禁止进入的内容

- Linux SPI 驱动框架实现、结构体逐项讲解、DTS 和 DMA；
- 完整 spidev 工具教程、故障排查大全和仪器选型；
- W25Qxx 页写、烧录、MTD 和完整上板实战；
- 重复讲授 B-B.4.1 已完成的四线连接、推挽与 CPOL／CPHA 基础；
- 无证据的器件参数、实测结论、源码行号或函数名单堆砌。

必要的最小回顾可以保留，但必须说明它如何服务当前 Fast Read 主线。

### 2. 当前正文的模型边界

正文已经说明 `RX[5]` 只适用于“全双工、等长 TX／RX 缓冲模型”，不是所有驱动都固定提供的接口。诊断应检查这一限定是否真正贯穿示例和验证步骤，而不是简单删除或保留一句话。

### 3. 缺口

当前工作区没有 ADS8341、ST7789 的官方手册。若诊断建议保留这些器件的具体帧格式、等待规则或时序结论，必须补可回到原文的官方证据；无法取得时标为“待核验”，不得凭模型记忆写成确定事实。也可以选择缩小比较范围，但要交代主线是否仍完整。
