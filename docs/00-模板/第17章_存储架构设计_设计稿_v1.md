## 1. 大纲对第 17 章的设计意图（docx 原文摘要）

- **核心决策问题**："文件系统怎么选？存储怎么分区？怎么防断电丢数据？"
- **核心洞察**（本章灵魂句）：存储架构设计不是选文件系统，而是**设计一个数据生命周期管理系统**——每类数据有不同的写入频率、持久化要求、恢复策略。
- **为什么需要**：存储是最容易设计失误的部分，不是因为技术难，而是**决策后果滞后显现**（断电丢数据量产半年后才暴露，介质寿命 1-2 年后爆发）。
- **决策场景**：户外工业网关，-40~85°C，8GB eMMC，日均 100MB 日志，5 年寿命，每天可能断电数次，OTA 必须可回滚。
- **大纲给定的 4 节**：17.1 介质选型 / 17.2 文件系统选型矩阵 / 17.3 分区策略 / 17.4 断电安全架构。
- **大纲给定的资产**：选项分析（介质 6 种、文件系统 7 种、分区 4 种）、三棵决策树（介质/断电需求/OTA 策略）、架构评审清单（4 组 16 项）、三个案例（智能音箱 SquashFS+OverlayFS、工业 HMI 全 UBIFS、汽车 T-Box eMMC F2FS，均带数字）。
- **第三部章模板（9 固定块）**：核心决策问题 → 为什么需要 → 决策场景 → 选项分析 → Trade-off 表格 → 决策树 → 架构评审清单 → 案例研究 → 各小节详述。

## 3. 本章结构提案（6 节组）

大纲的 4 节骨架保留但升维重组，每节标注**存在理由**与**边界指针**，落实"内容为主题服务、每个点不悬空"：

### 17.1 存储架构设计的真正对象：数据生命周期 [E]

- **存在理由**：本章方法论奠基节。大纲核心洞察"不是选文件系统，而是设计数据生命周期管理系统"必须独立成节——它是后面所有决策的生成器，不先立住，17.2~17.5 全是悬空的技术罗列。
- **内容要点**：决策后果滞后显现的失效时间线（为什么存储问题量产半年后才暴露）；产品数据分类法：按写入频率（启动时读一次 / 低频配置 / 高频日志 / 流式数据）× 持久化要求（丢了无所谓 / 可重建 / 必须保住）× 恢复策略（重新生成 / 出厂恢复 / 不可丢失）建立三维分类表；用章首工业网关场景把每类数据逐个过一遍分类表，得出存储需求清单——这份清单就是 17.2~17.5 的输入。
- **边界**：纯方法论，不涉及任何具体介质/文件系统细节。
- **预期行数**：≥ 250 行。

### 17.2 存储介质决策：寿命量化与 2026 格局 [E]

- **存在理由**：介质是架构决策的第一约束（选错介质，软件层做什么都补不回来）。但参数对比 16.4.5 已完备，本节只做三件事：寿命量化、黑盒风险、时代演进。
- **内容要点**：
  - 寿命估算公式（寿命(年) = 容量 × P/E 次数 × (1-写放大) / 日均写入量 / 365）+ 80% 规则 + 日均写入量实测方法（`/sys/block/*/stat` 采样，不靠估算）；用工业网关场景算一遍：100MB/天 × 5 年 vs 8GB eMMC TLC 3K P/E。
  - eMMC FTL 黑盒问题：控制器磨损均衡算法不可见，工业级（pSLC 模式、增强型 MLC）与消费级的真实差异，供应商数据手册里要盯哪几个参数（TBW、P/E、数据保持力随温度的衰减）。
  - 2026 格局（调研实证）：UFS 4.1/5.0 进入车载 ADAS 与边缘 AI（全双工、命令队列、10.8GB/s），NVMe BGA SSD 进工业（-40~105°C、硬件 PLP 掉电保护），eMMC 退守低带宽 IoT——给出"什么时候该跳出 eMMC"的判据。
  - 为什么消费级 SD 卡不能进产品（16.4.5 已讲原因，此处给供应链与寿命维度的补强 + 显式指针）。
- **边界指针**：介质参数/接口/对比矩阵 → 16.4.5；UFS/MIPI M-PHY 协议层 → B 扩展 C 板块（8.x）。
- **预期行数**：≥ 300 行。

### 17.3 文件系统决策：故障模式视角与 EROFS 时代 [E]

- **存在理由**：12.3 讲了"每种 FS 怎么工作"，12.3.5 讲了"按介质和读写模式怎么选"。本章的增量是**架构师视角的两个问题**：断电后每种 FS 表现为什么（故障模式对比），以及 2026 年只读 rootfs 该选 SquashFS 还是 EROFS。
- **内容要点**：
  - 故障模式矩阵：ext4（journal replay 时间、fsck 概率）、F2FS（checkpoint 恢复）、UBIFS（日志结构天然抗断电的原因一句话 + 指针）、SquashFS/EROFS（只读即免疫）。每种给"断电后最坏情况是什么"。
  - EROFS vs SquashFS 2026 现状（调研实证）：页对齐压缩带来的随机读 3 倍 IOPS、6.1 起块级去重（Yocto 多变体镜像省 5~15%）、与 dm-verity 哈希树对齐降低校验开销、定长块对 OTA delta 更新友好（SquashFS 大块压缩导致小改动大面积变化）；SquashFS 的保留场景（极致压缩率 xz、顺序读为主、老内核 <5.4）。
  - 选型输入的时代更新：dm-verity 已成产品安全基线（与 19 章呼应），OTA delta 更新需求（与 21 章呼应）——这两个需求 12.3.5 写作时不在选型维度里。
- **边界指针**：FS 内部机制 → 12.3.1~12.3.4；基础选型框架（介质定候选集、fio 方法论）→ 12.3.5，本节不重复，只补架构维度。
- **预期行数**：≥ 300 行。

### 17.4 分区架构：只读 rootfs 是产品化的分水岭 [E]

- **存在理由**：大纲原话"分区策略是架构决策，不是技术选型"。这是全书首次正面讲分区布局（12 章没有，21 章只从 OTA 流程消费分区）。也是 17.1 数据分类的直接落地——每类数据该住哪个分区。
- **内容要点**：
  - 四种布局模式对比：单分区读写（开发期）/ 只读 rootfs + 可写数据区（产品基线）/ A/B 双分区（OTA 原子更新）/ A/B + 独立数据区（平衡安全与空间）——每种给适用阶段与升级路径。
  - 为什么只读 rootfs 是分水岭：防篡改（安全）+ 整分区替换（OTA 原子性）+ 断电免疫（只读无 journal）三重收益；overlayfs 可写层的两种玩法（tmpfs 易失层 vs 持久数据区）。
  - 分区大小预留策略：rootfs 预留 20~30% 应对 OTA 膨胀、数据分区 80% 报警/90% 清理阈值、日志分区独立且硬限容（防日志撑爆 rootfs 的真实失效模式）、recovery/工厂重置分区。
  - eMMC 硬件分区的架构利用：Boot Area 放 bootloader、RPMB 放安全数据（指针 16.4.5 已讲配置，此处讲"哪些数据该放哪"的决策）。
- **边界指针**：A/B 切换的 bootloader 侧实现、签名验证、灰度回滚流程 → 21 章；本章只定存储侧布局。overlayfs 机制 → 12.3.4。
- **预期行数**：≥ 300 行。

### 17.5 断电安全架构：代价量化与验证方法论 [E]

- **存在理由**：12.5 已把四层防护机制讲完。本章回答架构师的问题：**防护投入多少才够**——这是大纲"断电保护的真正代价是什么"的落点。
- **内容要点**：
  - 分层防护的代价表：barrier=1 的性能代价（写密集场景可达 40%）换什么、data=journal 再换什么、超级电容的 BOM 成本与充电管理电路复杂度换什么、应用层双写的代码复杂度换什么——每层"花什么代价、消除哪类失效"。
  - 超级电容方案工程实践：容量计算（最坏写入耗时 × 电流）、充电管理、寿命监控（电容老化）、与 PMIC 掉电中断的配合时序。
  - 断电测试方法论设计（不是"做 1000 次"一句话）：断电时机随机化（写中/擦除中/空闲各占比例）、测试工装（可编程电源 + 继电器自动循环）、判定标准（FS 损坏率 / 数据丢失容忍度）、多少次循环算"验证过"（按失效率目标倒推样本量）。
  - 断电需求分级决策树（大纲给定）：每天多次随机断电 / 偶尔断电 / 可控关机，各配什么组合。
- **边界指针**：barrier/fsync+rename/四层机制 → 12.5.1~12.5.3，本节开头一段收敛式回顾 + 显式指针，然后全程讲决策与验证。
- **预期行数**：≥ 300 行。
