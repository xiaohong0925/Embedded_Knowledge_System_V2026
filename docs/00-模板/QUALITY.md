# EKL 质量规范 V2026.07（QUALITY）

> 生效日期：2026-07-03
> 适用范围：docs/ 下全部 Markdown 文件
> 核心原则：**L1 阻断、L2 提醒、L3 优化**

---

## 规范分层总览

| 层级 | 性质 | 数量 | 违规后果 | 自动修复 |
|------|------|------|---------|---------|
| **L1 阻断级** | 结构性错误 | 8条 | CI 拒绝合并 | 部分可自动 |
| **L2 提醒级** | 体验性警告 | 10条 | CI 标黄，允许合并 | 部分可自动 |
| **L3 优化级** | 品质建议 | 其余全部 | 仅记录，不阻塞 | 不可自动 |

**写作原则：** 新文件先过 L1，老文件渐进迁移。不因格式完美而阻塞内容产出。

## L1 阻断级规则（违反 = 拒绝提交）

### L1-001 一级标题无序号
- **规则：** 正文内 `# ` 标题禁止含数字序号（如 `# 11.1.1 xxx`）
- **理由：** 编号仅在文件名/文件夹名中出现，正文标题纯文字
- **例外：** 知识图谱文件（`11.99_xxx.md`）可保留章节号用于索引
- **自动修复：** ✅ 安全（`# 11.1.1 xxx` → `# xxx`）

### L1-002 禁止四级及以下标题
- **规则：** 禁止使用 `#### ` 及更低级标题
- **理由：** 五级体系最大深度为 `### `（知识点级）
- **替代：** 用 `<strong>子标题</strong>` 或列表承载
- **自动修复：** ❌ 需人工判断如何降级

### L1-003 表格内禁止 span 标签
- **规则：** Markdown 表格单元格中不得出现 `<span>` 标签
- **理由：** 表格渲染引擎对 HTML 标签兼容性差，移动端易崩
- **自动修复：** ❌ 需人工重写为纯文本或移除标记

### L1-004 blockquote 不嵌套代码块/表格
- **规则：** `>` 引用块内部不得出现 ``` 代码块或表格
- **理由：** MkDocs 移动端渲染异常，嵌套结构脆弱
- **自动修复：** ❌ 需人工调整结构

### L1-005 代码块必须带语言标识
- **规则：** 所有 ``` 必须跟随语言标识（如 ` ```c `、` ```yaml `）
- **理由：** 语法高亮是阅读体验的基础
- **例外：** 纯文本输出日志可用 ` ```text `
- **自动修复：** ⚠️ 可猜语言，但需人工确认

### L1-006 无死链/错链
- **规则：** Markdown 内相对链接指向的文件必须存在
- **理由：** 读者点击404 = 信任崩塌
- **自动修复：** ❌ 需人工修正目标路径

### L1-007 mkdocs build 必须通过
- **规则：** `mkdocs build --strict` 不得报错
- **理由：** 构建失败 = 无法发布
- **自动修复：** 视情况而定

### L1-008 文件命名符合层级规范
- **规则：**
  - 模块文件夹：`0N-模块名/`（2位数字前缀）
  - 大章文件夹：`NN-大章名/`（2位数字前缀）
  - 章节文件：`NN.N.N_章节名.md`
- **自动修复：** ❌ 重命名涉及版本控制，需人工确认

## L2 提醒级规则（违反 = CI 标黄，可合并但记债）

### L2-001 段落长度 ≤ 4 行
- **规则：** 连续非空行（不含列表/代码/引用）超过 4 行即警告
- **理由：** 长段落降低阅读节奏，移动端体验差
- **自动修复：** ⚠️ 可按句号拆分，但需人工 review

### L2-002 单段"你"出现 ≤ 2 次
- **规则：** 一个自然段中第二人称"你"超过 2 次即警告
- **理由：** 过多"你"产生说教感，可用祈使/被动替代
- **自动修复：** ⚠️ 需语义理解，不可全自动

### L2-003 emoji 后不加粗第一个词
- **规则：** `💡 **提示**：` 等模式警告；应为 `💡 实际工作中，**核心观点**...`
- **理由：** 粗体应标在核心观点上，而非 emoji 后的第一个词
- **自动修复：** ✅ 安全（调整粗体位置）

### L2-004 无 AI 导航语
- **规则：** 禁止"下面介绍""接下来我们来看""下面逐一展开"等过渡语
- **理由：** 读者往下翻自然知道，AI 导航语徒增字数
- **自动修复：** ⚠️ 可高亮提示，删除需人工确认

### L2-005 无元叙述
- **规则：** 禁止"本节用 X 张图带你...""本节覆盖..."等自我指涉
- **理由：** 元叙述打断阅读沉浸感
- **自动修复：** ⚠️ 可标记，删除需人工确认

### L2-006 小节标题需 BIEM 徽章
- **规则：** `## <strong>小节名</strong>` 同行末尾需有 `<span class="badge-x">X</span>`
- **例外：** "本节导读""本节总结""下一步""常见问题 FAQ" 等固定小节
- **自动修复：** ✅ 安全（给固定小节加默认 badge）

### L2-007 图片标注格式
- **规则：** `[图 N：...]` 应改为 `> 📷 此处建议插图：...`（blockquote 格式）
- **理由：** 统一审稿备注格式，区别于正文
- **自动修复：** ✅ 安全

### L2-008 无伪百分比/伪数据
- **规则：** "90% 的时间""80% 的工程师"等无出处的定性百分比警告
- **理由：** 伪数据损害可信度，应用平实定性描述
- **自动修复：** ❌ 需人工改写

### L2-009 代码块无 $ 提示符
- **规则：** 代码示例中不应包含 `$ ` 或 `# ` 命令提示符
- **理由：** 提示符阻碍直接复制粘贴执行
- **自动修复：** ✅ 安全（行首正则替换）

### L2-010 生活化比喻审查
- **规则：** "厨房做菜""骑车""逛街"等生活化比喻标黄
- **理由：** 工程类读物宜用工程比喻或删除
- **例外：** "装修房子选材料"等贴近嵌入式场景的保留
- **自动修复：** ❌ 需人工判断

## L3 优化级规则（仅记录，不阻塞）

### L3-001 换行标签大小写
- **建议：** 使用 `<BR>` 大写以区分 Markdown 原生 `<br>`
- **优先级：** 低，不影响渲染

### L3-002 小结导读去"珍珠项链"式比喻
- **建议：** "本节把知识点串成珍珠项链" → "本节覆盖：xxx"
- **优先级：** 低

### L3-003 承诺型表述转清单型
- **建议：** "学完本节，你能..." → "本节覆盖：..."
- **优先级：** 低

### L3-004 Mermaid 图替代 ASCII 框图
- **建议：** ASCII 流程图逐步替换为 Mermaid
- **优先级：** 低，ASCII 图当前可读性可接受

### L3-005 难度范围标注
- **建议：** `难度：[B]` 改为 `难度：[B→I]` 范围法
- **优先级：** 低

## 质量等级标签

每章 README 和每节文件应标注质量等级：

| 标签 | 门槛 | 含义 |
|------|------|------|
| 🚧 Draft | 内容完整 | 初稿，仅保证内容完整 |
| 🔍 Review | 通过 L1 | 内容定稿，无结构性错误 |
| ✅ Publish | 通过 L1+L2 | 可对外发布 |
| ⭐ Polish | 通过 L1+L2+L3 | 出版级 |

**当前策略：**
- 第 1-2 部（已完成章节）：目标 ⭐ Polish
- 第 3-4 部（框架阶段）：目标 🚧 Draft → 🔍 Review
- 第 5 部 / 扩展模块：按实际进度定级
