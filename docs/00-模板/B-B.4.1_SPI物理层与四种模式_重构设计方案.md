## 二、现文失效诊断

### 1. 主实例缺少完整、可跟随的物理波形

现文虽有接线、四模式和菊花链 SVG，但没有把 CS、SCLK、MOSI、MISO 对齐到同一笔 `9F 00 00 00 → ?? EF 40 18` 事务。第 109～140 行用文字描述 32 拍，读者仍难以同时跟随首位预载、更新边沿、采样边沿、字节边界和有效响应的位置。

推挽、高阻、全双工移位和两个从机争用 MISO 也主要停留在文字结论。现有四模式图的抽象 `S/U/DATA` 没有充分回接到本例真实位流。

### 2. 关键概念先用后定义

第 99 行已经使用“全双工”描述主线，第 111 行先使用 CPOL/CPHA，第 146～148 行才正式定义。读者需要先带着未解释符号理解主实例，再回头修正认识。

“预载”“更新”“采样”“占位字节”等词虽然出现在正文中，但还缺少统一的逐拍对象和状态变化，使读者难以把它们与同一根信号线对应起来。

### 3. 软件实现段改变了本篇主问题

现文第 167～276 行依次进入：

- `spi_device`、`spi_transfer`、`spi_message` 等 Linux 对象；
- 一段 SPI 协议驱动代码；
- SPI Core 与 Rockchip 控制器驱动调用链；
- CTRLR0、CTRLR1、TXDR、RXDR、SER 等寄存器；
- BAUDR 计算及 `spi_sync()`、`actual_length` 返回判断。

这些内容把“怎样读懂物理波形”换成了“Linux 怎样提交并完成一次 SPI 传输”。读者尚未建立四线、移位和边沿模型，就被要求理解另一套内核对象和源码背景，因此即使局部技术事实正确，整篇仍然难以跟随。

上述内容不应继续以“补注释、补完整模块”的方式留在本篇，而应退出正文，由 B-B.4.3 系统讲解。

### 4. 多从机和电气内容没有充分服务主实例

菊花链另起一套抽象器件，不能推进 W25Q128JV 的主实例，还会让读者误以为它适用于本例 Flash。多从机只需保留独立 CS、共享线路和 MISO 驱动权。

电气部分应集中解释“为什么模式相同仍可能采错”，不扩展为硬件设计百科，也不引入新的驱动配置主线。

### 5. 上次验收失效

此前把源码核验、静态测试、严格构建和记录自评误当成教学质量证明，没有先检查篇目边界和读者是否理解物理机制。后续复核又集中于少量技术口径，漏掉了整篇教学结构。

本次必须先审查“读者能否看懂波形”，再审查技术细节。严格构建成功、SVG 文件存在和静态断言通过都不能代替人工教学验收。

## 三、唯一主问题与贯穿实例

主问题固定为：

> 一个主机和 W25Q128JV 通过 CS、SCLK、MOSI、MISO 交换位流时，双方怎样在 Mode 0 下用 32 个时钟完成 `9F 00 00 00 → ?? EF 40 18`？CPOL、CPHA 和电气条件为什么决定采样结果？

贯穿实例固定为：

- 主机：RK3568 SPI1，仅用于明确硬件角色，不展开 Linux 驱动；
- 从机：Winbond W25Q128JV-IQ/JQ；
- 标准四线 SPI、Mode 0、8 位字长、MSB-first、低有效 CS；
- MOSI 位流：`9F 00 00 00`；
- MISO 位流：`?? EF 40 18`；
- `??` 不参与器件身份判断；
- `EF 40 18` 只用于本例 IQ/JQ 后缀，IM/JM 的对应值必须按手册区分。

本篇不再把“软件的 4 字节请求怎样经过 Linux 变成波形”作为主问题。发送缓冲、接收缓冲和内核返回值只可在跨节边界中一笔带过，不进入机制讲解。

若保留时钟分频算例，100 MHz 源时钟、30 MHz 请求和 25 MHz 结果只能作为硬件分频的教学推导，不冒充实测，也不展开 Linux 寄存器写法。

## 四、正文结构与存在理由

### 1. 先手工完成一笔传输

先介绍主机、从机和四根线，再给出完整输入输出。读者应先知道：CS 选中器件，主机提供时钟，MOSI 发出命令和占位位，MISO 同步返回身份位。

这一部分只建立物理观察基线，不出现任何软件 API。

### 2. 推挽、高阻与全双工共同决定驱动权

用主机和 Flash 的具体输出状态解释推挽、高阻和全双工。通过“CS 无效 → CS 有效 → 命令阶段 → 响应阶段 → CS 释放”的操作序列，说明谁在何时驱动 MOSI、MISO，谁退出驱动。

再用第二个从机参与共享 MISO 的操作序列，推演两个推挽输出同时有效为什么会冲突。比较 I2C 开漏时，先准确指出前置篇目，不重复展开 I2C 电路。

### 3. 先定义 CPOL、CPHA，再进入 Mode 0

在主实例详细展开前就地定义：

- CPOL：空闲时 SCLK 停在高电平还是低电平；
- CPHA：在每个周期的第一个还是第二个边沿采样；
- 更新：发送端把下一位放到数据线上；
- 采样：接收端读取当前位；
- 预载：首个采样边沿前已经把首位放稳。

定义后立刻落回本例 Mode 0：空闲低、上升沿采样、下降沿更新、首位预载。

### 4. Mode 0 的 32 拍完整过程

对齐 CS、SCLK、MOSI、MISO，按参与者与时间顺序推演：

1. CS 拉低，双方准备首位；
2. 第 1～8 拍，Flash 收齐 `0x9F`，主机收到的首字节不作身份解释；
3. 第 9～16 拍，主机继续给钟并收到 `0xEF`；
4. 第 17～24 拍，收到 `0x40`；
5. 第 25～32 拍，收到 `0x18`；
6. 停止时钟，CS 拉高，Flash 释放 DO。

每一阶段都要写出谁在什么边沿做什么、数据何时稳定、何时被读取，以及为什么需要占位 TX。CS 释放不是 ACK，完整波形也不自动证明系统功能已经验证。

### 5. 从两个独立选择推出四种模式

在 Mode 0 已可跟随之后，再组合 CPOL 与 CPHA 推出 Mode 0～3。每种模式都必须回答：空闲电平、首位上线时机、采样边沿和更新边沿。

W25Q128JV 只把 Mode 0/3 作为本器件可用配置。Mode 1/2 用于理解通用机制，不能写成本例 Flash 的可选配置。

### 6. 多从机只讨论独立片选和驱动权

保留共享 SCLK、MOSI、MISO 与独立 CS 的拓扑，说明不同从机可以要求不同模式，但必须在一笔事务结束后再切换配置。

菊花链退出主线。它另涉整链字长和级联协议，不是理解本篇四种模式的必要前提。

### 7. 速率与电气条件决定理想规则能否成立

先区分源时钟、分频和实际 SCLK，再说明请求速率不保证等于引脚实测速率。若使用 100 MHz → 25 MHz 算例，只用通用算式，不出现 BAUDR、驱动函数或寄存器代码。

电气部分只保留软件工程师读波形所需的内容：共地、输入门限、耐压、建立时间、保持时间、传播延迟、过冲、下冲、振铃和边沿速度。详细 AC 时序预算归 B-B.4.2。

最后区分观测证据：逻辑分析仪适合检查数字位流与边沿关系，示波器适合检查模拟电平和边沿形态；二者均不能替代器件协议与目标功能验证。
