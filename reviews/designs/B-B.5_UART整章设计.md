## 3. 整章核心问题、读者与前置知识

### 3.1 核心问题

一颗 UART 外设发出的字节，怎样从引脚上的异步电平变成 Linux 用户程序可用的数据；当链路换成 RS-485／Modbus 或需要可靠解析真实数据流时，软件工程师应怎样配置、编程并用证据定位问题？

理解链：

```text
电气连接与电平
→ UART 帧、位序和采样
→ 波特率及实际误差
→ UART 控制器与 8250/DesignWare 驱动
→ serial core、TTY、线路规程和 termios
→ 用户态字节流
→ NMEA 或 Modbus 数据语义
→ 正常验证、分层排障与恢复
```

### 3.2 读者

- 有 C 语言和 Linux 命令行基础的嵌入式软件工程师。
- 能接触设备树、日志和用户态程序，但没有 UART、TTY、RS-485 或仪器使用经验。
- 主要目标是接入外设、阅读或移植 BSP、编写串口应用和定位通信故障，不是从零设计 UART IP。

### 3.3 前置知识

必须具备：二进制／十六进制、位和字节、C 数组／指针／返回值、`open/read/write/close`、设备树和 probe 的基本概念。

可以最小回顾并给准确指针：推挽、高阻、共地、通用设备模型、通用中断顶半部、逻辑分析仪与示波器的一般证据边界。

UART、TTY、serdev、termios、NMEA、Modbus 均不能预设读者已经理解。

- 5.1：正确连接后再讨论错接、耐压和收发器不匹配；不做破坏性故障注入。

## 9. 已确认的 B-B.5.1 节级方案

### 9.1 类型与主问题

类型：物理与电气机制篇。

主问题：NEO-6M 与 RK3568 UART4 为什么能够通过 TX／RX／GND 交换数据，软件人员怎样判断这条链路在电气上是否连接正确，以及什么时候必须增加收发器？

主实例：NEO-6M 模块 TX 向 RK3568 UART4 RX 连续输出 NMEA 数据。

- 输入：模块 TX 输出的 UART 信号。
- 物理路径：模块 TX → 开发板 UART4 RX，双方 GND 相连。
- 正常结果：信号到达正确接收引脚，高、低电平处于该 IO 允许且可识别的范围。
- 本篇不解释电平如何组成 `$` 或其他字节。

芯片、模块 breakout 和开发板不能混为同一个对象；供电电压、IO 电压和默认配置分别核验。

### 9.2 标题顺序与每节任务

1. **本节导读**
   - 先定义 UART 是什么、用途、发送／接收双方、TX／RX／GND。
   - 说明双方还需约定格式和速率，但细节归下一篇。
   - 随后给主问题和最小物理实例。

2. **先把一次接收落到 UART4 与 NEO-6M**
   - 区分 SoC、UART 控制器、模块和 breakout。
   - 说明为何使用 UART4，不默认占用调试 console。
   - 给出原理图、手册、教学假设的证据边界。
   - 建立责任线：原理图与接线／UART 控制器与驱动／用户程序，本篇只展开第一部分。

3. **发送端的 TX 为什么必须接接收端的 RX**
   - TX／RX 是各自设备的方向。
   - 单路接收的最小连接、反向发送何时需要、全双工／半双工／单工。
   - 使用真实内联 SVG，禁止 ASCII 连线。

4. **UART 与 TTL 为什么不是同义词**
   - UART 是串行收发机制，TTL 是电压表示方式。
   - 分别核对发送端输出、接收端识别和接收引脚耐受。
   - “能识别”和“不会损坏”是两个条件。

5. **供电电压、IO 电平与共地为什么要分别检查**
   - VCC 不能推导 IO 电平。
   - 板载 LDO 由具体模块证明。
   - 共地不等于连接所有电源正极，不能从信号线供电。
   - 软件配置不能解决 IO 过压。
   - 不预设某种电平转换器件万能适用。

6. **哪些问题能由 pinctrl 修，哪些只能改接线**
   - pinctrl 选择 SoC 内部功能到引脚的连接。
   - 它不能改变外部 TX 去向、GND 或 IO 耐压。
   - 本篇不写 DTS，节点和驱动建链归 5.3。

7. **USB 转串口在链路中替换了什么**
   - 分别介绍 USB 转 TTL、USB 转 RS-232、USB 转 RS-485。
   - 转接器输出侧电平比商品名“串口线”更重要。
   - 基础安装和终端配置只指向 1.4.1／1.4.2。

8. **同是 UART，为什么 RS-232 与 RS-485 都需要收发器**
   - 先分别介绍 RS-232 单端与 RS-485 差分，再比较。
   - UART 帧相同不代表电气可直接互连。
   - RS-485 的门限、共模、多节点、终端、偏置和 DE／RE 归 5.6。

9. **回到 UART4：怎样证明物理链路已经就绪**
   - 原理图和丝印确认引脚。
   - 断电检查连接。
   - 核对供电与 IO。
   - 上电测必要电压和空闲状态。
   - 在 RK3568 RX 附近观察模块输出。
   - 区分“有波形”“能解码”“模拟裕量充分”。

10. **本节总结与本节自查**
    - 散文总结；可展开 Q&A。
    - 不设方案对比、排障速查或下一步栏目。

### 9.4 正常路径与安全边界

正常路径：

```text
确认实际器件与资料
→ 确认 UART4 和模块引脚
→ 断电完成 TX→RX 与 GND
→ 核对供电和 IO 电平
→ 上电确认电压与空闲状态
→ 在接收端观察模块正常输出
```

错误路径放在正常路径之后：TX-TX、缺 GND、供电正确但 IO 不兼容、pinctrl 指向另一组引脚、误用 USB 转 RS-232、缺少必要收发器。
