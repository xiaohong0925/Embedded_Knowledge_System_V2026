# 嵌入式书写任务路由

以当前项目根目录为工作根目录。把本技能当作路由层：`agent.md` 与 `plan.md` 是唯一规则真源，不在本文件复制或改写其条款。

## 1. 建立最小上下文

1. 读取 `agent.md`、`plan.md`、目标正文及理解目标所需的必要前后文。
2. 若 `reviews/sections/<节号>.json` 已存在，读取它并用 `tools/check_review.py` 检查当前性；`current` 只表示记录和哈希有效，不表示教学质量通过。
3. 按 `agent.md` §13 判定 T0～T4 影响面，不因字数多少机械升级验收。
4. 先检查已有 Git 差异，保留用户和其他任务的修改，不批量回退或顺手整改。

## 2. 按信任层级加载资料

- **A：现行规则。** `agent.md`、`plan.md` 决定写作、修改与验收；其他资料与它们冲突时一律服从 A。
- **B：人工验证经验。** `docs/00-模板/B-B.3_I2C章级整改复盘与复用经验.md` 提供经用户连续人工复检形成的教学方法与反例。其他复盘只有在用户明确认可后才升入本层，AI 自评 `pass` 不足以升级。
- **C：设计意图参考。** 三篇大纲只提供篇目定位、内容边界、跨章分工和设计动机，不直接提供验收规则。
- **D：历史查询。** 索引、归档和旧设计稿只用于定位历史状态，不参与现行判断。

| 资料 | 加载时机与允许用途 |
|---|---|
| `docs/00-模板/全书框架设计学习整理_v1.md` | 主线新写、整篇重写或章级复检时读对应部与章；只取设计哲学、章级意图和跨章关系 |
| `docs/00-模板/扩展篇设计大纲_v1.md` | 扩展篇任务读对应扩展与篇目；只取定位、内容边界和分工 |
| `docs/00-模板/总线协议_2026深度调研与写作大纲_v3.md` | B 板块任务读对应总线与篇目；只取内容规划和跨章边界，继承自 v2 的旧格式要求同样无效 |
| `docs/00-模板/B-B.3_I2C章级整改复盘与复用经验.md` | B-B.3 必读；其他总线、Linux 子系统或 Framework Lab 任务优先作为人工验证正例，按问题选读 |
| `docs/00-模板/framework-lab-template/README.md` | 创建、修改或验收 Framework Lab |
| `docs/00-模板/section-review.template.json` | 需要建立新章节验收记录时 |
| 相近正例 | 新写或整篇重写时选择一篇，不堆叠全部范文；优先选 B 层实践，未经人工认可的章节只作候选 |
| 源码快照、厂商资料、`SOURCES.md` | 当前论述、调用链或教学代码实际依赖时 |

C 层资料中的固定栏目、数量配额、勾选清单、旧风格和历史完成状态均不得作为验收依据；发现内部冲突时记录并提交，不在新旧条款之间任选。`docs/index.md`、`docs/00-模板/AI复检归档.md` 和设计稿归档只按需查询，不通读。没有记录的历史章节不批量补录，也不据此推断质量合格或不合格。

### 阅读粒度与资料去重

1. 完整通读只用于 `agent.md`、`plan.md`、目标正文及必要的短前后文。大型大纲、复盘和正例先按标题定位，只读当前章节及直接关联区间；正例只读与当前障碍相近的结构或片段。
2. 内核源码、头文件和厂商手册先定位函数、结构体、宏、寄存器或命令，再读取包含定义、调用、正常路径和错误路径的必要区间。不得通读整份内核源码，不得为了“背景完整”扩展阅读。
3. 相邻章节只读目录、标题和实际重叠段落；需要判断跨章衔接时再读衔接段，不默认通读整篇。
4. 同一资料存在多个转换版本时，只选择与工具兼容且内容完整的一份。当前版本没有损坏或缺页证据时，不读取其他编码或转换副本；例如同一手册的 `.txt` 与 `.utf8.txt` 不得同时通读。
5. 在诊断或验收记录中保留证据路径、函数名和必要行号区间，使后续会话能回到原位置核验，而不是重新加载整份资料。

## 3. 执行任务

1. 遵守 `agent.md` 的诊断、用户确认、修改批量和源码核验流程；本技能不绕过确认闸口。
2. 用户已经确认诊断方案时，不重复全量诊断；只复核实际写入正文的结论和证据区间。若客户端显示第一阶段结束已超过 60% 上下文，停止扩展阅读，保留诊断与证据位置并换新会话重写，不在剩余上下文中强行整篇重写；没有客户端读数时不得编造上下文百分比。
3. 机械检查优先运行现有脚本。静态断言只用于防回归，不代替主问题、机制、代码跟随和四种读者的语义判断。
4. 仅修改用户批准的范围。局部修改不扩大为整篇重写，整篇重写不顺手修改其他章节。
5. 交互资产变化时运行对应章节的浏览器检查；没有交互变化时不默认执行全站浏览器回归。
6. 章节完成验收后，按模板更新对应记录；正文或规则再次变化后重新运行校验器，旧结果过期就标为 `stale`，不得继续写成当前通过。

## 4. 验收与汇报

按 `agent.md` §13 选择回归范围，并使用项目规定的用户 Python 执行严格构建：

```bash
"/c/Users/75672/AppData/Local/Python/pythoncore-3.14-64/python.exe" -m mkdocs build --strict
```

验收记录校验使用：

```bash
"/c/Users/75672/AppData/Local/Python/pythoncore-3.14-64/python.exe" tools/check_review.py reviews/sections/<节号>.json
```

分别汇报文档构建、静态检查、浏览器检查、教学代码编译、目标运行和硬件测量。未执行的项目写 `not_verified`，不适用才写 `not_applicable`；构建成功不得写成功能已验证。

不默认启用多智能体，不承诺技能会切换模型或降低模型档位，不把历史复盘自动提升为全局规则。
