# 嵌入式书写任务路由

本技能只负责路由，不携带另一套写作规则。`agent.md` 与 `plan.md` 是唯一规则真源。

## 建立最小上下文

1. 读取 `agent.md`、`plan.md`、目标正文及理解目标所需的必要前后文。
2. 检查已有 Git 差异，保留用户和其他任务的修改。
3. 按 `agent.md` §2 最多选择一类领域资料，只读当前篇目及直接关联部分；历史归档、旧设计稿、成本记录和验收 JSON 不作为写作规则。
4. 若 `reviews/sections/<节号>.json` 已存在，日常任务只用于恢复证据与验证状态，不默认刷新或运行 `check_review.py`；仅在 T2/T3 正式验收、用户统一批量验收或明确要求时检查当前性。`current` 不表示教学质量通过。
5. 按 `agent.md` §13 判定 T0～T4 影响面，选择相应检查范围。

## 资料使用边界

- 主线章、扩展篇和 B 板块分别使用 `agent.md` §2 指定的现行大纲，只取设计意图、内容边界和跨章分工。
- B-B.3 任务读取 I2C 人工复盘的对应部分；其他任务只有明确复用其经验时才选读。
- Framework Lab 任务读取 `docs/00-模板/framework-lab-template/README.md`。
- 源码和厂商手册只读取当前结论所需定义、正常路径、错误路径及证据区间；同一资料的重复转换版本不同时通读。
- 相近正例最多选择一篇，优先采用经人工认可的章节。旧 AI `pass` 不能作为正例或教学质量依据。

## 执行与验收

1. 遵守 `agent.md` 的诊断、用户确认、修改批量和源码核验流程；用户已确认方案时不重复全量诊断。
2. 只修改获批范围。静态测试防回归，不能代替连续阅读、机制推演和四种读者判断；T0/T1 局部修改不做全站构建、完整浏览器、窄屏测试或全局回归。
3. 验收 JSON 只在 T2/T3 正式验收、用户统一批量验收或明确要求时更新；日常局部修改不刷新哈希，旧记录可暂为 `stale`，不得把旧 `pass` 写成当前通过。
4. 严格构建按 `agent.md` §13 的影响面执行，不再每次写作默认运行。需要构建时使用项目指定 Python：

```bash
"/c/Users/75672/AppData/Local/Python/pythoncore-3.14-64/python.exe" -m mkdocs build --strict
```

5. 分别汇报文档构建、浏览器、教学代码编译、目标运行和硬件测量。未执行写 `not_verified`，不适用写 `not_applicable`；浏览器未执行时写 `not_verified（待统一桌面验收）`，不补跑手机或窄屏检查；构建成功不等于功能或教学质量已经验证。
6. 不默认启用多智能体，不承诺技能会切换模型或降低模型档位。
