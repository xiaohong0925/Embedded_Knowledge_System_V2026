41. EXP-1.1 开发板”体检”——器件与接口识别
42. 目标：能够独立指出开发板上所有关键器件的位置，说出其名称和大致功能。
43. 前置条件：已拿到开发板套件，已阅读本章1.2节。
44. 详细步骤：
45. 准备工作（2分钟）
46. 将开发板平放在光线充足的桌面上
47. 准备本章配套的开发板标注图（打印或电子版）
48. 准备一张白纸，画下板子的简单轮廓
49. SoC定位（3分钟）
50. 找到板子上最大的那一片BGA封装芯片（通常带有散热片或丝印标识）
51. 记录芯片丝印上的型号信息（如”Allwinner H6”、“RK3399”、“i.MX6ULL”等）
52. 在画的轮廓图上标记SoC位置，标注型号
53. 存储器件识别（4分钟）
54. 找到DDR芯片（通常是几片并排的BGA或LQFP封装，印有”SEC”、“Hynix”、“Micron”等字样）
55. 找到eMMC芯片（小尺寸BGA封装，印有容量标识如”8G”、“16G”）
56. 找到SD卡槽（侧面插入式或翻盖式）
57. 找到SPI Flash（如果有，通常是8脚SOP封装）
58. 在轮廓图上标记并标注容量
59. 电源相关器件（3分钟）
60. 找到电源输入接口（DC圆孔座或Type-C座）
61. 找到电源管理芯片（PMIC，通常靠近电源接口，丝印较小）
62. 找到板上的电源LED指示灯位置
63. 在轮廓图上标记
64. 接口与连接器识别（4分钟）
65. 从左到右、从上到下扫描板子边缘的接口
66. 识别：USB-A口、RJ45网口、HDMI口、音频口
67. 识别：调试串口排针（通常3~4针，旁边有”UART0”、“DEBUG”等丝印）
68. 识别：GPIO排针（双排或单排针座，旁边有引脚编号丝印）
69. 对照开发板手册核对
70. 填写”体检报告”（4分钟）
71. 使用本章配套的”开发板体检报告”表格模板
72. 填写所有识别到的器件和接口信息
73. 对于无法识别的器件，记录位置和形态，后续查阅手册
74. 预期结果： - 完成一张手写的开发板器件分布图 - 填写完整的”体检报告”表格 - 能够不看手册说出至少8个关键器件/接口的名称和用途
75. 常见错误与排障：
76. EXP-1.2 USB转串口环境搭建
77. 目标：在PC上完成USB转串口模块的驱动安装，能在设备管理器（或等效工具）中看到串口设备。
78. 前置条件：已准备好USB转串口线（CH340/CP2102/FT232），PC已联网。
79. 详细步骤：
80. 识别USB转串口芯片型号（2分钟）
81. 查看USB转串口模块上的主控芯片丝印
82. 常见型号：CH340G（南京沁恒）、CP2102（Silicon Labs）、FT232RL（FTDI）、PL2303（Prolific）
83. 记录型号
84. 下载并安装驱动（5分钟）
85. Windows用户：
86. CH340：访问沁恒官网(wch.cn)下载驱动
87. CP2102：Windows 10+通常自动识别，或访问Silabs官网下载
88. FT232：Windows Update通常自动安装
89. Linux用户：
90. CH340/CP2102/FT232驱动通常已内置在内核中
91. 执行lsusb查看设备是否被识别
92. Mac用户：
93. 新版macOS通常内置CH340/CP2102驱动
94. 可能需要安装CH340驱动（macOS 12+有内置）
95. 验证驱动安装（3分钟）
96. Windows：打开设备管理器→展开”端口(COM和LPT)“→应看到”USB-SERIAL CH340 (COMx)“等
97. Linux：执行ls /dev/ttyUSB*（CH340/FT232）或ls /dev/ttyACM*（部分CP2102），应显示设备节点
98. Mac：执行ls /dev/cu.*或ls /dev/tty.*，应看到cu.wchusbserial*或cu.SLAB_USBtoUART等
99. 记录串口标识（2分钟）
100. 记录COM口号（Windows）或设备节点路径（Linux/Mac）
101. 这个标识在后续实验中会用到
102. 拔掉USB线，确认设备消失；重新插入，确认设备出现（验证稳定性）
103. 波特率兼容性测试（3分钟，可选）
104. 使用串口工具的loopback测试功能（如果模块支持）
105. 或跳过，在下一个实验中自然验证
106. 预期结果： - PC能稳定识别USB转串口设备 - 已记录可用的串口标识符（COM口号或/dev设备节点） - 确认驱动工作正常（拔插测试通过）
107. 常见错误与排障：
108. EXP-1.3 硬件连接与串口终端配置
109. 目标：正确完成开发板与PC之间的所有物理连接，配置串口终端软件并建立通信。
110. 前置条件：已完成EXP-1.2，USB转串口可用。
111. 详细步骤：
112. 连接前的安全确认（2分钟）
113. 开发板未连接电源
114. USB转串口未连接PC
115. 检查开发板表面是否有异物、焊锡短路等
116. 连接调试串口（3分钟）
117. 找到开发板上的调试串口排针（通常为3针或4针）
118. 识别排针定义：GND（地线）、TXD（发送）、RXD（接收），部分有VCC（3.3V或5V）
119. 使用杜邦线连接：
120. USB转串口TX → 开发板RX
121. USB转串口RX → 开发板TX
122. USB转串口GND → 开发板GND
123. 重要：TX和RX必须交叉连接！VCC针通常不接（除非特殊说明）
124. 连接USB转串口到PC（1分钟）
125. 将USB转串口模块插入PC的USB口
126. 确认PC已识别（参考EXP-1.2的验证方法）
127. 打开串口终端软件并配置（5分钟）
128. Windows（MobaXterm）：
129. Session → Serial → 选择COM口号
130. Speed: 115200
131. 点击OK
132. Linux（minicom）：
133. sudo minicom -s → Serial port setup
134. A - Serial Device: /dev/ttyUSB0
135. E - Bps/Par/Bits: 115200 8N1
136. F - Hardware Flow Control: No
137. Save setup as dfl → Exit
138. Linux（picocom）：picocom -b 115200 /dev/ttyUSB0
139. Mac（screen）：screen /dev/cu.wchusbserial* 115200
140. 连接电源前的最终检查（2分钟）
141. 串口线连接正确（TX-RX交叉、GND连通）
142. 串口终端已打开并配置正确
143. 电源适配器电压与开发板要求一致（通常是5V或12V）
144. DC头极性正确（内正外负为常见标准）
145. 连接电源（2分钟）
146. 将电源适配器插入开发板电源接口
147. 开发板电源LED应亮起（不同板子可能不同颜色，通常为红色或绿色）
148. 观察串口终端是否有输出
149. 预期结果： - 开发板电源LED正常亮起 - 串口终端成功打开无报错 - 在下一步实验中能看到启动输出（本实验不严格要求看到输出）
150. 常见错误与排障：
151. EXP-1.4 第一次上电——观察启动信息
152. 目标：完成开发板首次上电，观察并解读U-Boot的启动日志，理解启动信息的含义。
153. 前置条件：已完成EXP-1.3，开发板已正确连接。
154. 详细步骤：
155. 确认终端就绪（1分钟）
156. 串口终端已打开，配置为115200 8N1
157. 终端窗口清晰可见，准备记录
158. 上电（1分钟）

277. 7. 各知识点详细编写说明
278. 7.1 关键知识点深度设计
279. 知识点6 [B][M] — SoC（System on Chip）— 1,200字
280. 应该写什么： - SoC的概念：把CPU、GPU、内存控制器、外设控制器都集成在一颗芯片上 - 外观识别：BGA封装的特点（看不到引脚，背面是焊球阵列），散热片的常见形态 - 丝印信息解读：型号命名规则（如Allwinner H6、Rockchip RK3399、NXP i.MX6ULL） - 为什么是”片上系统”而不是”处理器”：与单片机MCU的区别（SoC通常需要外部DDR才能运行）
281. 应该配什么代码/图示： - 配图：SoC芯片的实物特写照片（带散热片和不带散热片两种） - 配图：BGA封装底部焊球阵列的显微镜照片（可选） - 对比表：SoC vs MCU vs CPU的区别
282. 容易遇到什么误区： - 读者可能把SoC和CPU混为一谈 → 需要明确区分 - 读者可能不知道SoC本身不能独立运行 → 强调需要外部DDR和存储
283. 知识点19 [I][M] — 存储金字塔 — 1,200字
284. 应该写什么： - 存储层次的概念：从最快的寄存器到最慢的外部存储 - 每一层的特点：速度、容量、成本、易失性的对比 - 在嵌入式系统中的映射： - 寄存器：CPU内部（纳秒级访问） - SRAM：SoC片内（BootROM运行于此，微秒级） - DDR：板载内存（毫秒级初始化后才能使用） - eMMC/SD：板载/外部大容量存储（持久化） - SPI-NOR：小容量、可字节寻址（存储Bootloader） - 为什么需要这样的层次：速度vs成本的权衡
285. 应该配什么代码/图示： - 核心配图：存储金字塔图（纵向：速度从快到慢，横向：容量从小到大） - 对比表：各存储介质的具体参数对比（访问时间、容量范围、价格区间、易失性） - 示意图：数据在各层之间的流动路径
286. 容易遇到什么误区： - 读者可能不理解”易失性”和”非易失性” → 用断电后数据是否保留来解释 - 读者可能分不清DDR和Flash → 强调一个是”运行内存”（类似PC的内存条），一个是”硬盘”（存储数据）
287. 知识点33 [B][M] — 三步连接法 — 1,200字
288. 应该写什么： - 安全连接顺序的重要性：错误的顺序可能导致设备损坏或PC USB口保护触发 - 三步法的详细步骤： 1. 第一步：开发板不连接电源 2. 第二步：先连接串口线（USB转串口插PC，杜邦线接开发板调试口） 3. 第三步：最后连接电源，观察启动 - 为什么是这个顺序： - 串口先接好可以在上电瞬间 capture 到所有输出（有些启动信息非常快） - 电源最后接是安全习惯，避免带电插拔 - 拔下时的反向顺序：先断电源→再拔串口

476. 确认架构：file hello_cross应显示目标架构
477. 编译更复杂程序：带#include <stdio.h>、带math.h的-lm链接
