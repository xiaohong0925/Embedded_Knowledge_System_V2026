# 构建与观察：教学模块怎样验证并移交产品路径

> 所属章节：第五部 B. 总线协议 > B-B.4 SPI 总线 > B-B.4.3 SPI Linux 驱动框架
>
> 本组阅读：第 6 页，共 6 页

本页只回答一个问题：**怎样构建、加载并观察同一笔事务，为什么正式 W25Q 产品仍应进入 spi-nor 和 MTD？**

---

## <span class="blue"> 让同一教学模块走完构建、绑定与传输

前文已经在源码中组好了一笔 Fast Read 事务：向 W25Q128JV 的地址 `0x001234` 发送 5 字节前导，再接收 4 字节数据。现在不再改换实例，而是把同一个 `spi_frame_observer` 模块放到目标内核环境中，依次确认它能构建、能与 DTS 节点匹配、能提交传输，也能在卸载时走完解绑路径。

这条实践路径的职责边界保持不变：板级 DTS 描述 SPI1 CS0 上的教学设备，SPI Core 据此创建 `spi_device`；模块注册 `spi_driver`，匹配成功后进入 probe；probe 调用前述读取函数，由 Core 和控制器驱动完成实际传输。教学模块只负责理解这笔器件帧并观察结果，不承担完整 Flash 产品功能。

### 构建模块前先匹配目标内核

外部模块必须针对目标板的内核配置和构建树编译。`KDIR` 指向内核构建目录，其中需要有匹配内核的 Makefile、配置和头文件；只下载若干源码快照不能替代完整构建树。

本机针对正在运行的内核构建时，进入配套目录后执行：

```bash
cd "docs/B. 总线协议/B. 低速外设接口/code/B-B.4.3"
make KDIR=/lib/modules/$(uname -r)/build
```

为 RK3568 的 ARM64 内核交叉构建时，把 `KDIR` 换成实际使用的内核构建树，并使用已经安装的 ARM64 交叉工具链：

```bash
make KDIR=/path/to/linux-v6.6 ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
```

交叉编译是在 x86_64 开发机上生成 ARM64 目标文件。命令中的 `ARCH` 选择目标架构，`CROSS_COMPILE` 指定工具链前缀；两者随递归调用的内核 make 传递。本机构建则沿用内核构建树的默认架构设置。

配套 [`Makefile`](code/B-B.4.3/Makefile){: data-code-viewer="true" data-code-title="Makefile" data-code-path="本篇教学配套 · code/B-B.4.3/Makefile"} 的完整内容如下，构建目标是 `spi_frame_observer.ko`：

```makefile
obj-m += spi_frame_observer.o

KDIR ?= /lib/modules/$(shell uname -r)/build

all:
	$(MAKE) -C $(KDIR) M=$(CURDIR) modules

clean:
	$(MAKE) -C $(KDIR) M=$(CURDIR) clean
```

`obj-m` 请求把源文件构建为可加载模块；`-C $(KDIR)` 先进入内核构建树，`M=$(CURDIR)` 再让内核构建系统回到当前外部模块目录。命令行显式给出的 `KDIR` 会覆盖这里的默认值，因此同一份 Makefile 可以用于本机构建和交叉构建。

完整驱动实现见 [`spi_frame_observer.c`](code/B-B.4.3/spi_frame_observer.c){: data-code-viewer="true" data-code-title="spi_frame_observer.c" data-code-path="本篇教学配套 · code/B-B.4.3/spi_frame_observer.c"}。其中 probe 固定读取地址 `0x001234`，读取函数检查 `spi_sync()` 的返回值，并要求 `message.actual_length` 等于 5＋4 字节后才复制接收数据；解绑时只记录 `unbound` 日志。这些动作决定了后文应该观察什么。

### 让教学节点随板级 DTB 生效

模块与设备不会仅凭文件名建立关系。教学 DTS 片段提供 `compatible = "kimi,spi-frame-observer"`，与驱动中的 OF 匹配表对应；`reg = <0>` 指定 CS0，`spi-max-frequency` 把本例最高速率限制为 1 MHz。

配套 [`spi-frame-observer.dts`](code/B-B.4.3/spi-frame-observer.dts){: data-code-viewer="true" data-code-title="spi-frame-observer.dts" data-code-path="本篇教学配套 · code/B-B.4.3/spi-frame-observer.dts"} 是完整的板级 DTS 片段，不是可独立编译的 DTS，也不是带 `/plugin/` 的 overlay：

```dts
&spi1 {
	status = "okay";

	spi_frame_observer: spi-frame-observer@0 {
		compatible = "kimi,spi-frame-observer";
		reg = <0>;
		spi-max-frequency = <1000000>;
	};
};
```

把该片段合入实际板级 DTS，再使用完整内核或 BSP（Board Support Package，板级支持包）构建树重编 DTB。DTB 是 DTS 编译得到的二进制设备树，启动时由内核读取。通用内核树可以在合入后执行：

```bash
make -C /path/to/linux-v6.6 ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- dtbs
```

实际部署只更新目标板对应的 DTB，保留可恢复的原启动配置，并按板卡方式重新启动使新节点生效。节点生效后，SPI1 CS0 对应的设备名为 `spi1.0`。

> 🔴 这个实验会改变 SPI1 CS0 的驱动绑定。应用 DTS 前必须替换或禁用占用该片选的其他子节点，确认 `spi1.0` 没有被 spi-nor 或其他驱动占用；只在受控、只读的教学条件下加载观察模块，不要把它直接用于在用的存储设备。

### 用绑定关系和两类日志核对运行路径

目标板已经具备匹配的新 DTB、刚构建的 `spi_frame_observer.ko`，并满足上述只读实验条件后，按正常加载、观察、卸载的顺序执行：

```bash
insmod spi_frame_observer.ko
dmesg | grep -E 'spi_frame_observer|spi1.0'
ls -l /sys/bus/spi/devices/spi1.0/driver
rmmod spi_frame_observer
dmesg | grep -E 'spi_frame_observer|spi1.0'
```

`insmod` 加载模块并注册 SPI 驱动。若 `spi1.0` 与 OF 匹配表对应，内核进入 probe，先记录设备参数，再发起同一笔 Fast Read。第一条 `dmesg` 用于观察匹配和读取结果，`ls -l` 通过 `driver` 软链接核对当前绑定对象；`rmmod` 卸载模块并触发 remove，第二条 `dmesg` 再观察解绑记录。

若设备匹配成功，且 Flash 在地址 `0x001234` 的教学假设内容为 `A7 5C 3F 19`，两次 dmesg 合起来可以看到以下格式的日志：

```text
spi_frame_observer spi1.0: matched: cs=0, mode=0x0, max_speed_hz=1000000, bits_per_word=8
spi_frame_observer spi1.0: fast_read: ret=0, addr=0x001234, data=a7 5c 3f 19
spi_frame_observer spi1.0: unbound
```

**这只是预期输出样式，不是本项目实板日志。** 阅读时应把三行分别对应到三个阶段：

1. `matched` 表明已经进入该设备的 probe；`cs=0` 对应 DTS 的 CS0，`mode=0x0` 表示未设置额外模式位，`max_speed_hz=1000000` 和 `bits_per_word=8` 是驱动打印的设备参数。
2. `fast_read` 表明读取函数已经走到成功日志；`ret=0` 表示这次 SPI 同步调用在软件层面成功，地址与数据来自同一笔请求。源码还要求完成长度等于 9 字节，否则以 `-EIO` 返回，不会把短传输当作完整读取。
3. `unbound` 对应 `rmmod` 触发的 remove 路径，说明教学驱动已经走到解绑动作；它不代表 Flash 产品功能已经完成。

若读取返回负错误码，probe 会记录失败值并返回错误，不应把随后缺少成功数据行解释为“读到了全零”。此时保留错误值，沿“设备是否创建、驱动是否匹配、传输是否提交、控制器是否报错”分层定位。具体 spidev 命令、逻辑分析仪设置和示波器测量由 B-B.4.4 展开。

即使输出与上述样式一致，也只能证明该次软件路径完成了匹配、传输和字节返回。它不能单独证明全部电气裕量、长期稳定性或其他地址内容，更不能替代目标板运行和仪器测量。

### 正式 W25Q 产品改走 spi-nor 与 MTD

教学驱动故意绕过上层 Flash 框架，让设备匹配、message 分段和传输结果保持可见。这个取舍适用于观察，却不适用于正式产品：它没有实现器件识别、擦除、编程、分区和上层存储接口。

实际产品中的 W25Q128JV 应优先使用内核已有的 spi-nor 驱动。spi-nor 读取 JEDEC 标准定义的制造商标识和器件标识，处理擦除与编程约束，再接入 MTD。

> MTD：Memory Technology Devices，Linux 面向 NOR、NAND 等原始闪存设备的子系统。它向上提供擦除、读写和分区等接口，不等于 SPI 控制器驱动。

因此，正式节点的 `compatible`、识别流程、分区、烧录与校验应走 B-B.4.5 的 `jedec,spi-nor → MTD` 路径。本篇教学模块的 `kimi,spi-frame-observer` 只服务于受控观察，不应作为量产 Flash 的绑定入口，也不应被复制成产品驱动。

## <span class="blue"> 本节总结

读懂 SPI Linux 驱动框架，关键不是背出三层或五个结构体，而是能沿一笔事务说清对象的交接：DTS 建出 `spi_device`，匹配得到 `spi_driver`，协议驱动把器件帧翻译成 message 和 transfer，Core 调度，控制器驱动完成位移，最后把状态和数据带回同一个调用点。构建、绑定日志、传输结果和解绑日志分别验证这条路径的不同环节，任何一项都不应被扩大解释为完整硬件或产品验证。

手工 message 适合展示分段、CS、缓冲区和返回路径；`spi_write_then_read()` 适合缩短小量“写后读”代码，但不会替调用者理解器件帧。教学观察可以暂时绕过上层框架，正式 W25Q 产品仍应进入 spi-nor 和 MTD，不让一个 probe 示例承担完整存储系统的职责。

**速查表**

| 对象或操作 | 在本例中的责任 | 验证重点或边界 |
|---|---|---|
| `KDIR` 与交叉参数 | 选择匹配的内核构建树、目标架构和工具链 | 源码快照不能替代完整构建树 |
| 教学 DTS 与 DTB | 描述 SPI1 CS0 上的观察设备 | 合入板级 DTS，重建并部署目标板 DTB |
| `spi_frame_observer.ko` | 注册协议驱动并执行只读 Fast Read | 只在目标内核与实验条件匹配时加载 |
| `matched` 与 `driver` 链接 | 核对匹配、probe 入口和当前绑定 | 匹配成功不等于传输已经成功 |
| `fast_read` 日志 | 观察地址、返回值和 4 字节接收结果 | 预期样式不是实板日志，也不证明电气裕量 |
| `unbound` 日志 | 观察卸载时的 remove 路径 | 不代表上层存储功能已经验证 |
| `spi_controller` | 表示 RK3568 SPI1 及其硬件能力 | Rockchip probe 创建，控制器注销后失效 |
| `spi_device` | 表示 SPI1 CS0 上的教学设备 | Core 根据 DTS 创建并注册 |
| `spi_driver` | 理解 Fast Read 并构造传输 | 模块加载注册，卸载注销 |
| `spi_message` | 组织一次 5＋4 字节事务 | 同步调用期间有效，记录状态与完成长度 |
| `spi_transfer[0]` | 发送 `0B 00 12 34 00` | 长 5，丢弃同时接收的数据 |
| `spi_transfer[1]` | 提供时钟并接收 4 字节 | 长 4，同时移出零 |
| `spi_sync()` | 可睡眠的同步传输 | 成功 0，失败负错误码，不返回字节数 |
| `cs_change` | 请求改变 CS 行为 | 非末段与末段语义不同，本例保持 0 |
| `spi_write_then_read()` | 小量写后读的复制型封装 | 内部仍组 message 并调用 `spi_sync()` |
| 产品路径 | W25Q128JV 使用 spi-nor → MTD | 不使用教学 compatible 作为产品绑定 |

## <span class="blue"> 本页自查

??? details "Q8. 为什么教学模块能读 Fast Read，却不应成为正式 W25Q128JV 产品驱动？"

    教学模块只用于观察 SPI 设备匹配和传输路径，没有实现 Flash 识别、擦除、编程、分区和上层接口。即使日志证明某次软件事务成功，也不能推出这些职责已经实现。正式产品应使用已有的 spi-nor 驱动并接入 MTD，避免重复实现存储器件约束。
